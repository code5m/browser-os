## Product direction

Keep the current Chrome-like mental model: compact tabs and navigation above a large working surface. Add IDEA-style tool-window behavior and command discoverability without turning the whole application into an IDE clone.

The default view is calm and content-first. Advanced functions live in collapsible tool windows, context menus and a searchable command entry. A user can reveal power without permanently losing viewport.

## Global acceptance constraints

- At 1440x900, collapsed mode reserves at least 85% of the post-titlebar height and at least 92% of width for the active content.
- The normal top chrome uses at most two compact rows and at most 80px total height.
- Side tools and bottom tools support: open, close, collapse all, restore previous layout, expand active, pin, unpin, auto-hide and resize.
- Every hierarchical view supports collapse all, expand one level and bounded expand all; large trees must not freeze the UI.
- Only one primary tool window per edge is open by default; opening another on the same edge replaces it unless pinned.
- Full focus mode hides all tool chrome while preserving one obvious return action.
- No large dashboard cards, oversized feature buttons, permanent multi-panel squeeze, or duplicated navigation.
- Every context-menu action also has a command-registry identity, disabled reason, keyboard/accessibility path and safety class.
- Right-click menus are scoped to the object under the pointer; they do not become unstructured catch-all menus.
- Prototypes cover 1920x1080, 1440x900, 1366x768 and 1024x720, plus empty/loading/error/disabled/context-menu states.
- Research prototypes are self-contained and synthetic. No product source, dependency, ACL, capability, native runtime or user data changes.

## Git reference boundary

Use behavior and information architecture from:

- SourceGit, MIT: https://github.com/sourcegit-scm/sourcegit
- slio-git, MIT/Apache-2.0: https://slio-git.skwang.uk/

Required Git workflow: repository switch, status, stage/unstage file and hunk, unified/side-by-side diff, commit, amend, log/graph, branch, remote, worktree, stash, merge, rebase, interactive rebase, cherry-pick, revert/reset, conflict resolution, blame/file history, patch and command log.

Do not copy branding or assets. Exact source reuse remains subject to A10 provenance and license review. If “rebases” names a different project, A7 records it as an additional reference after A0/user supplies the exact identity.
