# SCR-20261125: Browser native mutation receipts and protected Coding execution

**Decision:** Owner-approved target, ADR-20261125 D01/D03/D04/D05/D06/D08. User explicitly requested implementation and durable decisions on 2026-11-25. Source candidate only; validation NOT_RUN.

## Semantic scope

The existing useBrowserStore remains owner of browser product state, and the existing native Browser owner remains responsible for WebView instances/layout. The receipt adapter serializes existing host mutations; it is not a second tab list or page lifecycle manager. Prepare/poll/inspect/ack do not dispatch a WebView effect. Start admits the stored action at most once per ticket. Cancel before dispatch terminates the request; a running cancellation request does not claim that the engine stopped. Only terminal host receipts can be acknowledged; unknown outcomes retain admission. Host dispatch is not renderer paint or navigation completion.

The existing Coding session owns the authenticated run receipts and Foundation task snapshot. A pending approval does not become task success; unknown external effects require explicit reconciliation. The existing Foundation TaskRegistry is reused, rather than introducing another task engine. Reviewed no-replace export is distinct from shared-file in-place apply; it does not overwrite proposal targets.

## Registry and gates

Native command inventory declares tab_mutation as Browser-owned, main-only. The legacy main-only mutation commands share its admission lane. Existing position/hide contracts and semantic registry owners do not change. No checker exclusions, whitelist of failures, or gate changes. Existing task and side-effect product semantics are preserved; this SCR records the internal receipt semantics and explicit owner-approved recovery boundary.

## Remaining evidence and accepted limitations

Full renderer cancellation / engine allocation isolation, complete Foundation tool-loop convergence, recovery after a frontend restart (including a usable UI for inspect/reconcile/ack), internal native bypass paths, GTK incident stacks, and platform-specific behavior still require verification or implementation as documented. Never treat a host receipt as a renderer completion certificate. Record all future regressions. No CI, tests, build, GUI verification or installation executed.


## Text-only durable continuation (2026-11-26)

Existing main-only ai_service request fields serve run_history/run_restore/run_continue/run_forget. Catalog pages are bounded and expose only authenticated project-free text records; a live/unreadable record is not represented as terminal. Explicit continuation reserves exactly one successor and its normalized input in the encrypted predecessor before dispatch. An interrupted text Task retains its Task/Session identity under a fresh Run; a new chat turn creates a new Task in the same Session. The provider is revalidated against current configuration; no persisted credential or tool grant. A committed successor may return its saved result without provider replay. An unpublished reservation is recoverable only with the same successor identity and input. Explicit terminal payload forgetting preserves replay identity and does not erase other records' context copies. Existing Coding/MCP effects remain outside these text-only actions. No command parameter, permission, checker or locked native layout change. NOT_RUN.


## Manual MCP durable effect evidence (2026-11-26)

The existing main-only coding_service accepts a stable manual run_id and bounded manual_mcp_history/manual_mcp_receipt/manual_mcp_reconcile actions. New manual receipts bind the native workspace directory identity, review digest and transport disposition. Queries authenticate/classify scope before recovery writes. A reconciliation is a bounded, revision-checked user observation; it is not proof of remote effect or executor exit, does not clear operation_unknown, and does not authorize old-run replay. Existing exact MCP review, credentials and process termination path remain the execution authority. No new native command or permissions. NOT_RUN.


## Experimental Channel checkpoint and recovery

Existing main-only ai_service fields carry channel_history/channel_restore/channel_fixture/channel_read/channel_resume/channel_forget. Offline fixture assignment or exact read-only arguments are authenticated before dispatch; same UUID and input may return a committed eligible result, never re-dispatch. An interrupted record reserves one successor under its OS lock and restores the same Task/Session, pinned offline engine and exact read resource. Read continuation obtains fresh local signed approval and still validates the original public capability. A shared blocking lane retains capacity across a dropped/timed-out read future. Old metadata-only receipts are view-only; pure A/B benchmark remains offline. No new native command signature or remote permission. NOT_RUN.


## Shared capture owner and independent mode

Existing capture_full_page request gains optional mode (default current_document) and expected_url for the explicit independent_address mode. Legacy invocation remains unchanged. Existing main-only source policy, tab identity/address binding, epoch, sequence, cancellation, receipt and ACK apply. The independently rendered address is a fresh request without live browser profile state. Shared process owner retains handles and retries retirement after first cleanup deadline; only confirmed exit allows publication or terminal cancellation. Live dispatch uses the existing bounded BlockingLane, so a revoked queued callback cannot multiply stalled native dispatch workers. Reversible app exit preflight cancels and waits for an active independent render before saving sessions; if cleanup remains unknown, exit is refused without changing the existing Session save contract. Source-only; NOT_RUN.


## Coding model checkpoint continuation

The existing main-only coding_service action gains resume_turn (explicit confirmation, exact previous_run_id, new registered run_id, same workspace/session). Native provider configuration is resolved once per model Run; the encrypted session stores only its non-secret fingerprint, plan/build mode, system/tool schema digest, and whether more model work is pending. Resume requires an authenticated paused Task, completely paired transcript, no unresolved operations or staged changes, unchanged provider/schema/mode, and the latest model Run. It appends a linked Run, not a duplicate user message; no previously approved external effect is executed by resume. Provider failure or cancellation cannot terminalize a Task with outstanding review work. File apply with unfinished model work preserves the paused Task and records that reviewed changes were applied. Legacy sessions without a binding remain readable, not eligible for exact continuation. Credential resolution uses the current keyring token; never serialize it. NOT_RUN.

## Frontend reattachment boundary (2026-11-26)

A mounted shell observes the native owner and adopts only a sequence-fenced, confirmed tab list. Initial attachment does not request cancellation of a still-running receipt; explicit recovery remains available. Shell unload no longer closes an active tab as an implicit side effect. The existing native graceful-exit coordinator remains authoritative for shutdown. Pending external URLs are left in the native queue while recovery is blocked; only one dequeued batch is processed, and an attempted URL is never automatically replayed after an unknown outcome. Source and regression fixtures only, not an installed GUI result.

## P0 native fault-domain recovery completion candidate (2026-11-26)

In addition to automatic continuous UI-heartbeat recovery, a responsive shell can explicitly request whole-application domain recovery for an unknown native receipt or a native worker/background owner that has actually entered and remains unresolved for at least 60 seconds. Preparation, queued work, terminal receipts, lost IPC alone, stale epochs/sequences and unsupervised launches are not eligible. The existing main-only tab_mutation request carries the confirmed exact epoch, admission sequence and ticket; a 15-second intent is revalidated by the existing authenticated supervisor after acquiring the same exit-admission latch as graceful shutdown. The original Browser Owner fences replacement admission while the recovery claim lives. A late result invalidates the unclaimed intent; disconnect releases the claim without inventing a terminal receipt. The supervisor still requires kernel domain-empty, original child exit and Linux guard retirement before its single bounded replacement launch, with no original argv or request replay. The UI explicitly warns that unsaved volatile state can be lost. No separate renderer, native command, permission expansion or new owner runtime; no locked GTK layout changes. Linux requires the supported delegated/systemd process domain, Windows requires the existing Job owner. Source and positive/negative regression fixtures only; CI, installed GUI, fault injection and platform evidence NOT_RUN. This is whole-application fault recovery, not single-renderer forced cancellation.

## Production Agent execution-loop convergence (2026-11-26)

All supported model paths retain the existing Foundation TaskRegistry and native ProductionExecution authority. General chat, installed text-only legacy Agent, local Ollama, and durable text resume now receive the actual native execution lease at the adapter boundary and invoke the owned complete-message engine; no production text-only adapter invokes the unowned helper. The combined cancellation predicate reaches HTTP provider admission/response handling, and the local loopback reader polls cancellation with a bounded read timeout. Coding retains its transcript, workspace checks and staged proposals, while checking the same lease at each tool admission and before accepting a completed batch. Native streaming and experimental Rig use ModelTurnGate; Rig now holds that gate across SDK transitions, provider transport, proposal and terminal publication, not just the transport await. The shared ToolRegistry supplies an opaque task/registry/revision/call-bound successful result receipt; the Rig SDK cannot accept arbitrary JSON as proof of an approved tool execution. Receipt ingestion itself uses the same task lease. Read-only experimental Channel keeps its signed host-approved capability route; native command/MCP adapters retain the existing durable approval and effect checkpoints rather than introducing another execution manager. These source changes do not grant new model-selected native effects or assert automatic reconciliation of a remote MCP side effect. Positive and negative fixtures are added, all runtime/CI/GUI verification NOT_RUN.
