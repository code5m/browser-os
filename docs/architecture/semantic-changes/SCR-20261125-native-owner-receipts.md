# SCR-20261125: Browser native mutation receipts and protected Coding execution

**Decision:** Owner-approved target, ADR-20261125 D01/D03/D04/D05/D06/D08. User explicitly requested implementation and durable decisions on 2026-11-25. Source candidate only; validation NOT_RUN.

## Semantic scope

The existing useBrowserStore remains owner of browser product state, and the existing native Browser owner remains responsible for WebView instances/layout. The receipt adapter serializes existing host mutations; it is not a second tab list or page lifecycle manager. Prepare/poll/inspect/ack do not dispatch a WebView effect. Start admits the stored action at most once per ticket. Cancel before dispatch terminates the request; a running cancellation request does not claim that the engine stopped. Only terminal host receipts can be acknowledged; unknown outcomes retain admission. Host dispatch is not renderer paint or navigation completion.

The existing Coding session owns the authenticated run receipts and Foundation task snapshot. A pending approval does not become task success; unknown external effects require explicit reconciliation. The existing Foundation TaskRegistry is reused, rather than introducing another task engine. Reviewed no-replace export is distinct from shared-file in-place apply; it does not overwrite proposal targets.

## Registry and gates

Native command inventory declares tab_mutation as Browser-owned, main-only. The legacy main-only mutation commands share its admission lane. Existing position/hide contracts and semantic registry owners do not change. No checker exclusions, whitelist of failures, or gate changes. Existing task and side-effect product semantics are preserved; this SCR records the internal receipt semantics and explicit owner-approved recovery boundary.

## Remaining evidence and accepted limitations

Full renderer cancellation / engine allocation isolation, complete Foundation tool-loop convergence, recovery after a frontend restart (including a usable UI for inspect/reconcile/ack), internal native bypass paths, GTK incident stacks, and platform-specific behavior still require verification or implementation as documented. Never treat a host receipt as a renderer completion certificate. Record all future regressions. No CI, tests, build, GUI verification or installation executed.


## Text-only durable continuation (2026-11-26)

Existing main-only ai_service request fields serve run_history/run_restore/run_continue/run_forget. Catalog pages are bounded and expose only authenticated project-free text records; a live/unreadable record is not represented as terminal. Explicit continuation reserves exactly one successor and its normalized input in the encrypted predecessor before dispatch. An interrupted text Task retains its Task/Session identity under a fresh Run; a new chat turn creates a new Task in the same Session. The provider is revalidated against current configuration; no persisted credential or tool grant. A committed successor may return its saved result without provider replay. An unpublished reservation is recoverable only with the same successor identity and input. Explicit terminal payload forgetting preserves replay identity and does not erase other records' context copies. Existing Coding/MCP effects remain outside these text-only actions. No command parameter, permission, checker or locked native layout change. NOT_RUN.


## Manual MCP durable effect evidence (2026-11-26)

New manual receipts bind the native workspace directory identity, review digest and transport disposition. Queries authenticate/classify scope before recovery writes. A reconciliation is a bounded, revision-checked user observation; it is not proof of remote effect or executor exit, does not clear operation_unknown, and does not authorize old-run replay. Existing exact MCP review, credentials and process termination path remain the execution authority. No new native command or permissions. NOT_RUN.


## Experimental Channel checkpoint and recovery

## Shared capture owner and independent mode

Existing capture_full_page request gains optional mode (default current_document) and expected_url for the explicit independent_address mode. Legacy invocation remains unchanged. Existing main-only source policy, tab identity/address binding, epoch, sequence, cancellation, receipt and ACK apply. The independently rendered address is a fresh request without live browser profile state. Shared process owner retains handles and retries retirement after first cleanup deadline; only confirmed exit allows publication or terminal cancellation. Live dispatch uses the existing bounded BlockingLane, so a revoked queued callback cannot multiply stalled native dispatch workers. Reversible app exit preflight cancels and waits for an active independent render before saving sessions; if cleanup remains unknown, exit is refused without changing the existing Session save contract. Source-only; NOT_RUN.


## Coding model checkpoint continuation

The existing main-only coding_service action gains resume_turn (explicit confirmation, exact previous_run_id, new registered run_id, same workspace/session). Native provider configuration is resolved once per model Run; the encrypted session stores only its non-secret fingerprint, plan/build mode, system/tool schema digest, and whether more model work is pending. Resume requires an authenticated paused Task, completely paired transcript, no unresolved operations or staged changes, unchanged provider/schema/mode, and the latest model Run. It appends a linked Run, not a duplicate user message; no previously approved external effect is executed by resume. Provider failure or cancellation cannot terminalize a Task with outstanding review work. File apply with unfinished model work preserves the paused Task and records that reviewed changes were applied. Legacy sessions without a binding remain readable, not eligible for exact continuation. Credential resolution uses the current keyring token; never serialize it. NOT_RUN.

## P0 native fault-domain recovery completion candidate (2026-11-26)

In addition to automatic continuous UI-heartbeat recovery, a responsive shell can explicitly request whole-application domain recovery for an unknown native receipt or a native worker/background owner that has actually entered and remains unresolved for at least 60 seconds. Preparation, queued work, terminal receipts, lost IPC alone, stale epochs/sequences and unsupervised launches are not eligible. The existing main-only tab_mutation request carries the confirmed exact epoch, admission sequence and ticket; a 15-second intent is revalidated by the existing authenticated supervisor after acquiring the same exit-admission latch as graceful shutdown. The original Browser Owner fences replacement admission while the recovery claim lives. A late result invalidates the unclaimed intent; disconnect releases the claim without inventing a terminal receipt. The supervisor still requires kernel domain-empty, original child exit and Linux guard retirement before its single bounded replacement launch, with no original argv or request replay. The UI explicitly warns that unsaved volatile state can be lost. No separate renderer, native command, permission expansion or new owner runtime; no locked GTK layout changes. Linux requires the supported delegated/systemd process domain, Windows requires the existing Job owner. Source and positive/negative regression fixtures only; CI, installed GUI, fault injection and platform evidence NOT_RUN. This is whole-application fault recovery, not single-renderer forced cancellation.

## P1 MCP provider-authoritative reconciliation (2026-11-26)

An explicitly reviewed opt-in provider-signed status-inbox contract is implemented for both manual MCP and Coding MCP, reusing the encrypted Run/session and native owners. Only the native user's coding-mcp.json may pin an Ed25519 authority; inline and project config cannot activate it. Review discloses account, namespace and public key. Before spawn, the native owner generates an independent effect UUID (not a caller-chosen Run ID), commits the exact authority binding and review revision, and supplies the idempotency key through reserved MCP _meta. An ordinary successful tools/call reply is no longer terminal for opted-in effects. A later signed final status from the original key/account/namespace/effect/run/review can settle the exact unknown record on return or subsequent receipt/session queries. Missing/pending/malformed/wrong-scope/forged evidence never implies non-application; no automatic replay, network access, new IPC command or relaxation of AppContainer is added. Terminal proof is stored in the existing authenticated encrypted record; manual user attestation remains separately labelled. This settles only the provider's bound effect, not arbitrary local process termination or unrelated external effects. The native consumer is implemented; an independently trusted provider/relay must actually publish final signed status and honor durable idempotency. No deployed provider or real network evidence was supplied. CI, native compile/tests and GUI verification NOT_RUN. See the adjacent provider contract documentation.

## P1 renderer isolation and cancellation (2026-11-26)

The existing independent-address screenshot worker now independently checks its real Linux cgroup v2 memory/swap/oom limits or Windows innermost Job memory/kill-on-close flags before initializing Tauri or WebView, and requires an exact parent pipe admission after process assignment. Inherited renderer profile/debug overrides are removed. Parent deadline begins before spawn and admission, with retained owner on cancellation or failed handoff. Windows live CDP dispatch permit stays owned through the metrics, screenshot and decode callbacks. Independent HTTPS mode is a separate fresh profile, with kernel-accounted memory containment (not all GPU/broker allocations); live-document capture remains best effort, not a per-WebView hard-cancel API. Source and regression fixtures only; CI, platform compilation, installed GUI and fault injection NOT_RUN.

Final source audit adds a mutex-protected cancellation intent even for an Unknown receipt, validates complete PNGs before live/isolated output publication, rejects Windows Job breakaway flags in the worker, and rejects results first observed after the shared parent deadline. ## P1 isolated interactive login rendering (2026-11-26)

The existing ordinary tab profile and one-WebView-per-tab/GTK geometry remain unchanged. Transplanting an already-running shared-profile WebView to another OS process is not implemented, and this mode does not copy cookies, passwords, browser storage, or memory/DOM state. An explicit InteractiveAddress mode instead opens a separate, user-operable native window inside the existing 2 GiB kernel-accounted renderer domain, with a fresh private temporary profile. It admits only the selected existing HTTPS tab address, follows the existing HTTPS navigation restrictions, and installs no new remote command or application plugin. The worker publishes a bounded ready marker after its first actual load; the same native capture owner exposes opening/awaiting-user/capture-requested, and requires an exact epoch/sequence/ticket and explicit confirmation from the main window. A single inherited pipe transfers the one-byte capture command and then closes; no reconnect or replay. After the user logs in and navigates, capture binds that same current loaded document, not a new URL request. Linux interactive mode does not scroll the authenticated page for tiling; full-document capture stays inside the isolated domain. Windows retains bounded CDP bands. Startup and capture each have a 60-second parent deadline; the interactive wait is at most 600 seconds after readiness. Cancel, window close, timeout, application exit and failed handoff retain the original domain owner until retirement. Complete PNG validation and publication fencing are reused; the temporary profile is removed on confirmed retirement where cleanup succeeds, otherwise the existing scratch-retained diagnostic applies. Sites requiring popup-based authentication may not work because the existing isolated worker popup/download policy is unchanged. This is an opt-in alternative for logged-in content, not transparent isolation of previously opened normal tabs or a security sandbox. Source and test fixtures only; CI, compilation, and real GUI/login flows NOT_RUN.

Interactive profile cleanup is a distinct failure boundary: if the retired worker's private scratch tree cannot be removed, the capture is not published and the UI reports the retained temporary login data. The scratch path stays in the existing native diagnostic. A hard crash of the parent may still leave private scratch data; no automatic deletion of unrelated temporary paths or claim of secure erasure is added. Trigger admission and parent dispatch recheck the existing exit latch under the Capture Owner. NOT_RUN.

## P1 persistent ordinary-browser profile ownership (2026-11-26)

Ordinary embedded tabs and Grid hosts retain the existing shared browser-webview-profile path and login data. The new native browser_profile_owner is a process-lifetime admission boundary, not a second WebView manager. Fixed private lock files serialize admission, hold the main leader exclusively, and retain a shared membership lease in every admitted main/Grid host until OS process exit. A replacement main must prove that both the old leader and all old participating hosts have released membership before publishing a fresh UUID epoch. Grid launches receive the exact current epoch from the native parent; stale epochs, missing leader, missing profile binding and changed native directory identity fail closed. The leader pins the SHA-256 digest of the real native profile directory identity after native preparation; a Grid checks it before and after preparation. Linux additionally retains the original directory descriptor in TabManager and checks inode/device/owner/privacy before creating a new WebView, matching the existing Windows prepared-root discipline. The locks are non-inherited native handles and no session contents, cookies, credentials or profile copy are read or exported. Stable lock objects are not deleted or replaced during normal lifecycle; a short interrupted metadata record can be rewritten only after proving all participating hosts have retired. The gate has a bounded acquisition wait. Windows reuses existing native private-file/ACL checks. The existing single-instance plugin and Grid peer transport retain their own responsibilities. This design is cooperative same-user lifecycle ownership, not a hostile same-user sandbox or proof of retirement of engine-only descendants. Existing ordinary tabs still embed their WebViews in the main host, and their GTK layout, navigation, BFC and persistent browser behavior are not migrated in this change. Full ordinary-tab independent renderer routing and cross-platform installed-GUI validation remain open. Added cross-process fixture source for surviving Grid membership, stale epoch rejection and root replacement, plus native profile contract assertions. No execution: NOT_RUN.
