# BrowserOS UI 2.0 A+ · 现状 / 上一版 UI2 / 本次 A+ 详细对比

> 日期：2026-11-01  
> 目标分支：`browseros-ui2-aplus-20261101`  
> 基线：`master@8a5e8380592bb772c7c9e5f63788f7443579169a`

## 一、三套方案的定位

| 维度 | 当前 BrowserOS（master / 用户实机截图） | 上一版 UI2（design/...） | 本次 A+（browseros-ui2-aplus-20261101） |
|---|---|---|---|
| 核心目标 | 功能覆盖优先，模块各自演化 | 统一 Shell、统一视觉和迁移边界 | 在不丢功能的前提下，做成可直接感知的 A+ 级产品原型 |
| 产品语言 | Chrome 外壳 + 多种模块视觉 | Chrome × Apple × AI Native | Chrome 浏览器习惯 + Apple 克制层级 + 专业工具高密度 |
| 页面一致性 | 中低：浅色首页/文件/设置与深色 DB/Git/Agent 分裂 | 中高：Token 和 Shell 更统一 | 高：统一左侧 IA、浏览器顶部 Chrome、卡片/工作区/面板体系 |
| 信息架构 | 首页入口平铺，模块入口较多 | 收敛到 Home/Browser/Files/Tools 四入口 | 保留一级分组，同时强化“工作台 / 项目 / 知识 / 数据开发 / 自动化” |
| 交互目标 | 各模块可用 | 建立统一规则 | 功能性与交互性第一，同时保留专业密度 |
| 交付形态 | 生产 UI | 多文件 standalone prototype | 独立单文件多页面 HTML 原型，不覆盖 production UI |
| 风险 | 视觉割裂、状态反馈不一致 | 更偏系统规范与迁移设计 | 更偏最终产品观感，需要后续按 Capability 边界落地 |

## 三、逐页面详细比较

### 1. 首页 / 工作台

**当前**
- 主要工作区功能以大量同级卡片平铺。
- 快捷方式、最近访问、收藏等区域均可用，但视觉权重接近。
- 页面更像“工具入口目录”，不像“工作操作系统首页”。
- 优点是功能不隐藏，缺点是高频动作和低频能力没有清晰优先级。

**上一版 UI2**
- 开始收敛一级导航。
- 强调 Home / Browser / Files / Tools 四入口。
- 更偏系统架构规范，首页视觉表达相对克制。

**本次 A+**
- 工作台变成真正的“继续工作入口”：Hero + 全局搜索 / 指令 + 核心模块 + 最近项目 + 最近活动 + 系统状态。
- 模块仍全部可达，但不再同级堆叠。
- 首页优先级：继续工作 > 搜索/命令 > 高频能力 > 发现能力。
- Chrome 风格顶部与 Apple 式卡片层级统一。

**结论**：A+ 首页比当前更像“OS 工作台”，比上一版 UI2 更接近可直接展示给用户的产品设计。

### 2. Browser Shell / 标签 / 地址栏

**当前**
- Chrome 式 Tab、地址栏、收藏栏已经是强项。
- 用户已有使用习惯，不应推倒重做。
- 地址建议与内部 `browseros://` 路由已形成产品辨识度。

**上一版 UI2**
- 最强的是规范：统一页签 Registry、Omnibox、BookmarkBar、Native WebView 边界。
- 工程边界定义最完整。

**本次 A+**
- 视觉上保留 Chrome 导航逻辑，但减少工具栏噪声。
- 统一内部页面与网页页签的视觉投影。
- 将左侧导航作为“BrowserOS App 导航”，而不是替代浏览器 Tab。
- 顶部只承担浏览上下文，左侧承担 OS 功能上下文。

**结论**：工程落地应沿用上一版 UI2 的 Tab Registry 约束；视觉与最终产品表现采用本次 A+。

### 3. 编码工作区 / Agent

**当前**
- 三栏结构已经合理：左资源 / 中编辑器 / 右 Agent。
- 用户截图中空项目时中央区域利用率低。
- Agent 模型、Plan 模式、会话、输出存在，但控制密度和状态呈现略割裂。

**上一版 UI2**
- 强调唯一 Document Manager、EditorHost、Agent Task Surface。
- 设计边界正确，但视觉表现偏工程规范。

**本次 A+**
- 明确形成“项目资源 → 编辑器 → Agent”的主工作流。
- 编辑器上方集中“对比修改 / 审核并保存 / 运行”。
- Agent 区明确模型、模式、会话和输入。
- 底部统一“工具输出 / 安全命令 / 问题”。
- 状态从“功能拼接”变成“任务生命周期”。

**结论**：功能架构用上一版 UI2；交互面板与视觉层级采用 A+。

### 4. Database Studio

**当前**
- 功能深度很高：连接、Schema、SQL、事务、结果集、Inspector、AI Assistant 都有。
- 最大问题不是功能不够，而是按钮层级密、视觉层次不稳定。
- 深色 Database 与浅色 BrowserOS Shell 风格割裂。

**上一版 UI2**
- 提出 SQL Tab / Schema / Result / Inspector / Readonly / Transaction 的统一状态。
- 工程风险分析最完整。

**本次 A+**
- 保留三栏专业布局。
- 数据区继续深色，BrowserOS Shell 保持浅色，形成“系统 Shell + 专业工作区”的刻意分层。
- SQL 运行成为唯一主操作。
- 查询结果、分析、计划、历史归入同一结果区 Tab。
- Inspector 只承载连接/表结构，不与 SQL 主流程抢权重。

**结论**：A+ 不减少任何专业能力，只重排控制层级。

### 5. Git / Diff

**当前**
- Log、分支、变更树、双栏 Diff 已经成熟。
- UI 密度较高，主操作、筛选、文件树和 Diff 容易竞争注意力。

**上一版 UI2**
- 明确 Preview → Confirm → Execute 的安全原则。
- 强调 Git Adapter Owner 不迁移。

**本次 A+**
- 原型保留 Git 独立工作区，不把 Git 塞进编码编辑器。
- 强化三块：Changes / History / Diff Inspector。
- 与 Agent 的修改审核视觉语言保持一致。

**结论**：A+ 主要是视觉统一和操作层级，不重写 Git 业务。

### 6. 文件

**当前**
- 目录树 + 列表功能完整。
- 行高偏大，大量操作隐藏在右键菜单。
- 文件页和编码页看起来像两个不同产品。

**上一版 UI2**
- 提出 FileTree / FileList / DocumentManager 统一语义。

**本次 A+**
- 文件页面保留浏览器式文件体验。
- 高价值操作前置：“新建文件 / 新建目录 / 在编码工作区打开”。
- 文件是“资源入口”，编辑器是“工作入口”，职责更清晰。

### 7. Grid

**当前**
- 截图显示 2/4 格等控制，但实际内容区为空。
- 空态没有解释“为什么空、下一步做什么”。

**上一版 UI2**
- 明确真实能力有 2/3/4/6/9 格，不能为了设计稿破坏原生 WebView 生命周期。

**本次 A+**
- 设计上把 Grid 定义为 WorkspaceLayout 的组合能力，不再作为孤立功能页。
- 必须有四种状态：Empty / Loading / Ready / Error。
- Grid 内可组合网页、编辑器、数据库、Agent，但资源 Owner 不迁移。

**结论**：工程实施必须以旧 UI2 的原生边界为准，A+ 负责产品表现。

### 8. 知识与内容 / BFC

**当前**
- BFC 内容库本身已有较完整视觉语言，但与 BrowserOS 主产品明显不同。
- 主题书架、全部视频、继续观看三个页面割裂。

**上一版 UI2**
- 更多关注 Knowledge / Graph 的边界与空态。

**本次 A+**
- 合并为“知识与内容中心”。
- Hero 搜索 + 学习进度 + 专题书架 + 视频库 + 继续观看统一一页。
- 浏览内容不再像第三方站点，而是 BrowserOS 原生能力。
- BFC 本地网页如果仍由独立站点维护，不应强制注入 BrowserOS Token；A+ 仅作为原生中心设计参考。

### 9. 定时任务 / 自动化

**当前**
- Cron、执行目标、失败策略、补跑、重试、超时等字段非常完整。
- 当前页面空态较大，新建任务弹窗一次性字段过多。

**上一版 UI2**
- 建议按“目标 → 调度 → 安全策略”分段。

**本次 A+**
- 自动化中心先给运行健康、成功率、失败数、任务分类和最近执行。
- 创建任务改成右侧 Drawer，不打断任务列表上下文。
- 基础配置与高级设置分离。
- 同步 / 离线执行状态直接可见。

**结论**：功能保留 100%，但信息从“配置表单”升级到“自动化运营中心”。

### 10. 终端 / 剪贴板 / 脚本库

**当前**
- 三个独立功能页，终端成熟，剪贴板和脚本库相对空。
- 页面切换成本高。

**上一版 UI2**
- 强调 TerminalDock 生命周期，但没有强制三者产品合并。

**本次 A+**
- 合并成“开发工具中心”。
- 左侧主终端，右侧剪贴板历史 + 脚本库。
- 适合开发者高频组合操作：复制命令 → 终端运行 → 保存成脚本。
- 仍保留独立路由能力，组合页面只是入口层。

### 11. 技能工作台

**当前**
- 目标、步骤、定义检查、权限与运行已经有合理流程。
- 表单感较强，缺乏完成度、风险、运行状态的视觉反馈。

**上一版 UI2**
- 对流程定义和权限边界更完整。

**本次 A+**
- 保留现有分步模型。
- 技能列表、完成度、验证状态、权限风险形成统一状态语言。
- 与 Agent Center 使用同一 Capability / Approval 设计语言。

### 12. 图谱

**当前**
- 0 节点空态很弱，只显示“暂无数据”。
- 用户不知道是未刷新、未授权、无索引还是确实无数据。

**上一版 UI2**
- 明确四类状态：无数据 / 加载失败 / 需授权 / 起始节点缺失。

**本次 A+**
- 继续采用这个状态模型。
- 搜索、过滤、节点 Inspector 和数据来源说明必须同屏。
- 空态必须给明确下一步动作。

### 13. 设置

**当前**
- AI 模型、主题、快捷键、性能、默认浏览器、模块、工程健康都在一条长页面。
- 信息完整，但查找成本高。

**上一版 UI2**
- 提出分类导航 + 设置搜索。

**本次 A+**
- 左侧分类 + 右侧局部设置面板。
- 将高频设置（AI / 外观 / 快捷键）前置。
- 将工程健康、模块管理作为高级设置。
- 不把密钥、敏感配置暴露在列表摘要。

## 四、设计系统比较

| 项目 | 当前 | 上一版 UI2 | 本次 A+ |
|---|---|---|---|
| 主色 | 模块各自定义较多 | 语义 Token | 蓝色主操作 + 语义状态色 |
| 圆角 | 4–12px 混用 | 6–12px | 10–18px，按 Shell/Panel/Card 分层 |
| 阴影 | 当前较少 | 克制 | 仅 Shell / Card 层级使用柔和阴影 |

| 主按钮 | 各模块不同 | 统一 Accent | 单一 Blue Primary |
| 错误提示 | 分散 | Status Feedback | 就地错误 + 状态栏，避免全局 Toast 滥用 |

## 六、为什么本次 A+ 不与上一版 UI2 混合

1. 本分支从最新 `master@8a5e838...` 新建，不从 `design/browseros-ui2-aplus-20261101` 派生。
2. 本分支只新增 `docs/prototypes/browseros-ui2-aplus-20261101/**` 和本对比文档。
3. 不引用上一版 `docs/prototypes/browseros-ui2/**` 的 HTML/CSS/JS。
4. 不修改 production `src/**`、`src-tauri/**`、`tauri-browser-tabs/**`。
5. 上一版 UI2 保留为“系统规范 / 迁移边界”参考，本次 A+ 是“最终产品体验 / 视觉与交互”方向。
6. 后续若开始生产迁移，应以“上一版边界 + 本次 A+ 体验”合并成新的实施计划，而不是把两个 prototype 目录直接合并。

## 七、落地优先级

### P0 — 必须先做
1. 统一 Shell：Tab / Omnibox / Sidebar / Status。
2. 统一 Design Tokens。
3. Coding Workspace + Agent 状态与审批。
4. Document Manager / EditorHost。
5. Database / Git 顶部控制层级统一。
6. 全局空态 / 错误 / 权限状态模型。

### P1 — 主工作流
1. Home 工作台。
2. WorkspaceLayout / Dock。
3. Database Studio。
4. Git Studio。
5. Automation Center。
6. Knowledge & Content Center。
7. Settings 分类化。

### P2 — 完成度
1. Clipboard / Scripts。
2. Graph。
3. Skill Studio 视觉完成度。
4. 动效 / 无障碍。
5. 720 / 1024 / 1440 响应式。
6. 安装版 GUI 人工验收和性能基线。

## 八、最终建议

- **保留当前产品的功能深度。**
- **保留上一版 UI2 对 Native WebView、Document Manager、Capability Owner、Agent Runtime 的工程边界。**
- **采用本次 A+ 作为最终用户可见的产品设计方向。**
- 不把 BrowserOS 做成 VS Code 换皮；BrowserOS 的核心身份应该是：
  **浏览器 Shell + 可组合工作区 + 专业开发能力 + AI Agent Runtime。**
