# BrowserOS 界面重构实施规范 v1

> 2026-10-10｜依据五张真实界面截图及用户逐项决策。此文档约束**当前 BrowserOS**，与 Asset Workbench/Instance Manager 无关。事实以 GitHub 提交与 CI 证据为准；方案写入不代表代码通过验收。

## 0. 产品裁决

**内容优先、工具随行、强大而安静**。浏览与文件是 P0 核心；主页是入口，工具页是其余能力的统一陈列处。避免顶部堆满按钮、重复收藏夹、宫格“模式/布局/格数/动作”平铺在同一行，禁止新增无解释的入口。
- 保留两条视觉连贯的顶部区域：页签与窗口控制独立（原生拖拽语义不变）；下面为四目的一级导航与智能地址栏。
- **顶层四入口：主页、浏览、文件、工具**。工具页是工具箱能力的升级，不创建第二个工具模块和第二份状态真源。专业功能分类为 AI 协作、开发、文件/知识、系统管理；用户仍能打开现有所有模块。
- 工具按钮不再因注册了 Contribution 就自动获得多个顶级快捷入口。用户看见一个业务目的、可在具体场景获得上下文快捷方式。
- 隐藏 ≠ 卸载能力 ≠ 释放资源。原生浏览器、文件管理器、GTK 多窗口和热插拔不因纯 UI 重排修改生命周期。

## 1. 一屏信息架构

| 区域 | 常驻的内容 | 不得常驻 |
| --- | --- | --- |
| 页签条 | 标签、新建、窗口拖拽/最小化/关闭 | 宫格布局、文件批量命令 |
| 导航/地址栏 | 主页/浏览/文件/工具；后退/前进/刷新；地址输入；单一收藏夹图标；单一宫格入口；右侧更多菜单 | 「前往」按钮、收藏夹文本副本、宫格单独的 ▾ 小箭头、资源轮询 |
| 地址建议（有交互时） | 纵向列表至多六条；图标/标题/来源；键盘上下/Enter/Esc；过滤 URL/本地路径，显示脱敏 | 一整排“历史/常用”碎片胶囊按钮 |
| 文件树 | 当前目录标题、刷新、新建与“更多”；目录树支持展开、缩进、键盘焦点 | 6 个不分组的无文字小按钮 |
| 宫格 | 一个图标打开/切换对比；进入对比主视图后才显示模式、2/4 格快捷动作 | 模式/布局/格数/网址/资源/关闭同级横排 |
| 工具页 | 搜索、精选业务功能、分类分区、内置/用户工具 | 与顶栏同等密度的第二排工具图标 |

默认顶栏不直接摆“收藏网页”和“打开收藏夹”两个同级按钮；收藏当前网页放进收藏夹侧栏，顶栏单一图标打开/关闭侧栏。收藏页保留后端 bookmarks.json 与凭据边界。

## 2. 组件与责任

| 组件/模块 | 改造范围 | 真源与安全 |
| --- | --- | --- |
| `src/stores/useLayoutStore.ts` | 顶层四入口、保持现有模块导航 | `mainView` 唯一 owner；不得引入 bridge |
| `src/capabilities/tools/ui/ToolBox.vue` | 在现有 tools 视图扩充“工具页”（仍支持内置/个人工具）；按任务分类 | `useToolsStore` 保留 `listTools/openTool`；复用 Workbench 公共导航 |
| `src/components/layout/ActivityBar.vue` | 目的导航、轻量地址栏、内联纵向建议；去前往/重复图标/旧横向扩展 | 不直接 import 各插件内部；尊重 native child WebView 的遮挡约束 |
| `src/capabilities/bookmark/ui/*` | 仅在地址栏尾部贡献一个收藏夹图标；收藏操作迁入侧栏 | 按能力 owner 导航，禁止 Shell 直接改 bookmark store |
| `src/capabilities/grid/ui/*` | 保留一个宫格入口；已进入宫格时出现上下文紧凑栏；高级 URL/资源分区 | Grid 资源创建仍经独立 capability 的准入与生命周期 |
| `src/capabilities/workspace/ui/FilePanel.vue`、`FileTreeNode.vue` | 文件树 3 个常用操作、低频菜单和清晰层级与空态 | 文件重命名/删除/拖放仍归 useFileStore |
| `scripts/check-ui-product-quality.mjs` | 结构化可机器判定的 UI 契约；集成 npm run check | 原有 W17/Capability/SCR/资源门禁继续执行 |

## 3. 地址栏交互

- Enter 打开用户输入的 URL 或目录，不出现“前往”按钮；仅用户主动输入时决定导航。
- 聚焦展示最多六条历史和目录建议；输入时依据源数据过滤；渲染仅使用脱敏显示字符串，点击使用原值。
- 上/下移动当前建议，Enter 选中则打开建议，否则打开输入；Esc 关闭并保留当前输入。
- **因 Linux WebKitGTK 原生子 WebView 优先于 DOM 浮层绘制**，建议框使用正常文档流中的单列整洁列表，暂不使用 `position:fixed/absolute` 遮盖浏览区域；这与 Chrome 的层次视觉一致，但不会冒充 Chrome 的真实悬浮实现。展开时 BrowserHost 只通过既有 RO 触发原生矩形定位。

## 4. 工具页

- 将既有 `tools` 视图升级为“工具”统一页面，保留真实工具列表（内置、用户创建）；不从 Shell 搬入第二套 Tool Store。
- 模块按「日常 / AI 与比较 / 开发 / 知识 / 系统」策展并共用当前 `MODULE_META`、公共导航；搜索工具名与用途。
- 模块 unavailable 时遵循现有 Capability 平台，不允许工具页自行 `invoke` 重资源或注入账号凭据。
- 为搜索结果、加载失败、空列表提供中文提示，鼠标和键盘都可用。

## 5. 文件与宫格

文件侧栏：左右仍可调整宽度；主菜单显示「新建」「刷新」「···」。展开/折叠、定位、新建文件/目录全部在有标签的更多菜单中，移除“默认所有六个按钮堆一排”的视觉。树行统一高度/hover/选中背景/缩进，沿用右键菜单、拖拽和文件预览。

宫格：顶层唯一入口只负责显示 AI 对比工作区，不带独立配置小箭头；处于 grid 视图时一行显示“浏览/AI”与“2 格/4 格”及一个“更多”按钮。更多区域分类展示布局与 3/6/9 格、地址编辑、资源信息及关闭操作。默认四格为兼容现状（是否自动降级由原有内存保护决定）；用户可切双格，无需在本轮改变子进程默认数量、布局算法、AI 网站适配脚本。

## 6. UI 产品门禁：有可执行边界，不冒充机器审美

新增 `check-ui-product-quality.mjs`，纳入 `npm run check`，默认 FAIL-CLOSED，要求：
1. 四个且仅四个默认目的入口，无重复 view；模块去向完整；
2. ActivityBar 不渲染“前往”、不直接渲染第二个收藏夹、宫格贡献只一个顶级按钮；
3. 地址建议纵向、至多六条、键盘上下/Enter/Esc；HTML 中含语义 label/role；
4. 文件栏常驻操作有数量预算，低频操作集中“更多”；
5. 宫格模式、布局、格数、动作的高级配置不得全部出现在同一个默认横排；
6. 工具页有可操作分类/搜索和已存在工具清单；旧功能可达。
7. 关键代码不得增加原生 WebView 覆盖浮层、绕过 Capability/语义/资源门禁。

**视觉是否好看、任务是否容易理解无法靠正则证明**：正式 GUI 执行前后截图审核、窄窗口 720/1024/1440 宽、文件 Dock/宫格界面、首页/工具页、高对比与焦点、鼠标操作路径。将自动化 UI 契约（机器可判定）和真人视觉评审（产品验收）独立标记，不能拿 CODE_PASS 冒充 UX_PASS。

## 7. 合并与交付

- 纯本 Markdown 按工程既有 docs 快速路径，不跑 Rust/GUI 重门禁。
- 涉及 Vue/CSS/测试代码：按现有 `npm run check`、build、Rust native GUI、pre-merge 相关门禁执行；不得把旧断言一律删除以求绿色。
- 文档截图未实际量测的性能数字不得编造；CPU/RSS 与尺寸基线需在真实安装版验收采集。
- 本项目暂不重写 `grid_process.rs` 等 Linux-only 实现为 Windows/macOS ；跨平台另做原生适配，不混入 UI 变更。
- PR 仅当所有仓库自动门禁通过且合并基线新鲜方可无人值守合并。若核心交互 GUI 专项证据缺失，必须记录 `UX_PENDING`，不可声称完全结束。

## 8. 对照验收清单

- [ ] 顶部只保留一个收藏夹按钮，内部能新增/删除；
- [ ] 宫格一个入口，配置分组，已有 2/3/4/6/9 格与 AI 功能完整；
- [ ] 文件栏三类常用入口，低频功能在“更多”，操作成功；

- [ ] P0 浏览与文件管理器保持可达，无原生 WebView 回归；
