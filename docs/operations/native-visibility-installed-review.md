# Installed native visibility review — manual only

Status: **NOT_RUN / GUI_PENDING**. This is the executable acceptance mechanism for the independent-tab / Grid desktop-pixel visibility target. It is not an automatic CI gate, and a source commit alone establishes no runtime pass.

## Prerequisites

- A separately built and installed **Release** from the exact reviewed source SHA, with normal default backend selection, enough memory for two ordinary renderers plus two Grid children, and no running BrowserOS instance.
- Dedicated disposable graphical login or VM without personal accounts, browser data, clipboard contents or unrelated windows. This is an explicit operator requirement, not something the runner can prove from environment variables.
- Linux: native X11 display with a working user-scope or delegated cgroup-v2 memory controller, Pillow XCB support, package tools, and the exact .deb. The runner uses a fresh temporary HOME and XDG data/config/cache. XWayland/Wayland is not accepted.
- Windows: an interactive single-monitor desktop, a fresh disposable Windows account whose Tauri app-data directory does not exist, and existing NSIS six-file installed-payload verification evidence. Do not redirect APPDATA to simulate a separate OS account.
- Python 3.10+, Pillow, psutil and Git; no dependency installation is performed by the script.

Provide a JSON build record from the reviewed build/package process, not a record generated by guessing the current checkout matches an old binary. Required keys: `source_sha` (40 lowercase hex), `installed_exe_sha256` (64 lowercase hex), and on Linux `package_sha256` (64 lowercase hex). On Windows the executable digest must identify the **installed NSIS payload**, not the unpatched release executable. Keep the original provenance separately; the runner does not verify a cryptographic source attestation.

## Manual commands (not executed during source remediation)

Linux:

```sh
python3 scripts/native-visibility-installed.py \
  --installed-exe /usr/bin/mvp-browser-os \
  --deb /path/to/reviewed.deb \
  --build-record /path/to/build-record.json \
  --output /path/to/new-local-evidence-directory \
  --disposable-desktop
```

Windows (PowerShell, after running the existing installed NSIS payload verifier for the exact source SHA):

```powershell
python scripts/native-visibility-installed.py `
  --installed-exe 'C:\path\to\installed\mvp-browser-os.exe' `
  --windows-payload-report 'C:\evidence\package-payload.json' `
  --build-record 'C:\evidence\build-record.json' `
  --output 'C:\evidence\visibility-new' `
  --disposable-desktop
```

The output directory must not already exist. Use the clean checkout of the final source revision; the runner also checks that its own script belongs to that checkout. Do not add the generated images, logs or test profiles to Git. The script does not build/install software, change the default backend, launch unrelated commands, or terminate existing BrowserOS processes.

## Acceptance contract

| Stage | Left region | Right region | Additional required observations |
| --- | --- | --- | --- |
| 1 baseline | No marker | No marker | Fresh host, no native renderer |
| 2 tab A show | A | No marker | A independent process and show receipt |
| 3 tab B switch | No marker | B | A hidden receipt; distinct B owner |
| 4 tab B move | B | No marker | Same B owner and new physical bounds |
| 5 tab A return | No marker | A | Same A owner, B hidden |
| 6 tabs hidden | No marker | No marker | Both hidden receipts |
| 7 Grid show | C | D | Both tabs hidden, separate Grid owners |
| 8 Grid hidden | No marker | No marker | All four hidden receipts |
| 9 closed | No marker | No marker | No live renderer routes; native driver terminal result |

Four randomly selected colors per marker occupy fixed page quadrants. Each phase requires three consecutive desktop samples with all visible quadrants at least 95% matching, bounded color tolerance, and no significant marker signature outside its expected physical region. The observer rejects insufficient sample density and any out-of-screen region. The original native owner, geometry, connection generation, navigation revision and visibility receipt must survive the observation interval; the main window must remain visible. The observer rechecks the original process birth times and ancestry after each sampling interval. The initial baseline rejects even a single broad marker-colored patch so it cannot mask a later ghost. Neither page JS nor a native show/hide flag can issue the pixel acknowledgement.

The runner checks installed bytes, package evidence, live image identity/ancestry, nine ordered phases, native terminal success, launcher exit status, sampled process retirement and final executable digest. The Linux observer samples the X11 display; the Windows observer uses desktop capture with physical DPI coordinates. Each successful sample has bounded local PNG crops and SHA256 hashes in `summary.json`. Full desktop images are not persisted. Keep the disposable profile until a human verifies complete cleanup; no force kill or automatic profile deletion. If the launcher stalls, close the isolated VM/login normally and retain the incomplete evidence.

## Interpretation

`DESKTOP_VISIBILITY_FIXTURE_PASS` means this exact installed binary, in this specific desktop configuration, passed the nine native-driven fixture phases. It is neither physical monitor scanout nor a proof of arbitrary webpage content, arbitrary occlusion, mixed-DPI multi-monitor behavior, real user interaction, Wayland, login state, all native commands or performance. The fixture does not exercise normal frontend mouse/keyboard actions; those still need installed GUI acceptance. Linux and Windows results are separate.

All other outcomes remain `GUI_PENDING` (including missing build records, unsupported desktop, timeout, missing receipts and pixel mismatch). This manual runner deliberately does not publish `GUI_PASS`, modify the gate registry, dispatch CI or substitute for full installation acceptance.
