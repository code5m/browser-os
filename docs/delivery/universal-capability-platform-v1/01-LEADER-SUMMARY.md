# 01 — 给领导的说明（非技术论文）

## 以前 → 现在

**以前**：功能是长在一个应用里的。想加一个能力，要改 `App.vue`/布局组件；想去掉，只能把 UI 藏起来，代码、状态、进程还在。

**现在**：`产品 = 最小底座 + 若干能力积木 + 装配配置`。
底座不知道「浏览器」「终端」「收藏夹」的存在；它们是被**装配**进来的。

## 什么叫「积木」

一块积木必须同时满足：独立身份、独立边界、显式依赖、可以加入、可以移除、可以启停、资源可治理。
**任何一条做不到，就不能宣布它是积木** —— 每一条都必须能被下列命令复现。

## 目前哪些已经是积木（4 个，全部 C3）

`收藏夹 bookmark` · `工作区 workspace` · `浏览器 browser` · `终端 terminal`

其中：
- **启动前拔插**（HP0）：4 个都支持 —— 装配里不写它，它就不存在。
- **运行时启停**（HP1）：**收藏夹**已验证（停用后 UI 贡献真实消失，启用恢复）。
- **运行时注册/注销**（HP2）：**收藏夹**已验证（应用不重启，贡献 3→0→3，可重复）。
- **运行时安装/卸载**（HP3）：**未做，也不做假**（需要动态加载外部包，风险高，明确延后）。

浏览器/终端仍是 HP0：它们的重资源（WebView / PTY）一旦启用就有真实副作用，必须先把停用与释放策略做完再声明更高等级 —— **这是我们今晚主动选择不高报的地方**。

## 怎么证明「拔掉」是真的

- **装配层**：缺席的能力不出现在 `RESOLVED`，不产生任何 `CONTRIBUTION`。
- **运行层（本次实测）**：`node scripts/capability-demo.mjs matrix` 16 个组合全部确定性通过；
  `runtime-demo bookmark` 演示贡献从 3 → 0 → 3。
- **诚实口径**：浏览器缺席 ⇒ **没有任何 WebView 宿主被注册**（结构性证据 PASS）；
  终端缺席 ⇒ **没有任何 PTY 出生点**（结构性证据 PASS）。
  进程级「数一数有没有 WebKit 子进程 / PTY」今晚 **UNKNOWN**（无运行中的应用实例），不估算。

## 下一块能力怎么开发

1. 建能力包 → 2. 写 manifest（依赖/贡献/资源/ hot-plug 等级）→ 3. 只暴露 public contract
→ 4. 注册到装配配置 → 5. 跑门禁。**不需要改 Shell 业务代码**（已由收藏夹运行时加入证明）。

## 一句话

> 以前我们开发的是一个越来越大的应用；
> 现在我们开发的是一个底座和一套可独立组合的能力积木。
