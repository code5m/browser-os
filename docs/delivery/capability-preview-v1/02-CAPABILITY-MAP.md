## 二、三种状态（请勿混淆）

```text
① 已接入（兼容包装）  = Bookmark，共 1 个
   含义：已经挂到新的能力体系上，能被登记、发现、激活；
        但底层仍是原来的系统，并没有被"物理拆出来"。

② 已登记，未接入      = 其余 14 个
   含义：清单、依赖、资源分类都已经写清楚并被机器校验；
        但还没有接到运行时上，不能单独启停。

③ 设计上不参与组合     = Credential / Session / Plugin，共 3 个
   含义：凭据（安全）、会话（关停链路）、插件（运行时尚锁定），
        出于安全与稳定考虑，不参与"按需装配"。
```

## 三、为什么先只做"书签"

选试点看四条：**影响小、无底层依赖、结构简单、有明确归属**。

| 候选 | 结论 |
|---|---|
| **书签** | ✅ 四条全满足 → **选它** |
| 浏览器 / 宫格 | ❌ 您已认可的稳定核心，且是多 webview 重资源，风险最高 |
| 终端 | ❌ 涉及系统进程（PTY），且和剪贴板共用一套内部状态，牵一发动全身 |
| 插件 | ❌ 插件运行时尚处于锁定状态 |

> 先拿最安全的模块证明"这套体系真的能跑通"，再逐步推进到重的模块——这是有意为之的顺序。

---

## 四、为什么浏览器/宫格/终端这次不动

它们是最有价值、也是最容易出问题的部分。在能力体系本身被证明可用之前动它们，
等于拿您每天都在用的稳定功能冒险。所以本版只做**登记与分类**，不动实现。
