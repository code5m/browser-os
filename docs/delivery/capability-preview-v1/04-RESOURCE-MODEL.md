# 04 — 资源模型：如何降低消耗？关掉某功能到底能省什么？

## 一、先把话说清楚（避免误解）

```text
本版没有实测任何内存/CPU 数字。
所有资源结论都是"声明式分类"——即根据代码结构判断它占用哪类资源，
不是"运行起来量出来的"。
```

为什么？因为项目当前没有"按能力统计资源"的测量机制。
与其给您一个编出来的数字，不如给您一个诚实但可演进的分类体系。

---

## 二、资源分类（13 类）

| 类别 | 含义 | 代表能力 |
|---|---|---|
| LIGHT | 纯内存状态，无底层资源 | 书签、笔记、技能、工作区 |
| MEDIUM | 中等内存/磁盘读写 | Git、知识图谱、工作台 |
| HEAVY | 占用浏览器内核实例 | 浏览器、插件 |
| VERY_HEAVY | 占用**多个**浏览器内核实例 | 宫格（Grid） |
| PROCESS / PTY | 会启动系统进程 | 终端、脚本 |
| NETWORK / SECRET | 联网、持有连接口令 | 数据库、Agent、Git |
| BACKGROUND | 后台定时活动 | 任务调度、采集 |
| SECURITY_SENSITIVE | 持有密码/令牌 | 凭据 |

---

## 三、「关掉某个功能能省什么」——直接回答

| 关闭对象 | 可预期释放什么 | 今晚能不能做到 |
|---|---|---|
| **宫格（Grid）** | 释放**多个**浏览器内核实例及对应渲染内存 —— **收益最大的一项** | ❌ 目标态，做不到 |
| **浏览器** | 释放浏览器内核实例 | ❌ 目标态，做不到 |
| **终端** | 结束子进程 | ❌ 目标态，做不到（进程不能安全冻结） |
| **数据库** | 断开连接、释放连接池 | ❌ 目标态，做不到 |
| **任务调度** | 停掉后台定时唤醒 | ❌ 目标态，做不到 |
| **书签** | 只释放很少一点内存状态 | ✅ 可编排，但**省得很有限** |

### 必须理解的一点

**省资源的大头（宫格/浏览器/终端）恰恰是今晚不能关的部分；**
而今晚真正能编排的书签，本身极轻量，关掉也省不了多少。

所以这一版交出的是 **"资源账本"**（谁重谁轻、谁常驻、谁能关），
而不是 **"一键省内存"**。真正的资源收益要等后续把这些重模块接入后才拿得到。

---

## 四、后续怎么拿到真实收益

1. 先把重模块（宫格、浏览器、终端）按能力体系接入 —— 需要单独评估与授权。
2. 补上按能力的资源测量（当前没有，已登记为债务）。
3. 到那时才能给出"关掉 X 大约省多少"的**实测**数字。
