# Capability Architecture Preview v1 — 领导验收说明

> 项目：`mvp-browser-os-v3`（极智简单·浏览器 OS）
> 日期：2026-09-19
> 状态：**CODE COMPLETE / 待人工 GUI 验收**（`HUMAN_GUI_ACCEPTANCE = PENDING`）

---

## 一句话结论

> 过去：所有功能"长在一起"，谁依赖谁、谁能关、关了能省什么，全靠人记。
> 现在：功能被整理成 **18 个能力（Capability）**，每个能力有**清单、依赖、生命周期、资源分类**，
> 并由一套**机器校验**守着——以后加功能、拆功能、关功能都有据可依、可回滚。
>
> ⚠️ 但必须说清楚：本版是 **能力体系的"第一版设计与试点"**，
> 目前**真正接入新体系的只有"书签"一个能力**，其余仍是"已登记、未接入"。

---

## 这套东西解决了什么问题

| 以前 | 现在 |
|---|---|
| 功能耦合，改一处怕牵一片 | 18 个能力边界清晰，依赖关系**被登记并被机器校验** |
| 不知道关掉一个功能能省什么 | 每个能力有**资源分类**（轻量/重量/进程/网络/敏感） |
| AI 或新人改代码容易制造重复逻辑 | 已有 Semantic Registry + 本次新增 Capability Registry，**双注册表分工不重复** |
| 没有"恢复点"概念 | 每个阶段一个 **annotated tag**，随时可回滚 |

## 三个必须记住的事实（避免被夸大表述误导）

1. **今晚没有做任何"物理卸载"** —— 没有任何能力可以真正独立关闭/重载。
   唯一接入的是"书签"，且是**兼容包装**（底层仍是原来的系统）。
2. **资源数字一个都没有实测** —— 所有资源结论是"声明式分类"，不是性能数字。
3. **Graph/Browser/Terminal 等高价值高风险模块今晚没动** —— 它们是您已认可的稳定基线。

详见 `06-KNOWN-LIMITATIONS.md`。
