# 06 — 已知限制（诚实清单，不做任何美化）

> 这一页的目的是防止任何人把"设计蓝图"误读成"已上线功能"。
> 演示时请一并展示。

---

## 一、能力装配

| # | 限制 | 说明 |
|---|---|---|
| L-1 | **没有任何能力可以真正独立启停** | 全部 18 个能力仍运行在同一个应用进程内；没有物理卸载/重载 |
| L-2 | **只有"书签"接入了新体系**，且是兼容包装 | 底层仍是原来的书签实现，只是外面包了一层声明 |
| L-3 | **三个组合方案（Minimal/Developer/Full）不能一键切换** | 它们是设计口径，不是已实现的开关 |
| L-4 | **Plugin（插件）运行时尚处于锁定状态** | 只能登记，不能装配、不能执行 |
| L-5 | **凭据/会话/插件不参与组合** | 出于安全与稳定考虑的设计决定 |

---

## 二、资源与性能

| # | 限制 | 说明 |
|---|---|---|
| L-6 | **没有任何实测资源数字** | 没有按能力统计内存/CPU 的机制；全部为声明式分类 |
| L-7 | **"关掉能省什么"目前只有定性结论** | 收益最大的宫格/浏览器/终端恰恰还不能关 |
| L-8 | `HIBERNATED`（休眠）状态未实现 | 没有任何能力声明支持，也没有资源释放实现 |

---

## 三、工程与验证

| # | 限制 | 说明 |
|---|---|---|
| L-9 | **未做人工界面（GUI）验收** | 自动验证了构建/日志/断言，但**界面观感、布局、交互体验未经人眼确认** |
| L-10 | **未构建原生桌面安装包（deb/二进制）** | 本次只产出了前端产物包；未执行任何安装动作，也未覆盖您当前的程序 |
| L-11 | 能力体系目前**没有界面呈现** | 只能在日志与报告中看到，界面上还看不到"能力清单"页面 |
| L-12 | 终端门禁存在**历史遗留失败** | 属既有债务，非本次引入，本次未修改 |
| L-13 | 部分能力（技能/笔记/脚本）**尚未登记归属** | 已在能力表中标为"待登记"，并强制它们不可被激活，直到补登记为止 |
