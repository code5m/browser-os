# 03 — 组合演示：哪些功能现在能组合？哪些只是目标？

## 一、先说结论（重要）

```text
现在能真正"按需装配"的：只有 1 个能力（书签），且是兼容包装。
三个组合方案（Minimal / Developer / Full）是"设计口径"，
用来展示未来的装配方式——今晚不能一键切换。
```

请把本页理解为**蓝图与演示**，不是"已经能用的开关"。

---

## 二、三个组合方案

| 方案 | 包含的能力 | 适用场景 |
|---|---|---|
| **Minimal**（最小） | 文件工作区、书签 | 只做文件整理与常用网页收藏 |
| **Developer**（开发） | 文件工作区、浏览器、终端、Git、数据库、书签 | 日常开发 |
| **Full**（完整） | 全部 18 个能力 | 完整体验 |

---

## 三、每个能力的"可组合性"真实状态

| 状态 | 数量 | 含义 | 名单 |
|---|---|---|---|
| **真正可独立启停** | 0 | 今晚**没有**任何一个能力做到物理启停 | — |
| **兼容包装（已接入）** | 1 | 已挂到能力体系，可被登记/发现/激活，但底层未拆出 | 书签 |
| **目标态（未实现）** | 14 | 清单已就绪，等待后续接入 | 工作区、笔记、技能、知识图谱、采集、工作台、数据库、Git、Agent、任务、脚本、终端、浏览器、宫格 |
| **设计上不参与组合** | 3 | 安全/常驻/锁定 | 凭据、会话、插件 |

---

## 四、明天演示时建议这样讲

1. **打开能力清单**：展示 18 个能力及其依赖、资源分类（由真源生成，不是手写）。
2. **演示"书签"接入**：展示它被运行时登记 → 发现 → 激活 → 暂停 → 再激活的完整过程。
3. **说明组合方案**：展示 Minimal / Developer / Full 三套配置，并明确"这是未来能力的设计口径"。
4. **强调没做的事**：没有物理卸载、没有一键切换、没有动核心模块。
