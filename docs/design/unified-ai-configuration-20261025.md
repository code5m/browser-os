# BrowserOS 统一 AI 配置 v1 · 2026-10-25

## 本期范围与入口

真实应用的“设置 → 统一 AI 配置”提供一键导入、手动新增、编辑、移除、逐模型连接测试，以及全局默认/数据库/Git/浏览器/工作台的模型分配。模块未指定模型时继承全局默认，可切回继承。已有配置重复导入不会覆盖。

本机也可在项目目录执行 `npm run ai:import` 完成同样的导入；执行 `npm run check:ai-config` 检查解析回归和密钥保护。配置读写遵循 Linux `XDG_DATA_HOME`。

数据库的 AI Assistant 页、Git 工作台的 Git AI 助手按钮、浏览器的 AI 导航面板已接入同一服务。各入口可临时选择聊天模型。数据库 SQL 和 Git Patch 仅在用户勾选附带上下文后发送；可先展开查看内容。回复仅作建议，不执行 SQL、Git 写入、网页脚本或工具。上下文切换清除旧回复及勾选，异步旧回复不能覆盖新上下文。

`src/settings/public.ts` 导出 `aiService`、`AiScope`、配置类型，后续模块和工作台复用这一出口及 `AiAssistant`，无需再保存独立密钥或接入另一套网络客户端。工作台本期提供配置分配和公共调用接口，未批量改造所有工作台界面。

## 配置和凭据

非敏感索引：系统应用数据目录的 `mvp-browser-os/ai-profiles.json`；本机通常位于 `~/.local/share/com.jizhijiandan.mvp/mvp-browser-os/`。索引原子替换，文件 0600。API 密钥仅写入系统 Secret Service，服务名 `com.jizhijiandan.mvp`，引用命名空间 `ai:<模型配置ID>` / `ai-plugin:<来源ID>`。新模型密钥必填；编辑留空保留原密钥，变更 API 主机必须重新提供密钥，避免旧密钥发送到新服务。

不会把源工具的配置文件复制到仓库，也不会执行导入来源中的 Shell/Python。导入器只读取用户指定来源的显式本机模型、插件配置和技能脚本；排除会话、账号登录态、Cookie、历史记录。动态环境表达式和占位示例不作为真实密钥导入。插件配置中的密钥只保存为凭据引用；插件目录为清单，并非已运行的工具。

本机结果（经过解析收紧和重新导入验证）：

- 36 条模型配置：28 聊天、6 图像、1 视频、1 其他协议。
- 模型及插件共 61 个凭据引用，包含重复供应商凭据；去重为 7 个不同凭据值。61/61 个引用已通过系统凭据库非空读取检查，索引不包含对应值。
- 35 个插件/技能配置目录项，其中 25 个插件凭据引用；另一些目录项只有无密钥的 MCP 描述。
- CodeBuddy：31 条自定义模型，读取 `.codebuddy/models.json`；WorkBuddy 本机仅发现技能目录，未发现独立模型配置。
- 两份指定生图技能及 CodeBuddy/WorkBuddy 的对应技能副本参与发现。补充专用图像/视频模型用途后去重为上述 36 条。
- 首轮解析发现的 15 个非密钥表达式已被剔除，仅删除了本轮临时创建的相应凭据条目；原工具配置没有改动。重新导入新增 0 个模型，证明按稳定 ID 幂等。

按两份 `ai-image-generation` 技能的接口约束标记图像/视频用途。聊天走 `/chat/completions`；图像/视频的生成任务执行器不在本期实现，不把它们放进聊天选项。音乐等非兼容协议显示为其他协议。没有把历史免费额度、供应商模型可用性当作当前承诺。

## 原生契约与失败行为

新增 `ai_service(request)`，定义在 `src-tauri/src/framework/ai.rs`，属于常驻框架服务，主 WebView 专用。仅扩展主界面的 default ACL；远程页面 ACL 保持原状，命令体也拒绝非 main 标签。

请求动作：`list`、`import`、`save`、`bind`、`remove`、`chat`。配置和请求元数据走统一前端 bridge，Vue 不直接调用 invoke。`credential` 仅允许输入保存，响应不含凭据；无可导出的明文密钥接口。

聊天仅访问用户配置的 HTTPS API，证书校验开启；凭据 URL、查询参数、重定向不接受。固定 `/usr/bin/curl` 读取标准输入配置；请求密钥不在进程参数、文件或日志中。单请求最大 45 秒、响应最大 256 KiB，进程等待结束即回收；一次只接受一个远程聊天请求，没有自动重试或后台轮询。模型返回内容仅作为纯文本呈现，当前请求密钥即使被上游意外回显也会替换。

系统凭据库不可用时返回错误，不降级为明文文件。导入写索引前先存密钥；写索引失败保留已有元数据，可重试。移除配置先撤销分配和索引，若凭据删除失败会明确提示。没有改 GTK/WebKitGTK、窗口拖动或 WebView 生命周期。

## 提交保护

`.env`、本机 AI 索引、秘密文件目录已加入忽略规则；`.githooks/pre-commit` 检查暂存内容，已有 pre-push 检查未推送提交中的文件，pre-merge 也调用同一个检查器。当前仓库 hooksPath 已指向 `.githooks`。

检查器内存读取本机来源和手动配置的系统密钥，匹配已知真实值，并检查高可信供应商 Token 形态；只报告文件及错误码，不报告值或所在行。既有确定性脱敏测试的字母表伪 Token 精确豁免，但已知真实值检查始终优先。没有外部本机配置的 CI 仍检查供应商 Token 形态。Git Hook 可被人为绕过，因此该机制不等于对任意未知密钥的绝对识别保证。
