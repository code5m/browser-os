# BrowserOS 智能体与技能工作台 · 基础实现蓝图

状态：`CURRENT: 蓝图 CRUD/步骤/本地存储/导入导出/原生定义校验；PLANNED: 安装、执行、真实对话`

## 产品目标
保持 BrowserOS 浏览器及文件管理器稳定，将“智能体”和“技能”转为可理解的工作台，先提供最小可用规划功能，不以静态假数据假冒安装和运行。

## 界面结构
- 顶部：模块身份、标题、当前能力说明、新建和导入按钮
- 概览数据：本地蓝图数、手动完成数、已保存定义数、后端状态
- 左侧：独立项目列表、搜索、任务完成度、本地存储说明
- 右侧：概览、任务步骤、定义检查、权限与运行状态四个视图
- 详情操作：复制、导出、删除（删除需要再次确认）

## 已落地的最基本流程
1. 新建蓝图，填写名称、用途、目标、输入、输出、约束
2. 添加和编辑步骤，手动勾选进度；状态仅代表手动规划
3. 即时保存到当前设备的本地工作台，Agent/Skill 使用独立存储键
4. 搜索、复制和删除；JSON 导入导出；导入定义默认清除避免继承信任
5. 使用 Rust 现有 agent_validate/skill_validate 和权限预览接口
6. 仅在本轮定义验证成功且定义内容未变化时保存已验证定义

## 数据安全
- 本地存储不是云同步；重装、清理数据或变更应用域可能使草稿丢失，请自行导出备份
- 拒绝明显密钥、Token、私钥；任何带凭据的内容都不应保存
- 单个定义至多 64 KiB；Agent 最多 64 项，Skill 最多 200 项；每项最多 32 个步骤
- 损坏存储时阻止覆写原文，需恢复或导出原数据后处理
- 非执行面；不把“定义验证通过”描述为“已安装”或“已运行”

## 后续执行能力蓝图（尚未完成）
- 安装器：持久化版本及授权范围、二段式权限确认、回滚、版本冲突处理
- 运行器：复用 script_runner 的取消、超时、审计、进程组及输出上限
- Agent 对话：明确 Provider、认证、会话状态、stream 协议、离线和异常行为
- 运行记录：真实执行后生成，不回填假记录
- 未来升级：从浏览器本地草稿迁移到 Workspace 受控文件/原生存储时必须有迁移回滚和兼容验收
