## 1. 使用规则

本文把双平台适配拆成可逐步实施的小任务。任务卡中的“高级模型”“普通模型”是工作分配建议，不是能力或权限边界；最终仍以代码审查、CI 和真实平台验收为准。

每个任务实施前必须补齐：

- 目标与非目标。
- 允许修改的文件和明确禁止修改的边界。
- 接口或行为合同。
- 测试命令与预期结果。
- 回滚方式和评审人。

每个 PR 默认不超过 150 行；超过就继续拆。文件移动、平台抽象和业务语义变化不得混为一个 PR。

状态只能使用：`未开始`、`进行中`、`阻塞`、`待评审`、`已完成`。没有证据不得标记已完成。

## 2. 模型路由原则

### 2.1 高级模型主导

任一条件命中即升级：

- 跨三个以上模块改架构。
- OS API 或行为存在不确定性。
- 涉及凭据、ACL、远程页权限、文件安全或沙箱。
- 涉及并发、进程树、取消竞争或数据一致性。
- 错误可能导致越权、隐私泄漏或用户数据损坏。
- 需要判断“编译成功”是否被误写为“功能支持”。

高级模型负责：设计合同、技术验证、关键实现、安全审查和最终 Diff 终审。

### 2.2 普通模型执行

必须已有明确接口、修改范围、禁止事项和验收命令：

- 单文件或小范围确定性修改。
- 按既有接口做机械替换。
- 补普通单元测试、页面夹具和参数化场景。
- CI、安装包、图标、文档和证据整理。
- 按测试矩阵执行并记录真实结果。

普通模型不得自行扩大权限、修改测试预期或改变成功语义。

### 2.3 脚本与 CI 执行

重复工作不消耗模型：静态扫描、格式、类型、编译、单元测试、重复安装启动、故障夹具回归、进程残留和产物哈希核对。失败必须保持红色，不能自动生成 PASS。

## 5. 高级模型必须亲自完成初版的关键实现

以下工作不能只给普通模型一句“实现跨平台”：

1. XP-005 WebView2 技术验证。
2. XP-007 脚本执行回执。
3. XP-008 BFC 页面事件与现有状态机的映射。
4. XP-011 Windows 安全读取和 CAS 替换。
5. XP-012 Job Object 进程树管理。
6. XP-016 Named Pipe 身份与 ACL。
7. XP-017 Agent/LSP 沙箱原型。
8. 上述模块的最终安全 Diff 审查。

## 6. 普通模型可并行领取的工作包

在高级模型已经给出合同后，可并行执行：

- XP-001 静态清单与生产/测试代码分类。
- XP-002 workflow 和产物上传。
- XP-003 中已经确定接口的机械路径替换。
- XP-009 普通 BFC 夹具、伪服务和参数化测试。
- XP-010 安装、升级、卸载矩阵执行与证据整理。
- XP-013 已确定合同下的 PowerShell 配置和普通测试。
- XP-014 已确定 HTTP/密钥合同下的实现和测试。
- XP-015 数据库测试配置、SQLite 用例和凭据存储测试。
- XP-018 NSIS 模板、图标、开始菜单和卸载。
- XP-019 Linux 包格式与 Secret Service 矩阵。
- 支持文档、故障排查、发布说明和证据索引。

## 7. 普通模型不得独立执行的变更

- 修改 BFC ACL、远程 URL、WebView 来源或主窗口授权。
- 增加 Cookie 读取、导出、远程调试或 CDP 端口。
- 将安全读取改为普通 `fs::read`。
- 将原子替换改成先删除再写入。
- 用只读权限位代替 Windows ACL。
- 修改登录、分页、导入、取消和结果未知的成功判断。
- 删除断言、跳过测试、把失败改成警告。
- 在无沙箱的 Windows 上静默开放 LSP。
- 用 Linux GUI PASS 标记 Windows PASS。
- 将平台重构、文件移动和业务语义变化合并成大 PR。
