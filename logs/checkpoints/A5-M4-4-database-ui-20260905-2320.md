## 4. 关键设计决策

### 4.1 Live wiring（P-A5-2，本次完成）

`src/bridge.ts` 新增（命令名沿用 A1 冻结，未改名）：

```ts
// 类型导入补：DbConnectionConfig, DbConnectResult, DbQueryResult

dbConnect: (cfg: DbConnectionConfig, password: string) =>
  invoke<DbConnectResult>("db_connect", { cfg, password: password || null }),
dbQuery: (p: { conn_id: string; sql: string; timeout_secs?: number | null; confirm_write: boolean }) =>
  invoke<DbQueryResult>("db_query", p),
dbDisconnect: (conn_id: string) => invoke<null>("db_disconnect", { conn_id }),
```

`src/types.ts` 新增 DTO（镜像 `domain.rs`，snake_case 嵌套，Tauri 仅转换顶层 camelCase）：
`DbKind / DbSslMode / DbLimitKind / DbQueryState / DbValue`（带标签枚举）/`DbConnectionConfig`/`DbConnectResult`/`DbQueryResult`。

`src/stores/useDatabaseStore.ts`：
- 移除 `DbBridgeApi` 探测接口，直接 `import { bridge }` 调 typed wrapper；`backendReady` 改为探测 `bridge.dbConnect/dbQuery/dbDisconnect` 是否为函数（命令缺失仍 fail-closed 禁用）。
- `connect`：`cfg = buildConnectPayload(form)`（含 `id/created_at/updated_at`），`bridge.dbConnect(cfg, password)` → `activeId = res.conn_id`；密码只作瞬时参数，**不进** payload/store/表单。
- `execute(text, confirmed)`：`bridge.dbQuery({ conn_id, sql: text, timeout_secs: null, confirm_write: confirmed })`；`timeout_secs:null` 沿用后端默认（`DB_DEFAULT_QUERY_TIMEOUT_SECS`）。
- `disconnect`：`bridge.dbDisconnect(activeId)`。
- `requiresConfirm = form.allowWrite`（写权限连接需二次确认；只读连接直接发 IPC，后端仍逐条闸门）。前端不自行分类（F4）。
- `refreshConnections`：A4 未提供连接列表命令（M4-4 聚焦「即连即查」），保留空实现，待将来 `db_list_connections` 接入时无需改调用点。

### 4.2 其余沿用设计

1. **密码零落地**（F2）：密码仅作 `connect(password)` 瞬时入参。
2. **确认前不发 IPC**：`requiresConfirm` 时先挂起 `pendingSql`，用户点「确认执行」才 `invoke`。
3. **不造第二套分类器**：风险等级只消费后端回带值，缺失即 `unknown`（按最严）。
4. **截断非静默**：`truncated/field_truncated/limit_hit/state` 任一异常均有明确告警行；DOM 仅渲染前 200 行并注明「另有 N 行未渲染（数据未丢失）」。
5. **不接成果库导出**：M4-1.c §1 的 `DB_MAX_EXPORT_BYTES=16 MiB` 仍无消费方（见 P-A5-3）。
