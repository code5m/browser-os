## 二、真实运行与驱动尝试

1. **release 构建已存在**（`src-tauri/target/release/mvp-browser-os`，9/1 前构建）。按模板要求用 release 产物。
2. **普通持久模式启动成功**：`WEBKIT_DISABLE_DMABUF_RENDERER=1 GDK_BACKEND=x11 ./...release/mvp-browser-os` → 主窗 `浏览器OS融合` 1854x1011 正常渲染，FE alive、`m0_ready` 正常。
3. **尝试触发出宫格（失败）**：
   - `xdotool key ctrl+shift+g`（宫格快捷键，来自 `useSettingsStore.ts:15`）→ 日志无 `create_grid`，无子进程。
   - `xdotool click` 点击 ActivityBar 宫格按钮坐标 → 同上无效。
   - 应用无 URL/env/CLI 直接开宫格的入口（`rg` 确认无 `OPEN_GRID`/`GRID_AUTO` 等）。
   - **结论**：普通模式下无法触发出持久宫格会话，无法做交互验证。
4. **经 `GRID_SELFTEST=1` 确认真实多进程架构可用**：
   - 子进程 `--grid-child 0/1` 真实 spawn（独立 PID）。
   - `grid_open(0/1)` 加载 `https://www.baidu.com` / `https://www.bing.com`（`navigationFinished` 确认 webview 真实渲染）。
   - **崩溃自愈真实发生**：`kill -11 grid-child-0` → `异常退出 code=139，自动重启` → 新 PID spawn → `状态重放完成 url=https://www.baidu.com`（同 URL 恢复）→ `grid-1-survived`。`SELFTEST_RESULT=ALL_PASS`。
   - 证据：`/tmp/grid-selftest-result.txt`、app.log（已归档至 `logs/m0-6c-gui-evidence/20260901-0037/`）。
5. **子窗口可识别但不可截屏**：
   - `xwininfo` 确认 `grid-child-1` 为真实 `InputOutput` 窗口（706+189 560x420）。
   - 但 `scrot` 全屏/主窗截图均为 **1920x1080 全黑 (0,0,0)**；`xwd -id $MAIN` 报 `BadMatch / X_GetImage` 失败、0 字节。
   - 根因：会话是 **Wayland（wayland-0）**，应用跑在 Xwayland 上；截图工具走 X11 `XGetImage`，对 compositor 合成内容读不到（黑屏/失败）。这是 Xwayland 已知限制。
