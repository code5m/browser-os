## 2. 安全边界（与 REQUIRE 1–12 逐条对齐）

1. push 是 `GitWriteOp::Push`，走既有 `GitWriteJob` 双阶段，无旁路。✅
2. `request_git_write` 阶段只做只读预检（HEAD/分支/远端存在性/领先数），不构造任何网络调用、不读 KeyringStore。✅
3. `confirm_git_write` 阶段才执行 push（后台线程）。✅
4. `Push.is_dangerous()=true` → 必须 `confirmed_dangerous=true`，否则 `Err("需二次确认")` 且任务不取出（零执行）。✅
5. refspec 内部构造，无 `+` 前缀（force）、无前导冒号（删除远端分支）、无 mirror；`build_push_refspec` 输入经 `validate_branch_name`（拒 `:` 等）。✅
6. 只允许推「当前检出的本地分支」到 `origin` 同名远端分支；`write_push` 无 remote/refspec 参数（调用方无法注入）；`GIT_PUSH_REMOTE` 常量收敛。✅
7. 凭据复用 `push_artifacts` 同一思路：`KeyringStore::get_token`（仅推送瞬间）→ `cred_cb`（token 作 HTTPS 密码）；无新增明文 token 存储；错误串经 `scrub_sensitive_error`（token 精确替换 + URL userinfo 掩码）后才落审计/回前端。✅
8. 审计字段：`op=push`、`repo_id`、`job_id`、`branch`、`remote_name`、`confirmed`、`path_count`、成功/失败；不含 token、带凭据 URL、diff。✅（测试 `git_write_push_audit_fields_present_and_sanitized`）
9. fail-closed：未配置 origin / detached HEAD / 远端拒绝 / 非 fast-forward / 网络失败 → 全部 Err，本地工作树与索引不变（非 FF 测试断言本地与远端 OID 均不变）；job 一次性移除后可重新 request 重试。✅
10. `push_artifacts` 链路零改动（diff 证据：`git diff 1de6bcb -- src-tauri/src/sync.rs` 对 `push_artifacts/pull/clone_repo/commit/fast_forward/three_way_merge` 函数体无改动；策略脚本行为锚点检查通过）。✅
11. `check-git-write-policy.py` 已扩展 push 不变量并通过。✅
12. b/c/d 证据齐全后签 M1-6 整体 PASS（§7）。✅

- `GIT_WRITE_PUSH_NOT_DANGEROUS` / `GIT_WRITE_PUSH_GATE_MISSING`（`execute_git_write` 必须有 push 映射）
- `GIT_WRITE_PUSH_AUDIT_FIELDS_MISSING`（审计签名必须含 branch/remote_name；签名切片只到 `{`）
- `GIT_WRITE_PUSH_ARTIFACTS_BROKEN`（`push_artifacts` 行为锚点：pull/commit/push/KeyringStore）
