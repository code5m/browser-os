## 2. 候选方案

| 方案 | 形态 | 直接依赖增量 |
|---|---|---|
| **C1** sqlx（async） | 三驱动统一 API，需运行时 | `sqlx`（runtime-tokio + 三驱动）+ `tokio`（直接依赖，F-1 选项 a） |
| **C2** rusqlite + mysql + postgres（sync） | 三驱动各自 API，`DbPool` 枚举适配 | `rusqlite`(bundled) + `mysql` + `postgres` |
| **C3** diesel | 编译期 schema 绑定 | `diesel` + 三后端 feature |

C3 **首轮即淘汰**：本项目做的是「用户输入任意 SQL 的控制台」，schema 在运行期才知道；
diesel 的价值（编译期类型安全查询）在本场景**无消费方**，强加即成无人使用的复杂度。
（与 M2-3 拒绝 `ScriptRunRecord` 空结构、M2-5 拒绝 mock 执行器同一口径。）

## 3. F-1 裁决：不把 `tokio` 提升为直接依赖（选 b）

**裁定：F-1 选 (b) —— 应用层保持 `std::thread` + 可中断等待（Condvar/AtomicBool），不引入 `tokio` 直接依赖，不自建 async runtime。**

理由（按权重排序）：

- **R1 现状一致性（最高权重）**：全仓零 async 业务代码（实测 10）。M2-4 的 `script_runner`（进程组/超时分层/取消/输出背压）、M3.a 的 `terminal`（worker→mpsc(128)→pump→sink）、M1-6 的 `sync` 三条最复杂的生命期链路**全部是 std::thread**。M4-7 还被护栏强制「复用 M2-4 执行通道」。引入第二条并发模型，收益为零、认知与排障成本为实。
- **R2 结果上限必须在取数循环内生效（A10 G-6）**：同步行迭代器可逐行计数、超限立即 `break` 并丢弃剩余；异步需 stream + 取消令牌 + 丢弃语义，表达更绕而能力不增。
- **R3 取消**：SQLite 有 `interrupt_handle`；MySQL/Postgres 需独立连接发 `KILL QUERY` / `pg_cancel_backend`（**A3 实现时按 crate 实际 API 核对，本卡未实测**）。异步栈在这一点上不占优（同样依赖带外取消）。
- **R4 供应链与构建基线（A10 G-11）**：sqlx 栈额外引入运行时 feature 与 TLS 栈，并把 tokio 从「传递实现细节」提升为「应用级运行时」，与 M0-4「依赖清理」的既有口径相冲。
- **R5 可测性**：同步栈可在 `cargo test` 内对 SQLite 内存库做真实断言；异步栈需为测试再备一个 runtime。

**反方检验（必须记录，否则裁定不成立）**：实测 `tauri::async_runtime` **真实存在**（实测 3），
因此「异步必须新增 tokio 直接依赖」这一前提**并不严格成立**——技术上可以走
`sqlx + tauri::async_runtime::block_on` 而不碰 `Cargo.toml` 的 tokio 行。
**仍不采用**，原因有二：
① `async_runtime` 是**应用共享**运行时，连接池后台任务与可能的驱动阻塞会与 UI/IPC 抢同一 runtime；要隔离就得自建（回到 C1，等于引入 tokio）；
② 它把数据库层的可用性绑在 Tauri 的 re-export 上——这是一条我们**不控制版本与语义**的通道。

## 4. F-2 裁决：不做 `build.rs` + YAML 代码生成（选 b）

**裁定：F-2 选 (b) —— `SupportedDb` 手写于 `domain.rs`，`build.rs` 保持 `tauri_build::build()` 不变，不新增 YAML 及解析器。**

理由：

1. **代码生成省不掉真正的成本**：新增一个驱动的实质工作是「`DbPool` 变体 + 该驱动的
   connect/query/cancel/close 适配实现 + 方言分类表 + 前端字段显隐 + 三库测试」，
   其中**没有一项能靠生成枚举完成**。所谓「加库只加 YAML」在本项目**不可兑现**
   （dbx 的收益建立在 5 成员 workspace 的多 crate 复用上，本项目是单 crate，实测 11）。
2. **成本真实**：需新增 `serde_yaml`（或自写解析）+ `OUT_DIR` 生成物，生成物不可 grep、
   不可 rust-analyzer 跳转，审计性变差（A10 G-11 正要求 **YAML 需 schema 校验**——
   不做生成就不需要这套校验机）。
3. **穷尽性已经足够**：手写枚举后，所有「按驱动分支」的 `match` 都是**编译期穷尽**的，
   漏改即编译失败——这是比代码生成更强的保证。

**「生成契约」在本项目的真义（写进契约，避免后人误读）**：
`SupportedDb` 是**唯一驱动身份定义点**，其余扩展点由「`match` 穷尽性（编译期）+ §5 六处清单（夹具与测试矩阵）」共同兜住。
契约**明确不宣称**「加库只改一处」。

## 6. 驱动选型裁定

**裁定：采用 C2 —— `rusqlite`（`bundled`）+ `mysql` + `postgres`，同步栈。**

配套硬约束（写入契约，A3 落地时必须遵守）：

1. **禁止 JDBC 侧车**（WBS 明令，重申）：不得引入 JRE / JDBC / Maven / Gradle 任何形态；由 `DB_JDBC_SIDECAR` 码位静态守。
2. **禁止未裁定驱动**：`sqlx` / `diesel` / 任何 ORM，以及把 `tokio` 提升为直接依赖——由 `DB_UNDECLARED_RUNTIME` 码位静态守；**推翻本裁定必须 A0 书面裁决**。
3. **禁止多语句**：用户 SQL 一律走单语句通道
   （sqlite 用 `prepare` **禁** `execute_batch`；postgres 用扩展协议 `query` **禁** `simple_query`/`batch_execute`；mysql 关闭 `CLIENT_MULTI_STATEMENTS`——**A3 按 crate 实际 API 核对，本卡未实测**）。
4. **凭据不参与字符串**：连接参数以类型化字段构造，禁止拼接 DSN 字符串；错误串与审计一律先脱敏（A10 G-2）。
5. **诚实声明（重要）**：实测 6 证明 `postgres` crate 内部依赖 `tokio`。因此
   **「同步栈」的正确表述是「应用层不使用 async、不自建 runtime、不新增 tokio 直接依赖」，
   而**不是**「依赖树里没有 tokio」**。任何以「tokio 还是在 lock 里」为由推翻本裁定的论证无效。

- **A3 引入 C2 三依赖后必须做**：`scripts/measure-build-metrics.py` 采集并与 M0 基线同口径对比，
  记录 cargo check 耗时、warning 数（必须仍为既有 2）、前端总体积（≤15%）。

  只能与「M0 基线的构建维度」比，不能与吞吐维度比。**M4 不得借机关闭 D24**，也不得把
  「受 D24 影响无法对比」当作免做对比的理由——构建维度不受 D24 影响，必须比。
