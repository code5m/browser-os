## 2. 语义澄清（沿用 `M3-4.b-prework` §4.1 的裁定，未推翻）

`TEMPORARY_HISTORY_LIMIT=40` 与 xterm `scrollback` 是**两件事**，本卡按既有裁定执行：

| 概念 | 含义 | 本卡处置 |
|---|---|---|
| xterm `scrollback` | 能往上翻多少行 | **不动**（"历史上限"任务卡另有草案，未在本卡范围） |
| temporary history（重建回放） | 面板重建/重连时补回最近 N 条输出 | **本卡实现**，N=40 |

草案曾以"本项目无重连场景"为由**暂不采纳**；该前提在 **M3.a 之后已不成立**——
`MainArea.vue:102` 的 Dock 终端是 `v-if` 兄弟分支（`files`/`net`/`session`/`term` 互斥），
**切 Dock Tab 即卸载 `TerminalPane`、xterm 随之销毁并重建**，而后端 PTY 会话仍活着
（`terminalOpen=false` 只隐藏不 kill）。实测：切到"📂 文件"再切回"💻 终端"，
终端一片空白但 `echo` 仍有响应 → 正是"临时历史"要解决的重建回放场景。

## 4. 契约

### 4.1 E1 临时历史

| 项 | 契约 |
|---|---|
| 上限 | 出口块数组长度恒 ≤ **40**，超限丢最旧 |
| 内容 | 仅 `kind==="data"` 的 PTY 输出块；`flow`（丢弃统计）与 `exit`（结束提示）**不进历史** |
| 生命周期 | 会话内；`killShell` / `startShell(force)` 清空；进程退出随内存消亡 |
| 消费 | 面板 mount 后 `replayTermHistory()` 补写给新 xterm；回放**不回写**历史（不翻倍、不自喂） |
| 落盘 | ❌ **绝对不落盘**（不写文件、不进 `audit.json`、不写 debug 日志正文） |
| 内存上界 | 40 × 单块 ≤ 64 KiB（`TERM_BATCH_MAX_BYTES`）≈ **2.5 MB**，与输出量无关 |

### 4.2 E2 resize 静默窗口（三条硬规则，`M3-4.b-prework` §4.2）

1. **去重**：行列未变 → 零排程、零 invoke（`ResizeObserver` 抖动不产生 IPC）。
2. **静默窗口 140 ms**：连续 resize 只在停手后下发一次。
3. **硬上界 500 ms**：距上次下发超过 500 ms 立即下发（`wait=0`），避免"持续慢拖时终端一直不重排"。

附加：`fit()` **每次都调**（前端渲染实时跟随），静默只作用于后端上报；
`term_resize` 失败一律 `.catch(() => {})`，**不弹窗/不吐司**（高频路径刷屏）；
新会话 `reset()` 清去重态，保证新 PTY（默认 100×24）一定收到首个真实行列。

### 5.1 新增逻辑测试覆盖（25 断言）

E1（8 条）：无 writer 时回放安全 / 灌 100 条后长度=40 且保留最新 / `flow`+`exit` 不进历史 /
重建后回放 40 条且内容一致 / 回放不回写（长度不翻倍）/ `killShell` 清空 / 重启清空（无跨会话残影）/
全流程后 `localStorage` 零终端内容（不落盘）。

E2（17 条，假时钟）：同尺寸去重只发 1 次 / 首帧零等待下发 / 30 次快速 resize 只再发 1 次且为最后尺寸 /
持续慢拖 3 s 至少下发 6 次且受硬上界约束 / 超硬上界后 `wait=0` / `dispose()` 后零回调 /
`reset()` 后同尺寸可再下发 / `NaN`/`Infinity` 零下发。

`TERM_HISTORY_LIMIT_MISSING`、`TERM_HISTORY_RECORD_MISSING`、`TERM_HISTORY_REPLAY_MISSING`、
`TERM_HISTORY_CLEAR_MISSING`、`TERM_HISTORY_PERSIST` / `TERM_HISTORY_AUDIT` / `TERM_HISTORY_BACKEND`
