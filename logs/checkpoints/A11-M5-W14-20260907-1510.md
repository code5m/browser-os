## 2. 阻塞项 (BLOCKER) — pre-merge FAIL `PLUGIN_UI_NO_SECRET_RENDER`

`bash scripts/pre-merge.sh` 输出：
```
[pre-merge] FAIL: check-plugin-ui-privacy.py --self-test
[pre-merge] FAIL: check-plugin-ui-privacy.py（插件 UI 隐私不变量被破坏）
[pre-merge] PRE_MERGE_RESULT=FAIL
```
夹具命中 20 条 `PLUGIN_UI_NO_SECRET_RENDER`：`\.pubkey` ×4、`pubkey` ×16。

### 根因判定：结构性误报 (false positive)，A6 代码实质合规

`check-plugin-ui-privacy.py::detect_hits` 的 A2 分支对 `SECRET_RENDER_TOKENS` 做**全文子串扫描**（含 `pubkey` 且 IGNORECASE），不区分"展示存储的密钥"与"瞬时输入表单字段"。

`pubkey` 字面量在 A6 代码中的**唯一**出处是受信任密钥的**瞬时粘贴输入**，从未被展示或持久化：

- `src/components/plugin/PluginManager.vue`
  - L24-25 `keyForm = reactive({ keyId:"", pubkey:"", note:"" })` — 表单瞬时字段
  - L66-67 校验 `keyForm.pubkey.trim()` 非空 + 错误文案
  - L94 `store.addKey(keyForm.keyId, keyForm.pubkey, keyForm.note)` — 传入即清空
  - L96 `keyForm.pubkey = ""` — 成功后立即清空
  - L173 `<input v-model="keyForm.pubkey" placeholder="pubkey（仅用于登记，不回显）">` — 用户输入框
- `src/stores/usePluginStore.ts`
  - L195-196 `addKey(keyId, pubkey, note)` 注释明确"pubkey 为瞬时入参，后端仅回 16-hex 指纹，不持久化原文"
  - L205 `pubkey: pubkey.trim()` — 经 `bridge.pluginKeysAdd` 上送，后端只回指纹

**关键合规证据**：受信任密钥列表 (`PluginManager.vue` L165-170) 只渲染 `{{ k.key_id }}` 与 `{{ k.fingerprint }}`；`pluginUi.ts::redactKeyRecord` (L168-170) 投影也只含 `key_id/fingerprint/note/added_at`，**不含 `pubkey`**。因此 A6 从不展示存储的公钥原文。

> 结论：A6 未违反 W14 Hard Stop（"不展示/不持久化公钥原文"）。唯一 `pubkey` 出现处是用户自粘贴、立即清空的瞬时输入缓冲，属合规设计。夹具的子串扫描粒度过粗导致误报，使 pre-merge 误红。

### 推荐修复（二选一，需 A4/A6 择一落地后复跑）

- **方案 A（推荐，改夹具，A4 负责）**：`detect_hits` 的 A2 分支仅对"展示/输出位置"的 `pubkey` 判违——即只保留 `\.pubkey`（含 `{{ x.pubkey }}`、`:xxx="...pubkey"` 绑定），并删除裸 `pubkey` 子串 token；或显式排除 `<input ... v-model>` / `reactive({...})` 表单字段声明上下文。这样既放行 A6 的瞬时输入，又仍能在 `{{ detail.pubkey }}` 类真实回显时报警。
- **方案 B（改 A6 代码）**：将瞬时字段与 placeholder 中的 `pubkey` 字面量改名（如 `keyMaterial` / 占位文案去掉 `pubkey`），使裸 token 扫描不再命中。保持夹具严格不变。

## 2b. 阻塞项 (BLOCKER) — 构建指标回归 (+24.91% > 23% 上限)

`bash scripts/pre-merge.sh` 输出：
```
[pre-merge] FAIL: build metrics regression vs logs/m0-build-metrics/build-metrics-4f0e8ab.json
```

### 根因
`measure-build-metrics.py` 的 `TOTAL_BYTES_GROWTH_LIMIT_PCT = 23.0`，pre-merge 固定与 M0 基线 `build-metrics-4f0e8ab.json` 比对：
- M0 基线：`dist.file_count=8`, `total_bytes=612943`
- 当前（a7eefbb + A6 UI）：`dist.file_count=22`, `total_bytes=765705`
- 增长 = (765705 − 612943) / 612943 = **+24.91%** → 超 23% 上限 → 门禁 FAIL
- 佐证：`cargo_warnings=2`（与基线持平，未增）、`fmt_clean=true`、无 >500KB chunk，故仅体积越限。

### 归因
脚本头部注释记录了阈值演进史（M0=15% → M4=16% → W5=19% → W6=21% → W8=22% → W12=23%，每次均附"当前实测%"，W12 实测 22.26% 刚好压线）。本波（W13/W14）前端新增以 **A6 插件管理器面板**（`PluginManager.vue` 全量面板 + `usePluginStore.ts` + `pluginUi.ts`）为主，把基线增长从 W12 的 22.26% 推到 24.91%，越过 23% 红线。属真实门禁失败（非工具误报）。

### 推荐处置（需 A0 / A6 决策，**非 A11 越权修改**）
- **方案 C（推荐，A0 重定基线）**：沿用历史先例（W5/W6/W8/W12 均由 A0 书面抬阈），在脚本注释中追加一条 M5-W14 记录并 `TOTAL_BYTES_GROWTH_LIMIT_PCT` 抬至 26%（当前实测 24.91%，留 1pp 余量），附书面理由。
- **方案 D（A6 减量）**：若不愿抬阈，A6 可将插件面板改为路由级懒加载（动态 import）并剔除未用依赖，压低主包；但注意本门禁比对的是 dist **总**体积，懒加载只能降主包、难降总量，效果有限。
