## 允许根目录的取值理由

`allowed_roots()` = 主目录 / `~/Desktop` / `~/Documents` / `~/Downloads` / 成果工作区 / 笔记目录。

刻意与 `get_start_dirs` 对外承诺的入口保持一致——否则文件管理器会出现「能列出来却写不进去」的不一致。效果是：用户目录内增删改名照常，`../` 逃逸、符号链接逃逸、写到 `/etc`、`/usr` 或其他用户目录全部拒绝。

## 本轮修掉的一个真实逃逸

`rename_path` 原实现是 `parent.join(new_name.trim())`：`new_name` 取 `../../etc/x` 时，重命名即变成跨目录移动（写入逃逸）。新增 `check_path_component` 拒绝任何含 `..` 或分隔符的名称。

## 只读浏览（按裁决保留，登记 SEC-09）

`list_dir` / `read_file` / `browse_workspace` / `get_start_dirs` 仍可读任意路径——外部页面或恶意内容理论上存在信息泄露面。按裁决不一刀切破坏文件管理器功能，已登记为 `READ_ONLY_BROWSE_WITHOUT_PATH_POLICY` 并在夹具中持续跟踪，留待后续裁决。

1. 夹具缺 `function_body` 辅助函数（该方法只存在于生命周期夹具），新增的检测器直接 `NameError`。
