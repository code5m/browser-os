## 2. 对冻结裁定书的 5 处澄清 / 微调（**需裁定者确认**，同 M2-3「两处微调」口径）

### 2.1 【必须裁】argv 模式下**一律不加引号**，`raw` 在 b 卡为 no-op

- **冲突**：a 卡 §8.1 要求「参数值独立 argv 元素（shell 不重解析）」，同时 §8.1 末条写「`raw=true` 参数跳过单引号包裹」。
- **事实**：`Command::arg(v)` 走 `execve` 的 argv 数组，**shell 根本不参与**。此时给值加 `'...'` 会把单引号作为**字面量**传进脚本（真实 bug：`Path` 值会被脚本读到带引号的路径）。
- **裁定建议**：`build_argv` 对所有参数**一律不加引号**；`ScriptParam.raw` **保留字段**（M2-3 已落库 + 定义期校验），在 argv 模式下不产生任何差异，注释标注「argv 模式下 no-op，仅在未来若引入 shell 拼接模式时才有意义」。
- **安全不变弱**：防注入由「argv 数组 + `validate_param_value` 九条 fail-closed」双重保证，不依赖引号。此方向为 fail-safe。

### 2.2 【中间态】b 卡 `stdout/stderr` 用 `Stdio::null()`，d 卡改 `piped`

- **冲突**：a 卡 §8.1 最终形态为 `.stdout(Stdio::piped()).stderr(Stdio::piped())`。
- **事实**：Linux 管道缓冲默认 64 KiB。**piped 而不读会导致子进程阻塞**；而读输出 + 环形缓冲 + 事件流属 d 卡（a 卡 §9 边界）。b 卡若上 piped 就必须同时实现 drain 线程 = 越界做 d 的活。
- **裁定建议**：b 卡用 `Stdio::null()`，代码留 `// TODO(M2-4.d): 改 piped + reader 线程 + 环形缓冲` 指向 d 卡。
- **风险登记**：d 卡若忘记接管会出现管道阻塞，已写入 §7 移交清单（d 卡任务卡 PASS_CRITERIA 必须显式验证）。

### 2.3 【一致性】`ScriptMeta.timeout_secs` 注释 `300` → `60`

- a 卡 §2 裁定全局默认 **60s** 并明确「裁决修正 M2-3 注释口径」，但代码注释仍写「0 = 使用全局默认（300）」（`domain.rs:620`）。
- b 卡实现时同步改注释为 60（**仅注释，不改语义**）。§1.15 已确认不影响既有门禁。

### 2.4 【新增】`ScriptInterpreter::binary()` 落 `domain.rs`

- a 卡 §8.1 给的映射表（Bash→`bash` / Sh→`sh` / Python3→`python3` / Node→`node` / Shebang→无解释器，直接 exec 脚本文件）目前**在代码里不存在**。
- 落位建议：与 `ext()` 同处 `impl ScriptInterpreter`（`domain.rs:565`），保持解释器白名单**单一来源**；`Shebang` 返回 `None`。
- 注意 `ext()` 中 `Bash`/`Sh`/`Shebang` 均返回 `"sh"`（M2-3 定义），但 `binary()` 必须区分 `bash` 与 `sh`——两者不冲突，是不同用途（扩展名 vs 可执行程序）。

### 2.5 【落位确认】`RunStatus` 落 `domain.rs`（a 卡 §7 已定，b 卡执行）

- `Running | Succeeded | Failed | Cancelled | Timeout`（用 `Succeeded`，不用 `Success`）。
- a 卡 §7 已明确「定义位置：`domain.rs`，与 `ScriptMeta` 同文件」，b 卡照此执行（**不新建文件**）。
- `ScriptRunRecord` 结构体**本卡不落**（a 卡 §9 归 d 卡，因其主体是 `output_tail` 落盘）。

## 3. b 卡设计（本卡冻结，实现时不得偏离）

### 3.1 新文件与常量

新增 `src-tauri/src/script_runner.rs`（纯进程/生命周期层，**不含任何 `#[tauri::command]`**）：

```rust
pub const DEFAULT_TIMEOUT_SECS: u32 = 60;    // a 卡 §2
pub const MAX_TIMEOUT_SECS: u32 = 600;       // a 卡 §2，脚本级上限
pub const HARD_GRACE_SECS: u32 = 5;          // soft 后多久 SIGKILL
pub const CANCEL_GRACE_SECS: u32 = 5;        // 取消后多久 SIGKILL
pub const MAX_CONCURRENT_RUNS: usize = 8;    // a 卡 §3，全局并发护栏
pub const MAX_TABLE_ENTRIES: usize = 200;    // 对齐 a 卡 §7 MAX_RUN_RECORDS
pub const POLL_INTERVAL_MS: u64 = 50;        // supervisor 轮询间隔（见 §3.4 选型理由）
```

### 3.2 类型

```rust
// domain.rs（与 ScriptMeta 同文件）
pub enum RunStatus { Running, Succeeded, Failed, Cancelled, Timeout }

// script_runner.rs
pub struct RunSnapshot {           // 内存中运行状态快照，供 c 卡 script_status 查询
    pub run_id: String,
    pub script_id: String,
    pub status: RunStatus,
    pub started_at: DateTime<Utc>,
    pub finished_at: Option<DateTime<Utc>>,
    pub exit_code: Option<i32>,
    pub error: Option<String>,
}

struct RunEntry {
    script_id: String,
    pgid: Option<i32>,                  // unix: setsid 后 == child.id()；非 unix: None
    started_at: DateTime<Utc>,
    effective_timeout: u32,
    cancel: Arc<AtomicBool>,            // c 卡 cancel_script 只置此位，不阻塞
    state: Arc<Mutex<RunSnapshot>>,
}

pub struct ScriptProcessTable {
    runs: Mutex<HashMap<String, RunEntry>>,   // key = run_id
}
```

**进程表语义（明确裁定）**：
- 终态后 **entry 不立即移除**，保留 `RunSnapshot` 供 c 卡 `script_status` 查询（否则状态查询无从返回）。
- 容量 `MAX_TABLE_ENTRIES = 200`，**只淘汰终态** entry（FIFO，丢最旧终态）；`Running` 永不淘汰。
- `output_tail` **不在**本卡（d 卡负责，见 §2.2）。

### 3.3 所有权与线程模型（**关键**）

- **进程表不持有 `Child`**。`Child` 在 spawn 成功后**立即移入 supervisor 线程**。
  - 理由：`Child` 需可变借用且要跨线程移动；若进程表持 `Child`，任何 `wait` 都必须在锁内进行，会阻塞 `script_status`/并发上限判定（锁竞争 + 潜在死锁，同 M0-2.b「清理任务持业务锁」的教训）。
- 进程表只存 `pgid` + 状态快照 + 取消信号；取消与查询均**不阻塞**。

### 3.4 超时 / 取消状态机（supervisor 线程）

- **选型：单线程轮询**（`try_wait` + `sleep(POLL_INTERVAL_MS)`），而非「wait 线程 + timer 线程」双线程。
  - 理由：无需跨线程同步 `wait` 结果；行为可测；50 ms 精度对秒级超时（≥5 s）完全够用；8 并发 = 最多 8 个常驻线程，可接受。
- 状态机：
  ```
  spawn(setsid) -> 记 pgid=child.id() -> Running
  轮询：
    已退出          -> Succeeded(exit 0) / Failed(non-zero)，waitpid 已回收，无僵尸
    cancel 置位      -> killpg(SIGTERM) -> 等 CANCEL_GRACE_SECS -> killpg(SIGKILL) -> Cancelled
    elapsed > soft  -> killpg(SIGTERM) -> 等 HARD_GRACE_SECS    -> killpg(SIGKILL) -> Timeout
  ```
- **终态不可互转**（a 卡 §2）：`Timeout` 与 `Cancelled` 一旦落定不得改写。
- **幂等**（R13）：对已终态 `run_id` 调 cancel → `Ok(())`，无副作用。
- **僵尸**：`try_wait()` 返回 `Some(status)` 即已完成 `waitpid`，无僵尸残留。

### 3.5 平台降级（a 卡 §4）

```rust
#[cfg(unix)]     fn spawn_in_new_group(cmd: &mut Command) -> io::Result<Child>   // pre_exec(|| { libc::setsid(); Ok(()) })
#[cfg(not(unix))] fn spawn_in_new_group(_: &mut Command) -> io::Result<Child>     // Err(Unsupported, "UNSUPPORTED_PLATFORM")
#[cfg(unix)]     fn kill_group(pgid: i32, sig: i32)                               // libc::killpg
#[cfg(not(unix))] fn kill_group(_: i32, _: i32)                                   // 空实现（不可达）
```
- 非 unix 不做 Windows Job Object（a 卡 §4 明确）。
- **`pgid == child.id()` 假设**：`setsid` 成功后子进程成为新会话组长，`pid == pgid == sid`。b 卡测试**必须实测验证**（读 `/proc/<pid>/stat` 第 5 字段），并在假设不成立时降级为「kill 直接子进程 + 记录能力缺口」。

## 6. 静态夹具：`scripts/check-script-exec-policy.py`（b 卡新增，接入 pre-merge 第 19 项）

**b 卡职责内的 6 个码（默认模式必须零命中）**：

| 码 | 检测内容 |
|---|---|
| `EXEC_NO_SETSID` | spawn 路径未调用 `pre_exec`/`setsid` |
| `EXEC_NO_KILLPG` | 取消/超时路径未使用 `killpg`（或仍在用 `child.kill()`） |
| `EXEC_TIMEOUT_NOT_LAYERED` | 缺少 soft/hard 分层常量（`HARD_GRACE_SECS`/`CANCEL_GRACE_SECS`） |
| `EXEC_NO_WAIT_REAP` | 无 `wait`/`try_wait` 回收（僵尸风险） |
| `EXEC_ARG_QUOTED` | `build_argv` 中出现单引号包裹（§2.1 回归） |
| `EXEC_PLATFORM_STUB_MISSING` | 无 `#[cfg(not(unix))]` 分支或非 unix 未返回 `UNSUPPORTED_PLATFORM` |

**c/d 卡预留码位（b 卡登记，默认模式**不判定**，用 `--expect-pending` 单独运行）**：
`EXEC_ACL_MISSING`、`EXEC_HANDLER_NOT_REGISTERED`、`EXEC_NO_SOURCE_CHECK`、`EXEC_SHUTDOWN_NOT_REGISTERED`、`EXEC_RUN_RECORD_MISSING`、`EXEC_NO_RING_CAP`、`EXEC_NO_OUTPUT_CAP`、`EXEC_VALIDATION_BYPASSED`、`EXEC_AUDIT_LEAKS_VALUE`、`EXEC_INTERPRETER_NOT_WHITELISTED`、`EXEC_CWD_NOT_LOCKED`、`EXEC_ENV_NOT_CLEARED`。

> 设计说明（沿用 M0-3.a 成熟模式）：夹具**一次性定义全部码位**，但默认门禁只判 b 卡职责内的 6 个，避免 c/d 未实现的码把 pre-merge 染红。c/d 卡实现后把对应码从 pending 转入默认判定。

**防呆（沿用 M2-3.b 教训）**：`--self-test` 的坏样本必须**真的改变内容**，`str.replace` 未命中（返回原文）时按**漏检测**计，不得静默通过。

## 7. 风险与移交清单

| # | 风险 | 处置 |
|---|---|---|
| 1 | `Stdio::null()` 中间态，d 卡未接管会管道阻塞（§2.2） | 移交 d 卡：PASS_CRITERIA 必须显式验证 piped + reader 生效 |
| 2 | `pgid == child.id()` 假设在少数平台不成立 | B12 实测验证；不成立时降级「kill 直接子进程 + 记录能力缺口」，不在 M2-4 做 Windows Job Object |
| 3 | supervisor 轮询 50 ms，8 并发 = 8 常驻线程 | 可接受；若后续并发上调需重估（登记 NON-BLOCKER） |
| 4 | `kill_all_running()` 在 b 卡无调用者（`#[allow(dead_code)]`） | 注明消费者 = M2-4.d；d 卡接入后删除该标注并核对 warning 数 |
| 5 | 进程表终态 200 上限与 d 卡落盘 200 上限是**两份独立容量** | 移交 d 卡明确二者关系（内存快照 vs 落盘记录） |
| 6 | `Shebang` 依赖可执行位与 shebang，若脚本无执行位会失败 | b 卡给可读错误码；种子脚本（M2-9）需保证执行位 |
