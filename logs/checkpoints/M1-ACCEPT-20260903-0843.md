## 3. 跨模块集成审计（跨任务回归）

结论：后续 M1-* 未破坏前序能力，证据如下。

| 交叉契约 | 核查结果 |
|---|---|
| tab 创建/关闭 | `create_tab` 建会话草稿 + 启动全局唯一资源扫描线程（`swap` 防重入）；`close_tab` 依次清理 child_layouts/position/idle/hibernation/recovery/**resource_buffer.remove_tab**（M1-8）/**session_drafts.remove**（M1-9）/tabs/active_tab，无残留 |
| webview 生命周期 | 关闭走插件 `TabManagerState.close_tab`；shutdown close-tabs 全量销毁并清空全部关联状态 |
| resource capture | M1-9 未改动 M1-8 采集/脱敏/容量代码路径；pre-merge 中 M1-8 两门禁继续全绿 |
| resource clear/remove | `clear_tab_resources` 命令 + close_tab/shutdown 双路径清理；审计仅 tab_id/计数 |
| session save/restore/delete | save=立即落盘+容量裁剪+草稿释放；restore=读已脱敏 URL 走 `create_tab`（单一全局事件订阅，无重复监听实例化）；delete 幂等 |
| shutdown flush → close-tabs | `ShutdownCoordinator` 任务存 `Vec` 按注册序**串行**执行（`shutdown.rs:184` 顺序遍历，报告顺序与注册序一致有专项测试）；`register_shutdown_tasks` 中 flush-sessions 先于 close-tabs（policy `SP_FLUSH_AFTER_CLOSE_TABS` 静态守护）→ **无竞态**：flush 先确定落盘/释放，close-tabs 再清 resource_buffer |
| close-tabs 与草稿 | flush 后草稿已 clear，close-tabs 不再触碰草稿，无双清/漏清 |
| event listener 清理 | 前端资源/会话事件均为 App.vue 全局单订阅（unlisten 于 unmount）；恢复页签复用全局订阅，不新增 listener |
| ACL/source check | M1-8 四命令 + M1-9 十命令全部 `check_invocation_source` + 进 `default-commands.toml` + 注册 `invoke_handler`（policy 双向守护） |
| privacy redaction | 采集时脱敏（M1-8）→ 入库即脱敏 → 落盘前 `build_session` 二次脱敏 URL/预览（M1-9）→ 导出即落盘内容（已脱敏） |

## 4. M1-8 × M1-9 交叉验证（专项）

| 核查点 | 结果 |
|---|---|
| 保存 session 时 resource DTO 仍脱敏 | ✅ `build_session_for_tab` 取 `resource_buffer.records(tab_id)`，缓冲内即 `build_resource_received` 脱敏产物；落盘 JSON 结构性无 cookie/authorization/headers/body（T-sp-1 实测落盘文本断言） |
| resource 数量有界 | ✅ 单会话裁剪至最新 50 条，`resource_count` 记真实总数不伪造（T-sp-4） |
| tab close 与 remove_tab/close protocol 顺序 | ✅ 前端「保存」→ `session_save`（落盘+释放草稿）→ `closeTabNow` → 后端 `close_tab`（清资源+清草稿，草稿已释放为幂等 remove）；「删除」→ `session_discard` → `closeTabNow`；「取消」→ 零副作用 |
| shutdown flush → close-tabs 竞态/数据丢失 | ✅ 串行 Vec 执行，顺序静态+单测双守护；`beforeunload` 前端 flush 与 shutdown flush 双保险**幂等**（首次 flush 后草稿已清空，二次 flush persisted=0），无数据丢失 |
| restore 重新引入敏感 URL | ✅ 恢复 URL 为落盘时已脱敏形态，代码路径不会重新引入；一次性 token 不可恢复为如实声明的设计代价（本地磁盘文件被手工篡改注入 URL 属用户自有文件范畴，出威胁模型） |
| export 泄漏 | ✅ `session_export` 序列化落盘内容（已脱敏），不落盘新增路径写入面 |
| audit/log 出现完整 URL/token | ✅ 全部会话审计格式串仅 id/tab_id/计数/开关值（T-sg-4 + policy `SP_AUDIT_LEAKS_URL`）；M1-8 插件信号块零打印（policy `RC_PLUGIN_LOGS_URL`） |
| session 绕过 M1-8 privacy policy | ✅ 会话资源唯一来源是受 M1-8 policy 守护的 ResourceBuffer，无第二数据通路 |

## 5. 安全/隐私审计（D 项）

| 敏感面 | resource 路径 | session 路径 | audit/log 路径 | export 路径 |
|---|---|---|---|---|
| Cookie / Authorization / Set-Cookie | 信号层不读、DTO 无字段（结构性） | 同上（资源来自同一 DTO） | 格式串无（静态守护） | 落盘内容已脱敏 |
| headers / request body / response body | 信号层不读、DTO 无字段 | 同上 | 无 | 无 |
| token/password/secret/signature 等 21 键 | 采集时 `redact_sensitive_url` → `***` | 落盘前二次脱敏 + 预览文本内 URL 逐个脱敏（UTF-8 安全扫描器，多字节回归 T-sp-8b） | 无 URL | 已脱敏 |

结论：**关键契约无缺口**。userinfo 移除、fragment 脱敏、非 http(s) 丢弃、2048B URL 限长均有测试。

## 6. 生命周期/容量审计（E 项）

- 无无界 Vec/Map：资源两级 FIFO、会话双容量上限、草稿 keyed by tab（随 tab 关闭释放）。
- tab close 后无残留（§3 表逐 state 核对）。
- shutdown 后无 listener/thread 泄漏：资源扫描线程全局唯一且 `shutdown_requested` 退出；GTK 信号随 webview 销毁。
- tmp 文件不积累：原子写 rename 无半截 JSON；启动 + flush 双路径 `prune_tmp_files`（T-sp-8）。
- restore 无重复实例化/重复监听（全局单订阅 + create_tab 唯一建 tab 路径）。
- **观察项（NON-BLOCKER）**：打开页签总数无硬性上限（M0 既有范围，非 M1 引入），`session_drafts` 随之线性增长但单条目 ≤~2.3KB 且随关闭释放；如需硬上限归后续里程碑评估。

### NON-BLOCKER
1. `session_get/delete/export/restore` 的 `id` 参数无格式校验（理论上 `../` 路径遍历）；主窗口本就处于信任边界内（持有全部 invoke 能力），列为加固项，建议后续加 UUID 形态校验。
