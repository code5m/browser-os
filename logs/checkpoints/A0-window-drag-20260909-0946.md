## 已确认事实

1. 用户重装后仍无法拖动；实际活跃主进程 PID 2132761 来自本仓库 `target/debug/mvp-browser-os`，该二进制时间为 06:01:48，不是 09:24 安装的 `/usr/bin/mvp-browser-os`。
2. 原生日志实测拒绝：`window.start_dragging not allowed`，要求 `core:window:allow-start-dragging`。仓库权限已有，不代表旧进程获得新权限。单实例机制使再次启动可能仅聚焦旧窗口。
3. 正常关闭旧窗口、重新构建并启动 debug 主进程 PID 2136703 后，原生拖动请求获准；日志显示同一次按下会同时经过 pointer/mouse 两条显式路径，源码还存在 Tauri 自动拖动属性。
4. 将入口收敛为一次 `mousedown` 请求，并阻止默认行为和 document 冒泡后，用户在本会话实际拖动并回复“现在可以移动”。这是本轮实际桌面确认，不是根据静态脚本推测。

## 修复边界

- 删除重复 pointerdown、自动拖动属性和 Chromium 专用拖动 CSS。
- 页签、按钮及输入控件不触发窗口拖动；双击空白处保留最大化/还原。
- 原生调用失败显示固定提示，不吞错、不显示原始 URL/权限错误内容。

- 不能仅凭现有证据断言“多次请求”是所有 Linux 环境失效的唯一原因；本轮包含旧实例权限纠正和事件入口纠正。
