- `set -euo pipefail`；根目录 `git rev-parse --show-toplevel` 动态解析，无硬编码路径。

## M0-1.a-fix1 修复记录（2026-08-29 08:55 CST，commit `3a7bbac`）

**缺陷**：正式模式（非 fixture）前端构建失败时（如 `node_modules` 缺失导致 `vite: not found`、
warmup 构建失败），`run_frontend_build` 提前 return 未设置 `DIST_TOTAL_BYTES/LARGEST_JS_*`，
`write_measurements_frontend`（行 ~753）在 `set -u` 下报 `DIST_TOTAL_BYTES: 未绑定的变量` 崩溃，
留下无 summary.json/SHA256SUMS 的不完整 run 目录——违反「门禁失败返回非 0 且输出完整证据」语义，
且会弄脏工作树导致后续正式 run 全部被拒（M0-0.b 会踩坑）。

**修复**：
1. `run_frontend_build` 开头初始化 dist 指标默认值（`DIST_TOTAL_BYTES=0` 等），任何失败路径均不 unbound。
2. `write_summary_json` 的 `dist_total_bytes / largest_js_*` 状态与 `FRONTEND_STATUS` 联动（前端失败即 FAIL，符合契约「缺原始证据为 FAIL」）。
3. `--self-test` 新增用例 6：`BS_SELF_TEST_FRONTEND_FAIL=1` fixture 模拟前端失败，断言退出非 0 +
   summary status=FAIL + summary.md/dist_size.json 证据完整 + 不崩溃。
4. self-test 用例 3 退出码捕获改 `|| code=$?`（防御 `set -e` 下简单赋值命令替换非零触发 errexit）。
5. 脚本版本 `M0-1.a-1` → `M0-1.a-2`。
