## 2. serde 契约（TS 镜像唯一依据）

### 2.1 `SupportedDb`

| Rust 变体 | JSON 串 | 说明 |
|---|---|---|
| `Sqlite` | `"sqlite"` | |
| `MySql` | `"mysql"` | **必须显式 `#[serde(rename = "mysql")]`** |
| `Postgres` | `"postgres"` | |

> **踩坑记录（单测 T-db-c1 当场抓到）**：`#[serde(rename_all = "snake_case")]` 会把 `MySql` 序列化成
> **`"my_sql"`**，与前端/落盘/CLI 惯用的 `mysql` 不一致。该缺陷在首次 `cargo test` 即被 T-db-c1 拦截
> （left `my_sql` / right `mysql`），已加显式 `rename` 修复。**这是本卡最具体的一条实证收益**。

### 2.2 `DbConnectionConfig`（落盘 `data_dir/db_connections.json`）

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `id` | `String` | 必填 | UUID v4，与 Keyring 键 `db:<id>` 一一对应 |
| `name` | `String` | 必填 | 展示名 |
| `kind` | `SupportedDb` | 必填 | |
| `host` | `Option<String>` | `null` | SQLite 为 `null` |
| `port` | `Option<u16>` | `null` | `null` → 用 `kind.default_port()` |
| `database` | `String` | 必填 | SQLite = 文件路径（过 `check_path_within_roots`）；其余 = 库名 |
| `username` | `Option<String>` | `null` | SQLite 为 `null` |
| `ssl_mode` | `DbSslMode` | `"prefer"` | |
| `allow_write` | `bool` | **`false`** | 缺字段 = 拒绝写（F1 fail-closed） |
| `production_hint` | `Option<bool>` | `null` | 显式生产标记；`null` = 未标记 |
| `enabled` | `bool` | `true` | |
| `created_at` / `updated_at` | `DateTime<Utc>` | 必填 | 与 `Bookmark`/`Artifact` 同口径 |

**结构性红线（F2）**：不存在 `password` / `dsn` / `connection_string` 等任何凭据承载字段，
且**永不由此结构序列化出连接串**。单测 T-db-c3 逐键断言。

### 2.3 `DbSslMode`

| 值 | JSON | 语义 |
|---|---|---|
| `Disable` | `"disable"` | 不加密 |
| `Prefer` | `"prefer"`（**缺省**） | 有则用、无则降级；连上后由 M4-2 记录**实际**加密状态 |
| `Require` | `"require"` | 无 TLS 即连接失败 |

**配套规则（写入契约）**：**非回环地址 + 实际未加密 ⇒ 写操作拒绝**（生产判定信号 S6，见 `M4-1.d`）。
即 TLS 降级不单独阻断连接，但会吃掉写权限——与「写默认拒绝」同源。

## 3. 凭据命名空间裁定（A1 F-7 与 A10 G-1 的冲突裁决）

**冲突**：A1 F-7 定「`db_disconnect` **默认不删**凭据（避免误断连即丢密码）」；
A10 G-1 定「`db_disconnect` **必须**吊销凭据」+ 要求移除 `delete_token` 的 `#[allow(dead_code)]` 并补删除路径测试。

**裁定（拆成两个动作，两条要求同时满足）**：

| 动作 | 命令 | 凭据处置 | 归属 |
|---|---|---|---|
| 断开连接 | `db_disconnect(pool_id)` | 关池、释放连接、清内存态；**保留** Keyring 凭据 | A3 |
| 忘记连接 | **`db_forget_connection(conn_id)`**（新增，见下） | 删配置 + 吊销 Keyring 凭据（调 `delete_token`），**移除 `#[allow(dead_code)]` 并补测试** | A3 |

- **键格式：`db:<conn_id>`**（与 git 的 `repo_id` 命名空间隔离，防互相覆盖；A1 F-7 与 A10 G-1 同议）。
- `db_forget_connection` 是**第 4 条 db 命令**，超出 A10 G-10 列出的 8 条命令清单（3 db + 5 task）。
  → **登记为待 A0 裁决项 + 债务 D28**。若 A0 不批准新增命令，退化为：
  「断开即保留凭据，`delete_token` 维持 `#[allow(dead_code)]`」，此时 A10 G-1 的吊销要求**降级为挂账**，须显式记录。

## 4. 错误码表（18 码，闭合）

| 枚举变体 | 稳定串 | 触发语义 |
|---|---|---|
| `UnsupportedKind` | `DB_UNSUPPORTED_KIND` | 驱动标识不在 `SupportedDb` 内 |
| `InvalidConfig` | `DB_INVALID_CONFIG` | 配置字段非法（缺库名、非法端口等） |
| `PathOutsideRoots` | `DB_PATH_OUTSIDE_ROOTS` | SQLite 文件路径不在允许根内 |
| `CredentialMissing` | `DB_CREDENTIAL_MISSING` | Keyring 无该连接凭据 |
| `ConnectFailed` | `DB_CONNECT_FAILED` | 连接失败（错误串必须脱敏） |
| `NotConnected` | `DB_NOT_CONNECTED` | 池不存在/已断开 |
| `PoolExhausted` | `DB_POOL_EXHAUSTED` | 连接池耗尽 |
| `SqlEmpty` | `DB_SQL_EMPTY` | 空语句 |
| `SqlTooLarge` | `DB_SQL_TOO_LARGE` | 超 `DB_MAX_SQL_BYTES`（见 M4-1.c） |
| `SqlParseFailed` | `DB_SQL_PARSE_FAILED` | **不可解析 → 拒绝**（A10 G-4 fail-closed） |
| `MultipleStatements` | `DB_MULTIPLE_STATEMENTS` | 检出多语句（A10 G-4） |
| `WriteDenied` | `DB_WRITE_DENIED` | 写被拒（未授权 / 生产不确定 / TLS 降级） |
| `ProductionUnknown` | `DB_PRODUCTION_UNKNOWN` | 生产判定 `Unknown` 且请求为写 |
| `QueryFailed` | `DB_QUERY_FAILED` | 执行失败 |
| `Timeout` | `DB_TIMEOUT` | 超分层超时 |
| `Cancelled` | `DB_CANCELLED` | 用户/系统取消 |
| `LimitExceeded` | `DB_LIMIT_EXCEEDED` | 导出/落盘超 `DB_MAX_EXPORT_BYTES`（**结果集超限不是错误**，走 `truncated=true`；语义细化见 `M4-1.c` §7） |
| `NotSupported` | `DB_NOT_SUPPORTED` | 驱动不支持该能力（含非 Linux 平台降级） |

**闭合性约束**：增删码必须同步三处 = 本文件单测 T-db-c5 的计数断言（当前 18）、
A4 的 TS 镜像、`check-database-policy.py` 码位表。
