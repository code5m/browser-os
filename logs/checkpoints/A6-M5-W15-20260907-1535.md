## 3. 关键设计决策

1. **纯决策 / DOM 接线二分**：所有可判定逻辑下沉到 `src/utils/*.ts`，Vue 组件只做接线。这让 UI 打磨在本仓库既有范式（无 GUI 测试运行器）下**可测**——`check-ui-a11y-logic.mjs` 断言的是产品代码行为，不是测试内的复刻实现。
2. **`watch(root)` 而非 `onMounted`**：同时兼容两种挂载形态（组件级 `v-if` 打开即挂载；模板内 `v-if` 组件常驻、mask 随状态显隐）。两种形态下焦点陷阱都正确启停，`onBeforeUnmount` 兜底解绑。
3. **confirm/danger → `role="alertdialog"`**：屏幕阅读器会 Announce 并提示需显式决策；普通 dialog 用 `role="dialog"`。纯信息 alert 不响应 ESC（防误关）。
4. **初始焦点跳过 disabled**：推送/执行中主按钮为 disabled，直接 `focus()` 会静默失败导致焦点停留在 body；改为在候选集中取第一个非 disabled、非 `aria-hidden` 的元素。
5. **ESC 不双重触发**（ImageLightbox）：原 `window` 上的 `keydown` 为**冒泡**阶段监听，composable 在 mask 元素上 `stopPropagation()`，事件不再冒泡到 window，因此只关闭一次；←/→ 等非 Tab 键不受拦截。
6. **Tab 拦截范围**：仅拦截 `Tab`，且列表为空时 `preventDefault` 兜底；不影响对话框内其它快捷键。

## 6. 遗留 / 说明

1. **error 态未在 UI 组件上实例化**：`AsyncState` 支持 error（`role=alert` + `assertive`），也有单测覆盖，但本波只在 empty×2、loading×2 上接线——既有无 error 字段的面板不宜为接状态而新增状态字段（超出 narrow polish 口径）。后续哪个面板要接 error，直接 `:error="xxx"` 即可，无需改组件。
2. **`AsyncState` 复用约定**：必须用**插槽**承载非空内容（`<AsyncState ...><ul>…</ul></AsyncState>`）；不可在其后写 `v-else`（组件内部才有 `v-if`，外部 `v-else` 无相邻 `v-if`，语义错误）。本波实现中曾踩此坑并已修正。
3. **焦点归还依赖触发元素仍在 DOM**：若触发按钮随对话框一起卸载，归还为 no-op，浏览器焦点落到 body（无异常）。
4. 本 lane 未触碰三份主文档与任何他 lane 文件；补丁路径已限定，可直接 `git apply`。
