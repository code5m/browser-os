## Client failure root cause

The native client failures shown by the user were origin authorization failures, not missing feature implementations:

1. The debug main window is created programmatically with `WebviewUrl::External("http://localhost:1421")`.
2. The default Tauri capability grants the main window local-origin permissions. Commands such as `list_bookmarks`, `term_spawn_channel`, and `list_tools` were already registered and present in ACL, but the debug external origin did not match that local capability.
3. Rebuilding ACLs could not fix an origin mismatch. Broadening the default remote capability would have hidden the cause and enlarged release authority.
4. Restoring global `build.devUrl` was also unsafe because this repository previously produced a raw release binary that inherited the dev source and depended on the Vite server.
5. The accepted fix at `8e67ab0` is an exact `window=main` + `http://localhost:1421/*` debug capability, stored outside the auto-scanned capability directory and registered only under `#[cfg(debug_assertions)]`. Release remains bundled and local.

Permanent guards were added to `WORKSPACE_IDENTITY.md` and the active board. Agents must distinguish browser preview from the native client and deliver every command as implementation + source check + handler + ACL + typed bridge/types + tests.
