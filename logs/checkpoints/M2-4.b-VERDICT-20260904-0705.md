## 3. §3.1【必裁 · P0】argv 引号

**CONCLUSION = 路线 A（argv 数组 + 一律不加引号），但附带两项强制处置。**

**REASON（须回应矛盾本质，而非仅「引号是否有害」）**：

矛盾的本质是 `M2-3.a §3` 与 `M2-4.a §8.1` 同时承诺了两条互斥路线。要裁断，必须回答「哪条是安全的根基」：

- **argv 数组是安全的根基**。`M2-4.a §8.1` 把它列为 P0 红线，理由成立：不经 shell 则命令注入面在结构上被消除（R1/R2/R6）。这是**主动防御**。
- **单引号包裹是 shell 语法层的补救**。它只在「命令行经 shell 解释」时才有意义，而那条路径恰是 P0 红线要消灭的。argv 模式下它退化为**字面量污染**（实测 `"'/tmp/x'"`），从「防御」变成「功能 bug」。

因此两条路线不可兼得时，**放弃单引号包裹是唯一自洽的选择**，且防注入不因此削弱（由 argv 数组 + `validate_param_value` 九条 fail-closed 承担）。

**为何不选 B（保留引号）**：B 的唯一价值是配合 shell 拼接，而 shell 拼接违反 P0 红线。选 B 必须同时回答「是否推翻 P0 红线」，而推翻它等于放弃命令注入的结构防御——不可接受。B 排除。

**为何不现在选 C（废弃 `raw`）**，而是 A + 后续检查点：
- C 的动机（不留 no-op 字段）成立，但 `raw` 是 `M2-3` 已冻结并落库的结构，废弃它要改 `domain.rs` + `scripts.rs::validate_meta`（去掉 `INVALID_RAW_PARAM`）+ 重跑 M2-3 门禁（含 17 坏样本夹具），**与进程组内核实现混在一个检查点会扩大 b 卡 diff、不利于复核**，违反「逐张展开」。
- A 的 no-op 风险可用**改注释 + 登记后续检查点**管控，成本远低于现在就废弃。

**两项强制处置**：
1. **作废 `M2-4.a §8.1` 末条**：「`raw=true` 参数（仅 Path/Enum）：跳过单引号包裹」这句预设了「会加单引号包裹」，与 argv 模式矛盾，**自本裁定起作废**（不回改 `M2-4.a` 正文，以本裁定为追加裁定记录）。
2. **登记后续检查点**：在 `后续需求TODO.md` 登记「评估废弃 `ScriptParam.raw`（argv 模式下永无语义）」，优先级与 `M2-4.e` 同级，待 b/c/d 稳定后单开。

**IMPLEMENTER_ACTION**：
- `build_argv` 一律不加引号；B5 测试断言「值含空格/单引号/中文时 argv 元素原样保留、不含额外引号」。
- 修改 `domain.rs:591` 的 `raw` 注释：从「是否允许不加单引号包裹直接入命令行」改为「**argv 模式下无效果**（argv 不经 shell，不存在单引号包裹概念）；仅为未来若引入受控 shell 拼接模式时预留，见 M2-4.b-VERDICT」。
- 实现时顺手清理 `M2-3.a §3` 遗留在实现注释里的「单引号包裹」措辞（如 `PATH_ESCAPE` 注释的「因为单引号包裹下」改为「argv 模式下」）——**结论不变，仅修正论证措辞**。

## 4. §3.2【必裁】b 卡 stdio

**CONCLUSION = 路线 B（b 卡就上 `piped` + 只丢弃的 drain 线程）。——推翻了输入包中自己的初始倾向（A）。**

**REASON（须回应「drain 是否等于越界实现背压」）**：

核心问题是 **drain 是否构成「实现 d 卡的背压」**。逐一比对 d 卡的核心职责（`M2-4.a §8.5` + §9）：

| d 卡职责 | drain 是否触碰 |
|---|---|
| 内存环形缓冲 4 MB / 5000 行 | **不**——drain 只读丢弃，不保留任何字节 |
| 事件节流 30 ms、`script-output`/`script-finished` | **不**——drain 不 emit 任何事件 |
| 截断标记 `truncated`、尾存 256 KB 落盘 | **不**——drain 无截断概念、不落盘 |

drain 的唯一动作是「从管道读走字节并丢弃」，**其目的不是实现输出功能，而是防止「piped 而不读」的结构性阻塞**（§1 复跑确认：不读则子进程卡 `write` 无法退出）。它是 b 卡让「用 piped 的进程能正常跑完」的**最小必要手段**，不构成实现 d 卡内容。**故 drain ≠ 背压，路线 B 不越界**。

**为何 B 优于 A（反方检验的关键）**：
- A（`null` 中间态）有两个真实缺陷：①中间态依赖 d 卡接管，而「d 卡忘记接管」靠人纪律而非机制防呆；②b 卡阶段无法验证「有输出的脚本能正常结束」这一真实场景——恰是 §1 实测确认的阻塞场景。
- B 把管道结构在 b 卡就位（与 `M2-4.a §8.1` 最终形态一致，**不再有中间态**），d 卡只需把 sink 从「丢弃」换成「环形缓冲 + 事件」，工作量不增；且 b 卡即可新增「持续输出 2 MB 脚本能正常结束且不阻塞」的回归测试，把阻塞风险从「移交项」变成「已测项」。
- 代价可控：+2 线程/run（8 并发最多 24 线程），远低于系统限制。

**范围限定（防止 B 被滥用成提前实现 d 卡）**：
- drain 线程**必须只读丢弃**（等价 `io::copy(&mut stdout, &mut io::sink())`），不得保留字节、不得置 `truncated`、不得节流、不得 emit 事件。
- 代码注释标注「d 卡将替换本 sink 为环形缓冲 + 事件流」。

**IMPLEMENTER_ACTION**：
- 修订展开卡 `§2.2`：从「路线 A（`Stdio::null()` 中间态）」改为「路线 B（piped + 只丢弃 drain）」。
- 展开卡 `§3.6` 命令构造的 `stdout/stderr` 由 `Stdio::null()` 改为 `Stdio::piped()` + drain 线程；`// TODO(M2-4.d)` 注释保留但语义改为「替换 sink 为环形缓冲」。
- 新增测试：「脚本持续输出 ≥2 MB 能正常结束（Succeeded）且不阻塞」。
- 展开卡 `§7` 移交清单删除「d 卡接管 stdio 否则阻塞」项，改为「d 卡替换 drain sink 为环形缓冲 + 事件」。
