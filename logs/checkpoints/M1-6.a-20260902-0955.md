## 4. 确认闸门（三级，冻结）

沿用既有 `request_sync`/`confirm_sync` 的**双阶段状态机范式**，但 Git 写是独立任务类型，
不得复用 `SyncJob`（其 `artifact_ids` 语义属成果推送，混用会污染既有流程）：

1. **新增 `GitWriteJob`（domain.rs）**：`id / repo_id / op: GitWriteOp / preview / status / created_at / finished_at / error`，
   状态机与 `SyncJob` 同构：`Pending → Running → Success/Failed`。
2. **新增 `AppState.pending_git_jobs: Mutex<HashMap<String, GitWriteJob>>`**（与 `pending_jobs` 分开，互不干扰）。
3. **阶段一 `request_git_write(repo_id, op, params)`**：
   - 预检：`check_invocation_source` → `sync::repo_dir`（路径锁定，未配置/逃逸直接 `Err`）→ 操作白名单校验（黑名单直接 `Err`）→ 必要时只读探测生成预览（如 commit 前用 `read_status` 给出待提交文件数与路径列表）。
   - 生成 `GitWritePreview{ job_id, repo_id, op, summary, affected_paths(截断至 20 条), dangerous: bool, expires_at }`，写 `AuditEntry{action:"git_write_request"}`。
   - **不执行任何写**。
4. **阶段二 `confirm_git_write(job_id)`**：
   - 校验 job 存在、`status == Pending`、**未过期（冻结：5 分钟）**、一次性（取出即从表移除）。
   - `dangerous`（W3 push）要求前端已展示二次确认，后端校验 `preview.dangerous` 且入参带 `confirmed_dangerous: true`，否则 `Err("需二次确认")`。
   - 后台线程执行（不阻塞 UI），完成/失败发事件 `git-write-completed`（payload = 最终 `GitWriteJob`），并写审计。
5. **fail-closed**：预检不过 / 非白名单 / 确认未过 / 过期 / 路径校验失败 → 直接 `Err`，**零写入**。
6. **既有成果推送流程（`push_artifacts`）必须零改动、零回归**：M1-6 只新增命令，不改 `request_sync`/`confirm_sync`/`push_artifacts`。

## 5. 审计字段（冻结）

`AuditEntry.action` 取值：

| action | 时机 | detail（JSON 字符串）示例 |
|--------|------|---------------------------|
| `git_write_request` | 阶段一生成预览 | `{"op":"commit","repo_id":"r1","job_id":"j1","affected":3,"dangerous":false}` |
| `git_write` | 阶段二成功 | `{"op":"commit","repo_id":"r1","job_id":"j1","result":"ok"}` |
| `git_write_failed` | 阶段二失败 | `{"op":"push","repo_id":"r1","job_id":"j1","error":"push 失败: ..."}` |
| `git_write_rejected` | 预检/闸门拒绝 | `{"op":"reset","repo_id":"r1","reason":"操作禁止"}` |

硬约束：`detail` **不得**含 token、含凭据的 remote_url、完整文件内容；错误串需去掉凭据后再落审计
（自审：`grep -n "userpass_plaintext" src-tauri/src` 只应命中 `sync.rs:71 cred_cb`）。
