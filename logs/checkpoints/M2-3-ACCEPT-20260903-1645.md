   复核：`raw` 只影响 M2-4 的命令行拼接策略（是否单引号包裹），对本函数的
   字符拒绝规则确实无作用；其合法性已在 `validate_meta` 定义期校验
   （`raw=true` 且类型非 Path/Enum 即拒）。签名简化合理，未削弱安全。
2. **未新增 `check-script-domain-logic.mjs`** → **接受**。
   复核：本卡无前端脚本逻辑（UI 属 M2-5），强加 `src/utils/script.ts` 就是
   无人消费的死代码——与裁定书 §2 拒绝在 M2-3 定义 `ScriptRunRecord` 是同一
   理由。T-scr-1~17 全部由 22 项 Rust 单测覆盖（含真实磁盘往返）。已在
   `pre-merge.sh` 第 18 项注明「前端逻辑测试随 M2-5 UI 落地」。

## 5. 风险逐项表态

- **D12 命令端到端 IPC 未实测** → **DEBT，不阻塞**。理由：纯函数与持久化层有
  22 项 Rust 单测（含真实临时目录的落盘/读取/删除/历史 JSON 兼容往返）；命令层有
  静态夹具（来源校验/id 校验/ACL/handler/审计脱敏）+ 编译期类型保证；无 UI、无 GUI
  自动化通道，无法取证。与 M2-1/M2-2 同口径。
- **D13「危险值被拒」运行时链路未打通** → **DEBT，不阻塞**。理由：
  `validate_param_value` 的调用方是 M2-4 `run_script`，本卡无执行能力，故该链路
  只能停留在单测证据。M2-4 落地时须用 N1~N13 用例做**运行时**回归。
- **NON-BLOCKER：`can_delete` 对内置脚本返回 `InvalidId`** → 记录待后续修正。
  错误码语义不准（内置不可删是「操作被禁」，不是「id 非法」），但不影响正确性
  （命令层 `map_err(e.to_string())` 直接透出）。建议后续增加专用错误码
  `BUILTIN_NOT_DELETABLE`，不阻塞本次裁定。

实现者踩到的三个问题（ACL 顺序、坏样本静默失效、dead_code）经复核**均未降级
既有门禁**：M2-1/M2-2 门禁脚本零改动，`check-image-policy.py --self-test` 在
本次 pre-merge 中仍 PASS；新增的**变异防呆**（坏样本必须真的改动内容）是提升
夹具可信度的正向改动。
