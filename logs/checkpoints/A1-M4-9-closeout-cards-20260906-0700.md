## 1. IF-3 根因裁定（**推翻 A11-D41 的定性**）

### 1.1 现象

```text
$ python3 scripts/check-tools-policy.py --self-test
self-test FAIL: 坏样本「ACL 顺序错误：list_tools 晚于 list_artifact_images」未改动任何内容（变异失配，按漏检计）
```

A11 在 `A11-M4-verification-batch2-20260906-0629.md` 登记为 **D41「既有门禁缺陷，非 M4」**，并建议 A0「修变异样本**或临时豁免该项**」。

### 1.2 根因（实测）

`scripts/check-tools-policy.py` 的自检**不是**用静态夹具，而是 `good = read_repo(root)` 直接读当前仓库。第 10 号坏样本的变异是**相邻字面量替换**：

```python
acl=good["acl"].replace(
    '    "list_tools",\n    "list_artifact_images"',   # 要求两行严格相邻
    '    "list_artifact_images",\n    "list_tools"', 1)
```

而项目规则（冻结条款 F-5 / 各卡通行要求）是：**新命令必须插在 ACL 末条 `list_artifact_images` 之前**。M4 各 Lane 合规地插入 `task_list/task_add/task_update/task_remove/task_run_now/db_connect/db_query/db_disconnect` 之后，`list_tools` 与 `list_artifact_images` 不再相邻，变异退化为空操作 → `add()` 按漏检计 → 自检 `sys.exit(1)`。

**定向模拟取证（可复现）**：

```python
OLD='    "list_tools",\n    "list_artifact_images"'
NEW='    "list_artifact_images",\n    "list_tools"'
# 对 git show origin/master:.../default-commands.toml 与当前工作树同名文件分别做同一次 replace + 同一条判序规则
[origin/master (fb5b78f)] 变异生效=True  检出码=TOOL_ACL_ORDER_WRONG
[当前工作树 (M4 在途)]     变异生效=False 检出码=N/A(变异失配→self-test exit 1)
```

`origin/master` 的 ACL 中 `list_tools` 在 L109、`list_artifact_images` 在 L110，**严格相邻**，故该自检在合流前是 PASS 的。

### 1.3 结论

| 判断 | 结论 |
|---|---|
| 脆弱写法（用相邻字面量对**活仓库**做变异）是否既有？ | **是**，自 M2-7 引入该夹具即存在（同类问题 M2-9 已修过一次：`B-M2-9.a-seed-acceptance-20260905-2010.md` §4） |
| 该自检是否在 M4 之前就 FAIL？ | **否**。`origin/master` 上变异可生效 → 自检 PASS |
| 因此 D41「既有缺陷，非 M4」是否成立？ | **不成立**。它是 **M4 触发**的门禁失败：M4 做的是规则要求的正确动作，错在夹具假设。定性为「非 M4」会误导 A0 选择「临时豁免」而不是修夹具 |
| 是否属于 M4 功能缺陷？ | **否**。不是功能回归，是**门禁夹具写法的可维护性缺陷**，且失效方向是**fail-closed**（自检报错、门禁变红），不存在漏检风险 |

**给 A0 的建议**：**不要豁免**。豁免会永久关掉 `TOOL_ACL_ORDER_WRONG` 这条守「末位逗号坑 / ACL 顺序」的不变量。改夹具是一处局部替换，代价远低于豁免。
