## 实现要点

### 1. 地址栏 ⭐（`BookmarkStar.vue`）

- 收藏态判定：`useBookmarkStore.isBookmarked(currentUrl)`，`currentUrl` 取
  `browser.activeTab?.url || browser.url`。
- 未收藏 → 空心 `☆`，点击调 `bridge.bookmarkAdd({url, title, category})`（`category` 用默认档 `default`）。
- 已收藏 → 实心金色 `★` 高亮，点击调 `bridge.bookmarkRemove(id)`（**按 id 删除**，不是按 url）。
- 不可收藏态（空地址 / `about:blank` / 本地目录路径）按钮置灰禁用，避免把地址栏 📁 目录模式误存成收藏。
- 挂载在 `.omni-wrap` 内部（地址栏输入框右侧），仅在 `mainView === 'browser'` 时渲染。
- 组件 `onMounted` 兜底触发 `bookmarks.load()`：ActivityBar 常驻挂载，是首屏最早的可靠加载点，
  保证一进浏览器视图 ⭐ 就能正确高亮。

### 2. 收藏夹侧栏（`BookmarkPanel.vue`）

- 数据源 `bookmarks.sorted`：`created_at` 倒序，同时间戳按 `url` 稳定排序。
  （后端 `list_bookmarks` 也已按 `created_at` 倒序返回，前端再排一次做双保险。）
- 点项 → `browser.url = b.url; layout.setView('browser'); browser.openBrowser()`，
  走 `bridge.tabNew` 在内嵌页签打开。**不调用 `open_source` / 系统默认浏览器**（那是 M1-4 范围）。
- 每项右侧 ✕ → `bookmarks.remove(b.id)`，按 id 删除。
- 顶部提供 ↻ 重新拉取与 ✕ 收起，失败时红条显示 IPC 错误原文。

### 3. URL 归一化（`useBookmarkStore.normalizeUrl`）

统一协议/主机名大小写、去掉路径末尾斜杠后再比对，避免「同一页面因末尾多一个 `/` 被判成两条收藏」
导致 ⭐ 高亮与实际收藏对不上。`add` 成功后同样按 `id` 或归一化 url **替换**本地项而非 push
（后端同 URL 是更新语义），防止侧栏出现重复条目。

### 4. 与 M1-0 `useHomeStore` 的边界

`useHomeStore`（主页快捷方式，存 localStorage）**保持原样、未并入本检查点**。
两套机制并存：主页快捷方式是用户手工整理的入口墙，收藏夹是后端持久化的书签。

### 5. 侧栏挂点与布局安全

`BookmarkPanel` 挂在 `MainArea` 的 `.browser-body`（`Sidebar.vue` 目前是未被任何地方引用的死代码，
不是真实挂点）。侧栏展开会撑窄 `.viewport`，`BrowserHost` 上已有的 `ResizeObserver`
会自动重定位子 webview，无需手动 `relocate`。侧栏限定 `mainView === 'browser'`，
不进入宫格视图（M0-6 刚收口的宫格定位链路不纳入本次改动范围）。

## 未验收项（遗留观察项，需人工确认）

以下 3 项**已按设计实现并通过静态审查，但本会话未能做真机 GUI 验收**，不宣称已实测：

1. ⭐ 点击真的写入 / 取消收藏；
2. 侧栏真的按 `created_at` 倒序渲染、点项跳转、按 id 删除；
3. 重启后收藏不丢。

未做 GUI e2e 的原因与已尝试路径：

- 环境本身可用：`DISPLAY=:0` 存在，`xdotool` / `wmctrl` / `scrot` / `ffmpeg` 齐备，
  release 二进制已用新前端重编（`cargo build --release` 1m45s），应用可正常启动并输出
  `[FE] FE alive` / `m0 ready ok` 日志，**启动无崩溃、无前端报错**。
- 但收藏 UI 的交互状态在前端，仓库既有的应用内驱动（`GRID_SELFTEST` / `GRID_GUI_REGRESSION`）
  都在 Rust `main.rs` 侧，无法点击 Vue 组件；改用 xdotool 坐标自动化需要先目视定位按钮，
  而本会话**无法读取截图**（已确认 ffmpeg/scrot 产出的是有效画面，但当前模型不支持读图），
  属于盲操作，误点风险高于收益，故停止。
- 与 `M1-1` 的处理方式一致（图标渲染未人工目视确认 → PASS + 列为遗留观察项）：
  机器门禁全绿即判定检查点 PASS，功能目视验收转人工。

最小人工验收步骤：

```bash
cd <worktree> && npm run build && WEBKIT_DISABLE_DMABUF_RENDERER=1 GDK_BACKEND=x11 ./run-gui.sh
# 1) 进「浏览」视图 → 地址栏输网址回车 → 点地址栏右侧 ☆ → 应变金色 ★
# 2) 点 📑 展开收藏夹 → 该项应在列表 → 点项跳转 → 点 ✕ 删除
# 3) 关闭应用重启 → 重新点 📑，未删除的收藏应仍在（读 data_dir/bookmarks.json）
```
