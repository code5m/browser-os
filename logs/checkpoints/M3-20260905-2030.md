## 3. 对既有草案 `fileterm-study/终端改造-详细设计.md`（V5，2026-08-26）的事实修正

> 草案写于 M2 之前且未经本轮实测；以下 5 处与现状不符或前提失效，**以本卡裁定为准**。

| # | 草案原陈述 | 实测修正 |
|---|-----------|----------|
| 1 | `term_spawn(app)` 加 `channel` 参数，前端同批次改 | **不可行于单一命令**：`term_spawn` 被 `main.rs:778/1000` 的 M0 回归驱动以 Rust 内部方式调用（无 Channel 可传），且 `Option<Channel>` 因缺 `Deserialize` 不能作参数。改为**新增 `term_spawn_channel`**（前端用）+ 保留 `term_spawn`（内部驱动，Event sink），共享 `spawn_terminal`（F4） |
| 2 | 16 ms/64 KiB 合并无条件生效 | **测量模式必须禁用合并与丢弃**，否则 `__M0_TERM_BEGIN__/__M0_TERM_END__` 计数与 M0-0.b 基线不可比（F2/F3） |
| 3 | 阻塞缓解路径是 tokio mpsc + `tokio::spawn` pump | 项目无 tokio 且**不新增依赖**：改 `std::sync::mpsc::sync_channel(128)` + 独立 `std::thread` pump + `try_send` 丢弃（F1/F9）；草案的「缓解路径」即本卡主线（WBS M3-1 原文），Channel 化是并发的 sink 升级 |
| 4 | worker 退出靠 child drop → reader EOF | **不成立**：`Child` drop 不 kill 进程（现有代码靠 `term_kill` 显式 kill）。本卡改进程组回收 + 显式 `stop` 标志（F6/F7） |

## 4. 冻结裁定（F1~F13）

| 码 | 裁定 |
|----|------|
| **F1 三段式管道** | worker（PTY reader）→ `std::sync::mpsc::sync_channel(TERM_QUEUE_CAPACITY=128)` → pump 线程 → `sink.send`。worker **永不阻塞**：满则 `try_send` 失败即丢弃（F2）。pump 用 `recv_timeout(TERM_FLUSH_INTERVAL_MS=16)` 聚批 |
| **F2 背压与丢弃** | 队列满丢弃当前块，累计 `dropped_chunks/dropped_bytes`；≥64 块或 ≥1 s 经控制消息 `term-flow` 告知前端（**不向终端字节流插任何伪内容**，避免污染 ANSI 语义）。**测量模式（`m0_config.driver == "term-throughput"`）禁用丢弃**（worker 阻塞 `send`，保 begin/end 完整） |
| **F3 合并** | pump 聚合窗口 16 ms 或 64 KiB 到点即发。**测量模式窗口 = 0（立即发）**，保持与 M0-0.b 基线可比 |
| **F4 sink 抽象 + 双入口** | `enum TermSink { Event(AppHandle), Channel(Channel<serde_json::Value>) }`；`spawn_terminal(app, sink)` 为唯一实现；`term_spawn(app)` = Event（M0 内部驱动，`main.rs` 零改动）、`term_spawn_channel(app, channel)` = Channel（**前端唯一入口**）。两者均进 `default-commands.toml`；夹具锚定「前端不得调用 `term_spawn`」 |
| **F5 resize 真实化** | `TerminalSession` 持 `master: Box<dyn MasterPty + Send>`；`term_resize` 调 `master.resize(PtySize{rows,cols,pixel_width:0,pixel_height:0})`，失败返回明确错误（不再静默 `Ok(())`）。前端 `fit()` 后 **140 ms 防抖**再 `termResize` |
| **F6 进程组回收** | spawn 记 `pgid: Option<i32>`（来源 `child.process_id()`；unix `setsid` 保证 `pid==pgid`；非 unix `None` 降级）。`term_kill` 与生命周期 `kill-terminals` 统一走 `terminate_group`：`SIGTERM` → 50 ms 轮询 `script_runner::process_group_alive`（至多 2 s）→ 仍活则 `SIGKILL` → `child.wait()`。**复用 M2-4.b 的 pub `process_group_alive`，不改 `script_runner` 冻结面** |
| **F7 关闭协议** | session 持 `stop: Arc<AtomicBool>`；`term_kill` 置位 → 杀组 → 移除 session（drop sender/writer/master）。worker 退出：EOF 或 `stop`；pump 退出：`Disconnected` 或（`stop` 且队列空）。**两线程不得泄漏**（T5 断言 `is_finished`） |
| **F8 退避与停止条件** | pump 发送失败 → 指数退避 `10ms × 2^n`，上限 `TERM_RETRY_MAX_BACKOFF_MS=30_000`，总预算 `TERM_RETRY_BUDGET_MS=60_000`；连续成功重置。超预算 → 置 `stop`、杀组、发控制消息 `term-exit { reason: "channel_dead" }` 结束（不无限重试、不静默丢弃） |
| **F9 零新依赖** | 不引 `tokio`/`crossbeam`/任何新 crate；只用 `std::sync::mpsc` + `std::thread` + 既有 `libc`。夹具锚定 `Cargo.toml` 无 `tokio` |
| **F10 前端接入** | `bridge.ts` 从 **`@tauri-apps/api/core`** 导入 `Channel`（非顶层）；新增 `createTermChannel(cb)` 与 `termSpawnChannel(ch)`；`startShell` 改走 Channel；`termBuffer` 兜底保留；`TerminalPane` 增 `scheduleResize`（140 ms）。M0 吞吐钩子逻辑不变，只换数据来源 |
| **F11 夹具** | 新增 `scripts/check-terminal-policy.py`：不变量覆盖 F1~F10，每个存在性不变量至少 1 个变异坏样本；接入 `pre-merge.sh` 第 21 项（原 21 git diff --check 顺延为 22） |
| **F12 范围外** | M3-4 体验项（临时历史 40、resize 静默窗口）不在 M3.a/b，登记 `M3.c`；多终端停靠（fileterm F15）不在 M3 |
| **F13 审计** | 终端为交互式 shell、命令由用户键入，无新攻击面（区别于 `script_*`/`snippet_*` 的参数化执行）：**不写 `audit.json`**；`channel_dead` 与丢弃超阈值走 `eprintln!`（既有 stderr 镜像入 `session-*.log`）。若将来开放程序化批量 `term_write` 须重估并补审计 |

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| M0 基线工具（`main.rs:778/1000`）被破坏 | F4 双入口：`term_spawn` 签名与行为（Event sink）保持不变，`main.rs` **零改动** |
