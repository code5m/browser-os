## 4. a 卡必须裁决的七组分歧（**真实冲突，不是形式主义**）

### 4.1 输出上限：4 MB vs 256 KB
- taskcard §4.8：环形缓冲上限 **5000 行或 4 MB**（先到先算），单片 ≤ 8 KB，30 ms 节流。
- M2-3.a-prework §4.5：单 run 保留最后 **256 KB**。
- **相差 16 倍**，直接影响内存占用与 OOM 风险（R9：100 MB 输出脚本不得 OOM）。

### 4.2 超时默认值：60 s vs 300 s
- taskcard §4.6：soft timeout 默认 **60 s**，上限 600 s；hard = soft + 5 s。
- M2-3.a-prework §4.5：`timeout_secs`（脚本级，缺省取全局 **300**）。
- M2-3 已落库 `ScriptMeta.timeout_secs`（0 = 用全局默认），**默认值必须与之一致**。

### 4.3 并发上限：8 vs 10
- M2-3.a-prework §4.5：同一 `script_id` 禁止并发，总数上限 **8**。
- taskcard R14 反向用例：「高并发跑 **10** 个脚本互不干扰」。
- 两者不可同时为真（10 > 8）。

### 4.4 平台范围与降级策略
- `setsid` / `killpg` 是 **Unix-only**；Windows 需 Job Object，macOS 可用 setsid 但需注意签名后行为。
- 项目 release 验证**一直在 Linux**；`tauri.conf.json` 的 bundle 虽含 Windows/macOS 目标，但无实测证据。
- **a 卡须裁决**：只实现 unix 分支 + 非 unix 显式降级（记录能力缺口），还是三平台都实现。
  建议：**只做 unix（Linux）**，非 unix 平台 `run_script` 直接返回明确错误，并在文档标注限制。

### 4.5 env 策略：`env_clear()` + 最小集 vs 继承宿主
- taskcard §4.3：`env_clear()` 后显式注入 `PATH`/`HOME`/`LANG`/`TERM`，**不继承**宿主环境（防 `LD_PRELOAD`/`IFS`）。
- 风险：`env_clear()` 会破坏依赖 `SSH_AUTH_SOCK`、代理变量、locale 的脚本。
- **a 卡须裁决**：固定最小集（不可配置）vs 允许 `ScriptMeta` 声明额外 env 白名单。
  倾向：先做固定最小集（最小攻击面），配置能力后续按需扩张。

### 4.6 `shell:allow-spawn` 的处置（**本卡新发现**）
- 实测：`shell:allow-spawn`（bash/sh/powershell，**args: true**）**全仓零调用点**，
  前端也未引入 `plugin-shell` 的调用；`package.json` 虽有 `@tauri-apps/plugin-shell ^2.3.5` 依赖但无引用。
- 即：这是一个**开着但没人用**的完全开放能力（ACL 不校验参数，见 taskcard K4）。
- M2-4 走 `std::process::Command`（不经 shell 插件），因此该权限在 M2-4 之后**更无存在理由**。
- **a 卡须裁决**：
  1. 在 M2-4.e 移除 `shell:allow-spawn`（低风险高收益，但属 capabilities 安全边界变更，须单开检查点）；
  2. 或保留不动（维持现状，风险挂账）；
  3. 是否**同步移除无引用的 npm 依赖** `@tauri-apps/plugin-shell`（注意：会影响 `package.json`/`package-lock.json`，
     而 M2-2/M2-3 的夹具锚定了这两个文件的哈希，需同步更新基线——**这是跨卡影响，必须显式裁决**）。

### 4.7 `RunStatus` 命名与运行记录落盘
- M2-3.a-prework §4.2：`Running | Succeeded | Failed | Cancelled | Timeout`，另含 `ScriptRunRecord`（output_tail/error/triggered_by）。
- taskcard §4.1：`Running | Success | Failed | Cancelled | Timeout`。
- **变体名冲突**（`Succeeded` vs `Success`）+ 是否落盘 `script-runs.json`（M2-5 审计入口需要历史）。
- **a 卡须裁决**：统一命名、是否落盘、上限多少（prework 建议独立文件带上限）。

## 6. 静态夹具违规码（check-script-exec-policy.py 必须覆盖）

| 违规码 | 判定 |
|---|---|
| `EXEC_SH_C_PRESENT` | 出现 `sh -c` / `bash -c` / `"-c"` 拼接（P0，立即整改） |
| `EXEC_STRING_INTERPOLATION` | 命令行由 `format!` 拼接而成（必须 `.arg()` / `.args()` 数组传递） |
| `EXEC_INTERPRETER_NOT_WHITELISTED` | 解释器非 `ScriptInterpreter` 枚举（不接受用户输入） |
| `EXEC_CWD_NOT_LOCKED` | 未设置 `current_dir` 或 cwd 来自用户输入 |
| `EXEC_ENV_NOT_CLEARED` | 未 `env_clear()`（或未显式注入最小集） |
| `EXEC_NO_PROCESS_GROUP` | unix 下未 `setsid`（`pre_exec`）→ 无法 `killpg` 回收进程树 |
| `EXEC_KILL_DIRECT_CHILD_ONLY` | 取消/超时只 `child.kill()`，未 `killpg` |
| `EXEC_NO_HARD_TIMEOUT` | 只有 soft timeout，无 hard（SIGKILL）兜底 |
| `EXEC_NO_OUTPUT_CAP` | 输出无上限/无截断（OOM 风险） |
| `EXEC_AUDIT_LEAKS_VALUE` | 审计含参数明文或输出正文 |
| `EXEC_RUN_RECORD_MISSING` | 未落盘运行记录（若 a 卡裁定落盘） |
| `EXEC_SHUTDOWN_NOT_REGISTERED` | 未在 `ShutdownCoordinator` 注册 `kill-running-scripts` |
| `EXEC_ACL_MISSING` / `EXEC_HANDLER_NOT_REGISTERED` | 新命令未进 ACL / `invoke_handler` |
| `EXEC_NO_SOURCE_CHECK` | 新命令未过 `check_invocation_source` |
| `EXEC_VALIDATION_BYPASSED` | 未调用 M2-3 的 `validate_param_value`/`validate_enum_value`/`check_required` |
