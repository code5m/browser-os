## 持久化设计
- **文件路径**: `data_dir()/bookmarks.json`（与 `audit.json` / `repos.json` 同级）。
- **格式**: `Vec<Bookmark>` 平铺 JSON（pretty print）。
- **去重语义**: `add_bookmark(url, ...)` 同 URL 视为更新——保留原 `id`/`created_at`，仅覆盖 `title`/`category`。这是收藏语义的自然选择（同 URL 不应有两份）。
- **删除语义**: 按 `id` 删除，幂等（不存在不报错）。
- **重启不丢**: 依赖现有 `load_bookmarks` 直接读 `bookmarks.json`；无 schema 迁移路径（首版无版本字段）。

## 边界与限制
- **无 category 校验**: 当前 `category` 字段为自由字符串，前端消费方（M1-3）按需展示。后续若需预设白名单，扩展 `BookmarkCategory` enum 即可。
- **无 UUID 重排序**: `add_bookmark` 同 URL 更新场景下，`id`/`created_at` 保留。这意味着按 `created_at` 倒序时该条不会"浮到顶部"。这是设计选择：收藏的"价值"由用户首次添加时间确定，更新只是修正元数据。
- **未持久化测试**: 没写 tauri-runtime 模拟测试（mock AppHandle）。契约通过 `Bookmark` serde 单测 + 与 audit 同源的 `data_dir` 写入模式证明。如 M1-3 UI 阶段发现写入路径异常，再补 integration test。
- **无并发锁**: 连续两次 add 同一 URL 不加锁——串行 IPC（tauri command 单线程池）下安全。MVP 阶段可接受。
