## 0. 一句话结论

**取数循环内计数 → 双上限（行/字节）任一超限即停止取数并丢弃剩余 → 返回带 `truncated` 标记的截断结果；
取消分三层（标志 / 循环检查 / 驱动中断），取消即无结果但连接必须归还可复用；超时分层复用 M2-4 的 60/600/5 口径。**

## 1. 上限数值表（冻结）

| 常量（建议落 `database.rs`） | 值 | 依据 | 前端可调 |
|---|---|---|---|
| `DB_MAX_SQL_BYTES` | **64 KiB**（65 536） | 直接复用 `security_policy::MAX_TEXT_FIELD_BYTES`（既有常量，M1-8 已在用），不新造量级 | 否 |
| `DB_MAX_ROWS` | **1000** | 结果表首期无虚拟滚动（M4-4，A5 确认前按无虚拟滚动计），1000 行是 DOM 渲染与 JSON 物化的可接受上界 | **否**（同 M1-8「`max_total` 不开放调大」口径） |
| `DB_MAX_RESULT_BYTES` | **4 MiB**（4 194 304） | 复用 M2-4 输出硬上限 4 MB 的量级；超过即会把主进程 JSON 物化与 IPC 打到 OOM 区 | **否** |
| `DB_MAX_TEXT_FIELD_BYTES` | **64 KiB** | 复用 `security_policy::MAX_TEXT_FIELD_BYTES`，单字段截断（BLOB/CLOB/长文本） | 否 |
| `DB_DEFAULT_QUERY_TIMEOUT_SECS` | **30** | 交互型查询；比脚本默认 60s 更短（用户盯着结果表） | 否 |
| `DB_MAX_QUERY_TIMEOUT_SECS` | **600** | 复用 `script_runner::MAX_TIMEOUT_SECS`（实测 600），不新造上限 | 否 |
| `DB_SOFT_TO_HARD_GRACE_SECS` | **5** | 复用 `script_runner::HARD_GRACE_SECS`（实测 5） | 否 |
| `DB_CANCEL_CHECK_EVERY_ROWS` | **64** | 每 64 行检查一次取消标志（与 terminal 的 64 KiB 聚合量级同思路，避免逐行原子读） | 否 |
| `DB_MAX_EXPORT_BYTES` | **16 MiB**（**待 A5 确认是否做导出**） | 落盘/CSV 导出上限；A1 F-6 将「导出成果库」列为待确认范围项，未确认则无消费方 | 否 |

**规则**：
1. 行/字节**任一**超限即停止取数（不是先物化再截断——A10 G-6 明令「物化后再截断等于没截断」）。
2. 超限**不是错误**：正常返回结果 + `truncated: true`；**禁止静默截断**（前端必须能判「结果不完整」）。
3. 单字段截断额外置 `field_truncated: bool`（沿用 M1-8 的 `truncated` 明示语义）。
4. 审计记 `limit_hit`（`rows` / `bytes` / `fields` 三选一的命中原因），**不含** SQL 原文（A10 G-3）。

## 2. 结果 DTO 字段语义（结构归 A3 落 `database.rs`，字段名以此为准）

| 字段 | 类型 | 语义 |
|---|---|---|
| `columns` | `Vec<String>` | 列名 |
| `rows` | `Vec<Vec<DbValue>>` | 已截断的数据 |
| `row_count` | `usize` | 实际返回行数（≤ `DB_MAX_ROWS`） |
| `truncated` | `bool` | **行/字节任一超限即 true** |
| `field_truncated` | `bool` | 任一单字段被 64 KiB 截断即 true |
| `elapsed_ms` | `u64` | 取数耗时（前端展示用） |
| `query_id` | `String` | 取消句柄 |

`DbValue` 只承载可序列化标量（`Null` / `Bool` / `I64` / `F64` / `Text` / `Bytes`（忽略或计长度）），
**BLOB 一律不回传字节**（只回长度 + `<binary>` 占位），避免二进制经 JSON 打到前端。

## 3. 取消语义三层（与 M2-4 分层超时对齐，机制不同需显式说明）

| 层 | 触发 | 行为 |
|---|---|---|
| **L1 标志** | 前端 `db_cancel(query_id)`（命令名待 A4 与 `db_*` 三命令一并冻结） | 置该 `query_id` 的 `AtomicBool` |
| **L2 循环检查** | 取数循环每 64 行检查标志 | 命中即停止取数 → 返回 `DB_CANCELLED`，**不返回半成品**（与 `script_runner` 取消后不留半成品同口径） |
| **L3 驱动中断** | 与 L2 同步发起（尽力而为） | SQLite `interrupt_handle`；MySQL `KILL QUERY`；Postgres 取消令牌——**具体 API 由 A3 按 crate 实测核对，本卡未实测**；失败不阻塞返回 |

- **取消后连接必须归还池中并保持可用**（A10 G-6 明确要求；测试须断言）。
- 若 L3 驱动中断不可用，L2 仍保证「前端不再收到数据」，但服务端查询可能继续跑 → 由 L4 超时兜底（§4）。

## 4. 超时分层（复用 M2-4，不新造）

| 阶段 | 语义（M2-4 原语义 → DB 适配） |
|---|---|
| 默认 | `timeout_secs = 0` → 30s |
| 上限 | > 600s → 拒绝（`DB_TIMEOUT`？否：属配置校验，用 `DB_INVALID_CONFIG`） |
| **soft** | 到达超时 → 发起 L3 驱动级中断（**机制不同**：M2-4 是 SIGTERM，DB 无进程可杀，改为带外取消） |
| **hard** | soft 后 5s 仍未结束 → **放弃该连接**：丢弃（不归还）并标记池中该连接为不可用 + 记审计（M2-4 是 SIGKILL） |

**必须显式声明的差异**：M4 借用 M2-4 的 60/600/5 **量级与分层结构**，但 soft/hard 的**机制不同**
（进程信号 vs 带外取消 + 弃连接）。不得写成「复用 M2-4 超时」而让读者以为有 kill 语义。

## 5. 多语句与取数通道（A10 G-4.4 落地口径）

| 驱动 | 允许通道 | 禁止 |
|---|---|---|
| SQLite | `prepare`（单语句） | `execute_batch` |
| Postgres | 扩展协议 `query` / `prepare` | `simple_query` / `batch_execute` |
| MySQL | 单语句 | 关闭 `CLIENT_MULTI_STATEMENTS`（**不得依赖 crate 默认，须显式关闭**；本卡未实测各 crate 默认值） |

用户 SQL 在**进入驱动前**先过 A4 的分类器（剥离注释与字符串字面量 → 整批处理 → 任一语句非 SELECT 即整批拒绝 → 不可解析即拒）。
驱动层关闭多语句是**第二道**，不是唯一一道。

## 6. 测试策略（诚实区分自动化与人工）

| 场景 | 手段 | 归属 |
|---|---|---|
| 行数上限 / 字节上限 / 单字段截断 / `truncated` 标记 | **SQLite 真实临时库**（rusqlite 零外部服务），灌入超量数据做真实断言 | A3 |
| 取消（L1/L2）、取消后连接可复用 | SQLite 真实库 + 慢查询（如 `WITH RECURSIVE`） | A3 |
| 超时分层 | SQLite + 可注入时长（避免真等 30s：用 `DB_*_TIMEOUT` 常量的可注入变体，**不得为测试放宽生产常量**） | A3 |
| MySQL / PostgreSQL 的连接与只读查询 | **无 CI 服务** → 只做失败路径（不可达主机 / 错端口 / 凭据缺失）+ 配置校验；**真实服务连接列入人工验收清单** | A3 实现 + A11 清单 |
| 多语句被拒 | 三库均为**静态/配置层**断言 + SQLite 真实断言 | A3 + A4 |

> **不伪造原则**：不得用「本地起一个假的 MySQL 端口」冒充真实服务端用例。真实三库联调挂账为 **D27**。
