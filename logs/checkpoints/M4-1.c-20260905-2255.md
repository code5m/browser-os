## 0. 一句话结论

**取数循环内计数 → 双上限（行 / 字节）任一超限即停止取数并丢弃剩余 → 返回带 `truncated` 显式标记的截断结果；
取消分三层（标志 / 循环检查 / 驱动带外中断），取消即无结果但连接必须归还可复用；超时分层复用 M2-4 的 600 / 5 量级。**

## 1. 上限数值表（**已冻结进 `domain.rs`**，实现侧只消费、不得重定义）

| 常量（`src-tauri/src/domain.rs`） | 值 | 依据 | 前端可调 |
|---|---|---|---|
| `DB_MAX_SQL_BYTES` | **64 KiB** | 复用 `security_policy::MAX_TEXT_FIELD_BYTES`（既有常量，M1-8 在用），不新造量级 | 否 |
| `DB_MAX_ROWS` | **1000** | 结果表首期无虚拟滚动（M4-4，A5 确认前按无虚拟滚动计），1000 行是 DOM 渲染与 JSON 物化的可接受上界 | **否**（同 M1-8「`max_total` 不开放调大」口径） |
| `DB_MAX_RESULT_BYTES` | **4 MiB** | 复用 M2-4 输出硬上限 4 MB 量级；超过会把主进程 JSON 物化与 IPC 打到 OOM 区 | **否** |
| `DB_MAX_TEXT_FIELD_BYTES` | **64 KiB** | 与 `security_policy::MAX_TEXT_FIELD_BYTES` **必须相等**（单测 T-db-c6 守） | 否 |
| `DB_DEFAULT_QUERY_TIMEOUT_SECS` | **30** | 交互型查询；比脚本默认 60s 更短（用户盯着结果表） | 否 |
| `DB_MAX_QUERY_TIMEOUT_SECS` | **600** | 与 `script_runner::MAX_TIMEOUT_SECS` **必须相等**（单测 T-db-c6 守） | 否 |
| `DB_SOFT_TO_HARD_GRACE_SECS` | **5** | 与 `script_runner::HARD_GRACE_SECS` **必须相等**（单测 T-db-c6 守） | 否 |
| `DB_CANCEL_CHECK_EVERY_ROWS` | **64** | 每 64 行检查一次取消标志（与 terminal 的 64 KiB 聚合量级同思路），**必须 < `DB_MAX_ROWS`** | 否 |
| `DB_MAX_EXPORT_BYTES` | **16 MiB** | 导出/落盘上限；**A1 F-6 仍未确认「导出成果库」是否做**，未确认则无消费方 | 否 |

**为什么把常量放进 `domain.rs`（指挥板 Batch Dispatch 要求）**：这些是 **A3（取数循环逐行判定）与 A4（审计与夹具断言）共同消费**的跨模块契约；若各实现侧自行定义，必然出现「A3 按 1000 行截断、A4 按 500 行审计」的口径漂移。放 `domain.rs` 后用**单测把跨模块一致性钉死**（T-db-c6 直接比对 `script_runner` / `security_policy` 的既有常量）。初版曾为避免 dead_code 而只写在文档里，**本版按 Batch Dispatch 改为落码**。

**规则**：
1. 行 / 字节**任一**超限即停止取数（不是先物化再截断——A10 G-6 明令「物化后再截断等于没截断」）。
2. 超限**不是错误**：正常返回结果 + `truncated: true`；**禁止静默截断**。
3. 单字段截断额外置 `field_truncated: true`。
4. 审计只记 `limit_hit`（`Rows` / `Bytes` / `Field`），**不含** SQL 原文（A10 G-3）。

## 2. 冻结进 `domain.rs` 的结构（A3 直接消费，不得改名/改语义）

| 类型 | 形态 | 用途 |
|---|---|---|
| `DbQueryResult` | 结构体 | 结果 DTO：`query_id` / `columns` / `rows` / `row_count` / `truncated` / `field_truncated` / `limit_hit` / `elapsed_ms` / `state` |
| `DbQueryState` | 枚举 `completed` / `cancelled` / `timeout` / `failed` | **取数终止状态**（即「取消状态名」集合） |
| `DbLimitKind` | 枚举 `rows` / `bytes` / `field` | 上限命中原因（审计 `limit_hit` 与前端提示） |
| `DbValue` | 枚举 `null` / `bool` / `int` / `float` / `text` / `blob_len` | 单元格值；**二进制列只回长度、不回字节**（防二进制经 JSON 打到 webview） |

**设计裁定（消除重复表达）**：**截断不是状态**。截断由 `truncated` / `field_truncated` / `limit_hit` 三个字段表达，
`DbQueryState` 只回答「为什么停下来」。单测 T-db-c8 断言 `"truncated"` **无法**解析为 `DbQueryState`（fail-closed）。
`limit_hit` 带 `#[serde(default)]`，历史 JSON 缺该字段解析为 `None`（T-db-c7）。

## 3. 取消语义三层（与 M2-4 分层超时对齐，机制不同需显式说明）

| 层 | 触发 | 行为 |
|---|---|---|
| **L1 标志** | 前端 `db_cancel(query_id)`（命令名待 A4 与 `db_*` 三命令一并冻结） | 置该 `query_id` 的 `AtomicBool` |
| **L2 循环检查** | 取数循环每 `DB_CANCEL_CHECK_EVERY_ROWS` 行检查标志 | 命中即停止取数 → `state = cancelled`，**不返回半成品**（与 `script_runner` 取消后不留半成品同口径） |
| **L3 驱动中断** | 与 L2 同步发起（尽力而为） | SQLite `interrupt_handle`；MySQL `KILL QUERY`；Postgres 取消令牌——**具体 API 由 A3 按 crate 实测核对，本卡未实测**；失败不阻塞返回 |

- **取消后连接必须归还池中并保持可用**（A10 G-6 明确要求；测试须断言）。
- 若 L3 不可用，L2 仍保证「前端不再收到数据」，但服务端查询可能继续跑 → 由 §4 超时兜底。

## 4. 超时分层（复用 M2-4，不新造）

| 阶段 | M2-4 原语义 | DB 适配 |
|---|---|---|
| 默认 | `timeout_secs = 0` → 60s | `0` → **30s**（`DB_DEFAULT_QUERY_TIMEOUT_SECS`） |
| 上限 | > 600s → 拒绝 | 同（`DB_MAX_QUERY_TIMEOUT_SECS`）；超限属配置校验 → `DB_INVALID_CONFIG` |
| **soft** | SIGTERM | **发起 L3 驱动级带外取消**（DB 无进程可杀） |
| **hard** | SIGKILL | soft 后 5s 仍未结束 → **放弃该连接**：丢弃（不归还）+ 标记池中该连接不可用 + 记审计 |

**必须显式声明的差异**：M4 借用 M2-4 的 **600 / 5 量级与分层结构**，但 soft / hard 的**机制不同**。
不得写成「复用 M2-4 超时」而让读者以为有 kill 语义。

## 5. 多语句与取数通道（A10 G-4.4 落地口径）

| 驱动 | 允许通道 | 禁止 |
|---|---|---|
| SQLite | `prepare`（单语句） | `execute_batch` |
| Postgres | 扩展协议 `query` / `prepare` | `simple_query` / `batch_execute` |
| MySQL | 单语句 | 关闭 `CLIENT_MULTI_STATEMENTS`（**不得依赖 crate 默认，须显式关闭**；本卡未实测各 crate 默认值） |

用户 SQL 在**进入驱动前**先过 A4 的分类器（剥离注释与字符串字面量 → 整批处理 → 任一语句非 SELECT 即整批拒绝 → 不可解析即拒）。
驱动层关闭多语句是**第二道**，不是唯一一道。
