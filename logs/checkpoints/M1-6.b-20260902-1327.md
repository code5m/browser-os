## 2. 安全边界（与任务书 REQUIRE_SAFETY 逐条对齐）

1. **统一确认闸门**：六个操作无一直接执行；`request_git_write`（预检+预览+Pending 任务，
   零写入）→ `confirm_git_write`（一次性取出+后台线程执行+事件通知）。对齐
   `request_sync/confirm_sync` 范式但使用独立 `GitWriteJob`/`pending_git_jobs`，
   既有成果推送流程零改动。
2. **repo_id 锁定**：复用 M1-5 `sync::repo_dir`（命中 `repos.json` + 拒 `..`/绝对/分隔符
   + 拼接后二次校验在 `app_data_dir/mvp-browser-os/repos/<id>` 内）；request 与
   confirm 执行体两次校验（双保险）。
3. **paths 锁定**：仅仓库内显式相对路径；拒 `.git` 内部（含 `a/.git/b`）、绝对路径、
   `..`/.`/空分量（字符串级检查，补 `Path::components()` 归一化盲区）、反斜杠、
   空路径、控制字符；上限 200 条；空列表拒绝（杜绝整仓隐式操作）。
4. **commit message**：非空、≤500 字节、禁一切控制字符（含换行）。
5. **branch name**：禁 `HEAD`/`@`/空名/`..`/`@{`/反斜杠/前后斜杠/双斜杠/`-` 前缀/
   `.lock` 后缀/git 禁用字符/`.` 开头分量，兜底 `git2::Reference::is_valid_name`。
6. **discard 二次确认**：`dangerous=true`，confirm 必须带 `confirmed_dangerous=true`，
   否则 `Err("需二次确认")` 且任务不取出不执行；只允许显式已跟踪路径
   （未跟踪文件整体拒绝，防误删新文件）。
7. **审计**：`git_write_request` / `git_write` / `git_write_failed` / `git_write_rejected`，
   detail 为 JSON 且只含 `op/repo_id/job_id/path_count/confirmed/extra`（构造器签名
   不接收 paths/diff/凭据）；错误串 300 字节截断。自审：`rg userpass_plaintext src-tauri/src`
   仍只命中 `sync.rs cred_cb` 一处。
8. **fail-closed**：白名单外 op、确认缺失、过期、路径非法、repo 未配置/未初始化、
   脏工作区冲突、git2 错误，全部在执行前 Err；混合合法+非法路径整体拒绝，
   索引不落盘 = 零部分写；checkout 冲突在移动 HEAD 前判定。
9. **凭据隔离**：写链纯本地（git2 本地 API），不读 KeyringStore、不出现 cred/token；
   commit 签名复用既有 `极智简单 <mvp@jizhijiandan.local>`。
