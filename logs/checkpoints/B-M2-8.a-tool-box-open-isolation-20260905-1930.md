| 码 | 裁定 | 落地方式 |

| F6 | 生命周期 | `open_tool` label 去重（聚焦而非重开）；退出时 Tauri 自动关全部窗口，无额外钩子 |
| F7 | 错误页兜底 | 协议层异常返回静态错误 HTML（不 panic、不泄露路径/系统信息）；`open_tool` 非法 id 返回 `Err` |
| F8 | 零新增依赖 | 仅 `tauri::http`/`std::fs`/`std::path`/`tauri::Manager`；无新 crate |
| F9 | 验收基线（M2-9） | 每种子离线可开、零外链、零 bridge 写原语；工具窗口无法调任何桥命令 |

## 二、落地改动清单（仅追加 / 低风险）

1. `src-tauri/src/tools.rs`：新增 `open_tool` 命令 + `tool_html`（协议服务，含 `read_user_tool` 路径校验 + `error_page` 安全错误页 + `html_escape`）。`builtin_tool_html` 已存在（M2-7）。
2. `src-tauri/src/main.rs`：主 `Builder` 上 `register_uri_scheme_protocol("tool", ...)`（handler 经 `UriSchemeContext.app_handle()` 取句柄）；`generate_handler!` 注册 `tools::open_tool`。
3. `src/stores/useLayoutStore.ts`：`MainView` 联合增 `"tools"` + `MOD_META.tools`。
4. `src/components/layout/ActivityBar.vue`：「工具」分节增 `tools` 入口。
5. `src/components/layout/MainArea.vue`：增 `tools` 渲染分支 + import `ToolBox`。
6. `src/components/workspace/ToolBox.vue`（新）：调 `bridge.listTools()` 列出（内置/用户分组），点击调 `bridge.openTool(id)`。
7. `src/types.ts`：增 `ToolMeta`/`ToolSource` 前端类型。
8. `src/bridge.ts`：增 `listTools` / `openTool` 命令包装。
9. `scripts/check-tools-policy.py`：扩展 M2-8 不变量（open_tool 存在/注册、协议注册、路径防御、错误页、工具窗口零能力隔离）+ 6 个坏样本（共 16 坏样本变异防呆）。

> 注：Tauri 2.11.5 自定义协议 API 为 `register_uri_scheme_protocol`（App 版为 `mut self`，无法在 `&mut App` 的 setup 调），故注册于主 `Builder`；handler 经 `UriSchemeContext.app_handle()` 取 `AppHandle` 读 workspace。
