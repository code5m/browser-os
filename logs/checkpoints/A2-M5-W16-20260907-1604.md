## 4. 决策摘要（详见 assist 正文）

- **D-1** 运行时能力一律落 **bin**；`mvp_core` 不得获得执行/网络/监听/守护/线程能力。
- **D-2** core 只吸收**纯逻辑**（策略、校验、DTO、调度算法、图索引计算）。
- **D-3** 跨边界必经 `core::seam` trait 注入，实现留在 bin（沿用 `ProgressSink` 先例）。
- **D-4** 执行类能力**复用 `script_runner`**，禁止第二执行路径。
- **D-5** 新约束须落成 `check-core-boundary.py` 码位，而非仅写文档。
- **D-6** 未经 A0 书面批准的切片 = 非目标。

逐项覆盖：插件执行 / Agent-Skill 执行 / MCP 运行时 / 网络下载监听 / 守护 / 后台 worker /
模型调用 / 图写导出 / 动态加载 / 裸 invoke 与敏感持久化（§2 表）。
非目标 N-1~N-8、硬停 H-1~H-9、seam 扩展五原则（§5）、M6 准入闸门六条（§7）。

### 4.1 与 A1《M6 WBS / 排序提案》交叉核对

对象：`logs/checkpoints/A1-M5-W16-M6-WBS-proposal-20260908-1100.md`（A1 草案 · 纯文档，只读核对）。

| A1 候选 | 覆盖 | 结论 |
|---|---|---|
| M6-1 plugin stage-II 有界调用 | §2「插件调用」= bin，复用 `script_runner` | ✅ 一致 |
| M6-2 MCP stdio 真实 runtime | §2「MCP 运行时」= bin | ✅ 一致（门禁形态细化 → G-1） |
| M6-3 Agent/Skill 执行授权 | §2「Agent/Skill 执行」= bin；授权判定可留 core | ✅ 一致 |
| M6-4 graph 受控写/导出 | §2「图写/导出」= 混合 | ✅ 一致 |
| M6-5 后台 worker（非 daemon） | §2「后台 worker」= bin；调度算法可留 core | ✅ 一致 |
| M6-6 分发与签名 | §2 未直接覆盖 | ⚠️ 补充裁定 → G-2 |

- **G-1（修正 §5 码位建议）**：M6-2 首选形态是 **MCP stdio**，**不 bind 端口**但属长驻监听循环；
  闸门应以 `CORE_THREAD_SPAWN` / `CORE_DAEMON_LOOP` 为主，`CORE_NETWORK_BIND` 仅在未来
  HTTP/SSE 传输形态才需要。结论不变：MCP stdio 落 bin。
- **G-2（M6-6 补充裁定）**：分发/自动更新 = bin；真验签（纯算法，`sha2` 已在
  `CORE_DEP_ALLOWLIST`）= 可 core，但公钥读取与远程获取仍在 bin；多版本并存（纯状态）= 可 core。
  ⚠️ 语义联动：若真验签落地，须同步修订 `PluginSignatureView.status` 口径
  （当前 `structure_ok|structure_failed`，**刻意不含 `verified`**，W13 明令不得声称已验签）；
  交 **A0 / A9** 列为 M6-6 强制交付项。

**总体**：A1 的排序与 D-1~D-6 **完全兼容**——6 个候选全部是运行时权威，按 D-1 一律落 bin，
`mvp_core` 不会因 M6 而获得执行/网络/守护能力。
