## 0. 冻结前新发现的两个硬事实（改写了部分裁定）

1. **`check_shell_command`（`security_policy.rs:300`）只是"整条命令行"的字符级最小契约**，
   元字符集合为 `; & | \` $ > < \n \r`，**缺少**通配符（`* ? [`）、`(`/`)`、`..`、
   超长判定与其余控制字符（0x00-0x1F 只覆盖 `\n`/`\r`）。其注释自述"单靠字符过滤不足以
   对抗所有注入，刻意不做清洗只做拒绝"，且它被 `.desktop` 启动链路依赖。
   → **裁定：不复用、不修改它**；M2-3 新建"单个参数值"语义的独立纯函数，元字符集合
   以其为基线并扩展（§4.3）。
2. **`BLOCKED_LAUNCH_PROGRAMS = [sh, bash, zsh, fish, powershell, cmd]`（同文件:124）**，
   `check_launch_target` 明确"放行它们等于把 `sh -c` 换个壳重新打开"。
   → **裁定：`interpreter` 必须是白名单枚举，不得是自由字符串**（§4.1）。
   自由字符串等于在脚本库入口重新开放"任意程序执行"，与既有口径直接冲突；
   脚本库是**受控例外**，例外范围必须由枚举钉死，不能交给用户输入。

另有可**直接复用**的既有设施（b 卡不得另造）：
`check_path_within_roots` / `is_within_roots`（路径白名单，含软链接逃逸比对）、
`check_path_component`（文件名形态）、`check_text_field`（文本上限 64 KiB）、
`is_sensitive_query_key` + `SENSITIVE_QUERY_KEYS`（M1-8 既有 21 键脱敏）。

## 1. 第一组：`ScriptMeta` 字段口径

**裁定：以 prework 版为骨架，并入 assist 版的 `secret` 字段，并把 `interpreter` 收紧为枚举。**

```rust
/// 参数类型（决定前端控件与校验规则）
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum ParamType {
    String,  // 自由文本，危险字符校验最严
    Int,     // 整数（i64 可解析）
    Bool,    // 布尔，仅接受 "true"/"false"
    Enum,    // 枚举，options 必须非空且值必须在 options 内
    Path,    // 本地路径，必须过 check_path_within_roots 白名单
}

/// 脚本参数定义
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ScriptParam {
    /// 占位符名，对应脚本正文里的 `${name}`。字符集 `[A-Za-z0-9_]`，非空，≤32 字符
    pub name: String,
    pub label: String,
    pub param_type: ParamType,
    pub required: bool,
    pub default: Option<String>,
    #[serde(default)]
    pub options: Vec<String>,  // 仅 Enum 使用；Enum 时必须非空
    /// 是否允许不加单引号包裹直接入命令行。**仅 Path / Enum 允许 true**，
    /// 定义期即校验（raw=true 且类型非 Path/Enum → 保存拒绝）
    #[serde(default)]
    pub raw: bool,
    /// 敏感参数：UI 用密码框、审计值一律 `***`
    #[serde(default)]
    pub secret: bool,
}

/// 解释器白名单。刻意设为枚举而非 String：不得借脚本库开放任意程序执行。
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum ScriptInterpreter {
    Bash,
    Sh,
    Python3,
    Node,
    /// 不指定解释器：直接执行脚本文件（依赖 shebang 与可执行位）
    Shebang,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ScriptMeta {
    pub id: String,                    // uuid v4，落盘文件名即 <id>.<ext>
    pub name: String,                  // 展示名
    pub category: String,              // 分类/标签
    /// 脚本正文文件名（**相对 scripts 目录**，形如 `<id>.sh`）。
    /// 不存绝对路径：绝对路径会泄露环境且迁移即失效（与 M2-1 `rel_path` 同口径）
    pub path: String,
    pub interpreter: ScriptInterpreter,
    #[serde(default)]
    pub params: Vec<ScriptParam>,
    #[serde(default)]
    pub description: String,
    /// 内置模板：不可删除
    #[serde(default)]
    pub builtin: bool,
    #[serde(default = "default_enabled")]
    pub enabled: bool,
    /// 超时秒数；0 = 使用全局默认（300）。**字段本卡落，语义由 M2-4 实现**
    #[serde(default)]
    pub timeout_secs: u32,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
}
```

**逐字段裁决理由**

| 分歧 | 裁定 | 理由 |
|---|---|---|
| `args` vs `params` | **`params`** | `args` 与进程 argv 混淆；`params` 与「参数定义」语义一致 |
| 是否引入 `ParamType` | **引入**（String/Int/Bool/Enum/Path） | 无类型就无法做类型专属校验（Int 解析、Enum 取值域、Path 白名单），前端也只能全用文本框 |
| `interpreter: String` vs 枚举 | **枚举 `ScriptInterpreter`** | 见 §0 第 2 条：自由字符串 = 重新开放任意程序执行，与 `BLOCKED_LAUNCH_PROGRAMS` 冲突 |
| `secret: bool` | **并入** | 靠参数名正则兜底不够可靠；显式标记让 UI 与审计都有确定依据 |
| `path` 绝对 vs 相对 | **相对文件名** | 与 M2-1 `rel_path` 同口径；绝对路径泄露环境、迁移失效 |
| `timeout_secs` / `enabled` / `builtin` | **保留** | 字段本身无副作用；`timeout_secs` 语义由 M2-4 实现，本卡只落字段 |
| 向后兼容 | 新增 `Vec`/`Option`/`bool`/数值字段一律 `#[serde(default)]` | 与 `Artifact.images` 同口径，缺它会让 `scripts.json` 解析失败被吞、历史数据静默丢失 |

**字段上限**（校验器统一在 b 卡落地）：
`name` ≤ 128、`category` ≤ 64、`description` ≤ 1024、`label` ≤ 64、`param.name` ≤ 32，
均过 `check_text_field`；`params` ≤ 20 条；`options` ≤ 50 项；脚本列表总量 ≤ 200 条。

## 2. 第二组：存储布局

**裁定：`scripts.json`（元数据）+ `scripts/<id>.<ext>`（正文，独立文件）；运行记录整体推迟到 M2-4。**

| 项 | 裁定 |
|---|---|
| 元数据文件 | `data_dir/scripts.json`（`Vec<ScriptMeta>`，`to_string_pretty`） |
| 正文文件 | `data_dir/scripts/<id>.<ext>`，ext 由 `interpreter` 决定：`Bash/Sh → .sh`、`Python3 → .py`、`Node → .js`、`Shebang → .sh` |
| 为什么不内嵌正文 | JSON 内嵌大文本会让每次元数据读写都搬正文，也让 diff/审计变脏 |
| 落盘方式 | **原子写（tmp + rename）**，与 M2-1 `images.rs` / M2-2 同口径 |
| ⚠️ 既有范式 | `save_repos` / `save_bookmarks` / `log_audit` 目前是**非原子写**（直接 `fs::write`）。属既有技术债，**本卡不倒改既有代码**，只在新增的 `save_scripts` 上用原子写。违规码 `SCR_ATOMIC_WRITE_MISSING` 只检查新增的脚本持久化函数 |
| 删除语义 | 元数据移除 + 正文文件删除；重复删除幂等（`builtin=true` 的脚本拒绝删除） |
| `ScriptRunRecord` / `RunStatus` | **M2-3 不定义、不落盘**。理由：M2-3 无执行能力，定义了就是「无写入者的空结构」，容易出现永远为空的 JSON 与死代码。由 M2-4 与执行通道一同定义 |
| 目录创建 | `scripts_dir(app)` 内部 `ensure`（与 `sessions_dir`/`images_dir` 同款） |

## 3. 第三组：危险参数规则归属

**裁定：M2-3 落地纯函数 `validate_param_value`，含 9 条 fail-closed 规则 + 类型校验，配单测；M2-4 只负责在拼命令行前调用它。**

**不复用 `check_shell_command`**（§0 第 1 条）：语义不同（整条命令行 vs 单个参数值）、
错误码不同（它只有 `ShellMetacharacter`，缺 `PATH_ESCAPE`/`ARG_TOO_LONG` 等）、
且修改它会影响既有 `.desktop` 启动链路。元字符集合以其为**下界基线**并扩展。

```rust
/// 参数值校验（**纯函数、无副作用、fail-closed**）
pub fn validate_param_value(
    value: &str,
    param_type: ParamType,
    raw: bool,
) -> Result<(), ScriptError>
```

| 规则 | 触发 | 错误码 |
|---|---|---|
| 命令替换 | `` ` ``、`$(`、`<(`、`>(` | `DANGEROUS_SUBSHELL` |
| 链接/管道 | `;`、`&&`、`\|\|`、`\|`、`&`（含结尾） | `DANGEROUS_CHAIN` |
| 重定向 | `>`、`<`、`>>` | `DANGEROUS_REDIRECT` |
| 通配符展开 | `*`、`?`、`[` | `DANGEROUS_GLOB` |
| 换行/回车/NUL | `\n`、`\r`、`\0` | `DANGEROUS_NEWLINE` |
| 变量注入 | `${`、`$` 后跟标识符/`(` | `DANGEROUS_VAREXP` |
| 路径穿越 | `..`（**Path 类型必检；其余类型同样拒绝**，因为单引号包裹下 `..` 无意义却可能绕过路径白名单） | `PATH_ESCAPE` |
| 超长 | > 4096 字符（**按字节判定**，多字节下不得 panic） | `ARG_TOO_LONG` |
| 控制字符 | 0x00–0x1F（含 0x7F） | `DANGEROUS_CONTROL_CHAR` |

**类型专属校验**（在危险字符检查之后）：
- `Int`：`i64::from_str` 可解析
- `Bool`：仅接受 `true` / `false`
- `Enum`：值必须在 `options` 内，否则 `PARAM_NOT_IN_OPTIONS`
- `Path`：值须过 `check_path_within_roots`（复用既有白名单校验器）
- `required=true` 且值为空 → `PARAM_REQUIRED`（**调用方在组装 argv 前检查**，纯函数只提供 `check_required`）

**`raw` 的定义期合法性**（不是运行期）：
`raw = true` 且 `param_type ∉ {Path, Enum}` → 保存元数据即拒绝（`INVALID_RAW_PARAM`）。
理由：`raw` 意味着跳过单引号包裹，只允许出现在取值域可控的类型上。

**单引号包裹策略属 M2-4**：本卡只提供 `raw` 标记与定义期校验，不实现拼接。
`raw = true` 的参数在 M2-4 仍须受路径穿越与超长检查。

## 4. 第四组：审计与脱敏

**裁定：三条写命令各写一条审计；detail 只含元数据摘要；脱敏三重保险。**

| 命令 | action | detail 字段 |
|---|---|---|
| `script_add` | `script.add` | `id`、`name`、`interpreter`、`param_count` |
| `script_update` | `script.update` | `id`、`name`、`param_count`、`builtin` |
| `script_remove` | `script.remove` | `id`、`builtin` |
| `script_list` | **不审计** | 只读枚举无副作用，避免刷满 1000 条上限 |

**detail 硬红线**：不得含脚本正文、不得含参数**默认值**（默认值可能就是密钥/口令）、
不得含参数值、不得含绝对路径（`path` 是相对文件名，天然满足）。

**脱敏规则（三重，满足其一即 `***`）**
1. `ScriptParam.secret == true` —— 显式标记，优先级最高
2. 参数名命中既有 `is_sensitive_query_key`（M1-8 的 `SENSITIVE_QUERY_KEYS`，21 键）
3. 参数名匹配正则 `[Pp]ass|[Ss]ecret|[Tt]oken|[Kk]ey|[Aa]pikey` —— 正则兜底

**审计不写脚本输出**：M2-3 无执行能力，天然满足；M2-4 侧须遵守"只写 `output_tail` 前 200 字符"
（本卡为 M2-4 记录该约束，不代为决策）。

## 5. 第五组：M2-4 / M2-5 边界（本卡明确不做）

| 不做 | 归属 |
|---|---|
| `run_script` / `script_cancel`、任何 `std::process::Command`、shell 插件 spawn | M2-4 |
| 进程组 kill（setsid + killpg）、超时、输出上限（256 KB tail）、并发互斥 | M2-4 |
| `ScriptRunRecord` / `RunStatus` 定义与落盘 | M2-4 |
| 参数拼接成 argv（含单引号包裹）与实际执行 | M2-4 |
| 前端脚本库面板、参数表单、执行状态展示 | M2-5 |

**给 M2-4 的两条记录**（本卡不代为决策）：
1. `ShutdownCoordinator` 已支持 `register(name, task)`，M2-4 注册 `kill-running-scripts` 即可满足
   "退出前杀掉所有 Running"；草案 `M2-3.a-prework` §2.1 把「`request_app_exit` 未落地」列为
   高等级阻塞项，**该阻塞项已解除**（展开卡 §3 已记录）。
2. `shell:allow-spawn` 对 bash/sh/powershell 为 `args: true` 完全开放，ACL 不兜底；
   参数校验必须在 `run_script` 内部调用本卡的 `validate_param_value`，不得依赖 capabilities。
