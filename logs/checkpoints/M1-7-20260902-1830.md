## 3. 写操作安全链路（双闸门 + 双保险）

```
用户点击 → requestWrite(op, opts)
         ├─ 仓库已选？busy？已有待确认任务？         → 否：拦截（toast，不发请求）
         ├─ precheck(commit 非空 / 分支名非空 / paths 非空) → 失败：拦截（不发 request，无审计噪声）
         └─ bridge.requestGitWrite  ──► 后端白名单 + 路径锁定 + 只读预检
                                        → GitWritePreview{summary, affected_paths, path_count, dangerous, expires_at}
         ↓
GitWriteConfirmDialog（展示后端 preview + 前端派生风险等级）
         ├─ dangerous（discard/push）→ 必须勾选二次确认，否则按钮 disabled
         └─ 点击「确认执行」 → confirmWrite()
                  ├─ 前端再判：dangerous && !dangerousAck → 拦截（confirm 命令不发）
                  └─ bridge.confirmGitWrite(jobId, confirmedDangerous)
                           → 后端闸门：一次性 / 5 分钟 TTL / dangerous 二次确认 / 后台线程
                           → emit "git-write-completed"
                                    → 前端 onWriteCompleted → refreshAll() + toast（脱敏）
```

**风险等级声明**：后端 `GitWritePreview` **没有 `risk` 字段**（`domain.rs` 只给 `dangerous`
布尔）。UI 展示的 `low/medium/high` 由 `gitWriteRisk(op, dangerous)` **前端派生**，
纯展示用途，不参与任何安全判定；判定只看后端 `dangerous`。已在 `src/types.ts` 注明。

   后续可考虑默认改为「必须勾选」。

   本期 UI 侧只做 `busy` 串行化（同一时刻一个待确认任务），多仓库并发仍无互斥。
5. push 仅支持 origin 同名分支；真实 HTTPS 远端未实测。
