## 3. 对冻结裁定书的两处微调（已记录，需裁定者确认）

1. **`validate_param_value` 去掉 `raw` 参数**。裁定书 §3 给的签名是
   `(value, param_type, raw)`；实现改为 `(value, param_type)`。
   理由：`raw` 只影响 **M2-4 的命令行拼接策略**（是否单引号包裹），对本函数的
   字符拒绝规则**没有任何作用**（所有类型都拒绝 `..`、超长与控制字符），保留会
   成为一个无作用参数；`raw` 的合法性已在 `validate_meta` 定义期校验。
2. **未新增 `check-script-domain-logic.mjs`**（任务卡 WRITE 列了它）。
   理由：前端本卡**没有脚本相关的纯逻辑层**——UI 与参数表单属 M2-5，若现在加
   `src/utils/script.ts` 就是**无人消费的死代码**，而这正是裁定书 §2 拒绝在 M2-3
   定义 `ScriptRunRecord` 的同一理由。因此 T-scr-1~17 全部由 **Rust 单测**覆盖
   （22 项，含真实磁盘往返），mjs 随 M2-5 UI 一同落地。已在 `pre-merge.sh` 第 18 项
   注释中写明「前端逻辑测试随 M2-5 UI 落地」。

## 4. 过程中踩到并修掉的三个问题

1. **ACL 条目顺序（第二次踩同一个坑）**：M2-1 的 `check-image-policy.py` 坏样本按
   `'    "list_artifact_images"\n'`（**末行、无逗号**）定位。M2-2.b 时已因此把
   `workspace_images_dir` 插到其之前；本卡一度把 `script_*` 追加到文件末尾，导致
   该行变成带逗号、坏样本静默失配、`--self-test` 报「1/17 漏检」。
   修复：把 `script_*` 插到 `list_artifact_images` **之前**，保持其末行形态。
   **未改** M2-1 门禁脚本。**建议后续新增 ACL 条目一律插在 `list_artifact_images 之前`**。
2. **坏样本静默失效**：上述事故暴露出「变异字符串失配 → `str.replace` 返回原文 →
   什么都没测却显示通过」。已在本卡夹具的 `--self-test` 中加入**防呆**：坏样本必须
   与好样本**真的不同**，否则按漏检计（`X ... 坏样本无效（变异未生效）`）。
3. **12 个新增 dead_code warning**：5 个函数（`validate_enum_value`、`check_required`、
   `is_secret_param`、`redact_param_value`、正文读取）是为 M2-4/M2-5 预留的契约能力，
   本卡无调用者。处理：逐个 `#[allow(dead_code)]` 并**注明消费者**
   （同既有 `InlineTooLarge`、`join_image_path` 口径），warning 回到既有 2 个。
   不是删除函数、不是放宽 lint。
