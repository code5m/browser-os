## 2. Tauri 资源事件支持 / 降级边界（如实声明）

1. **设计文档假设的 `on_web_resource_response_received` 在 Tauri 2.11.5 不存在**；
   唯一的 `WebviewBuilder::on_web_resource_request` **仅对 `tauri://` 协议生效，
   外部 http(s) 页面不触发**（已核查 crate 源码 `tauri-2.11.5/src/webview/mod.rs:440`）。
2. 实际采集路径（Linux WebKitGTK 原生信号，已验证 webkit2gtk 2.0.2 绑定存在）：
   `WebView::resource-load-started`（`URIRequest` → method/url/开始时刻）
   → `WebResource::finished`（`URIResponse` → status/mime/content_length）
   → `WebResource::failed`（失败仅上报 method/url/时刻，status/mime/size=None）。
3. **字段边界（不伪造）**：
   - `size_bytes`：WebKit `content_length` 未知时返回 0，统一映射为 `None`（未知的空响应与真实 0 字节无法区分，取保守口径）；
   - `status/mime`：仅在 `finished` 且有响应时存在；加载失败为 `None`；
   - `duration_ms`：两个信号时刻差；时钟回拨为 `None`；
   - `method`：信号缺省时回退 `"GET"`（唯一回退值，已在 DTO 注释声明）；
   - `resource_type`：信号不提供 initiator 类型，由 mime + URL 后缀推断；
     **XHR/Fetch 为启发式**（json/xml/text 数据响应归入），可能含误判；
   - 不采集任何 headers / Cookie / Authorization / Set-Cookie / request body / response body（信号层即不读取，结构上无字段可承载）。
4. **平台边界**：资源信号仅 Linux（`#[cfg(target_os = "linux")]`，与既有 load-failed 同口径）；
   **宫格 grid-N 不采集**（grid 在独立子进程，插件事件未经 UDS 转发——本期范围只覆盖主进程 tab-N 页签，已在 `check_tab_id` 强制 `tab-` 前缀）。
5. 采集默认 **enabled=true**（纯内存、已脱敏、不留存）；设置为会话级不持久化，重启回默认。

## 3. 隐私过滤与容量上限

| 红线 | 实现 | 测试 |

## 4. 安全门禁

- 4 命令全部 `check_invocation_source`（远程 tab-*/grid-* 无令牌一律拒绝；`tab_id` 强制 `tab-` 前缀且 ≤64 字符）：T-rc-9、T-rc-12。
- main.rs 不直接转发原始 `resourceReceived` payload，唯一出口是 `on_resource_received`（脱敏后才 emit）：policy RC_RAW_PAYLOAD_FORWARDED / RC_EVENT_NOT_ROUTED_TO_BRIDGE。
- 插件资源信号块零打印（原始 URL 可能带 token）：policy RC_PLUGIN_LOGS_URL。
- 前端除 `bridge.ts` 不得直连 4 命令；store/组件零凭据标识符：policy RC_FRONTEND_DIRECT_INVOKE / RC_FRONTEND_CREDENTIAL_TOKEN。
- 无无限增长结构（两级 FIFO + 计数）、无新增后台线程、未改 M2/M3/M4/M5、未改 Git UI/后端。

## 8. 人工验收清单（可复现）

1. `cargo build --release` 后启动应用 → 「打开浏览」访问任意含多资源网页（如 https://www.baidu.com）。
2. 浏览器视图右侧 Dock → 「🌊 资源」Tab：应看到逐行资源记录（方法/状态/类型/大小/耗时/域名+路径）。
3. 依次点 All/Doc/JS/CSS/Image/XHR-Fetch/Other：列表按类型过滤。
4. 访问带 `?token=xxx` 的 URL：瀑布中该参数值应显示 `***`，全程无 token 明文。
5. 点「清空」：列表清空，`audit.json` 仅新增 `resource_clear tab_id=… removed=…`（无 URL）。
6. 关闭「采集」开关后刷新页面：无新记录；再开启恢复采集。
7. 持续刷新使单页签记录 >200 条：出现「已达容量上限」横幅，最旧记录被丢弃。
8. 关闭页签：该页签记录随之清除（重开同名新页签列表为空）。
9. 检查 `audit.json` 与 stderr：无任何带 query 的资源 URL。

2. 宫格 grid-N 不采集（子进程边界）；如需覆盖，需扩展 UDS 事件转发（留 M1-9 之后评估）。
3. 设置会话级不持久化（重启回默认 enabled=true）；如需求要求记忆开关，归后续检查点。
4. 运行时端到端联调与 GUI 目视验收挂账（§6），建议负责人按 §8 清单人工复核。
