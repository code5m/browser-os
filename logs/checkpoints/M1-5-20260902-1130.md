## 命令契约

```
git_status(repo_id)                                -> Vec<GitFileStatus>
git_diff(repo_id, path?, max_bytes?)               -> GitDiffResult { hunks, more }
git_branch_list(repo_id)                           -> Vec<GitBranch>
```
- `GitFileStatus.status`：`modified`/`added`/`deleted`/`renamed`/`untracked`/`conflicted`。
- `GitDiffHunk`：`truncated`=单文件超 `min(max_bytes, 256KB)`；`binary`=无文本补丁（二进制）；
  `more`=多文件累计触硬上限后停止收集。

## 只读安全边界

1. 路径锁定：`repo_id` 必须命中 `repos.json` 已配置仓库；拒绝空值、含 `/` `\` `..`、
   绝对路径的 id；拼接后二次校验落点仍在 `app_data_dir/mvp-browser-os/repos/` 之内。
2. 零写操作：生产路径 230 行自审（脚本 grep）**零** `checkout/reset/commit/push/pull/
   merge/rebase/fetch` 调用，也**不读** `KeyringStore`、不回传任何凭据。
3. 来源校验：三命令统一 `check_invocation_source`，阻断远程页面/子 webview 调用。
4. 只打开已初始化仓库，未 clone 返回「仓库尚未初始化（未同步过）」，不自动 clone（避免联网与副作用）。
5. 错误统一 `Err(String)`，不 panic；路径细节不回传前端。

## 实测中发现并修正的问题

1. `git2::Buf` 无 `as_bytes()`（应 deref 为 `[u8]`）→ 改 `String::from_utf8_lossy(&buf)`。
2. `repo.head().ok().and_then(|h| h.peel_to_tree().ok())` 临时 `Reference` 早释放（E0716）→ 先绑定 `head` 再 peel；`canonicalize()` 临时值同类问题 → 先绑定 `resolved`。
3. `Patch::to_buf()` 需 `&mut self` → `Ok(Some(mut patch))`。
4. 字节截断可能切在 UTF-8 字符边界（panic 风险）→ 新增 `truncate_at` 回退到字符边界，并加 T-util-1 覆盖。
5. **libgit2 不设 `DiffFlags::BINARY`**，而是生成 `Binary files ... differ` 文本补丁
   （已用临时调试用例读真实 flags 证实 `DiffFlags(0x0)`）→ 改按该文本标记判定 `binary`，
   避免把说明文本当补丁回传；调试模块已删除。
