## 1. 方法（可复现，且不触碰产品源码）

- 复刻而非猜算：把产品 CSS 中的**精确 px 常量**抄进一个自包含静态页面
  `logs/research/M5-W18/A2-R3-density-replica.html`（无网络、无外部字体依赖、无 Tauri/bridge 调用、
  不 import 任何产品文件；每个数值在页内注释里标注了出处行号）。
- 用无头 Chrome 真实布局后取 `getBoundingClientRect()`：
  `google-chrome --headless --no-sandbox --disable-gpu --dump-dom`（本机 `Google Chrome 150.0.7871.128`）。
- 驱动脚本 `A2-R3-measure.py` → 输出 `A2-R3-run-20260908.out`（表 + 明细 JSON 表）。复现：
  `cd logs/research/M5-W18 && python3 A2-R3-measure.py`。
- **视口无关**：无头 Chrome 的 `--window-size=1440,900` 实际给出 813px 视口，因此复刻页把根容器显式
  设为 `W×H` 再量子元素，测量与浏览器真实视口无关。
- **状态矩阵**：9 个状态 × 10 个尺寸（4 个 R3 目标尺寸 + 4 个"扣除约 37px 原生标题栏"的敏感度尺寸 +
  蓝图提到的 900x600 / 800x600）。
  主窗口 `decorations` 未显式关闭（`main.rs:1223-1228` 仅 `inner_size(1200,800)`、`min_inner_size(900,600)`、
  `maximized(true)`），因此标题栏高度随系统主题变化，故单列敏感度。
  ⚠️ `min_inner_size(900,600)` 意味着 **800x600 在现有产品里根本拉不出来**，与蓝图 §3 的"窄窗 1024x720、800x600"
  冲突——见 §8 交 A0/A1。

### 1.1 假设与误差来源（诚实声明）

| 项 | 处理 |
|---|---|
| 中文字体 | 复刻页用 `system-ui, "PingFang SC", "Noto Sans CJK SC"`；本机有 279 个 Noto/CJK 字体，与真机 PingFang 的换行点可能相差 ±1 行（影响"扩展行换行"状态，约 ±29px） |
| 页签数量 | 取 6 个页签（4 网页 + 2 目录）。页签条高度**不随数量变化**（单行 + 横向溢出滚动），故不影响 chrome 高度 |
| 横向滚动条 | `.unified` 为 `overflow-x:auto`；WebKitGTK 为覆盖式滚动条（0px），Chrome 桌面版会占 15px。**本次实测已抓到**：900x600 `sidestack` 状态下页签条从 31px 涨到 **46px**（`EXECUTED_SYNTHETIC_TEST`）。故 §6.1 顶栏上限取 60px 而非 63px，预留 15px 滚动条后仍 ≤80px |
| 原生标题栏 | 未计入主尺寸（主尺寸 = 客户区 = R3 所说的"post-titlebar"）；另给 37px 扣除的敏感度表 |
| 未测量 | 各模块视图内部（数据库/图谱/Git/终端）的自有分栏——属 A5/A7 lane，A2 只测外壳 |
