## 1. A0 公式与本 lane 的口径替换（CORRECTIONS）

> Geometry SSOT uses the application inner viewport, excluding the OS titlebar. Normal top chrome is
> exactly 60px (two 30px rows); status bar is 24px. Collapsed active width is `(viewport width - 28) /
> viewport width`; collapsed active height is `(inner height - 60 - 24) / inner height`.

本 lane 据此替换 R3 的私有口径：

### 4.1 为什么 Δ 是 0，以及这个 0 说明什么、不说明什么

- **说明**：A0 公式在当前 CSS 盒模型下可被精确编码；30px 行在 900px 宽下没有因内容溢出而增高
  （实测 `rowA/rowB` 的 `scrollWidth − clientWidth = 0`，行高锁死 30px，溢出走裁剪）。
  这排除了“公式算得出但布局撑不住”的一类风险 —— 这是纯算术给不出的证据。
- **不说明**：Δ=0 是**编码一致性**证据，不是物理客户端证据。修订复刻就是把公式写成 CSS，
  它无法证明真机 WebView、DPI 缩放、原生标题栏、字体回退下的表现。真机记 `NOT_RUN`（§9）。

## 8. 900x600 专项与 800x600 的剔除

- 900x600 是产品 `min_inner_size(900,600)`（`src-tauri/src/main.rs:1226`）的下界，也是 A0 六尺寸里唯一
  余量 <2pp 的尺寸（86.00%，余量 1.00pp）。**任何 chrome 增量都必须先在 900x600 上复算。**
- 800x600：A0 已剔除（低于产品最小窗）。本波主表与门禁均不再包含；R3 的 800x600 数字保留在
  `A2-R3-run-20260908.out` 作为历史，**不作为验收依据**。
