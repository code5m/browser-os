## 2. 契约草案（供强模型复核，非定稿）

### 2.1 新增/复用命令与事件

```
# 后端 → 前端（冷启动重放锚点）
event  "app://open-url"   payload: { url: string }   # RunEvent::Opened 收到后 emit
# 后端内部状态
state  PendingOpenUrls: Mutex<Vec<String>>           # 进程启动时 URL 早于前端就绪的缓存
# 前端消费（App.vue onMounted 内新增监听）
bridge.onAppOpenUrl((u) => { if (isHttp(u.url)) browser.tabNew(u.url); })
# 前端就绪后重放
bridge.m0Ready() 返回后，前端 emit "app://replay-pending" 或后端在 m0_ready 命令内flush
```

### 2.2 setup-linux.sh 新增段落（用户显式触发，非静默）

```bash
# 仅当用户在设置里点「设为默认浏览器」后，由前端调起本脚本（或等价 IPC）才执行
register_default_browser() {
  local desktop="/usr/share/applications/mvp-browser-os.desktop"  # 文件名待实测
  # 1. 写入 MimeType=x-scheme-handler/http;x-scheme-handler/https;
  # 2. update-desktop-database /usr/share/applications
  # 3. xdg-settings set default-web-browser mvp-browser-os.desktop
}
```

### 2.3 tauri.conf.json 可能改动

- 若 bundler 生成的 `.desktop` 缺 `MimeType`，需加 `bundle` 段自定义 desktop 模板，
  **或**在 `setup-linux.sh` 直接 sed/patch 生成文件。二选一，待强模型实测决定。

## 3. 风险点（按严重度排序）

| # | 风险 | 说明 | 缓解 |
|---|------|------|------|
| R1 | 冷启动 URL 丢失 | 进程未运行时 `xdg-open` 的 URL 早于 `App.vue` onMounted 到达，`tabNew` 落空 | `PendingOpenUrls` 缓存 + `m0Ready()` 后重放（见 §2.1） |
| R2 | `.desktop` 文件名不确定 | bundler 可能生成 `mvp-browser-os.desktop` 或 `com.jizhijiandan.mvp.desktop` | 实现前必须先 `ls /usr/share/applications/*mvp*` 实测，禁止凭猜 |
| R3 | 静默改系统默认浏览器 | 属安全/体验红线，安装或首启自动改写会被用户视为流氓行为 | 只做设置页显式按钮 + 确认弹窗；`setup-linux.sh` 不主动调用 |
| R4 | 非 http/https scheme 注入 | `file://`、`javascript:`、`data:` 等经 `on_open_url` 传入可能被拼进导航 | 统一 `isHttp()` 前置校验，拒绝即 `log_audit` + toast，绝不 emit |
| R5 | 与既有 `security-policy-v2` 冲突 | 新增 IPC/事件须纳入 ACL | 在 `capabilities/default.json` 显式声明新权限，不放开 `core:default` 之外的隐式授权 |
| R6 | 门禁回归 | 新增 Rust 代码易触发 `cargo fmt` / clippy；新增 `.desktop` 易触发 build metrics 体积告警 | 开工前先跑 `cargo fmt --check` + `bash scripts/pre-merge.sh` 取绿基线（M1-2-fix1 教训） |
