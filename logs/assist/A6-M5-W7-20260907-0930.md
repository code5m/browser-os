## 3. 核心接线错配（MISMATCH — 必须在本笔记澄清，供 A0 开 UI 时纠正）

**M1（命令面错配）**：W5 `bridge.ts`（行 352-382）登记的 11 个 Agent/Skill 封装里，`skillList`/`agentList`/`skillInstall`/`agentInstall`/`confirmSkill`/`confirmAgent`/`skillRun`/`agentChat`/`agentRunCancel`/`skillRunsList`/`agentRunsList` 对应的后端命令（`skill_list`/`agent_list`/`skill_install`/`skill_run`/`agent_chat`…）**在 W7 一律不存在**（W7 仅 `skill_validate`/`agent_validate` 只读）。这些占位会让未来 UI 误以为有 list/install/run 能力。

**M2（store 形态错配）**：W5 `useAgentStore.ts` 维护 `skills[]`/`agents[]` 注册表（由 `loadSkills`/`loadAgents` 填充）并暴露 `installSkill`/`installAgent`/`runAgent`/`skillRun`。W7 无 list/install/run 命令 → 不应维护注册表，也不应暴露安装/运行动作；只读面只需「最近一次校验结果」。

**M3（权限弹窗流向错配）**：W5 `PermissionPreviewModal.vue` 接 `pendingConfirms`（approve/deny 二段式闸门）。W7 是**只读预览**（无 approve/deny，无落库）；弹窗应只渲染 `preview` + 关闭，不含确认按钮。

→ **结论**：当 A0 后续开放 UI 接线时，W5 壳必须**重定位为「Skill/Agent 校验器」**，而非「管理器」。本笔记 §4-§8 给出纠正后的契约。

## 4. A5 W7 只读命令契约（建议命令名/参数/返回，对齐 A5 纯函数）

> 仅建议；A5 在 W7 产品代码包内定稿，但命名须与前端桥一一对应（见 §5）。所有命令须过 `check_invocation_source` + 注册于 ACL（在 `list_artifact_images` 之前）+ 不写审计（无凭据/无 body）+ 不应返回 `SkillDef` 的 secret 值（当前 DTO 无 secret 字段，天然满足）。

| Tauri 命令 | 参数（snake_case） | 返回 | 实现映射（A5 纯函数） |
|---|---|---|---|
| `skill_validate` | `text: String`（SkillDef JSON 文本） | `SkillValidationResult` | `SkillDef::parse(text)` → 失败则 `ok=false, issues=[{field:"json",code:"PARSE_ERROR",message}]`；成功则 `def=Some`，`validate()` 的 `PolicyError` 映射为 `issues`，`preview=permission_preview()` |
| `agent_validate` | `text: String`（AgentDef JSON 文本） | `AgentValidationResult` | `AgentDef::parse(text)` → 同上；`validate()` 校验 id/version/能力单源/凭据防泄露；`preview=permission_preview()`（Agent 默认 `Confirm`） |

建议返回结构（Rust → TS 镜像）：

```rust
// src-tauri/src/skills.rs / agent.rs（W7 新增 #[tauri::command]）
pub struct ValidationIssue { pub field: String, pub code: String, pub message: String }
pub struct SkillValidationResult {
    pub ok: bool,                       // parse 且 validate 均通过
    pub def: Option<SkillDef>,          // parse 成功即返回（即便 validate 失败），供 UI 部分展示
    pub issues: Vec<ValidationIssue>,   // validate 失败项；空=通过
    pub preview: Option<PermissionPreview>, // def 存在即返回（gate + capabilities[]）
}
pub struct AgentValidationResult { /* 同构，def: Option<AgentDef> */ }
```

- `ok=false` 的两种来源：① JSON 解析失败（`code="PARSE_ERROR"`，`def=None`，`preview=None`）；② 语义校验失败（`code=EmptyRequiredField/UnknownCapability/CredentialLeak/InlineShell`，`def=Some` 但 `issues` 非空）。
- **禁止**返回任何凭据/body/secret；`preview.capabilities` 为已解析 id 列表（白名单缺失时仍回显原 id，由前端标 `unknown`，沿用 W5 `renderCapabilityList` 语义）。

## 10. 风险与红线（W7 Hard Stop 对齐）

- **R1 只读不可越界**：W7 命令仅 parse/validate/preview；**不得**出现 `skill_install`/`skill_run`/`agent_chat`/`agent_install` 等执行/安装/对话命令（W7 Hard Stop 行 168「no skill execution, no plugin install/enable/disable/uninstall」）。UI 侧（未来接线）也不得渲染这些控件。
- **R2 无持久化写**：`skill_validate`/`agent_validate` 不落盘、不写 `skills.json`/`agents.json`、不进审计（无凭据/body）。
- **R3 无 secret/凭据泄露**：`PermissionPreview.capabilities` 为 id 列表；校验错误信息 `issues[].message` 不得含 `system_prompt` 原文里的凭据（后端 `validate` 已拒凭据泄露，返回 `CredentialLeak` 错误码而非原文）；前端 `redactSecrets` 兜底。
- **R4 开关粒度**：`AGENT_SKILL_COMMANDS_AVAILABLE=true` 仅表示 validate 可用；store 必须区分 `canValidate` vs `canManage`，避免误解锁安装/运行（M1/M2）。
- **R5 类型单一真源**：`PermissionPreview { gate, capabilities[] }` 已是 Agent/Skill/Plugin 共用类型（`agent.rs`/`skills.rs`/`plugin.rs` 三处同形）；前端 `PermissionPreviewModal` 单组件直渲，勿为 Skill/Agent 另建预览组件。
- **R6 不引依赖**：W7 只读桥不引入新 Cargo/npm 依赖（YAML 解析留 M5-4.b；W4 已定仅 JSON）。
