## 5. 关键一致性发现（RED LINES for A8）

### F1 · vue-router 是过时假设 → 改用 `useLayoutStore` `MainView`
M5-9 卡 §3 列 `src/router/graph.ts`、§2 列 `src/router/agent.ts`。但：① 项目检索 `vue-router`/`createRouter`/`useRouter` 全 0；② `src/router` 目录不存在；③ 我的 W5 壳经 A1 W5 协调**已移除 vue-router 假设**，改用 `useLayoutStore` `MainView`+`MOD_META`+`ActivityBar`（见 P11）。
**红线**：A8 **不要新建 `src/router/graph.ts`**。应把图谱视图加进 `useLayoutStore` 的 `MainView` 联合（加 `"graphs"`）+ `MOD_META` 条目 + `ActivityBar.vue` 工具组菜单项，并在 `MainArea.vue` 加 `<div v-else-if="mainView==='graphs'">` 懒加载分支——与我 W5 的 `skills`/`agents` 接线**逐字同构**。M5-9 卡的 router 表述需 A0/A1 回写为「`useLayoutStore` MainView 范式」。

### F2 · graph 命令未落地 → 必须复用 `backendReady` 闸门范式
`bridge.ts` 当前**无 `graph_*` 封装**（仅 `AGENT_SKILL_COMMANDS_AVAILABLE=false` 与 `TASK_COMMANDS_AVAILABLE=true`）。A8 W5 delta §2 已确认 `graph_*` Tauri 命令 = 0。W6 硬停止（行 167/169）亦禁止 A8 加后端命令。
**红线**：A8 须在 `bridge.ts` 加 `GRAPH_COMMANDS_AVAILABLE = false`（占位，**不实现真实命令**）+ `graphList`/`graphQuery`/`graphNeighbors` 等封装（签名对齐未来命令，内部仅在 `GRAPH_COMMANDS_AVAILABLE` 时调用）；`useGraphStore` 克隆我的 `guard()`（行 51-56），未就绪时**零 invoke**，`GraphViewer` 显示「只读壳」横幅。这与我 W5 的 `AGENT_SKILL_COMMANDS_AVAILABLE=false` 完全同构。

### F3 · RAG 注入复用 `useAgentStore` 的会话/流式缓冲，不得另造无界缓冲
`useGraphRag.ts` 仅构造「图谱上下文」字符串（节点 label+kind+关系，**不含 props**），注入 `agent_chat` 的 `system_prompt`。该 agent 对话的**流式响应仍由 `useAgentStore.sessions` + `appendChunk`（≤64KB 有界）承载**（P7）。
**红线**：`useGraphRag` 自身**不得持有任何流式缓冲/会话状态**；图谱上下文字符串须有界（节点数 ≤ `GRAPH_QUERY_LIMIT=1000`、不含 `props` 正文、不含 secret）。重造第二套无界缓冲即违反 P7/W6 边界（行 170「store 有界」）。

### F4 · Skill/Agent 类节点详情复用 M5-6 能力/权限渲染
图谱 `Uses`/`A2aWith`/`Memorizes` 边直接引用 A5 `SkillDef.id`/A4 `agent_kv` 语义（A8 delta §4.5）。当 `GraphNode.kind ∈ {Skill, Agent}` 时，`NodeDetail` 应展示该 Skill/Agent 的能力与闸门。
**红线**：直接 import 并复用 `agentSkillUi.ts` 的 `renderCapabilityList` / `buildPermissionPreview`（P4/P5），**不要重实现**能力标签/授权判定/高危提示。单一真源保持在我 W5 的 `agentSkillUi.ts`。

### F5 · `derivePrivacy()` 已过时 → 与 M5-6 一致，脱敏后端侧、UI 只 K7
A8 delta §4.1 已确认 DTO **无 privacy 字段**，`props` 后端已脱敏；`derivePrivacy` 删除。这与 M5-6 的 P6（前端只 `redactSecrets` + 不显示原始值）立场一致。
**红线**：A8 不得在 UI 层重新发明隐私推导；`NodeDetail`/`EdgeDetail` **禁止渲染 `props` 正文**（K7 硬禁）。如需展示个别标量字段（label/kind/source），用 `nodeLabelSafe` 之类纯函数且**永不含 `props`**。

### F6 · 纯逻辑层 + headless 测试范式（A8 必交付 `scripts/check-graph-ui-logic.mjs`）
board W6 A8 Must Deliver 已要求 `scripts/check-graph-ui-logic.mjs`。board §M5-W6 行 159。「纯逻辑层」是我 W5 的核心范式（P1/P12）。
**红线**：A8 须把图谱纯逻辑（布局提示 `layoutHint`、容量估算 `estimateCapacity`、元素判别 `elementKind`、节点标签安全化、图谱状态展示）抽到 `src/utils/graphUi.ts`（无 invoke/DOM/store，可 node import），并**复用我的 `check-agent-skill-ui-logic.mjs` 测试脚手架**（TS-import hook + `bridge` mock + pinia import），加入「未就绪零 invoke」「可见节点≤500」「查询返回≤1000」「props 不出现在展示态」等断言。测试 harness 不应各写一套。

### F7 · 有界 store / maps（W6 行 170）
我的 `sessions`/`pendingConfirms` 均有界（P7/P9）。A8 的 `useGraphStore` 必须：
- 可见节点 ≤ `GRAPH_VISIBLE_NODES_MAX=500`（>500 自动隐藏弱连接，M5-9 §4.1/§4.4）；
- 单次查询返回 ≤ `GRAPH_QUERY_LIMIT=1000`（A7 常量）；
- 邻居/子图走 A7 `bounded_neighbors`/`bounded_subgraph`，前端不缓存全量（`GRAPH_MAX_NODES=5000`/`GRAPH_MAX_EDGES=20000` 是后端总量上限，前端 store 不得接近）；
- `props`（`GraphProps` BTreeMap，≤64KiB）**不进前端 store**（K7 + 有界）。
**红线**：图谱常量集中放 `graphUi.ts`（镜像 `agentSkillUi.ts` 行 65-68 的「前端常量对齐后端冻结值」），前端绝不放宽。

### F8 · 面板三态复用 `panelState`
我的 `panelState(kind, opts)`（行 289-309）统一生成 loading/empty/ready/error，且 `backendReady=false` 时强调「只读壳」。
**红线**：A8 不要另写一套空/错状态机；在 `agentSkillUi.ts` 的 `panelState` 把 `kind` 联合从 `"skills"|"agents"` 扩为加 `"graphs"`（向后兼容，一行改动），`GraphViewer` 直接复用。若 A8 不便改我的文件，可导出同签名同名函数，但**不要重复实现**语义。

### F9 · i18n 是过时假设 → 跟随既有硬编码中文惯例
M5-9 §3 列 i18n 8 key、§7 PASS#6 要求 i18n 齐。但项目**无 i18n 系统**（检索 0 命中），我的 W5 壳全部硬编码中文。
**红线**：A8 默认跟随既有惯例（硬编码 zh），**不要为图谱 UI 单独引入 i18n 框架**（会与我及全项目不一致，且超出 W6 A8 scope）。若产品确需 i18n，由 A0/A1 单独立项，不在本波。

### F10 · dark/light 复用既有主题机制
主题系统已存在：`useSettingsStore.ts` 有 `Theme="light"|"dark"`、`theme=ref("light")`；`SettingsPanel.vue` 有浅色/深色切换。我的 W5 壳用普通 scoped CSS（未接主题变量）。
**红线**：A8 的 `graph.scss` 若需深色适配，**复用项目既有主题应用机制**（跟随 `useSettingsStore.theme` 的 CSS 变量策略），不自创第二套主题开关。
