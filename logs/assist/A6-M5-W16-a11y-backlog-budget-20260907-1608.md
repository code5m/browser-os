### 2.1 A11Y-1 为什么是 M6 的前置项（不只是"打磨"）

W14 的 hard stop 规定：**插件状态变更必须经用户显式确认**。当前 `.pm-modal` 只有鼠标可完成这条确认——键盘用户 Tab 能到按钮（无陷阱、无初始焦点、无 ESC），屏幕阅读器不会 announce 这是一个需要决策的对话框（`role` 缺失）。也就是说，**"显式确认"这道闸门目前只对鼠标用户真正成立**。

若 M6 批准任何与插件生命周期相关的运行时切片，A11Y-1 应在放行前收口；否则被放行的能力对键盘用户不可达，等于把可用性缺口固化进运行时。

### 2.2 A11Y-7 的实现约束（写给后续接手者）

插件面板空态是 `<li class="pm-empty">`，在 `<ul>` 内。正确做法沿用 A0 在 `AuditPanel` / `RunHistoryModal` 上已落地的写法——保留 `<li>`，只补属性：

```html
<li v-if="!store.list.length" class="pm-empty" role="status" aria-live="polite">…</li>
```

W15 曾尝试用通用组件统一空态，代价是 2.7 KB dist（见 §3），且会产出非法 DOM 嵌套——**属性级方案是这里的正确解**。

## 3. 预算提案（Budget Proposal）

### 3.1 计量口径与现状

`total_bytes_pct = (当前 dist.total_bytes − 基线 dist.total_bytes) / 基线 × 100`。

基线取 `logs/m0-build-metrics/build-metrics-4f0e8ab.json` = **612,943 B**；即 **1 pp ≈ 6.13 KB**。

| 数据点 | dist.total_bytes | total_bytes_pct | 说明 |
|---|---|---|---|
| `886ea29` 指标文件（A6 全量方案在工作树时实测） | 769,784 | **25.59%** | 与 A0 记录的"全量 25.60%"吻合 |
| `052b18a`（A0 裁剪后，已 PUSH） | 767,059 | **25.14%** | 现值 |
| 上限（`TOTAL_BYTES_GROWTH_LIMIT_PCT`，W15 一次性上调） | — | **25.20%** | 进一步增长需 A0 显式决策 |

**可用余量 = 0.06 pp ≈ 368 B。**

被裁剪切片实测成本：**2,725 B（0.45 pp）**——即"`AsyncState.vue` + `asyncView.ts` + 4 处接线 + `modalA11y` 扩展"的整体代价。

### 3.2 单件成本估算（方法已标注，非实测）

| 项 | 估算 dist 成本 | 方法 |
|---|---|---|
| 单组件接线（复用现成 `useModalFocus`，+4~6 行 script + `ref` 属性） | ~0.1~0.2 KB（≈0.02~0.03 pp） | 无模板/CSS 增量；TS 按 minify 后 ≈ 源码 40~55% 折算 |
| 新增带模板 + scoped CSS 的通用组件 | ~1.0~1.3 KB（≈0.17~0.21 pp） | 由被裁切片 2,725 B 反推（该切片含 1 组件 + 1 纯函数模块 + 4 接线） |
| 属性级 ARIA（`role` / `aria-live`） | ~60~80 B/处，可忽略 | 纯模板属性 |
| CSS 色值替换（A11Y-8） | **0 B** | 字符数不变的十六进制替换 |

推论：**余量 368 B 只够"一处接线 + 若干属性"，装不下任何新组件，也装不下 5 处接线（≈0.10~0.15 pp）。**

### 3.3 三个选项与推荐

**选项 A（推荐先做，压在余量内）**
1. A11Y-8 对比度（0 B）；
2. A11Y-7 属性级空态 ARIA（≈ +150 B，2 处）；
3. A11Y-1 插件确认弹窗单处接线（≈ +0.15 KB，最高风险面优先）。

预计合计 **+0.03~0.05 pp**，落在 25.20 以内。每步必须 `python3 scripts/measure-build-metrics.py --compare logs/m0-build-metrics/build-metrics-4f0e8ab.json --skip-build` 实测后再进下一步；一旦实测超 25.20 立即停手并回报 A0。

**选项 B（换空间）**
如需一次做完 A11Y-1~5（≈ +0.10~0.15 pp），需先释放等量字节。候选：`PluginManager.vue` 内注释与重复样式压缩、检查 `index-*.js` 是否有可 tree-shake 的死导出。**删除他 lane 代码需 A0 指派，A6 不擅自动手。**

**选项 C（申请上调）**
若 M6 要开插件运行时，建议 A0 把"上限上调"与"runtime 放行"绑定为同一次决策（例如一次性到 26%），并写进 M6 门禁条款，避免后续每 0.0x pp 反复走审批。

### 3.4 建议纳入 M6 的验收口径

把 `check-ui-a11y-logic.mjs` 的**断言条数**作为"a11y 覆盖率"代理指标写进 M6 验收矩阵：现值 **9 条**（仅覆盖 role/ESC/选择器），补齐焦点回环与状态判定后应回到 **28 条**。这样"是否真的做了 a11y"可被门禁量化，而不是靠人眼验收。
