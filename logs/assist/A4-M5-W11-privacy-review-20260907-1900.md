## 2. 逐项评审（含实跑证据）

### 2.1 原始参数绝不回显（W11 Hard Stop 行 208 核心）

- `tools/call` 仅取出 `params.name`（能力名，协议标识符），**从不读取/序列化 `arguments` 对象**（mcp_server.rs:250, 272-285）。
- 未绑定/未知能力失败文本只回显能力名 `other`（mcp_server.rs:278-283），形如 `"file_read is declared ... not yet bound"` / `"unknown tool 'x'; fail-closed"`——**不含任何 arguments 内容**。
- A3 已落地回归测试 `arguments_are_never_echoed_in_fail_closed`（mcp_server.rs:371-379）：向 `arguments.path` 注入 `SECRET_TOKEN_DO_NOT_ECHO_xyz`，断言整个响应序列化串不含该串 → 通过（`cargo test --features mcp mcp_server` 18/18）。
- 结论：**PASS**，且已有机器级回归保护。

### 2.2 URL / userinfo / query 脱敏

- `mcp_registry_list` 返回的 `McpRegistryEntryView` 仅含 `returns_url: bool`（mcp.rs:141-146），**从不序列化 URL 文本**；`tab_query`/`history_query` 虽 `returns_url=true`，dry-run 下未绑定、不返回内容。
- `mcp_policy_get` 返回 `McpPolicySnapshot`（仅 `capabilities: Vec<String>` + 常量 `policy_version`），无 URL。
- 真正绑定 URL 返回的工具若未来落地，必须经过 `redact_mcp_url`/`redact_sensitive_url`（mcp.rs:104-108，单一真源），且 `MCP_FS_TOOL_PATH_POLICY` 静态守门要求注册表含 `redact_sensitive_url`。
- 结论：**PASS**（dry-run 无 URL 内容外泄；未来路径有脱敏单一真源 + 静态守门）。

### 2.3 audit / log 载荷泄漏

- `mcp_server.rs` 全文 **0 处 `log_audit` / `println!` / `eprintln!`**；所有输出仅经 `write_response` → `writeln!(stdout,...)` 的 JSON-RPC 响应（mcp_server.rs:123-126）。
- 无审计写入、无 stderr 泄漏，参数不会落入 audit/日志/检查点/UI 状态（stdio 是 server 进程内通信，不经 Tauri IPC，前端不读 stdin/stdout）。
- 结论：**PASS**。

### 2.4 错误信息确定性、不泄露请求体

- 全部错误为固定文案：Parse error(-32700) / Invalid Request(-32600) / Request too large(-32600) / Method not found(-32601) / Invalid params: missing tool name(-32602) / Response exceeded size limit(-32603)（mcp_server.rs:93-119, 267-271）。
- 超界响应经 `serialize_bounded` 替换为固定错误串，绝不回吐业务/参数内容（mcp_server.rs:105-121, 484-491 测试）。
- 结论：**PASS**。
