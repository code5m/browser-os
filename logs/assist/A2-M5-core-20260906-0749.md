## 2. 四边界（core / web / mcp / cli）职责与依赖方向

M5-1 原文（`详细设计与实施计划.md:562`）："**拆出 core/web/mcp/cli 边界，保持现有二进制可逐步迁移**"。
v1 只覆盖了 core 一边，v2 补齐四边界。

| 边界 | 职责（应含） | 明确禁止 | M5-1 阶段动作 |
|---|---|---|---|
| **core** | 领域类型与契约（`domain`）、策略纯函数（`security_policy`）、持久化原子写（`session`）、凭据（`keyring_store`）、数据库逻辑（`database`）、脚本/片段/图像领域、执行引擎（seam 化后的 `script_runner`）、调度领域（`scheduler`/`tasks`）、路径解析（seam 化后的 `workspace`） | 禁止 `tauri`/任何插件；禁止 `use crate::bridge`/任何 bin 模块；禁止自起进程（执行必须经 `script_runner`） | **实际落地**（切片 0a/0b/1/2） |
| **web** | 浏览器/webview 能力层：宫格子进程（`grid_process`）、终端 Channel Sink（`terminal`）、browser-tabs 插件适配、前端 `src/**` | 禁止把领域逻辑写回 web 层；禁止 core 反向引用 web | **只定契约，不拆 crate**（`grid_process`/`terminal` 与 Tauri 强绑，拆出无收益）。M5-1 只要求在 core 边界断言里点名"web 层单向依赖 core" |
| **mcp** | MCP server / transport（`rmcp`），把 core 能力以 MCP tool/resource 暴露（M5-2，Lane A3） | 禁止依赖 bin crate；禁止自建执行路径（必须复用 core 的 `script_runner`）；禁止绕过 source check / ACL / Keyring | **只定契约**：`mcp → core`，`mcp ⇸ bin`。crate 到 M5-2 再建，M5-1 只需保证 core 边界成立 |
| **cli** | 命令行入口（并列 `[[bin]]`），与 GUI bin 同级消费 core，用于无 GUI 环境跑脚本/任务/图谱维护 | 禁止 cli 与 GUI bin 互相引用；禁止把只在 bin 里才有的能力下沉进 core | **只定契约**：`cli → core`，`cli ⇸ gui bin`。当前不存在，M5-1 不建 |

### 2.1 依赖方向硬规则（写入断言脚本）

```text
R-B1  core ⇸ tauri / tauri-build / 任何 tauri-plugin        （编译层守不住，靠脚本，见 §3.3）
R-B2  core ⇸ crate::bridge 及任何 bin-only 模块             （脚本 + 编译双重可守）
R-B3  bin → core 单向；web → core 单向；mcp → core 单向；cli → core 单向
R-B4  web ⇸ mcp ⇸ cli ⇸ gui-bin，四者横向互不依赖
R-B5  core 内不得出现 std::process::Command / shell 词法解析（沿用 M2-4 P0 红线）
R-B6  core 新增依赖必须显式登记在 §3.3 白名单，越界即 FAIL
```

### 3.2 已实测的落地机制（/tmp 最小工程，2026-09-06 07:56）

| 机制 | 实测结论 |
|---|---|
| 同 package 双 target：`[lib] name=… path="src/lib.rs"` + 默认 bin `src/main.rs` | ✅ `cargo build` 通过；`cargo build --lib` 与 `cargo test --lib` 可独立运行 |
| **re-export shim**：bin 根写 `pub use mvp_browser_os_core::domain;`，二进制子模块仍写 `use crate::domain::Foo;` | ✅ 编译通过 → **二进制侧 40+32+… 处 `crate::X::` 引用全部免改写** |
| **core 内部免改写**：lib 根写 `pub mod core; pub use crate::core::*;`，core 内文件仍写 `use crate::domain::Foo;` | ✅ 编译通过 → **A 类模块搬移时内部 `use` 语句零改动** |
| lib target 是否可见 package 级 `[dependencies]` | ⚠️ **可见**（core 内 `use serde::Serialize` 编译通过）→ **编译层无法阻止 core 引用 tauri** |

> 复现方式（M5-1.a 实施前可自行复跑，不影响仓库）：
> ```bash
> d=$(mktemp -d) && cd $d && mkdir -p src/core
> # Cargo.toml: [package]+[lib] name="probe_core" path="src/lib.rs"
> # src/lib.rs:      pub mod core; pub use crate::core::*;
> # src/core/mod.rs: pub mod domain; pub mod other_core;
> # src/core/other_core.rs: use crate::domain::{A, Foo};
> # src/main.rs:     pub use probe_core::domain; mod other; fn main(){…}
> # src/other.rs:    use crate::domain::{A, Foo};
> cargo build && cargo build --lib && cargo test --lib
> ```

**R3 风险降级**：v1 把"`use crate::X` 全量机械改写"列为 MED 风险，实测后降为 LOW
（改写面从"数百处"收窄为"`main.rs` 一行 shim + `domain.rs`/`scripts.rs` 两个测试块"）。

### 3.3 边界断言：必须前置，不是可选项

因 §3.2 第 4 行实测结论（编译器守不住），边界只能由脚本守住。
建议新增 `scripts/check-core-boundary.py`（**A2 在 Wave 0 不落地，仅给规则与骨架**；
扩展名 `.py` vs A1/A10 所写 `.sh` 的裁定见 **§13.3**，A2 建议 `.py`），
并接入 `scripts/pre-merge.sh`（现有模式：`python3 "$SCRIPT_DIR/<script>.py" --self-test` + 默认扫描，
风格对齐 `scripts/check-command-domain-policy.py`）。

**必须断言的规则（建议规则码 `COREBOUND_*`）：**

| 规则码 | 断言内容 | 严重级别 |
|---|---|---|
| `COREBOUND_TAURI_IN_CORE` | `src-tauri/src/core/**` 中不得出现 `use tauri` / `tauri::` / `AppHandle` / `AppState`（**排除注释行**——见 §1.1 口径，否则会误报） | FAIL |
| `COREBOUND_CORE_TO_BIN` | `src-tauri/src/core/**` 中不得出现 `crate::bridge::{...}` 或引用任何 bin-only 模块名（`bridge`/`terminal`/`grid_process`/`tools`/`shutdown`） | FAIL |
| `COREBOUND_LIB_DECLARED` | `src-tauri/Cargo.toml` 必须含 `[lib] name = "mvp_browser_os_core"` | FAIL |
| `COREBOUND_SHIM_ORDER` | `src-tauri/src/main.rs` 中 A 类模块不得再出现 `mod X;` 声明（必须走 shim） | FAIL |
| `COREBOUND_DEP_ALLOWLIST` | core 可见依赖白名单外的新依赖不得出现在 `[dependencies]`（白名单见下） | FAIL |
| `COREBOUND_TREE_TAURI` | `cargo tree -p mvp-browser-os --lib` 不得出现 `tauri` 节点（**注：同 package 下此断言必然 FAIL，仅阶段二拆成独立 crate 后才可能 PASS → 阶段一设为 PENDING，阶段二转 FAIL**） | PENDING → FAIL |
| `COREBOUND_EXEC_PATH` | `src-tauri/src/core/**` 不得出现 `std::process::Command` / `Command::new` / `sh -c` / `bash -c` | FAIL |
| `COREBOUND_NO_EMPTY` | 不产生空文件；占位必须含 `STATUS=BLOCKED` 与解锁条件 | FAIL |

**core 依赖白名单**（对齐 `src-tauri/Cargo.toml` 现有项）：
