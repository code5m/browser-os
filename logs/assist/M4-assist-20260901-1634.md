## 1. 数据库面板后续拆解（M4-1~M4-4）

### M4-1 数据库驱动与生成契约 `[DEEP|R:high]`
- 选定依赖（sqlx vs rusqlite+驱动），确定首期 sqlite/mysql/postgres。
- `plugins/db-types/*.yaml` 生成 `SupportedDb` 枚举（加库加 YAML，不碰核心）。
- `build.rs` 加代码生成（当前极简，需评估对现有 `tauri_build::build()` 的影响）。
- **风险**：`build.rs` 改动影响全量编译；须保持现有二进制可构建。

### M4-2 PoolKind 与生产安全策略 `[DEEP|R:xhigh]`
- `enum DbPool { Sqlite/MySql/Postgres }`，命令层只暴露 `db_query(pool_id, sql)`。
- 独立 `db_production_safety.rs`：`is_production_database` 纯函数层（判定与业务解耦）。
- SQL 风险分类（SELECT/DDL/DML/DCL），写操作默认拒绝。
- **风险**：生产判定误判 → fail-closed（不确定即拒写）。

### M4-3 数据库命令层 `[DEEP|R:xhigh]`
- `db_connect(cfg)->pool_id` / `db_query(pool_id, sql)->rows` / `db_disconnect(pool_id)`。
- 全部进 ACL + 写 `audit.json`；`KeyringStore` 取凭据（禁 FileSecretStore 主路径）。
- 结果上限 `DB_QUERY_ROW_LIMIT`（防内存放大）；凭据不进日志/前端。

### M4-4 数据库 UI `[BALANCED|R:high]`
- 连接表单 + SQL 编辑器 + 结果表 + 导出成果库 + 危险操作确认。
- 复用 `ConfirmModal.vue`（现有 `ws.preview` 确认范式）。

## 2. 定时任务调度后续拆解（M4-5~M4-8）

### M4-5 调度核心 `[DEEP|R:high]`
- `scheduler.rs`：`TaskDef{cron/command/enabled/last_run/next_run}`。
- `tokio_cron_scheduler` 或 `tokio::time::sleep` 轮询；`setup` 钩子 `tokio::spawn` 常驻。
- 错过执行策略（catch-up/skip）、可取消 `Scheduler`、同一任务不重入。

### M4-6 调度命令与持久化 `[BALANCED|R:high]`
- `task_list/add/update/remove/run_now`，进 `permissions/default-commands.toml`。
- `workspace/tasks.yaml|json` 原子落盘（tempfile+rename）+ 损坏恢复。
- **风险**：tasks 文件损坏 → 启动加载失败须降级（空任务列表 + 告警）。

### M4-7 安全触发与退出 `[DEEP|R:xhigh]`
- 触发即调 M2-4 `run_script`/`run_command`（Channel 回显），定时任务只调度不重写执行。
- `scheduler.abort()` 注册进 M0-2 生命周期协调器（无 timer 残留）。

### M4-8 定时任务 UI `[BALANCED|R:medium]`
- CRUD + 启用开关 + 下次执行 + 运行历史 + 失败重试状态。
