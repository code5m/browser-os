## 1. 请求/资源瀑布现状

- **已有**：每 tab 周期性 `scan_resources` → `report_resources` → 前端 `browser-resources` 事件。
- **缺口**：当前仅"资源项列表"（URL/type），**无**请求级瀑布（时序、大小、状态码、耗时、
  MIME）。Tauri 2 的 `WebviewWindow` 不直接暴露 `PerformanceObserver`/Network 面板数据，
  需经注入 JS（`resources_eval.js` 扩展）采集 `performance.getEntries()` 或
  `PerformanceObserver` 的 `resource` 类型条目。

---

## 2. 容量上限（草案，复用 security_policy 范式）

| 维度 | 现有 | 建议新增 |
|------|------|----------|
| 资源项数量 | `MAX_RESOURCE_ITEMS`（已用） | 瀑布条目 `MAX_WATERFALL_ITEMS = 500`，超则截断 oldest |
| 单条文本 | `MAX_TEXT_FIELD_BYTES` | 瀑布 URL 复用此上限 |
| 采集频率 | `start_resource_scanner` 周期 | 瀑布采样节流 `WATERFALL_SAMPLE_MS = 1000`，避免事件洪水 |
| 内存放大 | 已有 `check_items_count` 防护 | 单 tab 瀑布缓冲硬上限 `WATERFALL_BUF_CAP = 1MB` |

---

## 3. 隐私过滤（草案）

- **过滤项**：`Set-Cookie`/鉴权头/`Authorization`/`token` 查询参数不进瀑布详情；
  URL 中的 `?token=`/`?access_key=` 脱敏为 `?token=***`。
- **来源限制**：仅采集 `https://`/`http://` 同域或用户已访问页；`file://`/内联 `data:` 不记。
- **不落盘**：瀑布仅为会话内展示，不写 `audit.json`/成果库（避免凭据/隐私外泄）。
- **用户开关**：设置项可关瀑布采集（默认关，按需开）。

## 4. Tauri/WebView 钩子风险

| # | 风险 | 说明 | 缓解 |
|---|------|------|------|
| R1 | 注入 JS 性能开销 | `resources_eval.js` 扩展采集 `performance` 可能拖慢页面 | 节流 + `requestIdleCallback` 内执行 |
| R2 | 跨 webview 数据泄漏 | 子 webview 注入脚本若读 `parent`/opener 可能越权 | 子 webview 沙箱隔离（同 M2-8 策略），注入脚本仅读本页 `performance` |
| R3 | 事件洪水 | 高频 `browser-resources` 事件冲垮前端 | `WATERFALL_SAMPLE_MS` 节流 + `MAX_WATERFALL_ITEMS` 截断 |
| R4 | 钩子时机竞争 | webview 未 load 完时 eval 失败 | `scan_resources` 已在 `navigationFinished` 后触发（main.rs 转发），保持该时序 |
| R5 | 隐私合规 | 瀑布含第三方请求 URL 可能涉隐私 | §3 过滤 + 用户开关 + 不落盘 |

## 5. 实现路径建议（给强模型）

1. 扩展 `injected/resources_eval.js`：新增 `performance.getEntriesByType('resource')` 采集，
   经现有 `window.ipc.postMessage` 通道回传（不新建通道）。
2. 新增 `ResourceWaterfallItem` DTO：`{ url, type, size, duration_ms, status, mime }`。
3. `report_resources` 增加可选 `waterfall` 字段，复用 `check_items_count`/`check_text_field`。
4. 前端 `BrowserHost` 新增瀑布面板（默认隐藏，设置开启）。
5. 全部走 `check_invocation_source` + 容量上限 + 隐私过滤。
