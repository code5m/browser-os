## 2. A7 M5-7/8 graph 模型 — 与 M5-2 MCP 注册表/政策 的兼容性结论

### 2.1 设计定性：图谱是**本地** store + `graph_*` Tauri 命令，**非 MCP 能力**
- A7 的 9 条命令命名为 `graph_query`/`graph_node_*`/`graph_edge_*`/`graph_export`（M5-7 §5 / M5-8 §4.3），**非 `mcp_*`**。→ `MCP_PARITY`（只扫 `mcp_server_start|mcp_server_stop|mcp_policy_get|mcp_policy_set`）**不会误触发**；无虚假冲突。
- 当前 `MCP_CAPABILITY_V1` 未含 graph 能力 → 图谱**今天就不是 MCP 暴露面**，正确。
- 存储复用 `database.rs` 单 SQLite 连接（`graph.db` + `graph.db.bak`），路径经 root 策略校验；维护任务走 `script_runner`（`TaskKind::{Script,Command}`、`enabled=false`，禁新增 `TaskKind`）→ 无第二执行路径、无 rmcp/tokio/监听，与 M5-2 红线同源（`MCP_RUNTIME_LEAK`/`MCP_LISTEN_PORT`/`MCP_NPM_*` 不会误报）。

## 3. MCP 注册表暴露期望（IF 图谱未来经 MCP 暴露）

图谱当前非 MCP 能力；但若 M5-9「Agent 消费图谱」或某未来 `graph_query` MCP 工具决定暴露，则必须满足 M5-2 注册表范式。以下为**精确前向兼容清单**（给 A0/A7/A17）：

1. **注册单一真源**：向 `MCP_CAPABILITY_V1` + `MCP_COMMAND_REGISTRY` 追加 graph 能力（如 `graph_query`/`graph_node_get`，或合并 `graph_read`），**不得**在 A7 模块内另定义能力常量（防 `MCP_CAPABILITY_DRIFT`）。
   - ⚠️ **R1 仍生效（同 W4）**：能力单源须由 A3 M5-2.b 提升进 `mvp_core`（`core/capability.rs`），bin 侧 re-export、删 `domain.rs` 影子。A7 的 `core/graph_*` 模块届时 `use mvp_core::capability::MCP_CAPABILITY_V1` 即可（R-B3 满足）——A7 的 core-first 设计已为此铺路，无需返工。
2. **内部 API 而非命令层**：MCP graph 工具 handler 必须调 `core::graph_query::*` / `core::graph_store::*`（A7 已规划在 core），**不得**绕到 `bridge::db_query`（`MCP_TOOL_CALLS_COMMAND`）。
3. **路径/URL 守门**：graph.db 已用 `check_path_within_roots`；MCP graph 工具若 `touches_fs`/`returns_url`，必须把返回 `props`/`source_ref` 中的任一 URL/字符串叶先过 `redact_sensitive_url`（`MCP_FS_TOOL_PATH_POLICY` / `MCP_URL_NOT_REDACTED`）——即**读期脱敏**镜像 AGRAPH_9 写期扫描。
4. **命令命名**：除非 A0 决定真建 MCP 桥接命令，否则保持 `graph_*`（不触发 `MCP_PARITY`）；若确建 `mcp_*`，须满足 handler + ACL + `bridge.ts` 三处同现。
5. **容量硬上限**：见 G1。

## 4. 兼容性风险 / 开放项（精确文件清单 + 解锁条件）

### G1（前向兼容动作，属 A7 M5-7.a）— 必须钉死 `GRAPH_MAX_NODES`/`GRAPH_MAX_EDGES`
- **事实**：A7 W4 delta §3.4 把 `GRAPH_MAX_NODES` 列为「（未来）参照 `AGENT_KV_MAX_ENTRIES=5000` 量级」，**尚未定义为常量**；当前只有查询侧上限（`GRAPH_QUERY_LIMIT=1000`、`GRAPH_MAX_DEPTH=4`、`GRAPH_PROPS_MAX_BYTES`）。
- **风险**：W5 Hard Stop「all stores/maps/lists bounded」+ M5-2「bounded records」要求**存储本身**有硬上限，而非仅查询响应。图谱无节点/边总量上限 → 未来被 MCP 暴露或自动抽取时可能图爆炸、且不满足「bounded」红线。
- **建议（给 A7/A17）**：在 M5-7.a 实施期把 `GRAPH_MAX_NODES`/`GRAPH_MAX_EDGES` 定为 `domain.rs` 常量（建议 = `AGENT_KV_MAX_ENTRIES` 同量级 5000，或在 M5-2 集中常量同款不变量下另取合理值），并在 `graph_node_upsert`/`graph_edge_upsert` 写期**拒绝/淘汰**超量（与 A4 `AGENT_KV_MAX_ENTRIES` 同范式）。
- **解锁对象**：M5-8 存储层容量封顶；为未来可能 MCP 暴露消除「unbounded store」隐患。

### R1（同 W4，仍属 A3 M5-2.b）— capability 单源须进 `core/`
- 见 W4 note §4 R1。`MCP_CAPABILITY_V1` 现居 bin-only `domain.rs:1540`；A7 `core/graph_*` 模块未来若消费能力单源须走 `core/capability.rs`（R-B3）。A3 须在 M5-2.b 提升之；此阻塞属 A3 自身，非 A7 可解，但 A7 的 core-first 设计已对齐。

### R2（一致性提醒）— AGRAPH_9 与 MCP 读期脱敏须成对
- AGRAPH_9（写期凭据叶扫描）与未来 MCP `redact_sensitive_url`（读期）是同一隐私单向过滤的「写拒 + 读脱敏」两道闸（同 A4 C-5 值扫描 + M5-2 `redact_sensitive_url` 关系）。MCP graph 工具实现时**必须**对 `props`/`source_ref` 调用 `redact_sensitive_url`，否则 `MCP_URL_NOT_REDACTED` 判红。属实现期注意项，非当前阻塞。

### R3（范围澄清）— A6 M5-6 不在 MCP 注册表评审范围
- A6 W5 = Agent/Skill UI 纯逻辑/panel shell（前端 `src/components/**`/`src/stores/**`），不新增后端命令、不碰 MCP 注册表/ACL → 无 `MCP_PARITY`/`MCP_CAPABILITY_DRIFT` 影响。本波 A3 仅评 A7，A6 由 A5 W5 评 `AgentDef`/`SkillDef` 契约（board §M5-W5 A5）。
