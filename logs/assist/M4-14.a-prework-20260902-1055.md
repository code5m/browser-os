## 4. 接口 / 数据契约

### 4.1 领域模型

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum DbKind { Sqlite, MySql, Postgres }

/// 连接配置。**不含密码**——密码只存 keyring（凭据隔离红线）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct DbConnConfig {
    pub id: String,            // uuid v4
    pub name: String,          // 用户可见的连接名
    pub kind: DbKind,
    pub host: Option<String>,  // Sqlite 为 None
    pub port: Option<u16>,
    pub database: String,      // Sqlite 为文件路径
    pub username: Option<String>,
    /// 生产库标记：连上后若判定为生产，UI 全程红框 + 写操作默认拒绝
    pub is_production: bool,
    /// 该连接是否允许写操作（fail-closed：默认 false）
    pub allow_write: bool,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct QueryResult {
    pub columns: Vec<String>,
    pub rows: Vec<Vec<serde_json::Value>>,
    pub row_count: usize,
    /// 结果是否被截断（防止大结果集撑爆前端）
    pub truncated: bool,
    pub elapsed_ms: u64,
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum SqlRisk { Select, Explain, Ddl, Dml, Dangerous }
```

### 4.2 SQL 风险分类（fail-closed）

| 类别 | 判定（去注释、去字符串后取首关键字） | 默认行为 |
|---|---|---|
| `Select` | `SELECT` / `WITH` / `SHOW` / `DESCRIBE` / `PRAGMA`(读) | 直接执行 |
| `Explain` | `EXPLAIN` | 直接执行 |
| `Ddl` | `CREATE` / `ALTER` / `DROP` / `TRUNCATE` / `RENAME` | **拒绝**，需两段式确认 + `allow_write=true` |
| `Dml` | `INSERT` / `UPDATE` / `DELETE` / `MERGE` / `REPLACE` | **拒绝**，需两段式确认 + `allow_write=true` |
| `Dangerous` | 含 `DROP DATABASE` / `DROP TABLE` / `TRUNCATE` / `WHERE` 缺失的 `UPDATE/DELETE` / `;` 多语句 | **永久拒绝**，不提供确认通道（不允许"确认一下就能删库"） |

**硬规则**：
1. **拒绝多语句**（分号后出现第二个非空语句 → 直接拒绝）。这是防 SQL 注入追加语句的核心手段。
2. 结果集上限：默认 **1000 行**（超出 `truncated=true`），可配置但不建议开放到无上限。
3. 执行超时：默认 **30 秒**。
4. 生产库（`is_production=true`）：**只允许 `Select` / `Explain`**，写类一律拒绝，且不接受 `allow_write=true` 覆盖。

### 4.3 连接与查询命令契约（草案）

```rust
db_connect(cfg: DbConnConfig, password: Option<String>) -> Result<DbConnInfo, String>
//  - 密码立即写入 keyring，不进内存结构体、不进日志、不进审计
//  - 连接前做 is_production_database() 判定并回写 cfg.is_production
//  - 审计：action="db_connect"，detail 只含 id/name/kind/host/database（**无凭据**）

db_query(pool_id: String, sql: String) -> Result<QueryResult, String>
//  - 先 SqlRisk 分类 → 按 §4.2 处理
//  - 审计：action="db_query"，detail 含 pool_id + risk + row_count + sql 前 200 字符

db_disconnect(pool_id: String) -> Result<(), String>
//  - 关闭池并从注册表移除；审计

db_list_conns() -> Vec<DbConnConfig>       // 不含凭据
db_remove_conn(id: String) -> Result<(), String>   // 同步删 keyring 条目
```

> **写操作走两段式**（对齐既有 `request_sync`/`confirm_sync` 范式）：
> `db_request_write(pool_id, sql) -> WritePreview` → 前端展示影响预览 → `db_confirm_write(token) -> QueryResult`。

### 4.4 生产库判定（`db_safety.rs`，纯函数、必须单测覆盖）

判定信号（命中任一即 `is_production = true`）：
- 库名/实例名命中 `prod|prd|production|online|正式|生产`（大小写不敏感）
- 主机名命中上述关键字
- 用户显式勾选「这是生产库」
- 环境变量/配置文件标注（SQLite 场景：文件位于用户显式标记的生产目录）

**纯函数签名**：`pub fn is_production_database(cfg: &DbConnConfig) -> bool`，不依赖 IO，便于单测。

## 6. 风险

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **连到生产库误执行写/删操作** | **极高** | 生产库只读硬锁（§4.2 规则 4）+ `Dangerous` 永久拒绝 + 两段式确认 + 审计 |
| R2 | SQL 注入/多语句追加（`; DROP TABLE x`） | **高** | 拒绝多语句（§4.2 硬规则 1）+ 风险分类 + 只读优先 |
| R3 | 密码进日志/审计/前端内存 | **高** | 凭据只走 keyring；`DbConnConfig` **结构体内无密码字段**；审计不含凭据 |
| R4 | 连接池未关闭 → 退出时句柄/线程残留 | **高** | 依赖 M3-1.a ShutdownCoordinator（T8 为阻塞依赖） |
| R5 | 大结果集撑爆前端内存 | 中 | 1000 行上限 + `truncated` 标记 + 前端虚拟滚动 |
| R6 | sqlx 需要 tokio，与"无异步运行时"现状冲突 | 中 | T1 可行性探针先行；优先 `tauri::async_runtime` |
| R7 | sqlx 宏（编译期 SQL 校验）需要 `DATABASE_URL`，本项目是**运行时**连库 | 中 | 用 sqlx 的**动态查询**接口（`sqlx::query` / `fetch_all`），**不用 `query!` 宏** |
| R8 | 引入 sqlx 显著增加编译时间与二进制体积 | 中 | 只启用需要的 driver feature；记录构建耗时与体积变化，对比 `logs/baseline-2026-08-27.md` |
| R9 | `is_production_database` 漏判（库名不含 prod 字样） | 中 | 多信号 + 用户显式确认；**漏判兜底 = 写操作仍需两段式确认** |
| R10 | 与需求 #6 原文「结果导出到成果库」的范围蔓延 | 低 | 首期只做"查看"，导出列为后续 |

## 7. 反向用例

| # | 场景 | 期望 |
|---|---|---|
| N1 | `SELECT * FROM t`（1 万行） | 返回 1000 行，`truncated=true`，不卡死 |
| N2 | `SELECT * FROM a; DROP TABLE b` | **拒绝**（多语句），错误码 `MULTI_STATEMENT` |
| N3 | `DROP TABLE users`（非生产 + allow_write=false） | 拒绝 `WRITE_NOT_ALLOWED` |
| N4 | `DROP TABLE users`（非生产 + allow_write=true） | 走两段式确认；未 confirm 前**不执行** |
| N5 | `DROP TABLE users`（库名含 `prod`） | **永久拒绝**，即使 allow_write=true |
| N6 | `UPDATE users SET x=1`（无 WHERE） | `Dangerous`，**永久拒绝** |
| N7 | `DELETE FROM logs WHERE 1=1`（生产库） | 永久拒绝 |
| N8 | 连接密码错误 | 返回明确错误；**密码不出现在错误消息、日志、审计中** |
| N9 | `db_disconnect` 后再 `db_query` | 返回 `POOL_NOT_FOUND`，不 panic |
| N10 | 查询超时（30s） | 返回 `QUERY_TIMEOUT`，连接仍可用 |
| N11 | 应用退出时仍有活跃连接 | 全部关闭，无残留线程/句柄（依赖 T8） |
| N12 | 连接配置落盘后读回 | 密码**不在** `db-conns.json` 中（grep 校验） |
| N13 | SQL 含注释与字符串干扰（`/* SELECT */ DROP TABLE x`） | 分类仍判为 `Dml`（去注释后取首关键字） |
| N14 | SQLite 文件路径不存在 | 明确报错，不自动创建空库（避免误以为连上） |
| N15 | 前端展示生产库连接 | 全程红框 + 显式「生产库」标签 |

|---|---|

| 密码出现在日志/审计/落盘 JSON | 立即修 + 清理已泄露的 `audit.json`/`db-conns.json` 条目 + 强制用户改密 |
| T1 探针失败（async_runtime 驱动不了 sqlx） | 改为显式引入 `tokio`（记入依赖与体积成本），或换 `rusqlite`+同步驱动（但会失去 MySQL/PG 支持，需重估范围） |
| 退出后连接残留（N11 失败） | 阻塞：先完成 M3-1.a 的 ShutdownCoordinator（P2-2）再回来 |
| 构建耗时/体积增长不可接受 | 裁剪 driver features；或把数据库能力做成**可选编译特性**（`--features db`） |
| `db_*` 命令被 ACL 静默拒绝 | 检查 `default-commands.toml` 是否同步（历史坑，见 `后续需求TODO.md` 通用注意事项） |
