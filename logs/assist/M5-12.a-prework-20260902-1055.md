## 4. 契约

### 4.1 SkillDef

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, PartialOrd)]
#[serde(rename_all = "snake_case")]
pub enum AclLevel {
    /// 只读：只能调 Read 级能力（artifact.list / read_file / 等）
    Read,
    /// 写：可落盘（需确认闸门）
    Write,
    /// 执行：可跑脚本/命令（需确认闸门 + 完整审计）
    Execute,
    /// 出网：可发起网络请求（需确认闸门 + 完整审计，默认不授予）
    Network,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SkillTrigger {
    /// 仅用户手动调用
    Manual,
    /// 关键词/意图匹配（由 Agent 判断，非自动执行）
    Intent { hints: Vec<String> },
    /// 挂到定时任务（引用 M4-58.a 的 task_id）
    Scheduled { task_id: String },
}

/// Skill = 元数据 + 执行体引用。**执行体不得自带任意 shell 字符串**
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SkillDef {
    pub id: String,                  // slug（内置）或 uuid（用户）
    pub name: String,
    pub description: String,
    pub version: String,
    pub author: Option<String>,
    /// 声明所需权限等级（安装时展示给用户）
    pub acl_level: AclLevel,
    /// 触发方式
    pub trigger: SkillTrigger,
    /// 执行体：**只能引用既有 ScriptMeta**（M2-3.a），不允许内联 shell 命令
    pub exec: SkillExec,
    /// 参数定义（复用 M2-3.a 的 ScriptParam，保证同一套危险参数校验）
    pub params: Vec<ScriptParam>,
    pub source: SkillSource,
    pub enabled: bool,
    pub created_at: DateTime<Utc>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SkillExec {
    /// 引用脚本库中的脚本（推荐）
    ScriptRef { script_id: String },
    /// 引用命令片段库（#4）
    CommandRef { command_id: String },
    /// 复合：按顺序执行多个已声明引用（不做条件/循环，防图灵完备化）
    Sequence { steps: Vec<SkillExec> },
    /// ❌ 明确不支持：内联任意 shell 字符串
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum SkillSource { Builtin, User, Remote }
```

**硬规则**：
1. **禁止内联 shell 字符串**（无 `Command { line: String }` 变体）。所有执行必须经过 `ScriptMeta` → M2-3.a 的危险参数校验。这是 Skill 安全的核心。
2. `Sequence` 不允许条件/循环/变量传递（避免把 Skill 变成脚本语言的图灵完备替身）。
3. 安装时必须**展示 `acl_level` 并让用户确认**（对标插件与 Skill 红线）。
4. `Remote` 来源首期**不实现**（远程拉取 = 供应链攻击面）。

### 4.2 AgentDef 与能力边界

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct AgentDef {
    pub id: String,
    pub name: String,
    /// 方言：本地 LLM API / 外部 CLI Agent
    pub dialect: AgentDialect,
    /// 该 Agent 可调用的能力清单（**必须是既有命令子集**）
    pub capabilities: Vec<String>,
    /// 允许的最高权限等级
    pub max_acl_level: AclLevel,
    /// 是否允许在无人确认下执行（**默认 false**）
    pub auto_execute: bool,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum AgentDialect {
    /// 直连 OpenAI 兼容 HTTP API（凭据走 keyring）
    OpenAiCompatible { base_url: String, model: String },
    /// 外部 CLI Agent 子进程（如 codex/claude CLI）
    ExternalCli { program: String },
}
```

**能力边界（与 M5-7.a 共用一套白名单）**：
- Agent 可调用的能力 ∩ `McpGlobalPolicy.allowed_capabilities`（M5-7.a §4.1）。
- **同一份白名单两处复用**，不允许 Agent 侧另开一份更宽的清单。
- `auto_execute = false` 时，任何 `risk > Read` 的动作都走两段式确认闸门。

### 4.3 流式对话回传

现状无 `Channel<T>`，但已有 `app.emit` 的事件回传范式（终端 `term-data`）。

**契约（草案，二选一需定）**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 复用 `app.emit`** | 后端 `std::thread::spawn` 里按 token 粒度 `emit("agent-token", {run_id, delta})` | 零新机制，与现有终端/同步一致 | 无背压；高频 token 会事件风暴 |
| **B. 引入 `tauri::ipc::Channel`** | `agent_chat(msg, channel: Channel<Token>)` | Tauri v2 官方流式机制，有背压语义 | 新机制，团队无使用经验 |

**建议方案 A 先行**（与既有范式一致、风险低），但**必须做节流**：token 累积 ≥ 1 条或间隔 ≥ 50ms 才 emit 一次（同 M3-4.b 的 resize 静默思路）。
若实测高吞吐下 UI 卡顿，再升级到方案 B（与 M3-1 的 mpsc+pump 一起做）。

```rust
#[derive(Debug, Clone, Serialize)]
pub struct AgentToken { pub run_id: String, pub delta: String, pub done: bool }
```

### 4.4 记忆层（`agent_kv.rs`）定位

| 项 | 契约 |
|---|---|
| 用途 | **仅 AI 上下文/记忆**，不是用户成果库 |
| 存储 | `app_data_dir()/mvp-browser-os/agent-kv.json`（`HashMap<String, serde_json::Value>`） |
| 与成果库隔离 | **严格分离**：`workspace/` 是用户成果，`agent-kv.json` 是 AI 记忆，两者不互写 |
| 上限 | 建议 5 MB / 5000 条（超出按 LRU 或时间淘汰） |
| 敏感信息 | **禁止**存 token/密码（凭据只走 keyring）；写入前做键名黑名单检查（复用 M2-3.a §4.4 的脱敏关键字表） |

### 4.5 四者边界（Skill / 脚本 / HTML 工具 / 插件）

这是最容易混淆的地方，明确分层：

| 概念 | 本质 | 执行体 | 用户可写 | 生态位 |
|---|---|---|---|---|
| **脚本**（#1 / M2-3.a） | 多行 shell 文件 | 实际进程 | ✅ | 最底层执行单元 |
| **命令片段**（#4 / M2-4） | 单条命令 | 实际进程 | ✅ | 轻量执行单元 |
| **HTML 工具**（#2 / M2-7.b） | 单文件前端页面 | 浏览器渲染，**无后端执行** | ✅ | 纯计算/转换类小工具 |
| **Skill**（#12 / 本文） | **元数据 + 对脚本/命令的引用** | 间接（经 ScriptMeta） | ✅ | 语义化封装，供 Agent/定时触发 |
| **插件**（#15 / M5-15.a） | 统一编排外壳（可包装以上任一） | 依 kind | ✅ | 生命周期管理与分发 |

**判据**：如果一件事"脚本能做"，就不要新造 Skill；Skill 的价值在于**语义描述 + 参数封装 + 触发方式**，不在于新的执行能力。

## 5. 风险

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **Skill 自带任意 shell 字符串** → 绕过 M2-3.a 的危险参数校验 | **极高** | §4.1 硬规则 1：禁止内联命令，只能 `ScriptRef`/`CommandRef` |
| R2 | **提示词注入**：Agent 处理的网页/文档内容诱导其调用危险能力 | **极高** | `auto_execute=false` 默认；能力白名单不含执行类（M5-7.a §4.1）；`risk > Read` 必走确认闸门 |
| R3 | Agent 自动执行导致无人值守的破坏性操作 | **高** | 默认关闭自动执行；开启需显式配置 + 每次审计 |
| R4 | LLM API Key 泄露到日志/审计/前端 | **高** | 凭据只走 keyring；`AgentDef` 结构不含密钥字段；审计脱敏 |
| R5 | 依赖 M2-3.a 的 `run_script`（尚未实现） | **高** | 实现顺序：M2-3.a → M4-58.a → M5-12 |
| R6 | 流式 token 高频 emit 造成事件风暴/UI 卡顿 | 中 | §4.3 节流（≥50ms 或累积批量）；必要时升级 Channel |
| R7 | `agent_kv` 与成果库混淆 | 中 | §4.4 严格分离：不同文件、不同目录语义 |
| R8 | 远程 Skill 供应链攻击 | 中 | `Remote` 来源首期不实现 |
| R9 | Agent/Skill 执行未纳入退出收口 | 中 | 依赖 M3-1.a ShutdownCoordinator |
| R10 | 四个概念（脚本/工具/Skill/插件）互相重叠导致重复建设 | 中 | §4.5 分层表 |
| R11 | 对话历史/记忆无限增长 | 低 | §4.4 上限 |
| R12 | Agent 调用 LLM 产生费用且无上限 | 中 | 需配额/用量统计（列为待定，§10.4） |
