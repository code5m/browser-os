## 3. 状态模型（state model）

### 3.1 类型镜像（`src/types.ts`，camelCase，与 `domain.rs` 一一对应）

> 位置参照：`ScriptMeta:390-405`、`CommandSnippet:410-425`、`RunStatus:427`、`RunSnapshot:429-440`、`ScriptRunRecord:442-452`（`types.ts` 内有「与后端 `domain.rs` 一一对应」注释范式）。

```ts
// —— Skill（结构来自 agent-skill-contract-taskcard §4.1/4.2；此处仅 UI 镜像草案）——
export type SkillSource = "builtin" | "local" | "registry";
export type SkillParamType = "string" | "number" | "bool" | "path" | "enum" | "password";
export type SkillImplKind = "script" | "builtin"; // 禁止 inline（契约 §4.1 红线）
export type SkillOutputKind = "text" | "json" | "markdown" | "file";

export interface SkillParam {
  name: string; label: string; type: SkillParamType;
  required: boolean; default?: string; options?: { value: string; label: string }[];
  pattern?: string; dangerous: boolean; dangerReason?: string;
}
export interface SkillMeta {
  id: string; name: string; description: string; version: string;
  author?: string; source: SkillSource;
  inputs: SkillParam[]; outputs: { type: SkillOutputKind; schema?: unknown };
  capabilities: string[];
  implementation: { kind: SkillImplKind; scriptId?: string; handler?: string };
  timeoutSec: number; dangerous: boolean; tags: string[];
}
export interface SkillInstall {
  meta: SkillMeta; enabled: boolean; installedAt: string; updatedAt: string;
  grantedCapabilities: string[]; checksum: string; origin?: string;
  // 运行期仅在内存持有，不得落盘（K3）
  grantedScopes?: Record<string, string[]>;
}
export interface SkillRunRecord {
  runId: string; skillId: string; version: string;
  status: RunStatus; startedAt: string; finishedAt?: string;
  exitCode?: number; durationMs?: number; truncated: boolean;
  error?: { code: string; message: string; retriable: boolean; details?: string };
  // 参数值脱敏后镜像（password → "***"），输出正文不进前端持久状态
}

// —— Agent（外部进程，走 A2P-A2A；结构待 A2P-A2A-protocol-taskcard 冻结）——
export interface AgentDef {
  id: string; name: string; description: string; version: string;
  endpointKind: "stdio" | "websocket" | "http"; // 由 M5-1/3 裁定
  capabilities: string[]; enabled: boolean;
}
export interface AgentSession {
  sessionId: string; agentId: string; status: "active" | "idle" | "ended";
  createdAt: string;
}

// —— 复用 M4 RunStatus（domain.rs:667），并扩展 Skill/Agent 语义 ——
export type RunStatus = "running" | "succeeded" | "failed" | "cancelled" | "timeout"
  | "missed" | "retry" | "queued"; // missed/retry/queued 供 Agent 周期触发回显
```

### 3.3 状态机（Skill 调用）

```
idle ──skill_invoke──▶ running ──skill-output(chunk)──▶ running（累积 console）
   │                        │
   │                        ├── skill-finished{succeeded} ─▶ succeeded
   │                        ├── skill-finished{failed}    ─▶ failed（error 结构化）
   │                        ├── skill-finished{timeout}   ─▶ timeout（保留输出）
```

## 4. 流式显示（streaming display）

### 4.1 机制（复用 M3.c / useSystemStore 的 Channel 范式，禁止自造轮询）

- 后端经 Tauri `Channel` 推送 `skill-output` / `agent-output` 事件；前端 `bridge.createSkillChannel(cb)` / `createAgentChannel(cb)` 单播（F4 同 terminal，避免全局事件广播）。
- 事件载荷沿用契约 §4.3：`{ kind: "data" | "flow" | "exit", runId, data?, dropped_chunks?, dropped_bytes?, ... }`，与 `onTermChannelMsg`（useSystemStore:275）**同构**——A6 强烈建议后端 `skill.rs`/Agent 运行时**直接复用** `TermMessage` 形状或派生同构枚举，避免前端写两套分发。
- 切片/合并/上限：8 KB/片、30 ms 合并、5000 行 / 4 MB 上限 + `truncated`（契约 §4.3）；超限由后端截断并置 `truncated=true`，前端只渲染、不累加无限缓冲。
- **早期输出缓存**：`skill_invoke` 异步返回 runId 前，后端已开始吐 `data`；前端须设 `skillBuffer: string[]`（同 `termBuffer`，useSystemStore:142），runId 就绪后一次性写入 console，避免空白（M3.c 同坑）。

### 4.2 渲染器按 `SkillOutput.kind` 切换（仅影响渲染，不影响校验）

| kind | 渲染 |
|---|---|
| `text` | 等宽预格式（类 `ScriptRunDialog.vue` 输出区） |
| `markdown` | 轻量 markdown 渲染（只读，禁止执行其中脚本/链接自动跳转） |
| `json` | 高亮 + 折叠（复用既有 JSON 高亮，若无可引入零依赖高亮，禁新增 npm 重依赖） |
| `file` | 下载/打开入口（经 `bridge` 取文件，不内联二进制） |

### 4.3 权限预览（permission preview，融合 §3.3 `blocked` 与契约 §4.4；对齐 A1 M5-6 §4.3 两段式闸门）

> A1 M5-6 卡 §4.3 定义的是**后端驱动的二段式闸门**，前端只是展示与转发，不是前端本地拍板：

- **二段式 `CONFIRM_REQUIRED` 流程**（A1 M5-6 §4.3，前端 MUST 遵循）：
  1. UI 调 `skill_install` / `skill_invoke` 等命令（均经 `bridge.ts`）→ 后端若判定需二次确认，返回 `CONFIRM_REQUIRED` + `request_id`，**不执行**；
  2. UI 自动打开 `PermissionPreviewModal`（A1 命名；本预研沿用），**必显且禁折叠**：Skill/Agent 名 + 版本 + ACL + `capabilities`（逐项）+ 目标操作 + 风险提示；危险操作附 keyring 二次认证按钮；
  3. 用户点确认 → UI 调 `confirm_<action>`（带 `request_id`）→ 后端二次校验后执行；取消 = 拒绝（无「延后」）。
- **前端本地预检（辅助，非闸门本身）**：提交前仍做 `capabilities ⊆ whitelist`、`grantedCapabilities` 覆盖、危险参数标红等**提示性**校验，减少无谓往返；但**最终裁决权在后端**（fail-closed），前端不得因本地通过就绕过 `CONFIRM_REQUIRED`。
- 预览内容来自 `SkillMeta.capabilities` + `SkillInstall.grantedCapabilities`，**不展示密码明文**；危险参数名可显、值不显（复用 `redact.ts`）。
- Agent 侧：`AgentToolUsePreview` 只读展示 Agent 将要调用的 Skill + 参数脱敏摘要，用户可中途 `agent_chat_cancel`（经后端取消通道，复用 `script_runner::cancel` 同口径，无第二进程路径）。
- **红线**：任何 UI 路径不得直接 `invoke`（必经 `bridge.ts`）；闸门弹窗不得被折叠/隐藏/默认确认（A1 M5-6 §5 FORBID）。本预研 §7.2 的 `AGENTSKILLUI_DANGEROUS_NO_CONFIRM` 码位守护的是「危险调用须走 `PermissionPreviewModal` + `confirm_<action>` 二段式」，与 A1 卡一致。

## 5. 失败恢复（failure recovery）

### 5.1 失败态映射（契约 §4.7 结构化错误）

| 场景 | 后端 status / error | 前端表现 | 可恢复动作 |
|---|---|---|---|
| manifest schema 非法 | 安装拒绝 + 逐字段 | 安装表单字段红框 + 错误文案 | 用户改 manifest 重装 |
| checksum 不符 | 拒绝安装 | 显「清单已损坏/被篡改」 | 重新获取 manifest |
| 声明未知能力 | 拒绝 | 列出未知能力名 | 改 manifest |
| 引用 `script_id` 不存在（安装时） | 拒绝 | 显「脚本缺失」 | 先装脚本 |
| 引用 `script_id` 被删（调用时） | 可读错误 + 自动禁用 | 显「依赖脚本已删，已禁用」+ `SkillList` 标灰 | 重新绑定/卸载 |
| 参数校验失败 | 调用前拒绝 + 逐参数 | 表单字段级错误 | 改参数重提 |
| 能力未授予 | `blocked` 页 + 审计 | 显「已阻止：capability xxx」 | 去 `CapabilityGrantDialog` 授权 |
| 执行超时 | `Timeout`，输出保留 | 显「超时（已保留输出）」+ `truncated` 提示 | 若 `retriable` 可重试 |
| 执行被取消 | `Cancelled`，**不重试** | 显「已取消」 | 仅可重新发起（非自动重试，R9） |
| 输出超限 | `truncated=true` | 顶部横幅「输出已截断」+ 下载全文入口 | 下载完整 |
| 进程崩溃 | `Failed`，`error.code` | 显结构化错误 `{code,message,details}` | 若 `retriable` 重试 |
| 取消 in-flight（卸载/退出口） | `SkillShutdown` 收口 | 会话结束清理 console | — |

### 5.2 统一原则（前端侧）

- 任何失败**只消费结构化 `error`**，不解析裸字符串；`error.retriable=false` 时**隐藏重试按钮**（防误操作放大，R-3 同 A6 调度契约 `dangerous` 口径）。
- `Cancelled` **永不自动重试**（契约 R9）；重试按钮仅在 `retriable=true` 且非 `cancelled` 时可见。
- 运行明细（含脱敏参数、退出码、耗时）从 `bridge.skillRuns(skillId?)` 取，落 `SkillRunHistory.vue` 形态；**输出正文不进前端持久状态**（K5 同口径：高频调用不撑爆前端内存，`RunChunk[]` 超 4 MB 即停止累积并显 `truncated`）。
- 退出收口：组件卸载时若 `activeRun.status==="running"`，**不**前端杀进程（无第二执行路径），仅解绑 Channel；真实取消走 `skill_cancel`/`agent_cancel` 命令（归 A5/A16，复用 `script_runner::cancel`）。
