### 2.1 三个必须提前知道的关键约束

1. **asset scope 不含应用数据目录**。`workspace/` 位于 `$XDG_DATA_HOME/<app>/mvp-browser-os/workspace/`，不在当前 4 条 scope 内。前端若用 `convertFileSrc` + `asset://` 加载成果图片，会被 Tauri 静默拒绝。**必须先扩 scope**（见 §3），否则 M2-2.b 的 UI 无论怎么写都显示不出来。
2. **现有 `workspace/` 是扁平目录，且 `load_artifacts` 会遍历目录下所有文件尝试 `from_str::<Artifact>()`**。若把图片直接放进 `workspace/` 根目录，会被当成成果 JSON 解析（失败即跳过，但每图一次 IO + 解析，且未来任何 `.json` 图片元数据都会被误读为成果）。**图片必须放子目录**。
3. **`collect.js` 已把图片内联为 dataURL**。`html` 字段体积已含图片 base64，再存一份独立图片文件会**双倍占用**。契约必须区分"内联"与"落盘"两种 `ImageRef` 来源。

## 4. 接口 / 数据契约

### 4.1 Rust 侧

```rust
// src-tauri/src/domain.rs
use chrono::{DateTime, Utc};
use serde::{Deserialize, Serialize};

/// 图片来源：区分"网页采集内联"与"落盘文件"，决定读取方式
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum ImageSource {
    /// 落盘文件（推荐路径）：读取时走 asset:// 或后端直读字节
    File,
    /// 采集时已内联为 dataURL，仅存在 Artifact.html 中，无独立文件
    InlineDataUrl,
}

/// 图片附件引用。Artifact 只存引用，不存字节。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ImageRef {
    pub id: String,               // uuid v4
    pub source: ImageSource,      // File | InlineDataUrl
    /// 仅 source=File 时有值：相对 workspace_dir() 的路径，形如
    /// "images/<artifact_id>/<image_id>.<ext>"。禁止绝对路径，禁止 ".."。
    pub rel_path: Option<String>,
    /// MIME，必须是白名单之一（见 §4.3）
    pub mime: String,
    /// 字节数（InlineDataUrl 时为解码后字节数）
    pub bytes: u64,
    pub width: Option<u32>,       // 解析失败时为 None，不阻塞保存
    pub height: Option<u32>,
    pub sha256: String,           // 去重用（内容寻址）
    pub source_url: Option<String>, // 溯源：原始图片 URL
    pub caption: Option<String>,
    pub created_at: DateTime<Utc>,
}
```

`Artifact` 增量改法（保持向后兼容，旧 JSON 无该字段也能读）：

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Artifact {
    // ... 现有字段不变 ...
    #[serde(default)]
    pub images: Vec<ImageRef>,
}
```

> `#[serde(default)]` 是**硬要求**：现有 `workspace/*.json` 均无 `images` 字段，缺它会让 `load_artifacts` 静默丢弃全部历史成果（`workspace.rs:53` 的 `if let Ok(a) = ...` 吞错，极难排查）。

### 4.3 MIME 白名单（**扩展名由 MIME 反查，不接受用户传入**）

| MIME | 允许 | 扩展名 | 备注 |
|---|---|---|---|
| `image/png` | ✅ | `.png` | 首选 |
| `image/jpeg` | ✅ | `.jpg` | |
| `image/webp` | ✅ | `.webp` | |
| `image/gif` | ✅ | `.gif` | 仅首帧用于缩略图 |
| `image/bmp` | ⚠️ 待定 | `.bmp` | 建议首期不开，价值低 |
| `image/svg+xml` | ❌ **拒绝** | — | 可携带 `<script>`，XSS 面；首期不进白名单 |
| `image/*` 其他 | ❌ 拒绝 | — | fail-closed |

**扩展名映射表必须为常量表**（`MIME_EXT: &[(&str, &str)]`），落盘时 `ext = lookup(mime)`，杜绝 `foo.png.html`。

### 4.4 大小 / 数量限制（建议值，需强模型最终拍板）

| 限制项 | 建议值 | 超限错误码 |
|---|---|---|
| 单张图片 | ≤ 10 MB | `IMAGE_TOO_LARGE` |
| 单 artifact 图片数 | ≤ 50 张 | `IMAGE_COUNT_EXCEEDED` |
| 单 artifact 图片总字节 | ≤ 50 MB | `IMAGE_BUDGET_EXCEEDED` |
| 允许内联为 dataURL 的上限 | ≤ 2 MB（超出必须落盘） | `INLINE_TOO_LARGE` |
| 最小尺寸 | > 0 字节 | `IMAGE_EMPTY` |
| 单图最长边 | ≤ 8000 px（防解码 OOM） | `IMAGE_DIMENSION_EXCEEDED` |

### 4.5 路径策略

```
workspace_dir(app)                       // app_data_dir()/mvp-browser-os/workspace
├── <artifact_id>.json                   // 现有：成果本体（不变）
└── images/                              // 新增：图片根目录
    └── <artifact_id>/                   // 与成果同生命周期
        └── <image_id>.<ext>             // ext 由 MIME 反查
```

规则：
1. `rel_path` 只允许 `[a-zA-Z0-9_/-]` 且不含 `..`、不以 `/` 开头、不含 `.` 单独路径段。
2. 落盘前 `canonicalize()` 后**校验前缀必须是 `images_dir()`**，否则拒绝（软链接/路径穿越双保险）。
3. `image_id` 用 uuid v4，不用原始文件名（避免中文/空格/重名）。
4. **去重**：同 `sha256` 命中已有 `ImageRef` 时复用，不重复写盘。
5. **删除联动**：`delete_artifact(id)` 必须 `remove_dir_all(images/<id>)`，失败不阻断删 JSON 但要记审计。

## 8. 失败动作

| 失败场景 | 动作 |
|---|---|
| `cargo check` 报 `serde` 缺字段 / 反序列化失败 | 回退：只保留 `ImageRef` 结构定义，暂不改 `Artifact`，先让契约单独过编译 |
| 扩 asset scope 后 `asset:///etc/passwd` 可读 | **立即回退** scope 改动，改用"后端读字节 → base64 经命令返回"的替代方案，不走 asset 协议 |
| 历史成果加载回归失败 | 优先修 `#[serde(default)]`，不得改历史 JSON |
| clippy warning 数 > 13 | 按基线硬门槛，先清零再合入；不许"新增 warning 已说明"蒙混 |
| 图片落盘路径逃逸用例 N3 未通过 | 阻断合并，路径策略重做（canonicalize + 前缀校验缺一不可） |
| 大图导致前端卡死 | 降级：缩略图后端生成 + 前端懒加载；不允许前端全量解码原图 |
