## 1. 风险盘点

| # | 风险 | 说明 | 严重度 |
|---|------|------|--------|
| R1 | 越权提交 | 前端任意调 `git_commit` 改写工作区/历史，绕过用户意图 | 高 |
| R2 | 破坏性操作无确认 | `reset --hard`/`checkout`/`branch -D` 直接执行，丢失未提交改动 | 高 |
| R3 | 凭据泄露 | commit 的 author/committer 或 error 把 token 写进日志/前端 | 中 |
| R4 | 远程覆盖 | `push --force` 改写远端历史，影响协作者 | 高 |
| R5 | 工作区污染 | 写命令在错误仓库目录执行（路径校验缺失） | 中 |
| R6 | 与推送闸门冲突 | 新增通用写命令若不经 `confirm_sync` 闸门，破坏既有双阶段模型 | 高 |

## 2. 确认闸门策略（草案）

所有 Git 写命令统一走**三级闸门**（复用 `request_sync`/`confirm_sync` 范式）：

1. **预检**：命令入参校验（repo_id 合法、`path` 在 `data_dir/repos/<id>` 内、操作类型白名单）。
2. **确认**：破坏性操作（`commit`/`branch_create`/`checkout`/`reset`/`push`）生成 `SyncJob`
   式预览，前端弹确认框，用户显式同意才执行；只读与 `push`（已有闸门）不变。
3. **审计**：执行前后各写 `AuditEntry{action:"git_write", detail:{op, repo_id, args_keys}}`；
   失败亦审计 `action:"git_write_failed"`。

---

## 3. 禁止越权提交策略（硬规则）

1. **白名单操作**：仅允许 `commit`/`branch_create`/`checkout(local)`/`push(non-force)`；
   禁止 `reset --hard`/`checkout .`/`push --force`/`branch -D` 等不可逆操作（或标为
   `dangerous`，需二次密码/超时确认）。
2. **路径锁定**：所有写命令的 `repo_id` 必须命中 `load_repos`，且工作目录经
   `canonicalize` 校验在 `data_dir/repos/<id>` 内（仿 M2-1-assist §5 路径策略）。
3. **凭据隔离**：author/committer 用 `RepoConfig.username`（不碰 token）；token 仅
   `push` 时经 `Cred::userpass_plaintext` 传入，**绝不**进日志/`AuditEntry.detail` 明文。
4. **fail-closed**：操作类型不在白名单 / 确认未通过 / 路径校验失败 → 直接 `Err`，
   不执行任何 git 写。
5. **与推送闸门一致**：通用写命令复用 `request_sync`/`confirm_sync` 的双阶段，不另建旁路。

---

## 4. 审计字段（复用 AuditEntry）

```json
{ "at": "2026-...", "action": "git_write",
  "detail": { "op": "commit", "repo_id": "r1", "args": ["-m","fix"], "force": false } }
```
- 不记 token/明文凭据；`detail` 仅操作语义。
- 与 M4 §6.1 `production_safety` 思路同源（fail-closed + 审计）。
