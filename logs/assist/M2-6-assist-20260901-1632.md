## 1. CommandSnippet 字段草案（domain.rs 新增）

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CommandSnippet {
    pub id: String,
    pub name: String,
    pub category: String,        // 分类（文件/网络/文本/系统）
    pub line: String,            // 命令模板，如 "grep -r '{{PATTERN}}' {{DIR}}"
    pub args: Vec<ScriptArg>,    // 复用 M2-3-assist 的 ScriptArg
    pub description: Option<String>,
    pub dangerous: bool,         // 标 dangerous 需二次确认
}
```

- 存储：`data_dir/snippets.json`（仿 `scripts.json` 模式）。
- `line` 用 `{{KEY}}` 占位（同 M2-3 的 `${ARG_}` 思路，统一占位风格待强模型裁定）。

---

## 2. 参数化与注入防护

- 同 M2-4-assist §2：`run_command` **绝不** `sh -c "line"` 拼接。
- `line` 模板先按白名单替换 `{{KEY}}` → 拆为 `argv`（按 shell 词法或固定分隔），
  经 `Command::new(interpreter).args(argv)` 执行。
- `dangerous=true` 的片段（含 `rm`/`sudo`/`dd` 等）强制二次确认 + 审计。

---

## 3. 确认弹窗（前端草案）

- 点「运行」→ `ArgForm`（复用 M2-5.a-assist §4）渲染 `args` → 收集 → 若 `dangerous`
  弹二次确认「该命令含危险操作，确认执行？」。
- 确认后调 `bridge.run_command(meta, resolvedArgs)`（M2-4 通道）。
- 执行态 UI 复用 `RunConsole`（M2-5.a-assist §5）。

---

## 4. 审计字段（复用 AuditEntry）

```json
{ "at": "...", "action": "cmd_run",
  "detail": { "snippet_id": "s1", "name": "grep-log", "dangerous": false, "args_keys": ["PATTERN"] } }
```
- `dangerous=true` 额外记 `action="cmd_run_dangerous"` + 确认时间戳。
- 失败 `action="cmd_run_failed"`。

---

## 5. 复用 M2-4 执行通道（依赖）

- `run_command(meta, args) -> Channel<LogLine>` = `run_script` 的轻量版（同回显、同取消/
  超时/回收/背压），仅 `interpreter` 固定为 `bash -c` 的**安全替代**（按 argv 而非拼接）。
- **不另建执行旁路**（§4.2 明确"不另建执行旁路"），所有命令库执行走 M2-4。
