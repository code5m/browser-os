## 2. ToolMeta 字段草案（domain.rs 或 tools.rs 新增）

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolMeta {
    pub id: String,
    pub name: String,
    pub file: String,          // 工具 HTML 文件名（如 "json-tool.html"）
    pub builtin: bool,         // true=内置（include_dir），false=用户目录
    pub desc: Option<String>,
}
```

`list_tools() -> Vec<ToolMeta>`：扫描内置（编译期嵌入）+ 用户 `workspace/tools/`。

## 3. 内置资源嵌入方案

`src-tauri/src/tools/` 在打包后不在进程运行目录，两种方案（§4.3 已列）：
- **方案 A（推荐）**：`build.rs` 用 `include_dir!("src/tools")` 宏编译期嵌入，
  运行时由 `tauri::api::assets` 或自定义 `Assets` 暴露给前端 `asset:` 协议。
- **方案 B**：`tauri.conf.json` 的 `bundle.resources` 声明 `src/tools/*` → 安装目录，
  运行期读盘（简单但需处理路径）。

> 本 assist 不选定方案（不改 build.rs/tauri.conf.json），交由强模型按 M2-8 隔离层裁定。

## 4. 用户工具目录扫描策略

- 路径：`workspace_dir(app).join("tools")`（`workspace.rs:21` 同款 `data_dir/workspace`）。
- 扫描：`glob("*.html")` → 每个文件生成一个 `ToolMeta{builtin:false}`。
- 安全：用户工具**权限低于主窗口**（M2 门禁第 4 条），禁止读取 `app_data_dir` 外的文件、
  禁止 `fetch` 外部 URL（M2-9 验收项会核）。
- 新增工具无需改前端硬编码：`list_tools` 动态枚举渲染卡片。

---

## 5. ACL 与验收建议

- `list_tools` 进 `permissions/default-commands.toml`（所有新命令统一要求，§4.3/§5 已注）。
- 内置工具：`builtin=true`，来源受信任。
- 用户工具：`builtin=false`，加载时校验无 `<script src=外部>` / 无 `fetch(http)`（M2-9 核）。
- 验收：release 包内 5 个内置工具均可离线打开（M2 门禁第 4 条）。
