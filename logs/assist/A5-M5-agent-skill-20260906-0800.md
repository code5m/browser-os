M5-4（运行时）+ M5-5（命令与权限）共同构成 #12 Agent 与 Skill 生态的「编排层」。本预研给出：

1. **runtime / command 拆分**：纯逻辑运行时（`agent_runtime.rs` / `skill_runtime.rs`，脱 Tauri、可单测）放 `mvp-core`（承接 A2 M5-1 切片）；命令面 + transport 适配（`bridge.rs` / `main.rs` / `permissions/default-commands.toml`）留二进制 crate。

4. **权限闸门**：复用 A3 M5-2 的全局护栏（`McpGlobalPolicy` / `read_only` / `allow_dangerous_sql` / `allowed_connection_ids`）+ `security_policy::classify_sql_risk` / `is_production_database`；危险安装/执行复用 `request_*` / `confirm_*` 双阶段确认范式（对齐 `request_git_write` / `confirm_git_write`）。
5. **安全红线（机器可守门）**：梳理 9 条 `AGSK_*` 断言，附 `scripts/check-agent-skill-policy.py` + `scripts/check-agent-skill-ui-logic.mjs` + `pre-merge.sh` 接入提案。

核心结论：**M5-4/5 不是新执行层，而是编排层**。任何「执行 / 出网 / 落盘」动作都下沉到既有 `#1~#11` 能力，Agent/Skill 只做调度与权限封装，绝不旁路（对标 dbx 红线「命令不加 ACL 不可借鉴」）。

## 3. 类型模型（AgentDef / SkillDef）

> 与 `logs/assist/agent-skill-contract-taskcard-20260902-1146.md` 对齐；以下为收敛后的**契约提案**（不落地代码）。

### 3.1 `SkillDef`（替代旧 `SkillMeta` 命名，字段语义一致）

```rust
#[derive(serde::Serialize, serde::Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase")]
pub struct SkillDef {
    pub id: String,                 // 反向域名风格，如 "com.example.git.batch-status"
    pub name: String,
    pub description: String,
    pub version: String,            // semver
    pub author: Option<String>,
    pub source: SkillSource,        // Builtin | Local | Registry
    pub inputs: Vec<SkillParam>,
    pub outputs: SkillOutput,
    pub capabilities: Vec<String>,  // 如 ["fs:read","shell:execute"]
    pub implementation: SkillImpl,  // 仅 Script | Builtin，绝无 Inline
    pub timeout_sec: u64,           // 默认 60
    pub acl_level: AclLevel,        // Low | Medium | High（决定默认二次确认）
    pub dangerous: bool,            // 高危标红 + 每次二次确认
    pub enabled: bool,              // 安装后默认 false
    pub tags: Vec<String>,
}

#[derive(serde::Serialize, serde::Deserialize, Clone, Copy, Debug, PartialEq, Eq)]
#[serde(rename_all = "snake_case")]
pub enum SkillSource { Builtin, Local, Registry }

#[derive(serde::Serialize, serde::Deserialize, Clone, Debug)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum SkillImpl {
    /// 仅引用已登记脚本（推荐）：复用 script_runner 全部安全校验
    Script { script_id: String },
    /// 宿主内建纯计算：不执行外部进程
    Builtin { handler: String },
    // ❌ 明确不提供 Inline { code } —— 禁止 Skill 自带可执行代码（AGSK_3）
}

#[derive(serde::Serialize, serde::Deserialize, Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
#[serde(rename_all = "snake_case")]
pub enum AclLevel { Low, Medium, High }
```

### 3.3 流式回传与注入 seam

- `agent_chat(msg) -> Channel<Token>`：复用 Tauri2 `Channel`（对齐 `term_spawn_channel` 的 `Channel` 入参范式；`term_spawn` 是 Event sink 仅供内部，`term_spawn_channel` 才是前端唯一入口）。Token 流**不得序列化任何凭据/完整 SQL/私密参数**（AGSK_4）。
- 进度/输出回报走 A2 定义的 `ProgressSink` trait（`script_runner` 已用 `tauri::Emitter`；core 内改 trait 注入），使运行时可脱离 Tauri 单测。
- 记忆层 `agent_kv`：KV 持久化，**仅作 AI 上下文，不混为用户成果库**；需容量/保留上限（AGSK_6）。

## 4. 执行复用 M2-4（无第二路径）

### 4.1 契约现状（已实测）

`src-tauri/src/script_runner.rs`：

- `start_run(table, meta, script_abs_path, values, roots, home_dir, app, records_file) -> Result<String, RunError>`（行 843）
- `start_command(table, snippet, values, roots, home_dir, app, records_file) -> Result<String, RunError>`（行 882）
- 二者均经 `start_argv_run`，复用同一进程表 / supervisor / 输出 reader / 取消 / 超时 / 运行记录落盘链路。
- M4 scheduler（F6）已证明正确范式：`scheduler.rs` 只做触发，执行唯一入口是 `script_runner::start_run` / `start_command`（行 651/681）。

### 4.2 复用规则（强制）

| 调用方 | 必须调用 | 禁止 |
|---|---|---|
| `skill_runtime::run_skill(SkillImpl::Script{script_id}, args)` | `script_runner::start_run`（取 `ScriptMeta` by id） | `std::process::Command`、`sh -c`、自拼 argv |
| `skill_runtime::run_skill(SkillImpl::Builtin{handler}, args)` | 宿主内 `match handler` 纯计算（无进程） | 任何外部进程 |
| `agent_runtime` 调用工具 | 经 Skill 或 `script_runner::start_command` | 直接 spawn shell |
| 数据库类工具 | `db_query`（M4 命令，已含 `classify_sql_risk` 门）+ `allowed_connection_ids` 白名单 | Skill 内嵌 SQL 字符串绕过 M5-2 护栏 |

> **AGSK_1（机器可查）**：`skill_runtime.rs` / `agent_runtime.rs` 中 `grep -nE 'std::process|Command::new|sh -c|"-c"'` 必须为 0；否则视为「第二执行路径」P0 缺陷。

### 4.3 取消 / 退出收口

- Skill/Agent 发起的 `start_run` 返回的 `run_id` 登记进 `ScriptProcessTable`；`shutdown.rs` 复用 `kill-running-scripts`（M2-4.d）已注册在 `shutdown-grid` 之后、取消位置 cancel 后 `killpg`。
- 额外在 `shutdown.rs` 注册 `stop-agent-skill`（在 `stop-scheduler` 之后、`kill-running-scripts` 之前或同批），仅做「标记 Agent/Skill 会话 cancelled + 关闭 `Channel`」，**不另起进程管理**。

## 5. 权限闸门（复用 M5-2 + 双阶段确认）

### 5.1 能力白名单（共用 A3 M5-2）

- 能力集合（`fs:read` / `fs:write` / `shell:execute` / `net:fetch` / `db:query` / `ui:notify` …）**由 A3 在 M5-2 落地统一的 `capability.rs`**；A5 **复用**，禁止在 skill/agent 模块再写一份（旧 taskcard §6 禁止事项 #8 同口径）。
- 判定链（fail-closed）：
  1. `SkillDef.capabilities ⊆ 已知白名单`？否 → 安装拒绝。
  2. 用户授予 `granted_capabilities ⊆ declared`？否 → 拒绝执行。
  3. 本次参数在 scope 内？否 → 拒绝。
  4. `dangerous` / 含 `exec|net` → 每次调用前二次确认。
- **默认不降级**：未授予即拒绝，不「给只读凑合」（旧 taskcard §4.4）。

### 5.2 全局护栏复用（M5-2 `McpGlobalPolicy`）

Agent 把本地能力以 MCP 工具暴露给外部 Agent 时，套同一份 `McpGlobalPolicy`：`read_only` / `allow_dangerous_sql` / `allowed_connection_ids`，与 M4 的 `classify_sql_risk` + `is_production_database` 串接。A5 不新建 SQL 分类器。

### 5.3 双阶段确认闸门（对齐 `request_git_write` / `confirm_git_write`）

危险操作（**`skill_install` 任意新代码 Skill**、**危险 `skill_run`**、**Agent 首次授予 `shell:execute`/`net:fetch`**）采用两阶段：

- `request_skill_install(meta_path) -> job_id`：仅做 manifest 校验（schema + checksum + capabilities ⊆ 白名单），返回预览摘要；**不落盘、不启用**。
- `confirm_skill_install(job_id, granted_capabilities, confirmed_dangerous) -> SkillInstall`：取待确认任务（`take_confirmable_*` 范式，一次性 + TTL，如 5 分钟），写 `skills.json`（原子写），默认 `enabled = false`。
- 纯函数 `take_confirmable_skill_job` 复用 `bridge.rs:2124` `take_confirmable_git_job` 的签名形态（job map / ttl / `confirmed_dangerous` / 一次性移除）。

> **AGSK_8**：危险安装/执行必须走 `request_*` / `confirm_*` 双阶段；未 confirm 前**连 invoke 都不发**（前端亦不得提前绑定）。
