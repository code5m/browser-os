### 4.1 `cron-tool.html` — Cron 生成 / 检测 / 未来执行时间推算

**功能契约**
- 输入：cron 表达式（5 段：`分 时 日 月 周`，**不支持** `@yearly` 等特殊串与 6 段秒级表达式）。
- 输出：① 表达式合法性判定；② 人话描述；③ 接下来 N 次（默认 5，可配 1/5/10）执行时间。
- 时间基准：**本地时区**（需显式标注"本地时区"字样，避免与 UTC 混淆）。

**输入输出等价类**

| 输入 | 期望输出 |
|---|---|
| `0 9 * * 1-5` | 合法；"工作日每天 09:00"；给出 5 个未来时刻 |
| `*/5 * * * *` | 合法；"每 5 分钟" |
| `0 0 1 1 *` | 合法；"每年 1 月 1 日 00:00" |
| `60 * * * *` | **非法**（分 > 59），红色提示指出第 1 段越界 |
| `* * * *` / `* * * * * *` | **非法**（段数 4 / 6），提示"应为 5 段" |
| `0 9 * * 8` | **非法**（周 > 7） |
| `` （空） | 提示"请输入表达式"，**不得抛异常** |
| `abc` | 非法，提示"无法解析" |
| `0 9 31 2 *` | 合法但**永不执行**（2 月 31 日）→ 必须给出"该表达式无匹配时间"提示 |

**失败态**
- 表达式非法：输入框下方红色文案 + 结果区清空（不残留上次结果）。
- 无匹配时间（如 `0 0 30 2 *`）：**明确提示**"无匹配执行时间"，不得显示空列表或死循环搜索。
- 推算次数上限：搜索未来时间最多迭代 **2 年**仍无结果即停止并提示（防死循环）。

**证据要求**
- [ ] 上表 9 条输入的**逐条输出截图**（或复制输出文本）。
- [ ] 断网状态下打开工具的截图（证明离线可用）。
- [ ] 文件内 `grep -c "http" cron-tool.html` = 0 的回显。
- [ ] 文件体积 `ls -l` 回显 ≤ 100 KB。

### 4.2 `regex-tool.html` — 正则工坊

**功能契约**
- 输入：正则 pattern + flags（`g/i/m/s`）+ 待匹配文本 + 目标语言格式。
- 输出：匹配列表（含分组）、高亮、多语言格式转换。
- 目标格式：`Java` / `Python` / `Rust` / `Node(JS)` / `IDEA` / `VSCode`。

**输入输出等价类**

| 输入 | 期望输出 |
|---|---|
| `\d+` + `g` + `a1b22c333` | 3 个匹配：1 / 22 / 333 |
| `(\w+)@(\w+)` + `abc@xy` | 1 个匹配 + 2 个分组：`abc` / `xy` |
| `(` （未闭合） | **非法**：提示"括号未闭合"，不得崩溃 |
| `[` | **非法**：提示"字符类未闭合" |
| `a**` | 依 JS 正则语义判定；非法则提示，合法则正常 |
| 空 pattern + 非空文本 | 提示"请输入正则表达式"，不执行 |
| 空文本 | 提示"请输入待匹配文本"，不报错 |
| 10 万字符文本 + `.*` | **需在 2 秒内出结果**（性能门槛）；超时需提示而非卡死 |
| `(?<name>x)` 命名分组 | 至少不报错；是否展示命名分组可标注为待定 |

**格式转换验收（关键）**

| 目标格式 | 期望 |
|---|---|
| Java | 输出 `"\\d+"` 形态（反斜杠已转义，双引号包裹） |
| Python | 输出 `r"\d+"` 原始串形态 |
| Rust | 输出 `r"\d+"` 或 `Regex::new(r"\d+")` 建议形态 |
| Node/JS | 输出 `/\d+/g`（含 flags 后缀） |
| IDEA | 输出可直接粘贴进 Find 框的形态（不额外转义） |
| VSCode | 输出可直接粘贴进查找框的形态（`\d+`） |

> 转换必须**逐条人工核对**：把输出粘回对应环境实测能匹配，才算通过。这是最容易"看起来对、实际错"的部分。

**失败态**
- 正则非法：显示错误信息 + 高亮清空。
- 灾难性回溯（如 `(a+)+$` + 长 a 串）：**必须有超时保护**（建议 2s），超时提示"匹配超时，请简化表达式"，不得让页面无响应。

**证据要求**
- [ ] 上表 8 条输入的逐条截图。
- [ ] **6 种目标格式的输出 + 在真实环境中粘贴实测的截图**（必须，不能只截图输出）。
- [ ] 灾难性回溯用例的超时提示截图。
- [ ] 离线校验（无 http 引用）与体积回显。

### 4.3 `json-tool.html` — JSON 格式化 / 压缩 / 校验 / 键排序

**功能契约**
- 输入：任意文本。
- 输出：格式化（**2 空格**缩进）/ 压缩 / 校验结果 / 按键排序后的 JSON。

**输入输出等价类**

| 输入 | 期望输出 |
|---|---|
| `{"b":1,"a":{"d":2,"c":3}}` | 格式化后 2 空格缩进、换行正确 |
| 同上 | 键排序后 `{"a":{"c":3,"d":2},"b":1}`（**递归排序**，不止顶层） |
| `{"a":1,}` | **非法**：提示错误（**若能给出位置最佳**） |
| `{a:1}` | **非法**（键未加引号） |
| `{'a':1}` | **非法**（单引号，JSON 不允许） |
| `[1,2,3]` | 合法（数组作为顶层） |
| `"str"` / `123` / `true` / `null` | 合法（标量作为顶层 JSON） |
| 空输入 | 提示"请输入 JSON"，不报错 |
| 1 MB JSON | 3 秒内出结果 |
| 含中文/emoji | **不得被转义为 `\uXXXX`**（用 `JSON.stringify` 默认行为即可，但需实测确认） |
| 大整数 `12345678901234567890` | 允许精度损失但**必须提示**"超出安全整数范围" |
| 重复键 `{"a":1,"a":2}` | 提示"存在重复键"（JS 静默覆盖，需显式告警） |

**失败态**
- 解析失败：红色错误文案 + 原文保留（不清空用户输入）。
- 超大输入（> 5 MB）：提示"输入过大"并拒绝处理（防卡死）。

**证据要求**
- [ ] 上表 11 条输入的逐条截图。
- [ ] 键排序递归生效的证据（嵌套对象也排序）。
- [ ] 中文/emoji 不被转义的证据。
- [ ] 1 MB 输入的处理耗时截图（≤ 3s）。
- [ ] 离线校验与体积回显。

### 4.4 `base64-tool.html` — Base64 文本编解码

**功能契约**
- 编码：文本 → Base64（**UTF-8 安全**）。
- 解码：Base64 → 文本（需处理非法字符）。
- 变体：标准 / URL-Safe（`+`→`-`，`/`→`_`）。

**输入输出等价类**

| 输入 | 期望输出 |
|---|---|
| `hello` | `aGVsbG8=` |
| `中文` | UTF-8 编码后结果（**必须正确**，不能用 `btoa` 直接处理导致 `InvalidCharacterError`） |
| emoji `🎉` | 正确编码（4 字节 UTF-8，易错点） |
| `aGVsbG8=` 解码 | `hello` |
| `aGVsbG8`（缺 padding） | **容错解码**为 `hello`，或提示"padding 不完整"（二选一，**必须一致**） |
| `!!!` 解码 | **非法**：提示"不是合法 Base64"，不得抛异常 |
| 空输入 | 提示"请输入内容" |
| 含换行的多行 Base64 | 应先去除空白再解码 |
| `a+b/c=` 选 URL-Safe | `a-b_c=` |
| 1 MB 文本编码 | 2 秒内完成 |

**失败态**
- 非法 Base64：红色提示 + 输出区清空。
- 编码非 UTF-8 安全导致的异常：必须被捕获并给出中文提示（**这是本工具最高频的 bug**）。

**证据要求**
- [ ] 上表 9 条输入的逐条截图（**中文与 emoji 必须有**）。
- [ ] URL-Safe 变体截图。
- [ ] 与命令行 `echo -n '中文' | base64` 结果**逐字符比对**的证据（交叉验证，必须）。
- [ ] 离线校验与体积回显。

### 4.5 `timestamp-tool.html` — 时间戳 ↔ 日期

**功能契约**
- 输入：时间戳（秒/毫秒）或日期字符串。
- 输出：双向转换，支持本地/UTC/ISO 8601；实时时钟显示。

**输入输出等价类**

| 输入 | 期望输出 |
|---|---|
| `1700000000`（秒） | 对应本地时间 + UTC 时间 + ISO 8601 |
| `1700000000000`（毫秒） | 同上，需**自动识别**为毫秒（或提供显式单位切换） |
| `0` | 1970-01-01（UTC） |
| 负数 `-1` | 1969-12-31 23:59:59（UTC），不得崩溃 |
| `99999999999999` | **非法/超范围**：提示"超出有效范围"，不得输出 `Invalid Date` 原样 |
| `abc` | 非法：提示"无法解析" |
| 空输入 | 提示"请输入时间戳或日期" |
| `2023-11-14 22:13:20` | 反向转时间戳（秒 + 毫秒都给） |
| `2023-11-14T22:13:20Z` | 正确解析为 UTC，转时间戳 |
| 当前时间（实时时钟） | 每秒刷新，且**关闭/切换后定时器必须清理** |

**失败态**
- 解析失败：红色提示，输出清空。
- 超范围：明确提示范围，不输出 `Invalid Date` 或 `NaN`。
- **实时时钟必须在页面不可见/组件卸载时停止**（`setInterval` 泄漏是本工具最容易留的坑）。

**证据要求**
- [ ] 上表 9 条输入的逐条截图。
- [ ] 与命令行 `date -d @1700000000` 结果**逐字符比对**的证据（必须）。
- [ ] 时区正确性证据：明确标注本地时区（如 Asia/Shanghai）并与 UTC 相差 8 小时。
- [ ] 实时时钟存在且**离开页面后定时器停止**的证据（如 DevTools 性能面板或代码审查）。
- [ ] 离线校验与体积回显。

| G3（大输入）卡死 | 加输入上限 + 处理中提示；未解决前不发布 |
| G4（重复点击）结果不一致 | 检查是否存在未清理的状态/定时器 |

| 任一条缺证据 | **视为未通过**，补齐证据后重验（不接受"我跑过了"口头结论） |

## 10. 遗留待定

1. cron 是否支持 6 段（秒级）与 `@reboot` 等特殊串（当前建议**不支持**）。
2. 正则是否支持命名分组展示与替换功能（当前建议：展示匹配即可，替换不做）。
3. JSON 键排序是否为默认行为还是独立按钮（当前建议：独立按钮，不默认改用户数据）。
4. Base64 缺 padding 是容错还是报错（当前建议：**容错解码 + 轻提示**）。
5. 时间戳实时时钟是否默认开启（当前建议：默认开启但可关）。
6. 5 个工具是否共用一份内联样式基线（减少重复体积）——建议提供 `tool-base.css` 片段由各工具内联复制。
