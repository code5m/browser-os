## 3. 发现（Findings）

### F1（High）类型命名冲突面 —— 必须零碰撞
- A3 将新增 MCP 注册表/策略类型（预期 `McpRegistryEntry`/`McpCapabilityVerdict` 等），A5 将扩展 Agent/Skill 校验/预览类型（预期 `AgentPermissionPreview`/`SkillValidationResult` 等）。
- `src/types.ts` 已是高冲突文件（board §File Conflict Map）。图谱已占 `GraphNode/GraphEdge/GraphNodeKind/GraphEdgeKind`。
- **建议**：A3/A5 新类型一律带命名前缀（`Mcp*`/`Agent*`/`Skill*`），且与图谱类型无交集；`SkillDef`/`AgentDef` 已存在、不得重定义。A0 集成前跑 `git diff --check` + 全量 `tsc`/`vite build` 确认无重复声明。

### F2（High）bridge.ts 并发编辑 —— 串行集成
- `src/bridge.ts` 同时被 A3、A5 写入，且已含 A8 W6 的 `graphQuery` + `GRAPH_COMMANDS_AVAILABLE`。命令名彼此不同（`mcp_*`/`skill_*`/`agent_*`/`graph_query`），**无功能冲突**，但属 board 高冲突文件。
- **建议**：A0 集成顺序 = A3 → A5（或反之），最后确认 A8 图谱 `graphQuery` 占位仍在、可用；集成后重跑 `npm run build` + `node scripts/check-graph-ui-logic.mjs`（本次基线：build PASS、逻辑 34/34 PASS，见 §5）。

### F3（High）agent/skill 节点 ↔ AgentDef/AgentDef.id 对齐（AGRAPH-10）
- 图谱 `GraphNode.kind ∈ {"agent","skill"}` 的节点，其 `id` **必须**等于 `AgentDef.id`/`SkillDef.id`（A7 W5 W5 契约：64-hex sha256 派生，AGRAPH-10「图谱不重定义 Agent/Skill、按 id 引用」）。
- **建议**：A5 的只读 `agent_parse`/`skill_validate` 与 A7 未来 `graph_query` 必须共用同一 id 方案；图谱 NodeDetail 不另起 id 体系，避免引用完整性断裂（呼应 A4 W6 红线 R8-5「引用完整性只显 id+label」）。

### F4（High）systemPrompt 脱敏 —— K7/prompt-secret 红线
- `AgentDef.systemPrompt` 是 prompt-secret。A5 的只读 `agent_permission_preview`/`agent_parse` 返回的 DTO **不得携带 `systemPrompt` 明文**（或必须红移）；图谱 NodeDetail 对 agent 节点**绝不可渲染 `systemPrompt`**。
- **建议**：A5 在 W7 命令 DTO 设计即剔除 `systemPrompt`（改由后端权限预览只给 `PermissionPreview`）；图谱未来 agent 子视图仅消费 `PermissionPreview`，不触碰 `AgentDef.systemPrompt`。

### F5（Med）metadata 透明字段 = 图谱 props 同款脱敏
- `SkillDef.metadata`/`AgentDef.metadata: unknown` 与图谱 `GraphNode.props` 同属「后端可能填敏感值、前端不得渲染」。
- **建议**：A5 返回的 Agent/Skill 预览 DTO 中 `metadata` 保持最小/红移；图谱不消费 `metadata`（与 `props` 一致，UI 仅显 id/kind/label/消费标记）。

### F6（Med）PermissionPreview 复用，杜绝二次执行路径
- `PermissionPreview { gate; capabilities }` 已存在（L711）。图谱 agent/skill 子视图（官方 M5-9 卡 (b) 消费子视图）应**复用 A5 只读命令产出的 `PermissionPreview`** 展示闸门与能力，而非自行解析 skill/agent 文件——否则违反 M5 护栏「no second execution path」。
- **建议**：graph 壳 `NodeDetail.vue` 在 graph 转 live 时，对 agent/skill 节点改为调用 A5 的 `agent_permission_preview(id)`（占位待 W7 落地），用返回的 `PermissionPreview` 渲染「消费关系/闸门」。当前 W6 壳已用 `summarizeNode.isAgentConsumption` 标记，但无 PermissionPreview 明细——属已知 live 解锁项。

### F7（Med）MCP 注册表当前与图谱无节点对应
- A3 的 MCP 注册表是 registry 级（MCP server/能力），图谱 `GraphNodeKind` 无 `mcp` 种类。当前**零直接 UI 影响**。
- **建议**：若后续 wave 图谱纳入 MCP 能力节点，必须复用 A3 的 `McpRegistryEntry` 红移 DTO，且需 A7 扩展 graph 命令（非 W7 范畴）。本波不阻塞。

### F8（Low）构建体积（IF-2）—— 保持懒加载
- A5 可能把 Agent/Skill 面板从「无命令壳」接成「只读命令 live」，若引入 eager import 会撑大主 chunk。图谱 `GraphPanel` 已是 `defineAsyncComponent` 懒加载（9.12 kB 独立 chunk，主 chunk 164.15 kB 未变，见 §5）。
- **建议**：A5 接 live 时沿用现有 `defineAsyncComponent` 懒加载模式，避免主 chunk 超 IF-2 阈值；若必须 eager，需在 checkpoint 记录理由。

## 4. 对 A3/A5 的明确约束清单（供 A0 套用）

1. A3/A5 在 `src/types.ts` 的新类型必须前缀命名、不得与 `Graph*` 冲突。

3. A5 的 Agent/Skill 只读 DTO **不得回传 `systemPrompt`/`metadata` 敏感内容**（K7/prompt-secret）。

5. 图谱 agent/skill 消费子视图复用 A5 `PermissionPreview`，不二次解析。
