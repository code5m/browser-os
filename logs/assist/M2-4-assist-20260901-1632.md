## 1. run_script 命令契约（草案，bridge.rs 新增）

```
run_script(app, meta: ScriptMeta, args: HashMap<String,String>) -> Channel<LogLine>
```

- 复用 `request_sync` 的「后台线程 + 事件」范式（§4.1 已定首期方案）。
- `LogLine { ts, stream: "stdout"|"stderr", line }`，前端订阅 `script-output` 事件。

---

## 2. 参数注入防护（硬规则）

1. **绝不** `sh -c "..."` 拼接：用 `std::process::Command::new(interpreter).args([script_path, ...resolved_args])`。
2. `resolved_args` 仅含 `ScriptMeta.args` 声明的 key，未声明占位不替换（M2-3-assist §3）。
3. 每个 arg 值经 `shell_escape` 或作为独立 `argc` 参数传递（不进 shell 解析）。
4. 解释器由 `path` 扩展名/shebang 判定，不信任用户输入的解释器路径（锁定白名单
   `sh/bash/python3/node`）。
5. 工作目录锁定 `data_dir/scripts/<id>`，`canonicalize` 校验防 `..` 逃逸。

---

## 3. 取消 / 超时

| 机制 | 实现 |
|------|------|
| 取消 | `coordinator.register("kill-script-<id>", ...)` 复用 M0-2；前端 `script-cancel(id)` 命令触发 `child.kill()` + `wait()` |
| 超时 | `run_script` 带 `timeout_secs: u32`；后台线程 `channel::recv_timeout` 或独立 watchdog 线程，超时 `child.kill()` 并报 `LogLine{stream:"stderr", line:"timeout"}` |
| 退出收口 | `kill-script-*` 注册进 `ShutdownCoordinator`，应用退出无残留 |

---

## 4. 进程树回收

- `std::process::Command` 默认只 kill 直接子进程；脚本若 spawn 孙进程需**进程组**回收：
  `Command::new(...).process_group(0)` + `kill()` 发 `SIGKILL` 到进程组（Unix）。
- 复用 `TerminalSession` 的 `child.kill()`+`wait()` 范式（`:804-807`），确保孙进程不 orphan。
- 审计：kill 后仍写 `audit.json`（`action="script_killed"`）。

---

## 5. 输出背压（草案）

- 首期（§4.1）：复用 `request_sync` 的 `std::thread::spawn` + 事件，单条 `emit` 无背压保护，
  大输出可能冲垮前端 → **硬上限** `SCRIPT_OUTPUT_MAX_BYTES = 4MB`，超则截断并标 `truncated`。
- 升级期（M3-1 后）：改 `mpsc(128) + pump task`（§5 已定），解耦同步 `Channel::send` 阻塞。
- 前端：`RunConsole` 收到 `truncated` 标记显示「输出已截断」。
