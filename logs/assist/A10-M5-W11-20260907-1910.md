## 4. W11 A3 hardening 要求 vs 现状（A10 重点：bounded stdio dry-run）

> 当前 `mcp_server.rs` 仍是 **W10 基线**（commit `ba78092`），**A3 的 W11 hardening 改动尚未进入本工作树**。以下按 dispatch 给 A3 的 5 项 hardening 要求逐条比对现状。

| A3 W11 hardening 要求 | 现状 | 判定 |
|---|---|---|
| 确定性 JSON-RPC 错误 | `handle_request` 对解析失败返回 `-32700 Parse error`；未知 method 返回 `-32601 Method not found`；所有非法分支返回确定 code | ✅ 已满足（W10 即具备） |
| **有界输入/响应大小**（bounded input/response size） | ❌ **缺失**：`run_stdio` 用 `stdin.lock().lines()` 逐行读，**无单行长度上限、无单消息体积上限、无响应体积上限**；一行超长输入会被整行读入内存 | ❌ **W11 未交付（安全相关缺口）** |
| 稳定的 `tools/list` schema | 当前每个工具均返回 `{"type":"object","properties":{}}`（稳定但极简，无按工具的输入形状声明） | ⚠️ 稳定但最小化；不违反「稳定」要求，建议后续补齐每工具空 schema 一致性（现状已一致） |
| 对所有未绑定能力的显式 fail-closed `tools/call` | ✅ `match` 末臂 `other ⇒ isError:true` 覆盖一切未绑定/未知能力 | ✅ 已满足 |
| 非法 JSON / 未知工具 / 大参数的 smoke/测试 | ❌ **缺失**：无断言 `-32700` 的 invalid-JSON 测试；无「未知工具名经 `tools/call` ⇒ isError」测试（仅有 unknown *method* 测试）；无超长输入/大参数的 DoS 测试 | ❌ **W11 未交付** |

**判定**：A3 的 W11 hardening 包（有界大小 + 三类 smoke 测试）**尚未在仓库中落地**。这不是 Hard Stop 违规（现状未引入监听/执行/回显/依赖污染），但 **「有界输入大小」属安全相关项（stdin 无上限 → 单超长行内存耗尽 DoS）**，应在 A0 集成前由 A3 补齐。
