## 3. 对 A2 切片 1（`src/core/seam.rs`）的 seam 需求

A2 提案的三个 trait（`ProgressSink` / `PathResolver` / `RootsProvider`）中，M5-3 **复用 2 个、需要新增 2 个**。

| Seam | 状态 | M5-3 用途 | 建议签名 |
|---|---|---|---|
| `PathResolver` | ✅ **复用**（不需改） | `agent_kv` 落盘目录、`a2a_tasks.json` 目录 | `fn data_dir(&self) -> PathBuf` |
| `ProgressSink` | ✅ **复用**（与 A5 共用） | Agent 流式 token / 工具循环进度（目前 `script_runner` 用 `tauri::Emitter`） | `fn emit(&self, p: Progress)` |
| **`Clock`** | ❌ **新增（必须）** | TTL 过期判定、幂等键 FIFO 淘汰、空闲超时 —— **不可注入时钟则 `agent_kv` 的 TTL/淘汰单测无法确定性运行** | `fn now(&self) -> DateTime<Utc>` |
| **`AuditSink`** | ❌ **新增（必须）** | core 产出结构化审计事件，二进制落 `audit.json` / `agent-kv-audit.json`。**没有它，core 为了满足 F-A4-9（审计拆独立文件）只能调 `log_audit(app)`，直接违反 R-B1** | `fn record(&self, ev: AuditEvent)` |
| `KeyringProvider` | 🟡 建议（可选） | 凭据读写 `agent:<agent_id>`。白名单已允许 core 直接用 `keyring`；但加 trait 后 `agent_kv`/A2A 可脱离系统密钥库单测 | `fn get(&self, key: &str) -> Result<String, String>` / `fn set` / `fn delete` |

> **与 A6（M5-6 调度）的一致性**：A6 的契约已冻结"时钟可注入"（调度判重/错过执行依赖它）。
> `Clock` 与 A6 复用同一个 trait 即可，**不要出现第二套时钟抽象**（否则又是 A2 §2.1 要防的漂移）。

## 4. `capability.rs` 归属：**M5-3 要求落 core**

A1 `M5-2` 卡（§"依赖"）写的是 `capability.rs 已落 core **或二进制**` —— 这个"或"必须消除。

**M5-3 的立场：必须落 `src/core/capability.rs`。**

| 理由 | 说明 |
|---|---|
| 1 | M5-3 的能力判定纯逻辑（`declared` vs `granted`、scope 匹配）要在 core 内单测；若 `capability.rs` 在二进制，core 侧无法判定 → 只能把判定搬回 bin，**A2A 信封解析与能力判定被劈成两半** |
| 2 | 五处共用（A2P / A2A / Skill / Plugin / Agent）**全部跨 crate 边界**：其中 A2A 信封解析在 core、Skill 在 core（A5 也要落 core）、插件 manifest 在 core（A2 §8）、MCP 在 `mcp` crate（R-B3 规定 `mcp → core`）。落二进制会让 `mcp` 反向依赖 bin，**直接违反 R-B3** |
| 3 | 未来的 `cli` crate 同样要消费（R-B3：`cli → core`） |

**要求的最小形状**（core 内）：

```rust
// src/core/capability.rs
pub const MCP_CAPABILITY_V1: &[Capability] = &[ /* 常量表，非扫描 */ ];
pub struct Capability { pub name: String, pub maps_to: String, pub risk: RiskLevel,
                        pub requires_confirm: bool, pub requires_policy: Option<String>,
                        pub params_schema: serde_json::Value }
pub fn can_invoke(name: &str, policy: &McpGlobalPolicy) -> CapabilityVerdict; // 纯函数，fail-closed
```

`McpGlobalPolicy` 的**反序列化与解析**也应在 core（fail-closed 解析是纯逻辑）；
只有"从配置文件读 / 从 UI 写"留在二进制。

## 6. 对我 W0 契约的自我修订（delta）

### 6.1 `T-kv-22` 常量一致性断言**必须改为跨模块比较**（否则会退化成"自比"）

W0 §6.1 `T-kv-22` 写的是：

```
AGENT_KV_MAX_VALUE_BYTES == DB_MAX_TEXT_FIELD_BYTES；
A2A_MAX_TIMEOUT_SECS == script_runner::MAX_TIMEOUT_SECS；
A2A_SOFT_TO_HARD_GRACE_SECS == script_runner::HARD_GRACE_SECS
```

- 其中 `AGENT_KV_MAX_VALUE_BYTES` 与 `DB_MAX_TEXT_FIELD_BYTES` **都定义在 `domain.rs`**。
  一旦 A2 切片 0b 按 §13.4 把 `database.rs` 的副本删掉改 `pub use`，这条断言就变成
  ”`domain::AGENT_KV_MAX_VALUE_BYTES` == `domain::DB_MAX_TEXT_FIELD_BYTES`”——
  **两值仍会相等，但断言已不再守护任何跨模块口径**（A2 §13.5 指出的自比退化，同款）。
- **修订**：`T-kv-22` 改为比较 **`domain::AGENT_KV_MAX_VALUE_BYTES` vs `security_policy::MAX_TEXT_FIELD_BYTES`**
  （后者是 `security_policy.rs` 的自有常量，与 `domain.rs` 分属两个模块，切片 0b 后仍是真跨模块比较）；
  另两条（`script_runner::MAX_TIMEOUT_SECS` / `HARD_GRACE_SECS`）保持跨模块不变 ✅。
- **附加断言**：若某次重构使两侧合并为同一常量，则该断言**必须被替换**为
  "存在跨模块消费者 + `pub use` 单一定义"，**不得静默保留一个恒真的自比断言**。

### 6.2 常量"零影子副本"纪律（写给未来实现 M5-3 的 lane）

- `A2A_*` / `AGENT_KV_*` 常量**只在 `domain.rs` 定义一次**（W0 §4.10）；
- `agent_kv.rs` / `a2a.rs` 一律 `pub use crate::domain::{...}`，**禁止在本模块再 `pub const` 一次**；
- 违反者由 §5 的 `COREBOUND_CONST_SHADOW` 在 pre-merge 拦下。

### 6.3 `agent_kv` 落 core 后的路径注入形态

W0 F-A4-7 写的是"落 `data_dir/agent-kv.json`"；落 core 后**必须**改为注入形态：

```rust
// core 内：只吃 &Path，不知道 AppHandle 存在
pub fn kv_file_path(root: &Path) -> PathBuf { root.join(AGENT_KV_FILE) }   // AGENT_KV_FILE = "agent-kv.json"
pub fn load(root: &Path, now: DateTime<Utc>) -> Result<AgentKvStore, KvError>;
```
