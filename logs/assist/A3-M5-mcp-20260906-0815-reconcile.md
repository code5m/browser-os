## 2. P0 · A1 `M5-2` 卡的两处结构性冲突

### 2.1 冲突 A：**stdio-only（外部进程）与 `mcp_server_start/stop`（GUI 进程内启停）不能共存**

A1 卡同时写了两组互斥设计：

| A1 卡条目 | 原文位置 | 含义 |
|---|---|---|
| 传输 stdio-only，外部 Agent 以 `--mcp-server` 启动 | §4.1 + WRITE 表 `main.rs` 加 `--mcp-server` argv 分支 | MCP Server 跑在**独立进程**，stdin/stdout 即协议通道 |
| `mcp_server_start` / `mcp_server_stop` / `mcp_policy_get/set` 四个 Tauri 命令 | WRITE 表 `bridge.rs` + ACL 表 | MCP Server 跑在 **GUI 主进程内**，由前端按钮启停 |

**为什么互斥（实测证据）**：

1. GUI 主进程的 stdin/stdout 不归协议所有（桌面环境/启动终端占用），
   在 Tauri 窗口已起的情况下无法把 stdio 让给 JSON-RPC。
2. 白名单里 8 个能力所 `maps_to` 的命令，全部依赖 Tauri 运行时句柄，独立进程里一个都没有：
   - `list_artifacts`(2016) / `read_artifact`(2675) / `audit_log`(2669) / `list_repos`(2044) /
     `tab_list`(4464) 均签名 `(app: AppHandle)`，内部走 `workspace::load_*(&app)` 或 `app.state::<AppState>()`；
   - `db_query`(5990) 更需要 `webview: tauri::Webview`，**首行即 `check_invocation_source(&webview, "db_query", None, &app)?`**（5999）。
   → 独立 `--mcp-server` 进程若不构建 Tauri App，则 `AppHandle` 与 `Webview` **都不存在**，8 个能力**一个都调不动**。

**这恰好反向印证 A2 的 M5-1 抽取是 M5-2 的硬前提**（主篇 B4）：只有当 `workspace::` / `database::` /
`security_policy::` 这些逻辑脱离 `AppHandle`（A2 的 `PathResolver` seam）后，独立进程才可能工作。

**建议裁决（二选一，不能都要）**：

- **方案 1（推荐，首期）**：只做 `--mcp-server` 独立进程模式，**砍掉 `mcp_server_start/stop` 两个命令**。
  连带收益：`bridge.rs` / ACL / `types.ts` / `bridge.ts` **全都不用改**，冲突面最小；
  且"外部 Agent 能远程启停 GUI 内的服务器"这个面本身也不该给。
  `mcp_policy_get/set` 若仍需 UI 配置，可在**第二阶段**（届时进程内模式已裁决）再加。
- **方案 2**：只做 GUI 进程内启停，则必须放弃 stdio，改 UDS/命名管道，
  需 A0 书面接受"新增本地 socket 文件 + 权限 0600 + 残留清理"，并重新评估 §4.1 的红线。

### 2.2 冲突 B：`rmcp` 直接进主 crate → `tokio` 升为直接依赖，违反 M4-1.a F-1

A1 卡 WRITE 表：

> `| src-tauri/Cargo.toml | 修改 | 加 rmcp = { version = "...", default-features = false } |`
> `| src-tauri/src/mcp_server.rs | 新增 |`

问题：

1. **`default-features = false` 去不掉 `tokio`**。主篇 §3.1 已实测：`rmcp 3.2.0` 的 `tokio ^1`
   是 **normal、非 optional** 依赖（features `sync,macros,rt,time`）；`default-features=false`
   只影响 rmcp 自己的 feature 开关（那些 gate 的是 `macros`/`client`/`sse`/`hyper` 等 **optional** 依赖）。
2. 因此按 A1 卡实现后，`rmcp` + 一条 `tokio` runtime 会进入**主二进制 crate 的直接依赖**，
   与 M4-1.a 冻结的 **F-1「不引 tokio 直接依赖」**直接冲突。
   实测佐证：`grep -n tokio src-tauri/Cargo.toml` → **无直接条目**（当前 tokio 仅为传递依赖：
   `cargo tree -i tokio` → `tauri 2.11.5` 与 `postgres 0.19.14 → tokio-postgres 0.7.18`）。
3. A1 卡全文 `grep -i tokio` **仅 1 处命中**（第 32 行 READ 清单里把 tokio 列为"现有依赖"），
   即：**该卡未意识到这是一条需要裁决的红线**，而非既成事实。

**建议裁决（沿用主篇 §3.3）**：MCP Server 落**独立 crate/bin**（`crates/mvp-mcp` 或 `src-tauri/src/bin/mcp_server.rs`），
只依赖 `mvp-core`（A2 §3）+ `rmcp` + `tokio`；主二进制 `Cargo.toml` **保持零新增**。
若 A0 选择"主 crate 内 + 书面豁免"，则必须在卡里写明豁免编号、适用范围（仅 `mcp_server.rs`/`mcp_tools/`），
并由 `check-mcp-policy.py` 断言 `tokio::` 不出现在 mcp 目录之外的任何产品文件。

## 3. P1 · 新发现：`workspace.read_file` / `workspace.list_dir` 无路径根策略，经 MCP 暴露后升级为任意文件读

### 3.1 事实

```3491:3493:src-tauri/src/bridge.rs
pub fn read_file(path: String) -> Result<String, String> {
    std::fs::read_to_string(&path).map_err(|e| e.to_string())
}
```

- `read_file`(3491) 与 `list_dir`(3456) **均未调用** `sp::check_path_within_roots`；
  而同区的 `write_file`(3500)、`create_dir`/`rename_path`(3587/3612)、`delete_path`(3626) **都调用了**。
- 该缺口已被现有门禁**显式登记为已知待收口项**：
  `scripts/check-security-policy.py:25` 的 `EXPECTED_GAPS` 含 `READ_ONLY_BROWSE_WITHOUT_PATH_POLICY`
  （释义：读/浏览类命令缺路径策略，归 M0-3.c）。

### 3.2 为什么在 MCP 语境下性质变了

- **本地 GUI 语境**：路径由用户本人在文件树里点选，缺口可接受（且已挂账）。
- **MCP 语境**：调用方是**外部 Agent**，其输入可被提示词注入操纵。
  一旦 `workspace.read_file` 进白名单（A1 卡 §4.2 白名单第 6/7 项），
  一次注入即可读取 `~/.ssh/id_rsa`、`~/.aws/credentials`、`~/.config/**`、其他仓库源码等**根外任意文件**，
  且结果会通过网络回到攻击方。这是"本地可读性缺口"→"远程任意文件读"的**威胁等级跃迁**。

### 3.3 建议（三选一，按优先级）

1. **（推荐）把 `workspace.read_file` / `workspace.list_dir` 移出 M5-2 首期白名单**，
   等 M0-3.c 路径策略收口（或 MCP 层强制根校验）后再放行；
2. 或在 `mcp_tools/` 内强制前置 `sp::check_path_within_roots(&path, &allowed_roots(...))`
   —— 但独立进程里没有 `AppHandle`，需 A2 的 `RootsProvider`/`PathResolver` seam 先落地；
3. 或把这两项标记为 `requires_policy = Some("mcp_allow_arbitrary_path")` 且**默认关闭**，
   并在 `check-mcp-policy.py` 中把"默认关闭"做成断言。

> 附带同类提醒：`tab_list` 会回传所有页签的 URL/标题（含可能带敏感 query 的 URL）。
> 建议 MCP 侧对 URL 一律过 `sp::redact_sensitive_url`（416），与 M1-8 资源瀑布同口径。
> A1 卡 §4.5 只禁了"抽取文本正文/凭据/DSN/SQL 正文"，未覆盖 URL 脱敏，建议补上。
