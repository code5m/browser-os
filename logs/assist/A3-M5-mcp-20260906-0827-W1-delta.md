## 2. 假设变化 1（HIGH）：「独立 bin 隔离 tokio」在阶段一失效 → 改 feature-gated bin

### 2.1 为什么失效

我主篇 §3.3 的建议是「MCP Server 落独立 crate/bin，只依赖 `mvp-core` + `rmcp` + `tokio`，
主二进制依赖图与同步模型零变化」。该推理默认了「bin 有独立依赖集」——**在阶段一的同 package 双 target 下不成立**：

- A2 实测：`[dependencies]` 是 **package 级**，对 lib 与所有 bin **同时生效**；
- 于是 `rmcp` + `tokio` 会同时出现在 **core（lib）** 与 **主 bin** 的依赖面，
  与 A2 的 R8 是同一个病：**core 边界会在引入 MCP 时被静默腐化**；
- 且我主篇 §3.2 用 `cargo tree -i tokio` 论证"tokio 早已在树中"——恰恰说明
  **阶段一无法用 `cargo tree` 证明 tokio 没进 core**（A2 第 234 行已判 `COREBOUND_TREE_TAURI` 阶段一必然 FAIL）。

### 2.2 修订方案：optional dependency + `[[bin]] required-features`

关键点：**optional 依赖在未启用时不进入构建图**——即默认 `cargo build` / `cargo test` / `npm run build`
**完全不编译** `rmcp` 与 `tokio`，主应用二进制与 core 的依赖面**零变化**。
`required-features` 是 Cargo 对 `[[bin]]` 的既有能力（本机 cargo 1.96.0）。

```toml
# src-tauri/Cargo.toml（阶段一，M5-2 实现期；本轮 W1 不落地）
[dependencies]
# 既有的 tauri / rusqlite / mysql / postgres … 保持不动

# M5-2 MCP：**仅** MCP server bin 使用。optional + default-off，
# 未启用 --features mcp 时 rmcp/tokio 完全不参与构建与链接。
rmcp  = { version = "3", default-features = false, optional = true }
tokio = { version = "1", features = ["rt-multi-thread", "macros", "sync", "time"], optional = true }

[features]
# 默认不含 mcp：cargo build / cargo test / cargo build --release 均不编 MCP
mcp = ["rmcp", "tokio"]

[[bin]]
name = "mcp_server"
path = "src/bin/mcp_server.rs"
required-features = ["mcp"]   # 未开 feature 时该 bin 不参与构建
```

### 2.3 对 M4-1.a F-1 的诚实定性（**需要 A0 书面裁决，不能自行认定合规**）

| 口径 | 结论 |
|---|---|
| **字面**（`src-tauri/Cargo.toml` 是否出现 `tokio` 条目） | **仍触碰**：optional 依赖也是 Cargo.toml 里的一条 `tokio = …` |
| **实质**（主应用是否引入 tokio 编程模型 / tokio 运行时 / 编译进产物） | **完全未触碰**：默认构建不编译、不链接；仅 `cargo build --features mcp --bin mcp_server` 时才有 |
| 阶段二的解（**F-1 零触碰**） | workspace 落地后建 `crates/mvp-mcp/` **独立 package**，主 package `Cargo.toml` **无任何 tokio 条目** |

→ **请求 A0 二选一并书面记录**：
- **(a) 阶段一即上 MCP**：给 F-1 一条**限定豁免**（`optional + default-off + 仅 mcp_server bin`，
  由 `MCP_RUNTIME_LEAK` 断言兜底，见 §3）；阶段二再迁 `crates/mvp-mcp` 并撤销豁免。
- **(b) MCP 推迟到阶段二**：F-1 全程零触碰，但 M5-2 排在 `M5-1.b` 之后，时间线上更靠后。

我推荐 **(a)**，理由：MCP 是纯增量 bin，feature gate 后对主应用的构建/体积/依赖面影响为 **0**，
且可提前验证能力白名单与 `McpGlobalPolicy`；风险已被 §3 的 grep 断言机械兜住。
