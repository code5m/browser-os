## 3. A9 插件模型 + A8 图谱 UI 与 M5-2 注册表/政策的兼容性结论

### 3.1 Plugin form③ = 无第二执行路径（**兼容**，红线守稳）
- M5-10 §4.1 形态③（声明式资源包：入口 URL 走既有 webview、JS 钩子走受控 `bridge.ts` 子集、禁独立 webview/独立 stdio 进程）与 M5-2 红线（无 rmcp/tokio/监听/第二执行路径）**同向**。形态①(独立 stdio)/②(独立 webview) 已被否决（M5-10 §5 FORBID）。
- W6 Hard Stop「no plugin installation runtime」+ A9 W6 范围「no real plugins / no signature enforcement beyond pure validation」→ 不引入 MCP server/transport，满足 A3 「no MCP runtime expansion」。

### 3.2 Plugin capability 白名单**必须与 `MCP_CAPABILITY_V1` 同源单源**（**核心缺口**）
- M5-10 §4.2 `PluginCapability.capability` 引用 `capability.rs`；M5-11 §4.2/4.3 判定序要求 capability 在 `capability.rs` 白名单内；§5 FORBID「不 让 capability.rs 在多文件定义」。
- 但若 `PLUGIN_CAPABILITY_V1` 落到独立 `capability.rs`（bin 侧），而 `MCP_CAPABILITY_V1` 在 `domain.rs`（bin 侧）、`SKILL/AGENT_CAPABILITY_V1` 在 `security_policy.rs`（bin 侧），则**四类能力各据一文件**——`MCP_CAPABILITY_DRIFT` 守不住。
- **兼容性要求**：插件可声明的能力集合必须是 MCP 单源的**同一份**（或明确子集），且由**同一文件**定义。否则插件可声明 MCP 白名单外的 capability（如新增 `workspace.write`），形成 MCP 政策未覆盖的暴露面。

### 3.3 Plugin capability 评估**必须复用 `evaluate_mcp_command` 逻辑**（**兼容性硬要求**）
- M5-11 §4.3「风险等级与 `policy` 比对（**同 MCP §4.3 第 2-4 步**）」「与 MCP 一致」已明文要求对齐。
- `mcp.rs:84 evaluate_mcp_command` 三步（lookup→fail-closed / `touches_fs`→`check_path_within_roots` / 返回前 `redact_sensitive_url`）**必须**被 `plugin_runtime.rs`（M5-11 §3 新增）原样复用——最好是抽成 `core` 共享 `evaluate_capability`，`mcp.rs` 与 `plugin_runtime.rs` 同调。
- 否则插件 capability 评估若比 MCP 更松（如漏做 `check_path_within_roots`/`redact_sensitive_url`），即绕开 M5-2 路径/URL 守门（`MCP_FS_TOOL_PATH_POLICY`/`MCP_URL_NOT_REDACTED`）。

### 3.4 Plugin 命令/资源隔离复用 MCP 原语（**兼容设计**）
- M5-11 §4.2 capability 隔离（`plugin_invoke` 校验 manifest 声明）、§4.3 step6 路径校验（`..`/越界拒绝）、§4.2 资源隔离（`plugins_dir()/<id>/workspace/` + `storage.json`）——均应使用 M5-2 既有单一真源：`security_policy::{check_path_within_roots, redact_sensitive_url}`（mcp.rs:16 已复用）。
- ⚠️ **守门须服务端强制**：M5-10 §4.1「JS 钩子走受控 `bridge.ts` 子集（不允许裸 invoke）」必须由 `plugin_runtime.rs` 在分发前校验（capability 裁剪），**不能只靠前端不暴露**——前端可被绕。这与 `MCP_TOOL_CALLS_COMMAND`/`MCP_SECOND_COMMAND_PATH` 同精神。

### 3.5 Plugin storage 隐私/容量与 M5-2 一致（**兼容，需加门**）
- M5-11 §5「不 让 `plugin_storage_put` 存 token/密码（K3）」+ W6 Hard Stop「no token/cookie/Authorization/body/prompt-secret persistence」与 M5-2 隐私单向（`redact_sensitive_url` + 不持久化凭据）同向。
- `plugin-invokes.json` 500 上限 FIFO（M5-11 §4.4）+ 审计只记摘要（K3）——与 M5-2 审计脱敏 + W5「bounded」同向。
- **缺口**：A9 W5 §5 已规划 `check-plugin-policy.py` 同族 A3/A5，但**尚未含**隐私双扫（`AGENT_KV_SECRET_SUSPECTED` / `AGRAPH_9` 同款 `SENSITIVE_KEY_NAMES`/`SENSITIVE_VALUE_PATTERNS`）。应补 `PLUGIN_NO_SECRET_PERSIST` 守门（见 G4）。

### 3.6 Graph UI（A8 M5-9）= **MCP 惰性，无暴露面**（**兼容**）
- A8 W6 = graph UI pure logic/panel shell（`src/components/graph/*` + `useGraphStore.ts` + `useGraphQuery.ts`），消费 A7 `GraphNode`/`GraphEdge` DTO（本地 `graph_*` 命令，非 `mcp_*`）→ 不触发 `MCP_PARITY`；图谱今天仍非 MCP 能力（同 W5 结论）。
