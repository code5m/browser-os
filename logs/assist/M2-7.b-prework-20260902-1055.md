### 2.2 打包后资源不可达的根因

内置工具若放 `src-tauri/src/tools/`，**打包产物中不存在该目录**（只有二进制 + bundle 声明的资源）。运行时按相对路径/工作目录去读必然失败。所以必须在下列两条路中选一条：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. `include_dir!`（推荐）** | `build-dependencies` 加 `include_dir`；`build.rs` 或独立 `tools_assets.rs` 里 `include_dir!("$CARGO_MANIFEST_DIR/src/tools")` 编译期嵌入到二进制 | 单文件自包含、运行时零 IO 失败面、不受安装位置影响、天然"离线" | 增大二进制体积（5 个 HTML 约几十 KB，可接受）；改工具需重编译 |
| **B. `bundle.resources`** | `tauri.conf.json` 声明 `bundle.resources = ["src/tools"]`，安装时拷贝到资源目录 | 改工具无需重编译；资源可更新 | 运行时路径解析复杂（Linux 下资源目录位置因 deb/appimage 而异）；路径取不到 = 工具打不开；`frontendDist`/`resourceDir` 语义易踩坑 |

**结论（草案，待强模型确认）**：首期走 **方案 A `include_dir!`**。理由：本项目工具是「内置、离线、不可变、体积小」的种子工具，正是 `include_dir!` 的最佳场景；且能规避方案 B 的"资源目录路径在 Linux 各打包格式下不一致"这一已知坑（本项目已在子 webview 定位上踩过同类坑，见 `踩坑记录-子webview撑不满-根因与修复.md`）。

用户目录 `workspace/tools/` 的工具走**运行期读盘**（不走 include_dir）。

## 4. 接口 / 数据契约

### 4.1 Rust 侧

```rust
// src-tauri/src/domain.rs
use serde::{Deserialize, Serialize};

/// 工具来源：决定加载路径与是否可删除
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum ToolSource {
    /// 编译期嵌入（include_dir!），不可删除、不可编辑
    Builtin,
    /// 用户目录 workspace/tools/，可增删改
    User,
}

/// 工具元数据：清单只描述，不含 HTML 内容
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolMeta {
    pub id: String,              // Builtin: 文件名去扩展（如 "cron-tool"）；
                                 // User: uuid v4 或 slug（需唯一化，见 §4.3）
    pub name: String,            // 展示名（User 缺 frontmatter 时回退为文件名）
    pub description: String,
    pub icon: Option<String>,    // emoji 或内置图标名；无则前端用首字母占位
    pub category: String,        // "convert" | "dev" | "text" | "other"
    pub source: ToolSource,
    /// Builtin: None（运行时从嵌入资源取）；User: 绝对/相对 workspace 路径
    pub path: Option<String>,
    pub version: Option<String>,
    pub offline: bool,           // 是否离线可用（见 §4.4 校验）
    pub bytes: u64,
}
```

### 4.2 `list_tools` 契约（草案）

```rust
/// 返回内置 + 用户工具合并清单。不返回 HTML 内容（内容由打开命令按 id 提供）。
/// 失败不放空：内置清单来自编译期资源，理论上不会失败；
/// 用户目录读取失败时**降级为仅返回内置**，并在日志/审计中记录。
pub fn list_tools(app: AppHandle) -> Vec<ToolMeta>
```

**排序规则**：`Builtin` 在前（按 `id` 字典序），`User` 在后（按 `name`）。前端不重新排序。

### 4.3 清单枚举规则

1. **扫描范围**：内置 = `include_dir!` 的 `src/tools/*.html`；用户 = `workspace/tools/*.html`（首期**不递归**子目录，避免无限层级与符号链接环）。
2. **过滤**：仅 `.html` / `.htm`；忽略以 `.` 开头的隐藏文件；忽略单文件 > 5 MB。
3. **ID 冲突**：`User` 工具的 `id` 与 `Builtin` 冲突时，强制加后缀 `-user-<n>`，**不允许覆盖内置**（否则用户可劫持内置工具入口）。
4. **元数据来源**：User 工具从 HTML 头部的 `<meta name="tool-*">` 或 YAML frontmatter 解析；解析失败不拒绝加载，用文件名兜底（`offline` 标记 `false`，详见 §4.4）。
5. **失败降级**：任一 User 文件读取/解析异常 → 跳过该文件并在 `audit.json` 记一条，其余工具照常返回（**不允许整列表失败**）。

### 4.4 `offline` 校验（离线红线）

工具体现"数据不出本机"，`offline` 判定：HTML 源码中**不得**出现外链资源引用：

命中以下任一 → `offline = false`，并在 UI 上打「⚠ 需联网」标记（首期**仍允许加载**，但必须标注；是否强制禁止加载待定）：

- `<script src="http(s)://...">`
- `<link href="http(s)://...">`
- `<img src="http(s)://...">`
- `@import url(http...)` / `url(http...)`（CSS）
- `fetch(` / `XMLHttpRequest` 指向非相对地址（**静态检测，仅告警**）

> 静态检测有漏报可能（如拼接 URL）。**离线红线不能只靠静态检测**，最终保障应靠 CSP：工具 webview 加载时施加"禁止外链"的 CSP 头。此项列为强模型待定项（§10.2）。

### 4.5 打开方式契约（与子 webview 既有能力对齐）

- 复用 `tauri-plugin-browser-tabs` 的 `WebviewBuilder` 子 webview（宫格/页签同款），遵守 `PROJECT-RULES.md` 的子 webview 定位规则。
- Builtin 工具内容来自 `include_dir!` 内存，需落临时文件或走自定义协议提供给 webview —— **具体通道待定**（见 §10.1，候选：写临时文件 + `file://`、自定义 `asset:` 协议、或 `data:` URL）。
- User 工具直接 `file://` 读 `workspace/tools/`（注意：当前 `assetProtocol.scope` **不含** workspace 目录，若走 `asset://` 需扩 scope，同 M2-1.a §5.R1 的安全权衡）。
