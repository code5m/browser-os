### 4.1 依赖与运行时现状（实测）

- `src-tauri/Cargo.toml` 当前无 DB 依赖；既有直接依赖：`tauri 2`（`unstable`/`protocol-asset`）、`tauri-plugin-single-instance`、`tauri-plugin-browser-tabs`(path)、`serde`、`serde_json`、`keyring 3`、`git2 0.19`、`uuid`、`chrono`、`sha2`、`url`、`urlencoding`、`open`、`arboard`、`portable-pty 0.8`、`freedesktop-icons`、`strip-ansi-escapes`、`libc`。
- **`tokio 1.53.1` 已在 `Cargo.lock` 依赖树**（第 4114 行，传递依赖）。含义：新增 `tokio` 为直接依赖**大概率不引入新版本**，但会改变**特性并集**（需 `rt-multi-thread`/`macros`/`time` 等），须复核是否影响既有构建基线（M4-2 PASS 标准含 `measure-build-metrics.py --compare` 总体积 ≤15%；该脚本确认支持 `--compare` 与 `--skip-build`，见第 184/187 行）。
- **源码中零 `tauri::async_runtime` 调用**（`grep` 零命中）。推断：项目**尚无异步执行面的既有范式**；连接池若走 async（sqlx 必然），`tokio::spawn` vs `tauri::async_runtime::spawn` 的选型属**本项目首次引入异步执行面**，需显式约定。⚠️ 前半为实测、后半为推断，建议 M4-1 契约中裁定。

### 4.2 release profile 的硬约束（实测，影响面大）

```toml
[profile.release]
panic = "abort"
codegen-units = 1
lto = true
opt-level = "s"
strip = true
```

- **`panic = "abort"`**：连接池/查询路径中任何 panic（含 tokio worker 内 panic、`unwrap`、索引越界）都**直接终止进程**，而非返回错误。→ 池与查询核心必须**全程 `Result` 传播、零 `unwrap`**，并补「不 panic」的失败用例。**展开卡与 A10 评审均未显式提及此约束**，建议补入 M4-2 硬 PASS 条件。
- **`lto = true` + `codegen-units = 1` + `opt-level = "s"`**：引入 sqlx（尤其三驱动全开）会显著推高 release 构建时长与体积增幅，与「总体积增长 ≤15%」直接相关。建议 A2 选型时明确**驱动是否按 feature 拆分**（SQLite 常驻、MySQL/PG 可选），而非三驱动全量编译。
