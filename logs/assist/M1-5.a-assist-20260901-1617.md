## 1. 可复用函数盘点（建议在 `sync.rs` 或新建 `git_readonly.rs`）

```rust
// 以下均为 git2 只读 API，不修改工作区、不触网
fn repo_at(app: &AppHandle, repo_id: &str) -> Result<Repository, String> {
    let cfg = workspace::load_repos(app).into_iter().find(|r| r.id == repo_id)
        .ok_or("仓库未配置".to_string())?;
    let path = app.path().app_data_dir().map_err(|e| e.to_string())?
        .join("mvp-browser-os").join("repos").join(&cfg.id);
    Repository::open(&path).map_err(|e| e.to_string())
}
// status：repo.statuses(None) -> Vec<StatusEntry>
// diff：repo.diff_index_to_workdir(None, None) / diff_tree_to_workdir
// branches：repo.branches(Some(BranchType::Local)) + Remote
```

> 路径规则照搬 `sync.rs push_artifacts` 的 `base` 计算，避免重复发明。

## 3. 命令契约草案（bridge.rs 新增，进 capabilities）

```
git_status(repo_id: String) -> Vec<GitFileStatus>        # git2 statuses，纯只读
git_diff(repo_id: String, path: Option<String>, max_bytes: u32) -> Vec<GitDiffHunk>  # 截断守护
git_branch_list(repo_id: String) -> Vec<GitBranch>       # local + remote
```

- 三个命令均 `check_invocation_source` 校验来源（仿 `report_resources` 的 ACL 风格）。
- 均不接 token、不触网、不写盘。

---

## 4. 只读安全边界

1. 仅对 `app_data_dir/repos/<id>` 下的仓库调用 `Repository::open`，拒绝任意路径。
2. 不调用 `Repository::checkout`/`reset`/`pull`/`push` 等任何写/网命令。
3. `git_diff` 的 `max_bytes` 默认 64KB，超过则 `truncated=true` 且仅返回前 N 行（防前端卡死）。
4. 错误统一返回 `Err(String)`，不 panic、不泄露仓库内部路径到日志以外。

---

## 5. 大 diff 截断策略

- `max_bytes` 入参 + 服务端硬上限（建议常量 `GIT_DIFF_HARD_CAP = 256_000`）。
- 单文件超过上限：`GitDiffHunk.truncated = true`，`new_content` 截断并附 `"(truncated ...)"`。
- 多文件：按 `statuses()` 顺序返回，总大小累计超 `GIT_DIFF_HARD_CAP` 即停止追加并标 `more=true`。
