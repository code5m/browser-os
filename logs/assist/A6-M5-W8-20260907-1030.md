§10 设计要点（**零 bridge/store 调用，仅消费 `agentSkillUi.ts` 纯逻辑**）：
- 按 A5 W7 契约构造 `SkillValidationResult` 形状 `{ ok, def, issues[], preview }`，断言「校验通过 / 解析失败 / 语义失败」三态的 UI 消费：
  - 通过：`ok=true`、无错误项、回传 `preview` → 经 `buildPermissionPreview(def, preview.capabilities)` 派生 `PermissionPreviewView`（gate/标签/配色/目标摘要/能力列表/提示）。
  - 解析失败：`def=null`、`preview=null`、仅 `issues[].code="PARSE_ERROR"` → UI 走错误态，无预览。
  - 语义失败：`def` 仍回传（部分展示）、`preview` 仍回传（只读可看）、`issues` 驱动错误展示。
- `dangerous` 闸门：`buildPermissionPreview` 派生 `gate="dangerous"` + `gateTone="danger"` + `dangerHint` 必显；空白名单时 `capabilities` 全 `unknown`（不谎报已授权）。
- 单能力判定：`classifyCapability(id, whitelist)` 标 `granted`/`unknown`。
- secret 边界：`redactSecrets` 对 `TOKEN` 键脱敏，但 `system_prompt` 按值不按键名脱敏（真正的凭据泄露由后端 `contains_credential_leak` 判，W4/W7）—— 前端只做键名脱敏，不重复后端职责。
- 新增导入 `classifyCapability`（脚本 destructure 补一行）；其余复用既有 helper，无新依赖。

→ 这 22 条锁定了 W8 只读面板所依赖的**精确纯逻辑行为**，且对「A5 是否已在 mainline 落地命令」零依赖——命令到位后，store/组件只需把结果喂给这些已验证的 helper 即可，无需再为预览渲染写新逻辑。
