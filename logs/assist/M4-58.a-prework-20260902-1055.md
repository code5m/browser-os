## 4. 接口 / 数据契约

### 4.1 领域模型

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum Schedule {
    /// 标准 5 段 cron（分 时 日 月 周）。**不支持**秒级 6 段与 @reboot
    Cron { expr: String },
    /// 固定间隔（秒）。最小 60 秒
    EverySecs { secs: u64 },
    /// 应用启动后延迟 N 秒执行一次（仅一次）
    Once { delay_secs: u64 },
}

/// 错失触发策略：应用未运行/睡眠期间本该触发的时间点如何处理
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case")]
pub enum MisfirePolicy {
    /// 跳过（默认，最安全）
    Skip,
    /// 启动时补跑一次（**仅对幂等任务安全**）
    CatchUpOnce,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RetryPolicy {
    pub max_attempts: u32,        // 默认 1（不重试）
    pub backoff_secs: u64,        // 默认 60，指数退避
    pub backoff_max_secs: u64,    // 默认 1800（30 分钟封顶）
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct TaskDef {
    pub id: String,                 // uuid v4
    pub name: String,
    pub enabled: bool,
    pub schedule: Schedule,
    /// 执行目标：复用 M2-3.a 的执行通道，**不新建执行层**
    pub target: TaskTarget,
    /// 幂等键策略（见 §4.3）
    pub idempotency: Idempotency,
    pub misfire: MisfirePolicy,     // 默认 Skip
    pub retry: RetryPolicy,
    pub timeout_secs: u32,          // 默认 300
    /// 并发保护：该任务正在跑时是否允许再次触发
    pub allow_concurrent: bool,     // 默认 false
    pub last_run_at: Option<DateTime<Utc>>,
    pub next_run_at: Option<DateTime<Utc>>,
    pub created_at: DateTime<Utc>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum TaskTarget {
    /// 调用 M2-3.a 的 run_script
    Script { script_id: String, args: Vec<String> },
    /// 调用 M2-2 的 run_command（命令片段）
    Command { line: String },
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum Idempotency {
    /// 不做去重，每次触发都执行
    None,
    /// 同一 idempotency_key 在窗口期内只执行一次
    Key { key_template: String, window_secs: u64 },
}
```

### 4.2 调度语义

| 项 | 契约 |
|---|---|
| 时间基准 | **本地时区**（与 cron-tool 一致，UI 需显式标注"本地时区"） |
| 调度精度 | 轮询间隔 **≤ 1 分钟**（建议 15s 轮询 + 边界判定，兼顾精度与唤醒开销） |
| `next_run_at` | 落盘持久化，启动时据此判断错失 |
| 夏令时/系统时间回拨 | 采用"单调时钟推进 + 墙上时钟校验"；检测到时间回拨 > 60s 时记审计并**跳过**该轮（防重复触发风暴） |
| 并发 | 默认 `allow_concurrent=false`：在跑则跳过本次并记 `TASK_SKIPPED_CONCURRENT` |
| 全局并发上限 | 建议 4（防止 N 个任务同时到期打满机器） |
| 最小间隔 | `EverySecs` 最小 60 秒（防失控轮询） |

### 4.3 幂等契约

| 层 | 机制 |
|---|---|
| **任务定义层** | `Idempotency::Key`：`key_template` 支持占位（如 `backup-{yyyyMMdd}`），窗口期内同 key 只跑一次 |
| **执行层** | 复用 M2-3.a 的"同一 script_id 禁止并发"（§:M2-3.a 5.R5） |
| **落盘层** | `tasks.json` 写入必须**原子**：写临时文件 → `fs::rename`（防崩溃留下半截 JSON） |
| **启动层** | 启动时加载 `tasks.json`，**校验 `id` 唯一**；重复 id 保留首个并记审计 |
| **去重状态存放** | 幂等 key 记录放 `task-runs.json`（带上限），**不放内存**（否则重启即失效） |

> 原子写是硬要求：定时任务在后台跑，用户可能在写盘瞬间关机。半截 JSON 会导致**所有任务丢失**。

### 4.4 失败恢复

| 场景 | 处理 |
|---|---|
| 任务执行失败（非 0 退出码） | 按 `RetryPolicy` 退避重试；超过 `max_attempts` 记 `TaskRunRecord.status=Failed`，**任务本身不停用**（避免一次失败就永久静默） |
| 任务超时 | kill 进程树（复用 M2-3.a §4.5），记 `Timeout` |
| 应用崩溃/被 kill | 重启后：① 读 `tasks.json` 恢复定义；② 把 `TaskRunRecord` 中仍是 `Running` 的记录**标记为 `Unknown`（孤儿）**并提示用户；③ 按 `MisfirePolicy` 处理错失 |
| 错失（misfire） | `Skip`（默认）：把 `next_run_at` 推进到下一个未来时间点，不补跑；`CatchUpOnce`：启动时补跑**一次**（不补跑 N 次） |
| 持久化文件损坏 | 解析失败 → **不静默清空**：备份损坏文件为 `tasks.json.corrupt-<ts>`，返回空任务列表 + 显著告警 |
| 连续失败 | 连续失败 N 次（建议 5）后自动 `enabled=false` 并告警（防无限重试刷屏） |

### 4.5 审计契约（**关键：不能沿用 audit.json 的 naive 写法**）

问题：`audit.json` 上限 1000 条且 `drain` 队首。分钟级任务会在数小时内清空历史（1000 条 ÷ 每小时若干条）。

**契约**：
1. **`audit.json` 只记录"任务定义变更"**：`task_add` / `task_update` / `task_remove` / `task_run_now`（用户主动动作，低频）。
2. **每次自动执行记录到独立的 `task-runs.json`**（带上限，建议 500 条，同样 drain 保尾）。
3. **自动执行不写 `audit.json`**，避免刷掉安全事故线索。
4. `task-runs.json` 的每条记录必须包含：`task_id`、`run_id`、`started_at`、`finished_at`、`status`、`trigger`（`scheduled` / `manual` / `catchup`）、`exit_code`、`error`。
5. 若监管要求"所有执行都进 audit"，则**必须先改造 audit 分片**（如 `audit-<yyyyMM>.json`），属独立议题，不在本契约内。

## 5. 风险

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **退出无收口** → 残留 timer + 被触发的脚本进程 | **高** | **阻塞依赖**：M3-1.a §2.6 的 ShutdownCoordinator；未落地前不得合入定时执行 |
| R2 | 定时任务高频刷空 `audit.json`，安全事故无法追溯 | **高** | §4.5 拆分：自动执行进 `task-runs.json`，不进 audit |
| R3 | `tasks.json` 非原子写 → 崩溃留下半截文件，全部任务丢失 | **高** | 原子写（临时文件 + rename）+ 损坏备份 + 告警 |
| R4 | 依赖 M2-3.a 的 `run_script`（尚未实现） | **高** | 契约先定；实现顺序必须是 M2-3.a → M4-58 |
| R5 | 任务执行任意脚本 = 无人值守的任意命令执行 | **高** | 完全复用 M2-3.a 的危险参数校验 + 审计 + 超时；**不给定时任务任何绕过通道** |
| R6 | 系统时间回拨导致重复触发风暴 | 中 | §4.2 时间回拨检测（> 60s 跳过并记审计） |
| R7 | misfire `CatchUpOnce` 对非幂等任务有害 | 中 | 默认 `Skip`；选 `CatchUpOnce` 时 UI 强制警告 |
| R8 | 无 tokio 依赖，调度器需选运行时 | 中 | 见 §10.2：优先复用既有 `std::thread::spawn` 范式，或显式引 tokio |
| R9 | 任务数量过多导致轮询开销 | 低 | 任务数上限（建议 50）+ 单次轮询计算 next_run 而非每次解析 cron |
| R10 | 前端展示时区与后端不一致 | 中 | `TaskDef` 落 UTC，前端渲染本地时区；UI 显式标注 |
