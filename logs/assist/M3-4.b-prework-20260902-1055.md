## 4. 接口 / 数据契约

### 4.1 历史上限（先澄清语义，再定数值）

fileterm 的 `TEMPORARY_HISTORY_LIMIT=40` 与 xterm 的 `scrollback` 是**两件事**，必须先分清：

| 概念 | 含义 | 本项目的位置 |
|---|---|---|
| **scrollback** | 终端回滚缓冲区行数（用户可向上翻多少行） | xterm.js `scrollback` 选项，**当前用默认 1000** |
| **temporary history（重连回放）** | 断线重连/组件重建时，把最近 N 条输出重新写给前端 | 本项目**无此机制**（组件销毁即丢） |

**草案结论**：
1. **采纳显式 scrollback**：`new Terminal({ scrollback: 5000, ... })`。理由：1000 行对看编译/日志输出偏少；5000 行内存开销可接受（约数 MB，纯文本）。
2. **暂不采纳** `TEMPORARY_HISTORY_LIMIT`：本项目终端组件卸载即销毁会话，没有"重连回放"场景（面板切换是隐藏不销毁）。引入属于**无的放矢**，待真正做"终端会话持久化/重连"时再议。
3. 若未来要做，`termBuffer` 的既有模式（`useSystemStore.ts:129-145`）就是天然的重连回放雏形，届时在其上加数量上限即可，**不需要新概念**。

```ts
// TerminalPane.vue 草案
const TERMINAL_SCROLLBACK = 5000;   // 后续可迁到 settings
term = new Terminal({
  scrollback: TERMINAL_SCROLLBACK,
  cursorBlink: true,
  // ... 其余保持现状
});
```

### 4.2 resize 静默窗口

```ts
// src/composables/useTerminalResize.ts（草案）
export interface ResizeQuietOptions {
  /** 静默窗口：连续无新事件超过该时长才真正下发。建议 120ms */
  quietMs?: number;
  /** 硬上界：距上次真正下发超过该时长，无论是否仍在拖动都下发一次。建议 500ms */
  maxWaitMs?: number;
}

export function useTerminalResize(onCommit: (cols: number, rows: number) => void,
                                  opts: ResizeQuietOptions = {}) {
  const quietMs = opts.quietMs ?? 120;
  const maxWaitMs = opts.maxWaitMs ?? 500;
  let timer: number | null = null;
  let lastCommitAt = 0;
  let lastCols = -1, lastRows = -1;

  function notify(cols: number, rows: number) {
    // 去重：尺寸没变就完全不排程
    if (cols === lastCols && rows === lastRows) return;
    if (timer !== null) clearTimeout(timer);
    const elapsed = Date.now() - lastCommitAt;
    const wait = elapsed >= maxWaitMs ? 0 : Math.min(quietMs, maxWaitMs - elapsed);
    timer = setTimeout(() => {
      timer = null;
      lastCols = cols; lastRows = rows; lastCommitAt = Date.now();
      onCommit(cols, rows);
    }, wait) as unknown as number;
  }

  function dispose() { if (timer !== null) { clearTimeout(timer); timer = null; } }
  return { notify, dispose };
}
```

**三条硬规则**：
1. **值未变化不下发**（去重）—— 消除 `ResizeObserver` 抖动导致的无效 IPC。
2. **静默窗口 120ms** —— 拖动时只在停手后下发。
3. **硬上界 500ms** —— 防止"用户持续慢慢拖动 10 秒"期间终端完全不响应尺寸（这是纯静默窗口方案的经典缺陷）。

**接线方式**（`TerminalPane.vue`）：

```ts
const { notify: notifyResize, dispose: disposeResize } = useTerminalResize((cols, rows) => {
  if (system.termId) void bridge.termResize(system.termId, cols, rows);
});

const fitAndReport = () => {
  fit?.fit();
  const dims = fit?.proposeDimensions();      // { cols, rows }
  if (dims && dims.cols > 0 && dims.rows > 0) notifyResize(dims.cols, dims.rows);
};

resizeObserver = new ResizeObserver(fitAndReport);
// onBeforeUnmount 里务必 disposeResize()
```

> 注意：`fit.fit()` 仍要**每次都调用**（前端渲染必须实时跟随），静默只作用于**后端上报**。
