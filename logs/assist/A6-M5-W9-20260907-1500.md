## 3. 交付物 1：store 只读校验消费接线（`src/stores/useAgentStore.ts`）

新增（均为 additive，不删旧逻辑）：

- **状态 ref**：`skillValidation`/`skillParseDef`/`skillPreview`/`agentValidation`/`agentParseDef`/`agentPreview`（类型 `ValidationReport|null` / `SkillDef|null` / `PermissionPreview|null` 等）。**不持有原始输入文本**——满足 W9 Hard Stop「no prompt-secret in frontend state」。
- **确定性四态 computed** `skillStatus`/`agentStatus`：取值 `empty|loading|ok|error`。规则：`loading` 优先；无 validation → `empty`；否则按 `valid` 判 `ok`/`error`。组件据此无歧义渲染。
- **有界预览 computed** `boundedPreview`/`boundedAgentPreview`：经 `boundCaps()` 取 `capabilities` 前 `PREVIEW_CAP=20` 项 + `overflow` 计数 + `total`，前端按需展开，杜绝长能力列表撑爆视图。
- **动作** `validateSkill(text)`/`validateAgent(text)`：
  - 门控 `AGENT_SKILL_READONLY_COMMANDS_AVAILABLE`（与 `backendReady` 解耦——即便 W5 运行时未就绪，只读校验仍可用）。
  - `Promise.all` 并发拉取 `bridge.{skillValidate,skillParse,skillPermissionPreview}(text)`；`skillParse`/`skillPermissionPreview` 失败 `.catch(()=>null)` 不影响校验结论。
  - 落态前做 **secret 纵深脱敏**：`sanitizeErrors` 对错误串、`sanitizeSkillDef`/`sanitizeAgentDef` 对解析 def 的 `description`/`systemPrompt` 跑 `SECRET_REDACT_PATTERNS`（`sk-`/`AKIA`/`Bearer `/`eyJ..`JWT`/`PRIVATE KEY`），兜底后端已做的 CredentialLeak Display 脱敏。
- **`clearValidation()`**：清空六态回 `empty`。

类型来源均为既有 `src/types.ts`（`ValidationReport`/`PermissionPreview`/`SkillDef`/`AgentDef`），未新增类型；桥函数均为 bridge.ts 既有封装，未改命令名/载荷。

## 4. 交付物 2：纯 UI 逻辑测试 §11（`scripts/check-agent-skill-ui-logic.mjs`）

§11 设计（全部经 store 动作 + mock bridge 驱动，反映产品代码行为）：
- **确定性空态** W9-1/2/3：`clearValidation()` 后 `skillStatus/agentStatus==="empty"`、有界预览无溢出。
- **loading 优先** W9-4：`loading=true` 时 `skillStatus==="loading"` 压过其它态。
- **串联消费** W9-5/6/7/8/9：即便 `backendReady=false`，`validateSkill` 仍发出 `skill_validate`（只读路径不被 install/run 拦截）；结果 `valid=true`、解析出 `def`、回传 preview、`status==="ok"`。
- **错误态 + 不回显 secret** W9-10/11/12/13：校验失败 → `error` 态；普通错误可见；错误串中 `sk-ABCDE12345678` 经脱敏后不在状态里；原始输入文本（`skillInputText`/`lastInput`）绝不进 store。
- **有界预览** W9-14/15/16：100 项能力 → 展示前 20、`overflow=80`、`total=100`（不丢信息）。
- **agent 对称路径 + prompt-secret 不进状态** W9-17/18/19/20：`validateAgent` 发出 `agent_validate`、回 `ok` 态、`safe` 预览；解析出的 `AgentDef.systemPrompt` 中 `sk-ZZZ99999999999` 已脱敏，不落前端状态。

→ 覆盖 W9 A6 全部三项打磨目标（确定性态 / 不回显 secret / 有界预览），且对「只读桥是否已进 mainline」零硬依赖——`validateSkill` 经真实桥 mock 驱动，桥缺失时动作 no-op（只读开关为 const true，测试未伪造关闭路径）。
