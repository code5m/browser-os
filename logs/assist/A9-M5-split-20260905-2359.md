## 3. 数据库化知识图谱（M5-7~9，数据库支持）

**存储 = 随 M4 数据层，不再自建存储。**
`database-schema-taskcard` 的 D1 决策点与 M4-1 同源，A2 冻结 `SupportedDb` + rusqlite(bundled) 后**该决策已实质关闭**：`graph_node/graph_edge/graph_event/graph_meta` 作为独立迁移文件（如 `00N_graph.sql`）挂在同一 SQLite 实例，邻接表 + `ON DELETE CASCADE`，不引任何图数据库/重服务（沿用红线）。

**数据流：**

```
上游变更（Artifact/Repo/Script/Task/Skill 落库）→ GraphEvent(seq 自增) → 抽取器消费
  → 阶段一(确定性: URL/路径/#tag/@person/code-ref/front-matter) upsert 节点/边
  → 阶段二(语义, AI) 仅预留 trait SemanticExtractor 接口，标 source=ai 可校正
```

- 稳定 id：`{kind}:{natural_key sha256[:8]}`（幂等，禁随机 uuid——重抽/增量依赖）。
- 查询硬约束：`depth ≤ 2` 拒绝、limit≤1000、`truncated` 标志、隐私过滤在**查询层**（`max_privacy`，Agent 默认 `public`），凭据绝不进图谱。
- 容量：节点 5 万 / 边 20 万 / 度 500 / `sources≤20` / 事件表 90 天或 10 万条。
- 审计：`graph_rebuild`/`graph_prune`/restricted 越权访问记 `audit.json`；每次查询/事件消费**不记**（K5）。

**关键缺口已随 M4 收窄：** 旧卡"上游模型未落地只能 Artifact-only 建图"将在 M4 后解除（Script/Task 数据由 M4-7/A7、M4 数据层落地）；重画"Artifact-only 起步"边界即可。

## 4. 定时任务驱动图谱更新（M4-6/7 → M5 联结点）

M4-7/A7 交付 scheduler 后，M5 可把图谱维护做成**派生索引 + 调度**两层：

| 触发 | 机制 | 依赖的 M4 产物 |
|---|---|---|
| 实时增量 | 上游写后发 `GraphEvent`（app 内事件，不经 scheduler） | M4 数据层落库钩子（A3/A4 写路径） |
| 周期校验/重建 | `task_*` 注册一条内部维护任务（interval ≥60s / cron 5 段），周期执行 `graph_rebuild`/`graph_verify`/`graph_prune` | A7 `task_add` 命令 + `script_runner`（复用，无第二执行路径） |
| 溯源补采 | `task-runs.json` 历史 → `Task→Script/Artifact` 边 | A7 运行记录 |

**复用规则（与 A6 冻结口径一致）：**
- 判重/触发以 `tasks.json` 为准；图谱任务同样 `enabled=false` 默认 + `last_fired_at` 判重。
- 非重叠：单任务单实例（超长 rebuild 不能被下一 tick 顶掉）。
- 审计低频：rebuild 开始/结束、prune 记 `audit.json`；tick 内禁写审计（坑位⑤）。
- 退出：scheduler 停 → 图谱维护任务随 `stop-scheduler` 收口；图谱自身 `GraphShutdown`（flush 待写 + 关连接）注册在协调器尾部。
