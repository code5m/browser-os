# M1-6 强模型最小输入卡（≤80 行）

> 来源：M1-6-assist-20260901-1629.md。仅给 AI:DEEP/R:high，本卡不实现、不签 PASS。

## 目标
在已有"推送成果"专用流程外，评估是否开放 Git 通用写命令（commit/branch/checkout），并落地越权防护 + 确认闸门 + 审计。**当前结论：写命令须经三级闸门 + 白名单 + fail-closed。**

## 必改文件
- `src-tauri/src/bridge.rs`：新增 `git_write` 类命令（若开放），统一走 `request_sync`/`confirm_sync` 双阶段范式。
- `src-tauri/src/sync.rs`：复用 `git2` + `cred_cb` + `KeyringStore`，不新建凭据逻辑。
- `src-tauri/src/domain.rs`：复用 `AuditEntry`，新增 `git_write`/`git_write_failed` 审计 action。
- `security_policy.rs`/`permissions`：写操作类型白名单 + ACL。

## 禁止事项
- 不开放白名单外操作：`reset --hard`/`checkout .`/`push --force`/`branch -D`（或标 `dangerous` 二次确认）。
- 不把 token/明文凭据写日志/`AuditEntry.detail`。
- 不绕过 `confirm_sync` 闸门另建旁路。
- 不在 `data_dir/repos/<id>` 外执行写命令。
- 不移动 `NEXT`。

## 实现要点
1. 三级闸门：预检（repo_id 合法 + path 在 `data_dir/repos/<id>` + 操作白名单）→ 确认（破坏性操作生成预览弹框）→ 审计（前后各写 `AuditEntry`）。
2. 路径锁定：`canonicalize` 校验工作目录在 `data_dir/repos/<id>` 内（仿 M2-1 §5）。
3. 凭据隔离：author/committer 用 `RepoConfig.username`；token 仅 `push` 时经 `Cred::userpass_plaintext` 传入。
4. fail-closed：类型不在白名单 / 确认未过 / 路径校验失败 → 直接 `Err`，不执行。
5. 写命令加 `check_invocation_source`（仿 `report_resources`）。

## 反向用例（域模型）
- T-gw-1 未确认 `git_commit` → `Err("需确认")`。
- T-gw-2 `git_reset_hard` 白名单外 → `Err("操作禁止")`。
- T-gw-3 repo_id 指向 `/etc` → `Err("仓库未配置")`。
- T-gw-4 `git_push` force → `Err("禁止 force push")`。
- T-gw-5 正常已确认 → 成功 + 审计 `git_write`。
- T-gw-6 命令报错 → 审计 `git_write_failed`，token 不泄露。

## 失败动作
- 闸门冲突（新增写命令不经 confirm_sync）→ 退回复用双阶段，不新建。
- 路径校验缺失 → 补 `canonicalize` 后重测 T-gw-3。
- 凭据泄露风险 → 审计字段去敏，复测 T-gw-6。
