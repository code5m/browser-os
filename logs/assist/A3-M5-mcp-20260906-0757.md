## 0. 摘要（给 A0 / 后续 Lane）

M5-2 要「内嵌纯 Rust `rmcp` MCP Server + `McpGlobalPolicy` 全局护栏」（`详细设计与实施计划.md:500,563`）。
本预研用**实测证据**回答四件事：命令注册表形态、全局策略面、`rmcp` 可行性、no-npm 规则。

**核心结论（3 条）**

1. **可行，但有一个必须先裁决的冲突**：`rmcp` 3.2.0 把 `tokio` 列为 **normal 非 optional** 依赖
   （features `sync,macros,rt,time`），而 M4-1.a 冻结的 F-1 是「**不引 tokio 直接依赖**」。
   冲突性质不是"新拉一个没见过的库"（`tokio 1.53.1` 早已在锁里，见 §3.2），
   而是"异步编程模型会不会扩散进主二进制"。**建议解：MCP Server 落独立 crate/bin，只依赖 `mvp-core`（A2 提案）**，
   主二进制依赖图与同步模型不变，F-1 红线原样保持。
2. **命令注册表现状不干净，MCP 工具注册表不能建在它上面**。
   实测：`main.rs` 的 `generate_handler!` 有 **115** 个唯一命令，ACL `default-commands.toml` 有 **114** 条，
   差集 = `open_tool`（在 handler + `src/bridge.ts:97` 有调用，但**不在 ACL**，且
   `capabilities/default.json` 只授权 `default-commands`）→ 这是一处真实的**运行时会被 ACL 拒绝**的缺口（§2.2 F-1）。
   **没有任何脚本做 handler↔ACL↔前端三处全量奇偶校验**（§2.3）→ MCP 首卡必须先把这条门禁补上，否则工具注册表会掩盖同类缺口。
3. **no-npm 规则天然满足**：MCP 全在 Rust 侧，前端零改动；`package.json` / `package-lock.json` 的 SHA256
   实测与现有门禁锚点**逐字符一致**（§5）。需要新增的是"禁 npm MCP SDK"这一类门禁，而不是放宽现有锚点。

**需要 A0 书面裁决 6 项（§7）**，其中 **B1（tokio/F-1）与 B2（传输与端口）不裁决则 M5-2.a 无法开工**。

## 2. 现状实测（一）命令注册表形态

### 2.1 三处真源与实测数字

| 真源 | 位置 | 实测 |
|---|---|---|
| 命令实现 | `src-tauri/src/bridge.rs`（6070 行）+ `tools.rs`（302 行） | — |
| 注册 | `src-tauri/src/main.rs:1308` 起的 `tauri::generate_handler![...]` | **115 个唯一命令**（`bridge::*` 113 + `tools::list_tools` + `tools::open_tool`） |
| 权限 | `src-tauri/permissions/default-commands.toml` | **114 条**（113 条带尾逗号 + 末位 `list_artifact_images` 无逗号） |
| 能力绑定 | `src-tauri/capabilities/default.json` → `permissions: ["default-commands"]` | 主窗口 `main` 唯一许可集 |
| 前端 | `src/bridge.ts` `invoke("...")` | — |

> 计数口径：`main.rs` 1308 行起至首个 `])` 之间正则提取 `(?:bridge|tools|terminal)::(\w+)` 去重；
> ACL 取 `^\s+"(\w+)",?` 全量。**`terminal::*` 未走 handler**（M3 的 `term_spawn_channel` 等在 ACL 与 handler 中
> 均以 `bridge::` 前缀注册），故计数里没有独立 terminal 项。

### 2.2 F-1（发现）：`open_tool` 在 handler 与前端，但**不在 ACL**

| 证据 | 位置 |
|---|---|
| 已注册进 handler | `src-tauri/src/main.rs:1411` → `tools::open_tool` |
| 前端确实在调 | `src/bridge.ts:97` → `openTool: (id) => invoke<void>("open_tool", { id })` |
| **ACL 无此条目** | `grep -n open_tool src-tauri/permissions/ src-tauri/capabilities/` → **零命中** |
| 主窗唯一许可集只有 `default-commands` | `src-tauri/capabilities/default.json` |

→ `default-commands` 未包含 `open_tool`，而 `default.json` 只授予 `default-commands`，
按 Tauri v2 ACL 语义，前端 `openTool()` 的调用应被拒绝。

**性质判定**：这是「命令注册三处真源不同步」的既有缺口，**不是 M5-2 引入的**。
本 Lane 是 DOCS ONLY 且 `open_tool` 不属 A3 在 M4 的 DB 范围，故**不修**，按 §7 B5 上报 A0/A11。

**对本卡的直接影响**：MCP 工具注册表天然会"扫描 handler 生成工具清单"。若照此实现，
`open_tool` 这类**注册了但没权限**的命令会被 MCP 一并暴露，形成"前端被 ACL 挡住、MCP 却能调"的**权限倒挂**。
因此 MCP 工具清单的真源必须是**能力白名单**（§4.1），而不是 `generate_handler!` 的机械扫描。

### 2.3 F-2（发现）：没有「全量三处奇偶」门禁

只有 4 个脚本各自校验**自己那一条**命令的 ACL 存在性，无人做全量比对：

- `scripts/check-tools-policy.py`（只查 `list_tools`）
- `scripts/check-scheduler-policy.py`（只查 `task_*`）
- `scripts/check-database-policy.py`（只查 `db_*`）
- `scripts/check-resource-capture-policy.py`（只查 4 个资源命令）

`scripts/check-command-domain-policy.py` 读取 ACL 文本，但用于 `snippet_*` / `run_command` 的专项不变量，
**不做 handler↔ACL 全量奇偶**。→ 这解释了 F-1 为何能一路活着进 `master`。

### 2.4 来源校验（MCP 的护栏缺口）

```1138:1148:src-tauri/src/bridge.rs
fn check_invocation_source(
    webview: &tauri::Webview,
    scope: &str,
    intent: Option<&str>,
    app: &AppHandle,
) -> Result<(), String> {
    use crate::security_policy as sp;
    let registry = app.state::<sp::IntentRegistry>();
    sp::check_remote_invocation(webview.label(), scope, intent, &registry)
        .map_err(|e| e.to_string())
}
```

关键点：入参是 `&tauri::Webview` 且以 **`webview.label()`** 作为来源身份。
**MCP 请求没有 webview** —— 这是 MCP 接入时最大的护栏缺口：
要么伪造一个 label（红线，禁止），要么为 MCP 单列一条来源通道（§7 B3）。

## 3. 现状实测（二）`rmcp` 可行性

### 3.1 crate 事实（在线核验，2026-09-06）

- `rmcp` 存在于 crates.io，`max_stable_version = 3.2.0`，`updated_at = 2026-08-31`
  （`GET https://crates.io/api/v1/crates/rmcp`）。
- **首层 normal（非 optional）依赖中明确含 `tokio ^1`，features = `sync,macros,rt,time`**
  （`GET /api/v1/crates/rmcp/3.2.0/dependencies`）。另有 `futures`、`tokio-util`、`tracing`、
  `thiserror`、`serde`、`serde_json`、`chrono`、`indexmap`、`pin-project-lite` 为 normal。
- 传输相关均为 **optional**：`hyper`（client,http1）、`sse-stream`、`axum`（仅 dev）、`process-wrap`、`reqwest`。
  → **stdio 传输可不启用任何 HTTP/SSE 特性**，这对"禁监听端口"红线是利好。

### 3.2 依赖树事实（本地实测）

```
cargo tree -i tokio --manifest-path src-tauri/Cargo.toml
tokio v1.53.1
├── postgres v0.19.14            （M4-1.a 引入，同步客户端，内部 tokio-postgres）
├── tauri v2.11.5
├── tauri-plugin-single-instance v2.4.4
└── tokio-postgres v0.7.18 → tokio-util v0.7.19
```

- `Cargo.lock` 共 **593** 个 package；`tokio 1.53.1` **已在树中**。
- 即：加 `rmcp` **不会新拉一个陌生的 async runtime 进二进制**，只会把已有的 tokio 从"别人在用"变成"我们也要建 runtime 来驱动"。

### 3.3 冲突与建议解

| 项 | 事实 |
|---|---|
| 红线 | M4-1.a F-1：**不引 tokio 直接依赖**（std::thread + Condvar 实现调度） |
| 冲突 | `rmcp` 的 API 是 async-only，调用方必须自建 tokio runtime → 等于把 tokio 变成"我们的"直接依赖 |
| 建议解 | **MCP Server 落独立 crate/bin**（`crates/mvp-mcp` 或 `src-tauri/src/bin/mcp_server.rs`），只依赖 `mvp-core`（A2 §3）+ `rmcp` + `tokio`。主二进制 `Cargo.toml` 依赖图与同步模型**零变化**，F-1 原样成立 |
| 备选（需 A0 书面豁免） | 把 `tokio` 提为直接依赖并限定"仅 mcp 模块可用"，由 `scripts/check-mcp-policy.py` 断言 `tokio::` 只出现在 mcp 相关文件 |
| 不建议 | 自研 MCP 协议栈。MCP 是事实标准，自研会失去生态互操作，且要自己维护 JSON-RPC/能力协商/取消语义 |

### 3.4 传输：三条候选的实测评估

| 传输 | 仓库先例 | 暴露面 | 建议 |
|---|---|---|---|
| **stdio（NDJSON / JSON-RPC 2.0）** | 有 argv 早返回先例（§3.5） | **零端口**，身份 = "谁能启动这个进程" | ✅ **首期唯一推荐** |
| UDS（Unix Domain Socket） | `src-tauri/src/grid_ipc.rs`：UDS + 行分隔 JSON，Request/Response/Event 三帧 | 需文件权限控制（0600），有 socket 文件残留/复用问题 | ⚠️ 备选（第二阶段，可复用 `grid_ipc` 线协议风格） |
| TCP / HTTP+SSE | 无 | 局域网可达，历史上多个 MCP 实现 0day 源于默认 `0.0.0.0` | ❌ 首期禁止；若要，需 A0 书面接受并强制 `127.0.0.1` + 鉴权 |

### 3.5 启动方式：已有可直接照抄的 argv 先例

## 4. 契约提案（Contract Proposal）

> 全部为提案，M5 Wave 0 **不落任何代码**。类型签名供 A1 展开子卡时直接引用。

### 4.1 单一能力真源 `capability.rs`（MCP 与 Agent/Skill 共用）

继承 `M5-7.a` 的 `CapabilityManifest` / `Capability` 草案，收敛三条硬规则：

```rust
pub struct Capability {
    pub name: String,             // "artifact.list"
    pub maps_to: String,          // 必须是一个**已注册且已在 ACL 中**的命令名
    pub risk: RiskLevel,          // Read | Write | Execute | Dangerous
    pub requires_confirm: bool,
    pub requires_policy: Option<String>,   // 需显式策略开关才可用（默认关闭）
    pub params_schema: serde_json::Value,
}
```

1. **真源是白名单常量表，不是 `generate_handler!` 扫描**（F-1 直接推论）。
2. 每个 `maps_to` 必须在**同一提交**内通过"三处奇偶"：handler 已注册 ∧ ACL 已允许 ∧ `McpGlobalPolicy` 未禁用。
   建议由 `scripts/check-mcp-policy.py` 断言，并**顺带把全量奇偶门禁补上**（见 §6 第 2 条）。
3. `capability.rs` 与 A5（M5-4/5 Skill）、A9（M5-10/11/12 插件）**共用同一份**，防能力定义漂移。

### 4.2 `McpGlobalPolicy`（fail-closed）

```rust
pub struct McpGlobalPolicy {
    pub enabled: bool,                       // 默认 false
    pub read_only: bool,                     // 默认 true
    pub allow_dangerous_sql: bool,           // 默认 false
    pub allowed_connection_ids: Vec<String>, // 默认空 = 一个都不许
    pub max_rows: usize,                     // 复用 M4-1.c 行上限
    pub max_bytes: usize,                    // 复用 M4-1.c 字节上限
    pub request_timeout_secs: u64,           // 默认 30
}
```

硬规则：

- **解析失败 / 字段缺失 / 未知字段 → 视为最严格配置**（`read_only=true` 且全禁用），绝不通融。
- **不得在 MCP 层重造任何分类器**。必须调用 `security_policy.rs` 的现有纯函数：
  `classify_sql_risk`(915) / `is_write_statement`(969) / `is_production_database`(1015) /
  `require_write_confirmation`(1075) / `evaluate_db_query_gate`(1138) / `redact_sensitive_url`(416) /
  `check_text_field`(462) / `check_items_count`(473)。
- 首期 `RiskLevel` 只开放 `Read`；`Write`/`Execute`/`Dangerous` 一律不在白名单内（沿用 M5-7.a §4.1 结论）。

### 4.3 审计与隐私

| 项 | 要求 |
|---|---|
| 每次工具调用 | 写 `log_audit`，复用现有 1000 条 FIFO 上限 |
| detail 内容 | 只含 `capability` 名 + 结果计数 + 耗时；**禁** SQL 正文、参数值、DSN、密码、token、Cookie/Authorization/Set-Cookie |
| URL | 一律经 `sp::redact_sensitive_url` |
| 凭据 | 只能经 `keyring_store`；MCP 进程**不得**持有/回显凭据，db 工具走 `database::credential_key`（`db:<conn_id>`）在进程内取用 |
| 容量 | 请求 ≤ 1 MB、响应 ≤ 5 MB（超则截断并打标记，沿用 M5-7.a §4.2） |

### 4.4 生命周期

- MCP Server 必须注册进 `ShutdownCoordinator`（`shutdown.rs:85 register(name, task)`），
  顺序要求与 M4-7 的 `stop-scheduler` 同款：**在 `kill-running-scripts` 之前**停止接受新请求。
- MCP 进程模式（`--mcp-server`）走独立退出路径：stdin EOF → 排空在途请求 → 退出码 0。
- **禁止** MCP 层出现 `std::process::Command` / `sh -c` / 第二条执行路径：
  执行类能力（若将来开放）只能 `maps_to` 到既有 `run_script` / `run_command`，复用 M2-4 `script_runner`。

> **R-A** 构建体积：`rmcp` + `tokio` 会增大独立 bin；若最终并进主二进制，会冲击
