上面真正属于**产品层面的减法**，主要提了 4 项。

## 1. 减少同时运行的原生 WebView 数量

你现在接近：

```text
一个页签 = 一个原生 WebView
```

建议改成两种方案之一：

### 方案 A：只保留 1 个活动 WebView

页签只保存：

- URL
- 标题
- 图标
- 会话信息

只有当前页签真正加载网页。

优点是最简单，几乎消除多 WebView 的遮挡、尺寸漂移和恢复竞态；缺点是后台页签不能持续运行。

### 方案 B：固定 WebView 池，最多 4 个

推荐用于你的宫格场景：

```text
普通模式：1 个 WebView
2×2 宫格：最多 4 个 WebView
其他页签：只保存元数据和会话
```

这样即使有 100 个页签，原生 WebView 也最多只有 4 个。

**这是我最推荐的产品方案。**

---

## 2. 取消“关闭页签三选一确认框”

现在关闭页签时出现：

```text
保存
删除
取消
```

这一个交互引入了大量复杂度：

- 弹窗遮挡
- 暂停 WebView
- 隐藏 WebView
- 取消后恢复
- 保存与删除分支
- 异步竞态

建议改成：

```text
关闭页签 → 自动保存会话 → 立即关闭
```

然后另外提供：

- 最近关闭的页签
- 撤销关闭
- 会话管理页面
- 在会话管理页中彻底删除

也就是：

```text
关闭：默认安全保存
删除：放到专门的管理页面
误关闭：可以恢复
```

这样用户操作更直接，代码也会简单很多。

---

## 3. 考虑恢复系统原生标题栏

当前自定义无边框窗口，需要自己处理：

- 拖动
- 双击最大化
- 最小化
- 关闭
- Wayland/X11 差异
- Tauri 拖动权限
- WebKitGTK 事件冲突

产品上可以考虑恢复 Linux 系统标题栏：

```text
decorations: true
```

系统直接负责：

- 窗口拖动
- 最大化
- 最小化
- 关闭
- 双击标题栏
- 桌面环境兼容

代价是界面没有完全自定义标题栏那么统一。

如果产品视觉必须保留无边框，那么就继续保留，但要将拖动区域固定，不允许其他组件随意修改。

---

## 4. 禁止普通 HTML 浮层覆盖网页区域

制定明确的产品交互规则：

> 浏览器网页区域上方不出现普通 HTML Toast、Popover、Dropdown 或 Modal。

建议调整为：

- 新建页签成功：不提示，因为新页签本身就是反馈。
- 普通状态：显示在底部状态栏。
- 错误：显示在固定错误面板。
- 设置、会话管理：使用独立页面或侧边栏。
- 必须确认的危险操作：进入独立管理页执行。
- 不让组件自行弹 `position: fixed` 浮层覆盖网页。

这样就从产品设计上避开 Linux 原生 WebView 的层级问题，而不是每次出现浮窗后再想办法隐藏 WebView。

---

# 合并后的推荐产品形态

我上面最终建议的是：

```text
页签数量：可以很多，只保存元数据
原生 WebView：最多 4 个
普通浏览：使用 1 个 WebView
宫格浏览：最多使用 4 个 WebView
关闭页签：自动保存并直接关闭
误关闭：通过“最近关闭”恢复
彻底删除：到会话管理页面执行
成功提示：不弹浮窗
错误和状态：只在状态栏或独立面板显示
窗口标题栏：能接受就恢复系统原生标题栏
```

按降低复杂度的收益排序：

1. **关闭页签改为自动保存，不再弹三选一确认框**
2. **把原生 WebView 数量限制为最多 4 个**
3. **禁止网页区域上的 HTML 浮层**
4. **恢复系统标题栏**

其中前两项对项目复杂度下降最明显。
