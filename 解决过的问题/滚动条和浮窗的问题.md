对，你说的是刚才那一组 **浮窗/确认框被网页遮挡 + 外壳滚动条异常** 的问题。

当时不是靠单纯调 `z-index` 解决的，核心是确认了一个架构事实：

**Linux 下浏览器页签是原生子 WebView，它的窗口层级高于主界面的 HTML/Vue。**
所以像 toast、确认框这类普通 HTML 浮层，即使写 `z-index: 99999`，也可能被原生 WebView 盖住。

刚才实际上分三部分处理：

1. **新建页签提示**
   原来的“已新建页签”黑色 toast 会进入 WebView 覆盖区域，所以先把这种浮动提示移除。你后面又明确说“新建页签不需要任何提示”，于是最终就是彻底不显示成功提示。

2. **关闭页签确认框**
   这是关键修复。显示关闭确认框时，不再试图让 HTML 弹窗硬压过 WebView，而是：
   **临时暂停/移开原生 WebView → 显示关闭确认框 → 用户完成选择 → 再恢复 WebView。**

   所以你后面实测看到：
   - 关闭框完整可见
   - 不再被网页盖住

   这才是真正解决“浮窗遮挡”的办法。

3. **横向/纵向滚动条**
   一开始只在页签栏里隐藏横向 scrollbar，但你后来反馈纵向也有，而且页面布局被挤坏。
   后面继续修了两层：
   - 页签栏 `overflow-y: hidden`
   - 主外壳/主 WebView 尺寸持续校正，而不是只在启动时校正一次
   - 主页面整体禁止因为尺寸漂移产生额外外壳滚动条

   后来你实测确认：**纵向外壳滚动条消失了。**

最关键的一次修改是这个思路：

> **不要让 HTML 浮层和原生 WebView 争层级，而是在弹窗出现时主动处理原生 WebView 的显隐/位置。**

同时还补了一个原生层面的修复：之前创建多个 WebView 后，只持续校正各个网页的尺寸，**主界面本身只在启动时校正一次**。后来给主界面也补了持续的 native layout / physical size 校正，这正是解决“确认框被挤、纵向滚动条出现”的重要一环。

所以这次你重新打包安装，真正要验证的是：

- 新建页签：**不出现任何成功提示**
- 关闭页签：**确认框完整显示在最前面**
- 点击取消：**原网页正确恢复**
- 页面右侧：**没有外壳纵向滚动条**
- 页签很多时：**没有顶部系统横向滚动轨道**
- 多次开关页签后：**WebView 不错位、不残留、不被隐藏**

这组问题本质上已经从“CSS 浮层问题”升级成了 **Linux 原生 WebView 窗口层级与生命周期管理问题**。之前单纯改 `z-index` 是治不了根的。
